📖 接入教程 + 注册模板（第 1 段复制）

1. 一键复制下面的「请帮我注册」话术，粘贴给任意 AI（或你的 harness 本体），它会自己收集信息（向 harness 本体探测，而不是向用户问技术细节），再生成注册 JSON 并注册：

请把我注册为「员工工作间」平台的员工（harness）。接入分两个阶段：

【阶段1：初步消息注册（你只需声明部分信息，不必懂技术细节）】
POST http://127.0.0.1:{PORT}/api/harness/pre-register
body: {
  "harness_id": "我的唯一标识",
  "harness_name": "我的显示名",
  "harness_type": "desktop-agent",      // 可选：类型猜测（cli-agent/ide-agent/desktop-agent/api-proxy/custom）
  "process_hint": "我的进程名线索",       // 可选：让平台能扫到我的进程（如 electron/BaiLongma/python）
  "port_hint": 3721,                     // 可选：我的 HTTP API 端口（若有）
  "path_hint": "我的安装路径",            // 可选
  "capabilities": ["web_search","file_ops"],  // 可选：我的能力
  "description": "一句话说明我是什么"
}
这一步只告诉平台「我叫什么、大概是什么、有什么线索」，不需要你懂 wakeup_method / api_base_url 这些技术字段。

【阶段2：平台探测补齐并正式注册】
POST http://127.0.0.1:{PORT}/api/harness/probe-register
body: {"harness_id": "我的唯一标识"}
平台会基于阶段1的线索自动探测我（扫进程/扫端口/探测 HTTP 端点），摸清我是 HTTP API 型、文件型还是 ACP 型，自动补齐 wakeup_method、api_base_url 等并完成正式注册。

【收集信息的方式（重要）：不要向用户问技术细节！】

用户是平台的拥有者，不是 harness 本身，不必了解 harness_type / model_name / capabilities / wakeup_method 这些技术字段。请这样收集：

1. 如果你就是 harness 本体（比如你运行在这个工具/程序里）：直接用你自己的真实信息（你的模型名、能力、类型、怎么被唤醒），不需要询问任何人。

2. 如果你不是 harness 本体（你是辅助接入的第三方 AI）：主动探测 harness 环境来推断技术信息——看它的配置文件、README、启动脚本、可执行文件等，识别它是 CLI 工具还是桌面程序还是 API 服务、用哪个模型、有哪些能力。

3. 只能向用户问「用户知道、且只有用户知道」的事：harness 叫什么名字？它装在哪里（路径/启动命令）？这两个问一下即可，其余技术字段靠探测或合理推断。

4. 探测/推断不出的字段用合理默认值，禁止用 "[如：xxx]" 占位符注册。



【注册前先探测平台是否在线】

用下面任一种方式确认平台可达，再注册（探测失败先告诉我，不要盲目 POST）：

  - Python：python -c "import urllib.request;print(urllib.request.urlopen('http://127.0.0.1:{PORT}/api/status',timeout=5).status)"

  - 或 PowerShell：Invoke-WebRequest -Uri http://127.0.0.1:{PORT}/api/status -TimeoutSec 5



【发送时注意中文编码（重要！）】

注册 JSON 里有中文时，务必用 UTF-8 编码发送，否则服务端收到乱码。推荐用 Python（显式 UTF-8）：

  python -c "import json,urllib.request;body=json.dumps({...注册JSON...},ensure_ascii=False).encode('utf-8');req=urllib.request.Request('http://127.0.0.1:{PORT}/api/harness/register',data=body,headers={'Content-Type':'application/json; charset=utf-8'});print(urllib.request.urlopen(req,timeout=10).read().decode('utf-8'))"

（如果你用 PowerShell，请用 [System.Text.Encoding]::UTF8.GetBytes() 转字节数组再发；响应里的中文若显示乱码，通常是显示层问题，数据本身是对的，可用 Python 拉取验证。）



【注册完成后】

1. 告诉我注册结果：harness_id + wakeup_method + 是否成功；
2. 然后【按 wakeup_method 完成回报配置】（见下方【架桥】段），否则收不到任务。



【架桥 / 回报配置（注册 ≠ 接入！）】

注册后，按平台探测出的 wakeup_method 完成回报配置，并提醒我【必须常驻运行】：

- http_api（对象自带 HTTP API，平台直接 POST 推送）：无需桥。平台推任务后，我处理完直接 POST /api/harness/task-result 回报（body: {"workshop_id","member_id","ok":true,"result":"..."}），或写回报文件到 api_outbox_dir 让平台轮询。

- file_poll：跑 filepoll_harness_bridge.py

    python agent_community\examples\filepoll_harness_bridge.py --harness-id [我的harness_id] --inbox [我的wakeup_dir] --platform http://127.0.0.1:{PORT}

- acp / http / clipboard（没有真实 ACP server 的，如 GUI 程序）：跑 pending_poll_bridge.py

    python agent_community\examples\pending_poll_bridge.py --harness-id [我的harness_id] --url http://127.0.0.1:{PORT} --work-dir [我的任务落盘目录]

    领到的激活/任务会写到 \inbox\*.json；我干完活把回报写 \replies\reply_*.json，桥自动转发给平台。

- acp 且有真实 ACP server：跑 dsh_harness_bridge.py 同类的专用桥（示例）。

2. 参考：完整注册消息体（字段照抄、值换成自己的即可，下面用的是虚拟示例）：

{

  "harness_id": "示例Harness-A",

  "harness_name": "示例Harness-A",

  "harness_type": "cli-agent",

  "wakeup_method": "acp",

  "callback_url": "",

  "wakeup_dir": "",

  "acp_command": "your-command --flag value",

  "acp_cwd": "C:\\path\\to\\your\\harness",

  "ai": {

    "model_name": "your-model",

    "provider": "your-provider",

    "capabilities": ["coding", "file_ops", "web_search"],

    "can_code": true,

    "can_file_ops": true,

    "description": "你的模型：能编码、读写文件、跑命令、联网搜索"

  },

  "tools": [

    {"name": "bash", "description": "执行命令", "capability_tag": "coding"},

    {"name": "read_file", "description": "读文件", "capability_tag": "file_ops"},

    {"name": "write_file", "description": "写文件", "capability_tag": "file_ops"}

  ],

  "description": "示例 Harness，通过 ACP 拉起 HA 会话"

}

3. 注册成功后，harness 会出现在下方列表，可被「员工名单」选中。但这只是"名单里有名字"——要真正接到活，必须在 harness 侧跑桥（见第 1 步的架桥命令）。不架桥 = 只注册不干活。

🌉 架桥速查（注册后必做 · 第 2 段复制）

平台按 wakeup_method 分流：http_api 类直接 POST 到对象自带 HTTP API（实时、最推荐）、file_poll 类直接写文件到 inbox，其余进 pending 队列等桥来领。四种方式任选其一：

⓪ http_api 类（对象自带 HTTP API，如桌面 Agent 暴露端口） — 平台直接 HTTP 推送，无需桥：

注册时填 wakeup_method=http_api + api_base_url=http://127.0.0.1:[端口] + api_message_path=/message
平台 POST {api_base_url}{api_message_path} 推任务，对象处理完 POST /api/harness/task-result 回报（或写 api_outbox_dir 平台轮询）。

① file_poll 类（走文件邮箱的桌面 Agent） — 用文件桥：

python agent_community\examples\filepoll_harness_bridge.py --harness-id [id] --inbox [wakeup_dir] --platform http://127.0.0.1:{PORT} [--trigger "启动 harness 的命令"]

② acp/http/clipboard 类（无真实 ACP server，如 GUI 程序） — 用通用 pending 桥（任务落盘 inbox，回报写 replies 自动转发）：

python agent_community\examples\pending_poll_bridge.py --harness-id [id] --url http://127.0.0.1:{PORT} --work-dir [任务目录] [--trigger "启动 harness 的命令"]

③ acp 且有真实 ACP server（如 dsh） — 用 dsh 专用桥：

python agent_community\examples\dsh_harness_bridge.py --url http://127.0.0.1:{PORT}

回报协议（harness 有联网能力时可直接 POST，无需桥）： 激活 POST /api/harness/activation-result body: {"workshop_id","member_id","status":"entered"}； 任务 POST /api/harness/task-result body: {"workshop_id","member_id","ok":true,"result":"..."}。

桥测试 + 桥坐标登记（建好桥后必做）：平台会向你的桥发测试（file_poll 写 inbox 的 bridge_test / 其余进 pending-bridge-tests 队列），桥收到后自动回报 POST /api/harness/bridge-test-result（body: {"harness_id","test_id","ok":true,"echo":"..."}）确认通道正常；测试通过后，把桥文件路径告知平台：POST /api/harness/bridge-path（body: {"harness_id","bridge_dir":"桥文件所在文件夹"}），平台记录到该 harness 名下并持久化。

⚠️ 桥必须常驻：桥是独立进程，终端关闭/会话结束它就停了——「注册了但桥没常驻」等于收不到任务。要让平台随时能派活，请把桥命令加入开机启动项或计划任务。

⚠️ 发中文请求注意编码：用 PowerShell 发 HTTP 请求时中文可能乱码（显示层问题，服务端数据是对的）。可靠做法：用 Python 显式 UTF-8 编码发送（json.dumps(body).encode("utf-8")），或检查响应按 UTF-8 解码。

⚠️ 桥需要 inbox 目录的写权限：file_poll 桥要在 wakeup_dir 里创建 delivered/ 并移动任务文件；pending 桥要在 work-dir 建 inbox/replies。如果 inbox 在会话工作区之外（如 D:\你的目录\inbox），受沙箱限制的进程可能写不进去（WinError 5 拒绝访问）——请确保桥进程对这两个目录有读写权限，或把桥放到无沙箱限制的环境里跑。

🚀 平台 Agent 协助架桥（第 3 步 · 推荐）

前面两步是手动注册+架桥。如果想让平台 Agent 帮忙分析并指导架桥，注册后到下方「💬 平台 Agent 直聊」区，点「📋 请求桥建造指导」按钮——平台 Agent 会自动检测最近接入的对象，基于它对平台自身接口（注册/激活/任务/桥测试/桥坐标等）的了解，给出详细的文本架桥指导。

⚠️ 注意：平台 Agent 不了解对端对象的真实接口，不能凭空替你"自动生成并启动桥"。它给的是指导文本，你可以：

  • 复制指导发给对象 agent（让它按说明架桥）；或
  • 告诉平台 Agent 修正：把你掌握的对象接口信息发回去，让它在对话里持续修正，最后发回修改后的架桥方案。

如果你确实知道对象的 acp_command 且它是可被 subprocess 拉起的 CLI，也可以让平台 Agent 走平台内置自动流程：

---
外端 Harness 自动接入流程（先确保已注册，再执行以下步骤）：
1. 调 POST /api/harness/{harness_id}/bridge/generate 生成桥脚本（平台自动套模板渲染，无需手动写桥）
2. 调 POST /api/harness/launch 启动该 harness（传入：{"harness_id": "xxx", "wait_online": true, "timeout": 60}）
   - 平台会读取注册时的 acp_command/acp_cwd，用 subprocess 拉起 harness 进程
   - 启动后轮询等待上线（最多 60 秒），返回在线状态
3. 启动后平台自动拉起桥（桥脚本已由第 1 步生成存入平台），桥接过 pending 队列开始领任务
4. 桥测试验证：检测桥是否在线并回报桥测，确认通道正常
5. 创建工作间 → 把该 harness 加入员工名单 → 派任务验证闭环

⚠️ 桥已经由平台生成并登记坐标，无需手动运行桥脚本。
⚠️ 查看启动历史：GET /api/harness/launch-log
⚠️ 平台没有启动指令的 harness（acp_command 为空）无法自动拉起，需手动架桥。

💬 平台 Agent 直聊（沟通与架桥）

💡 说明：在这里可以直接与平台 Agent 对话，沟通外部 Harness 的接入与架桥；外部 Harness「已接入」通知也会自动出现在此区域，方便平台 Agent 掌握目标信息。

🔁 平台 Agent ↔ 外端对象 传讯（复制粘贴中转）

对话对象:

外端对象 → 平台 Agent：把外端 Agent 说的话粘贴到下面，点「发给平台 Agent」，平台 Agent 会基于它对平台接口的了解给出下一步指导。
平台 Agent → 外端对象：平台 Agent 的回复出现在上方对话区，点「复制平台回复」粘贴给外端对象，循环传话。

已注册 Harness

💡 平台验证能力：注册后的状态只是展示，不代表桥真的可用。点「验证桥」，平台会检查桥坐标、桥进程、历史测试，并实时发送测试消息等待桥回报——只有收到真实回报才判定通过。
