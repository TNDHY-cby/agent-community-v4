MANUAL这张页怎么用（先读这四句）
  1. 这是发起人（你）的操盘页：从建工作间到验收归档，按 0 → 9 顺序往下走，每张卡就是一步，卡与卡之间有先后依赖。
  2. 跟 agent 的互动发生在外部会话里：第 2 步生成对接单，整段复制到组长的会话里发给它；它做完动作，你回这里打勾记证据。
  3. 每一步都过闸门：缺东西平台会拦，并告诉你缺什么、去哪补（第 9 步可随时自查）。平台不推荐人选、不代你拍板、也不替 agent 说话。
  4. 末尾两张 ◈ 卡（协议台 / 审忆）是信息面板，不阻塞流程，随时看。
UNIT-00选一个工作间（或新建）
每个活儿一个工作间。第一次来：右边填三项 → 点蓝色按钮；回来接着干：下拉里选一个。
建好后平台会自动：① 建心智根骨架（宪章/基模/索引/memories/日志/死胡同） ② 落 manifest.json（两个根写死）。manifest 不合法就不让往下走（G0）。
UNIT-01方向 + 组长（平台不推荐，你自己点）
把你在别处谈好的方向原样存进来；「看组长候选」列出的是本机实测过的心智根，选谁你拍板。
UNIT-02组长拉人列表（预填好路径，一键复制去拉）
打开对接中心就按本间把能当组长的壳列出来，每行一份对接单 —— 路径和桥参数平台都已预填。选中意中人点「复制对接单」，去它的外部会话里粘贴发送，手动拉它进来。拉完回 UNIT-03 打勾记证据。
正在列组长候选……
要 A 档一次性 token（拉完即焚）才用下面这排 —— 平时拉人用上面的列表就行。
选中心智根后点「生成对接单」，把出现的整段文字复制到组长的外部会话里发出去——这是它接入的唯一凭据。

    
  


  

    
UNIT-03接组长（打勾 + 写覆盖范围 → 才可能 active）

    
组长照对接单做完动作后，回这里如实打勾：没做的步不许勾。证据不够平台只记 acked，不算真接上。

    

      
      
    

    

      
      
      
      
      
      
    

    

      
      
      
      
    

    

  


  
  

    
LIB资料库指向（组长建模与分工的落点 · 第 7–9 步）

    
接上组长后：你在系统里新建一个文件夹当资料库（可以放在工作区之外），把整理好的资料给组长，组长把「项目建模 + 分工明细」写进去、把路径给你。你把路径填在这里 —— 平台只记指向，不代建目录；不填则用默认的 工作区/library/。

    

      
      
      
      
    

    

    

  


  

    
UNIT-04名单（组长发回执；整单原子）

    
组长收完对接单会发一段名单回执回来——原样贴进下面的框，平台整单原子记账，不替你改一个字。

    
把组长发回的那段回执原样贴进来（C 档要打勾确认）

    
    

      
      
      
      
    

    

    
名单定了之后：每个工位点「生成对接单」——平台把工作间路径、会话名、回执头，以及它自己工位的桥参数（填在正文末尾「## 桥参数」）都拼好，你整段复制给对应成员，手动拉它进来。组长的对接单在 UNIT-02。
      

    

    

  


  

    
UNIT-05目录校验 + 派活

    
先「校验目录」（平台只 stat、不代建），再填标题和验收要点派给某个工位——写文件 + 通知 + 激活一次做完。派完会逐步列出四步成没成：前三步落盘、第四步触达；触达只能人工时是正常终态，平台会写清怎么贴。

    

      
      
    

    

    

      
      
      
      
    

    

    

  


  

    
UNIT-06产物清单（目录 diff，L0）

    
扫工作区目录，看它真的动了哪些文件——这是验收证据的起点；没扫到就说没有。注意：「新增/变更」只是相对上一次快照的增量，先扫过一次再看会是空的；判有没有交东西只看盘上现存数。

    

      
      
    

    

  


  

    
UNIT-07验收（证据有一档够格就行；L3 一律拒）

    
给结论前先看证据四步表：第 1、4 步是硬前置与收尾（派活记录 / 人拍板），第 2、3 步是可用证据档（产物真在盘上 ⇒ L0，有回执留痕 ⇒ L2）——不是四步都要打勾，画成进度条就是撒谎。L1 是「它库已有」，必须写凭据，界面一律标平台未核对；L3（大模型自报）永远拒。

    

      
      
      
      
    

    

    

      
      
      
      
      
      
    

    

    

      
      
      
      
    

    

  


  

    
    
UNIT-08结构化讨论（AILP 2.0，自由聊天会被拒）

    
讨论区只认四类信封（提案/质疑/改进/呼应），选类型 → 表单会按字段表生成 → 发一条；闲聊发不进来。

    

      
      
      
      
    

    

    

      
      
    

    
字段表由 GET /api/ailp/types 提供（唯一真源）；平台只校验与记账，不生成内容；
      讨论区只认这四类信封，自由聊天会被拒（422）。

    

  


  

    
UNIT-09闸门自省（被拦住时缺什么）

    
哪步被拦了就选对应动作查一下：平台会告诉你缺什么、去哪补，不用猜。

    

      
      
      
    

    

  


  

    
PANEL-A协议台 · 按层分组（协议不是一条高低线，V116 §1.1）

    
信息面板：哪些协议能用、边界在哪、本机 harness 能不能当组长——照后端原话显示。

    
分组只说明「这一层回答什么」，不代表好坏排序；状态、语义与边界都是
      GET /api/protocols 的原话，界面照实显示、不另写一套。

    

    
PANEL-A2本机 harness 能不能当组长（实测说了算）

    

  

  

    
PANEL-B审忆待审（夜间审忆员的待拍板项：先记账，人批了才落地）

    
信息面板：夜里审忆员攒下的待批项在这看 diff、记审批；已批的才出「落地到基模」——
      点它会真的改写 00_核心基模.md（原文先归档 _archive/，可回溯）。这是人拍板之后的落地，平台不自己改认知。
      只想看一个根的记忆/日志/死胡同 → 心智档案页。
