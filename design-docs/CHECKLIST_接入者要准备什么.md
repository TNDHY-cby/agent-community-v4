# 接入者要准备什么（CHECKLIST，2026-10-08）

> 这份清单回答：**要跑通主流程，我必须先准备哪些东西；没准备时系统会怎么表现**。
> 目的＝准则④「装好就能用」＋准则⑤「失败要说话」：**每一项都必须"没配时有明确说法"**，
> 不允许静默失败。事实来源：本仓库代码 + 隔离实例实测（2026-10-08）。

---

## 1. 一张表：准备项 / 是否必须 / 没配时的表现

| 准备项 | 必须? | 没配时系统怎么表现（**都实测或源码确认过**） |
|---|---|---|
| `harness_id` | **必须** | 注册 400：`harness_id required` |
| `ai.model_name` | **必须** | 注册 400：**中文、字段级**——"注册参数有问题：缺少必填字段 ai.model_name"，并附**最小可用示例**（照抄即可成功） |
| `acp_command` | 非 MCP 类**必须** | 注册 400：`acp_command 校验失败`（防解释器包装 RCE）。**file_poll 类也要求它**——这是刻意的安全校验，不是 bug |
| `api_base_url` | 仅 MCP 类必须 | MCP 注册 400：`mcp 类型需要 api_base_url` |
| **平台 AI（provider/key）** | 可选 | ① `select-members`（AI 初选）400「AI Provider 未配置」⇒ **不挡路**：用 `POST .../members` **手工给名单**即可；② 一级讨论**有规则兜底**（响应带 `action_source=rule_fallback`）。**其余步骤不依赖 AI** |
| `scripts`（新建对话/重命名/投递） | 可选 | 相关步骤走**人工模式**：返回退出码 10（未核实）+ `manual[].hint`（给用户看的话）。**不是报错** |
| `wakeup_dir`（file_poll） | 可选 | 平台改用**该成员的邮箱** `<成员隔间>/inbox`（2026-10-08 起），**同一 harness 多会话也不会串** |
| `AC_DATA_DIR` | 可选 | 默认写仓库内 `data/`。**演练/验证务必指定临时目录**（别动在用实例） |

## 2. 三条"必须先做"的顺序（顺序错了会白等）

1. **注册 harness**（步骤 0）—— 成员绑的 harness 若**平台完全不认识**（没注册、也没桥进程），
   `/start` 时该成员会被标 `blocked` + 原因「平台不认识…先注册它、或改绑」；
   **不会**再假装"已派发"（见 §12 硬规矩）。
2. **建间 + 名单**（步骤 1~3）—— 名单可以 AI 初选，也可以**手工给**。
3. **开工**（`/start`）—— 平台会在后台**先建会话并命名**，再派激活消息。

---

## 3. 接入方最常问的三件事

**Q1：我一定要让平台去"新建对话/重命名"吗？**
不必。不配 `scripts` 就走人工模式：平台把**该做什么**给成一句话（`manual[].hint`，
例如"请把该会话重命名为：`<名字>`（复制粘贴即可）"），并把一段可直接复制的文本落到
`<成员隔间>/deliver_text.md`。

**Q2：我的 harness 会不会被平台"抢桌面"？**
看动作的 `foreground`：`never`（不碰界面）/ `optional` / `required`（**必然占用**）。
`required` 的动作**不会在开工时自动执行**（会被跳过，留给界面按钮+人确认）；
界面应当在按钮上标明"会占用桌面"。

**Q3：我怎么知道"这一步到底做成没有"？**
看 `verified`：`true`＝脚本做了**并且自证了**；`false`＝**可能做了但没自证**（人工模式）。
平台一律标「⚠ 待人工/未核实」，**不会**显示成"完成"。

## 4. 自查命令（复制即用）

```bash
# 起一个隔离实例（别用在用端口）
AC_DATA_DIR=<临时目录> python -m agent_community.platform.server --port <端口>

# 看某 harness 的"哪几步能自动"
curl -s http://127.0.0.1:<端口>/api/harness/<harness_id>/action-scripts

# 看某工作间每个成员的：派发进度 / 会话名 / 隔间 / 邮箱积压 / 各步能否自动
curl -s http://127.0.0.1:<端口>/api/workshop/<ws_id>/members-status

# 看共享资料库（含每个员工的分工文件夹与内容预览）
curl -s http://127.0.0.1:<端口>/api/workshop/<ws_id>/library
```
