> **来源**：示例Harness-E 8 号发言四之①——老板当日口述规则「**一个会话＝一个隔间＋一个具体桥**」。
> **边界**：只读页（全 GET）；主流程 ①~③ 按 示例Harness-E 指示不动；不触发任何架桥/激活写操作。
> **v1.1 变更（2026-10-07 晚）**：后端上线 `GET /api/workshop/{ws_id}/compartments`（应答本稿 §7 申请），

> 权威隔间定义以 示例Harness-E 9 号发言为准：**架起具体桥那一步才创建隔间**（不是建工作间时）。

## 1. 页面定位

新建 `agent_community/frontend/booths.html?ws_id=<id>`（无参数时进入选择器模式）。展示一个工作间内**每个成员的隔间坐标与他那一份桥**。

**为什么值钱**（示例Harness-E 8 号原话）：此前所有人共用工作间根、同名 `bridge.py` 后写覆盖先写（有隔离实例实测为证）。把「谁、在哪个隔间、发过哪座桥」变成看得见的界面，就是把老板的新规则钉进产品叙事——**这属于治理闭环的"场地可见化"，不是列表美化**。

## 2. 数据源（全部只读、已实测 2026-10-07）

| 端点 | 用途 | 实测要点 |
|---|---|---|
| `GET /api/workshops` | 选择器列表 | `{"workshops":[{workshop_id,name,status,…}]}` |
| `GET /api/workshop/{ws_id}` | 主数据 | 含 `workspace_dir` 与 `members[]`：`{member_id, role, display_name, harness_ids[], status, entry_state, entry_reason, wakeup_method}` |
| `GET /api/audit?event=bridge.auto&target={ws_id}` | 每成员**发桥记录** | 条目含 `member_id, harness_id, artifact_kind, artifact_path, ts, detail`（时间倒序） |
| `GET /api/status` | 页头健康 | 同前两页 |

**隔间路径 = 客户端推导**（后端无现成 GET 返回隔间对象）：镜像 `platform/compartment.py` 的 `compartment_dir()`：

```
dir = <workspace_dir> + safe_part(role) + "_" + safe_part(member_id)
safe_part: 非法字符 [\ / : * ? " < > | 与控制符] → "_"；".." → "_"；
           去首尾空格与点；连续 "_" 折叠；空/./.. → 回退词(role→"成员", id→"x")；截断 48 字符
分区（展示为派生标签）：input / output / temp
```

已用后端真函数对拍样本：`组长_m0`、`前端_攻城狮_m 9`（`/`→`_`）、`.._m1`→`__m1`、空→`成员_x`。**JS 实现须与样本逐条一致**（见 §6 验收②）。

**桥状态 = 审计证据**：该成员（`member_id`）在本工作间最新一条 `bridge.auto` → 显示时刻 + `artifact_path`。
- 落点在隔间内（路径含 `<职位>_<成员id>` 段）→ 绿标「已落隔间（新规则）」；
- 落点在工作间根（V23 前旧记录）→ 黄标「旧落点（隔离前发出，仅存档）」；
- 无记录 → 灰态「尚未架桥」。
**不谎报磁盘现状**：审计只能证明"何时发过、落在哪"，不能证明文件此刻还在——如实措辞为"最近一次发桥"，磁盘实况见 §7 接口申请。

## 3. 信息架构

```
┌ topbar：🏗 成员隔间与桥  [健康]  ws选择器▾  ⟳ 刷新 ┐
├ 说明条：一个会话 = 一个隔间 + 一个具体桥（老板 2026-10-07 规则）│
├ 共享区一行：<workspace_dir>（工作间根·共享区，非成员可写）        │
├ 成员卡网格 auto-fill minmax(340px,1fr)：                        │
│  ┌─────────────────────────────────────┐                       │
│  │ [组长] 组长 · m0        [状态徽章]    │                       │
│  │ display_name · wakeup=file_poll      │                       │
│  │ 📁 隔间 <ws>/组长_m0        [复制]    │                       │
│  │ [input] [output] [temp]   ← 分区标签  │                       │
│  │ 🌉 最近发桥 20:01 · harness-x · 绿标   │                       │
│  │    落点 …/组长_m0/bridge.py           │                       │
│  └─────────────────────────────────────┘                       │
└ statusbar                                                        │
```

**三态**：加载=骨架；空=「该工作间还没有成员（先在工作间里选人）」/「未选择工作间」；错=内联红条（兼容 `error`/`detail` 两套 404）。

## 4. 关键呈现

- **职位彩色徽章**：组长=accent、码农=蓝、搜索者=青、其余=中性；成员 `entry_state`（pending/…）用小徽章。
- **隔间路径**：mono、可一键复制（`navigator.clipboard`，失败时选中文本提示）；路径按 Windows/POSIX 自动选 `\` 或 `/`（依 `workspace_dir` 是否含反斜杠）。
- **三分区**：三个小标签（`input/output/temp`）——**派生展示**，文案用「应含分区」避免宣称磁盘已建。
- **桥卡片**：见 §2 三态；`artifact_path` mono 截断 + title 全文；同一成员多条审计只取最新，点「历史 n 条」展开其余（数据都在本次 audit 拉取里）。
- **工作间选择器**：顶栏下拉（`GET /api/workshops`），切换即换 `?ws_id=`（history.replaceState，不刷新页面）。

## 5. 刷新与时间

30 秒轮询（workshop + audit 并行）+ 手动 ⟳ + `visibilitychange` 恢复即刷；选择器数据 5 分钟刷新一次。时间：audit `ts` 为本地 ISO 无时区串（与 ops 同规则，不补 Z），相对时间 + 悬停绝对。

## 6. 验收自查

1. `/booths.html?ws_id=<有成员的工作间>` 可达，Console 无红字，成员卡齐全。
2. **路径公式对拍**：页面内置 `__boothsTest.derive(...)` 暴露样本集，与 §2 四条后端真值逐条比对全过（含非法字符/回退）。
3. **桥状态**：选一个有 `bridge.auto` 的工作间（若已删则输入其 id）→ 显示记录或诚实灰态；旧落点记录标黄。
4. 只读：全部请求为 GET。
5. 1920 / 1280×720 / 1024 不破版（DOM 实测）。
6. 空态/错误态中文完整，无 `undefined`/`NaN`。

## 7. 接口变更申请 → **已落地（v1.1）**

原申请（新增 `GET /api/workshop/{ws_id}/compartments` 返回磁盘实况）**已由 示例Harness-E 实现并上线**
（提交 `51772bc`；行字段见其 9 号发言与路由文档字符串）。实现要点：

- 顶层 `rule` 与 `path_authority` 与本稿口径一致；404 形状 `{"error":"工作间不存在"}` 已兼容。
