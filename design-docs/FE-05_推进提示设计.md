# FE-05 设计稿 · 推进提示（action / action_source 可见化）

> **设计**：XiaomiMiMo（前端）｜ **日期**：2026-10-07 ｜ **状态**：DSH 11 号发言明确授权（"可以据此做提示了"），本稿落档
> **数据契约**（DSH 11 号实测）：`POST /api/workshop/{id}/discuss` 响应新增 `action_source: ai_marker|rule_fallback|""`，`action` 含 `none|select|continue|start|complete`（无破坏性改动）。

## 要解决的问题

用户说"开始选人吧"，AI 若没吐口令，界面无从推进（`action=none`）；现在有规则兜底后 `action=select` 可信，但——

1. **推进发生时用户看不见**：workshop 页只切了阶段高亮/开侧栏，没有一句话告诉用户"现在可以选人了"；
2. **`rule_fallback` 易被误读**：推进是规则判的，AI 那句回复可能还在聊细节——界面必须把"谁做的决定"标出来。

## 改动（两页，均为追加提示，不动推进逻辑）

| 文件 | 位置 | 行为 |
|---|---|---|
| `workshop.html` | `sendDiscuss()` 响应处理（现消费 `action` 处） | `action==='select'` → 在当前讨论区追加一条 **notice**：`✅ 需求已明确，可以选定员工了…`（`ai_marker`）或 `⚑ 推进提示（规则兜底）…别把 AI 的话当成已同意`（`rule_fallback`）；其余动作 + `rule_fallback` → 追加一条短 notice 标注"动作由规则判定" |
| `index.html` | 大厅讨论 `sendDiscussMessage()` 响应后 | 同语义的 system 消息：select → 引导"进入工作间点选成员"；rule_fallback → 标注规则兜底 |

- 复用现有 `addMsg('notice',…)`（workshop）与 `addToDiscussion({from_agent:'system',…})`（index）渲染，**不新增样式体系**。
- 现有 `action` 消费逻辑（select→phase2/侧栏等）**原样保留**；旧的字符串匹配分支保留（向后兼容）。

## 验收

1. 拦截 `/discuss` 返回罐头响应：`action=select + rule_fallback` → 讨论区出现 ⚑ notice（含"规则兜底"与"别当成已同意"字样），且原推进逻辑照旧（侧栏打开）；
2. `action=select + ai_marker` → ✅ notice；
3. Console 无红字；只追加不改旧分支（diff 可核）。

## 不做

- 不改后端；不动 `action` 的业务语义；不做选人 UI 本身（已有侧栏/名单流程）。
