## 1. status → 阶段与"下一步"映射（前向兼容）

出现过的 ws.status（代码/实测）：`draft / discussing / selecting / division / running / review / done`。
**未知值一律显示原样 + 通用指引**（不猜、不崩）。

| status | 阶段 | 「下一步」指引条文案（要点） |
|---|---|---|
| `draft` | ①待广播 | 该工作间尚在草稿；回大厅发布任务继续 |
| `discussing` | ③一级讨论 | 与平台AI明确需求；明确后点「结束讨论，选定员工」，或直接说"开始选人"（`action=select` 会自动提示，见 FE-05） |
| `selecting` | ④选人中 | AI 初选（select-members）或手工增补（members）→ **确认成员** → **启动工作** |
| `division` | ⑤已分工 | 名单已定：**分工安排已按当前名单更新**（`library/plan.md`，DSH `e9dc936` 起名单变更即重生成）→ 查看 📚 资料库 / 🏗 成员隔间 |
| `running` | 工作中 | 成员在各自隔间作业 → 查看 🏗 隔间与桥；完成后走 review 收口 |
| `review` | 收口 | 完成复核与收口（现有 review 流程），可查隔间成果 |
| `done` | 终态 | 任务完成；回顾隔间与资料库留档 |
| 其他 | 未知 | `当前状态：<原样>` · 查看隔间/资料库/工作间讨论 |

## 2. 改动清单

### A. `workshop.html`（工作间）
1. **「下一步」指引条**：fishbone 阶段条下方新增一条横幅（复用 `notice` 视觉系，右端带快捷按钮）：
   - 内容 = 按 §1 映射（载入时 + status 变化时刷新：并入现有 `setPhase` 调用点与轮询回调，不加新轮询）；
   - 右端按钮按阶段给：`discussing`→「结束讨论，选定员工」(已有 endDiscussBtn 逻辑)；`selecting`→「确认成员」「启动工作」(锚到已有按钮)；`division/running/review/done`→「📚 资料库」「🏗 隔间」(新窗口)；
   - **只指路，不新增写操作**——按钮全部指向既有控件或 GET 页面。
2. **启动成功出口**：`start` 动作分支（与 FE-05 notice 同处）追加一条 notice：「工作已启动——每位成员在自己的隔间作业」+ 链接 `booths.html?ws_id=<当前>`（串联 FE-03/06）。

### B. `index.html`（大厅）
3. **主流程阶段条（新，插入 `workflowSection` 顶部）**：当选中工作间时显示 ①→⑤ 简化阶段珠（广播·讨论·选人·分工·工作），当前珠高亮 = §1 映射；点击「进入工作间 →」即 `openWorkshopPage`。**旧任务路由图不动**（画布保留在下方——它是 task 视角，不是主流程视角；两层并存，不删旧逻辑）。
   - **数据源补记**：大厅 `task_id ≠ workshop_id`（①返回两个不同 id）——打开任务时**一次性**调 `GET /api/tasks/{task_id}/workshop`（13 号已给，404=还没建间）拿 `workshop_id`；status 优先取自现有 `workshops` 列表；**不加轮询**。
4. 讨论区 FE-05 提示已有；本稿不重复改。

### C. `booths.html`（隔间页）
5. 顶栏动态加「↩ 返回工作间」（有 `ws_id` 时显示，`workshop.html?ws_id=<id>`）——闭环双向。

### 实现注记（写码时的落地口径）
- `addMsg` 内容是 `textContent`（纯文本不渲染 HTML）——"启动后带链接"落地为：**指引条上的按钮**（可点）+ notice 文本附路径（可复制），不伪装富链接。
- 指引条按钮只指向**恒可见控件**（endDiscuss、booths 出口）或对隐藏按钮做「滚动定位+高亮」（不代点击，避免副作用）。
