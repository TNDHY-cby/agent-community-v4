## 0. ★全页最重要的一条（准则⑤，设计层面钉死）

```
verified=true  → 显示「✔ 完成（脚本自证）」
verified=false → 显示「⚠ 待人工 / 未核实」——⛔ 任何地方不许出现"成功/完成"字样
```

- `manual[]` 的 hint 是**给用户看的话**，原样渲染（含"请把该会话重命名为：xxx（复制粘贴即可）"这类句子）；
- `establish-session` 的 `verified` 是**按步字典**（`{4_new_session:bool, 8_rename_session:bool,…}`）→ 逐 step 徽章；`all_verified` 才允许总状态绿；
- `deliver-bridge` 的 `verified` 是**单 bool** → 直接二态。
- **验收有专门一条反向断言**：喂 `verified:false` 的响应——**我方状态文案**不得出现"完成/成功"、不得出现绿色 ✔ 徽章；后端 `note` 原样展示（其否定句如"不会把它当成已完成"属如实转述，不算违例）。

## 1. 数据源（全部已存在，形状=源码实测口径）

| 端点 | 用途 | 关键形状（函数名口径） |
|---|---|---|
| `GET /api/workshop/{ws}/members-status` | **卡片唯一数据源**（`members_status`） | `members[]`：`member_id/role/display_name/entry_state(+reason)/harness_id/harness_name/session_name/session_aliases/session_ref/compartment{dir,exists,mailbox_pending,root_files,output_files}/bridge_files[]/deliver_text_path/steps{4_new_session,5_deliver,8_rename_session each {automatic,mode,foreground}}`；`summary{count,all_steps_automatic,manual_members[]}` |
| `GET …/member/{mid}/session-name` | 步骤7 只算名（`member_session_name`） | `{name, project, existing_aliases[]}`——「复制名字」按钮的数据源，不碰脚本 |
| `POST …/establish-session` | 步骤4/8/9（`establish_session`） | `{steps, verified{按步}, all_verified, manual[], name, session_ref, note}` |
| `POST …/deliver-bridge` | 步骤5（`deliver_bridge`） | `{verified:bool, steps, manual[], text, text_path, bridge{ok,path,compartment,error}, note}` |

**写操作仅这两个 POST**（本页新增的全部写动作，均有审计 `workshop.establish_session` / `workshop.deliver_bridge` 留痕）；无二次确认弹窗（构造性动作+可审计），如老板要确认框，加一行即可。

## 2. 放哪、长什么样

**`workshop.html` 右栏、确认名单按钮之后新增独立面板「📇 会话流程」**（roster 行是编辑用的下拉行、不带 `member_id`，故不内嵌——30 号审阅后定型）：

```
┌ 📇 会话流程          [绿"全员可自动" / 黄"N名需人工"] ┐
│ ┌ 成员卡 ──────────────────────────────┐        │
│ │ 角色 · display_name · entry_state（读它不读status）│
│ │ 📇 会话名  <工作间>-项目-职位-成员   [复制]   │ ← session_name 恒显示（步骤7产物）
│ │ 步骤徽章：[4建会话 自动] [5送桥 需人工!] [8重命名 自动] │ ← steps.*.automatic
│ │ 隔间实况：已建/未建 · 成果 output_files · 产物 root_files · 邮箱积压 │ ← v1.1 字段拆分
│ │ [建立会话 4/8/9]  [送出具体桥 5]           │ ← foreground≠never 时按钮文案即「…（会占用桌面）」*
│ │ ─ 结果面板（POST 返回后渲染，可收起）─        │
│ │ 总态徽章：✔ 完成（脚本自证） | ⚠ 待人工/未核实      │
│ │ 逐条 manual hint 原样列表（含重命名句）      │
│ │ [📋 复制会话名]  [📄 复制投递文本]（deliver 人工模式）│
│ │ text 折叠预览（等宽、默认收起，一键复制）      │
│ └────────────────────────────────────┘        │
└──────────────────────────────────────────┘
```

> \* 采纳 30 号建议2：**按钮文案直写"会占用桌面"**——静态标签挡不住误点；不做额外弹窗（遵老板"不主动打扰"，该提示只长在按钮上，由用户主动点到）。

- **面板头部汇总**：`summary.all_steps_automatic` → 绿「全员可自动」；否则黄「N 名成员有需人工步骤」（`manual_members.length`）。
- **自动/人工 chip**：`automatic:true`→「自动」（青），false→「需人工」（黄）；`foreground` 为 `required/optional` → 附加「⚠ 会占用桌面」小标签（与按钮文案双保险）。
- **action-scripts 端点本稿不单独调**——其内容已由 `members-status.steps` 携带（同源），避免双源不一致。

## 3. 交互与状态

- **拉取时机**：进工作间载入 roster 时 + 每次 establish/deliver 成功返回后**局部刷新**该卡（调 `members-status` 一次）；**不加新轮询**。
- **错误态**：端点 404/5xx → 卡内黄条中文说明（兼容 `error/detail` 两套形状），既有卡片信息不受影响。
- **加载态**：折叠区骨架两行，不抖动布局。
- **按钮**：请求中禁用+文案「建立中…/投递中…」；失败（非 2xx）→ 红条 `error` 原文，**不算"待人工"**（那是 verified:false 的专用语义，失败是失败）。

## 4. 不做

- 不动 `action-scripts` 单独端点、不接 A2A/其他协议侧；不在 booths/ops 页重复本面板（将来要展示再出稿）；
- 不做自动重试/轮询"是否已人工完成"（人工步骤完成后由用户手动刷新按钮或重进页面）。

## 5. 验收（隔离实例 + AC_FE_BASE + 自建自清）

1. 建间+加成员（自建），`members-status` 渲染：会话名/步骤徽章/占用桌面标签/汇总行正确；
2. `establish-session` 实打（未配脚本 harness → 必然 `verified=false` 路径）→ 面板显示「⚠ 待人工/未核实」+ manual hint 原样 + 复制按钮；**全文无"完成/成功"**（反向断言）；
3. 罐头 `verified:true`（route 拦截）→ 绿「✔ 完成（脚本自证）」与逐 step 徽章对照 `all_verified`；
4. `deliver-bridge` 人工路径 → `text` 折叠预览 + 一键复制 `text`、展示 `text_path`；
5. 错误态（不存在成员）→ 中文错误条；1920/1280/1024 不破版；Console 无红字；写请求仅那两个 POST 且都在隔离实例。
