# FE-12 设计稿 · 工作间成员卡：通道状态与停用/新建通道

> **术语（老板 2026-10-10 定稿，协作书规则 15）**：本文的「通道」＝**成员通道**（某成员"通着的那条路"：
> 一个会话 ＋ 它的桥 ＋ 它的邮箱收发，可停用/新建）；与「接入通道/接入协议」（平台对外接入方式：HTTP/A2A/gRPC/桥脚本）**不是一回事**。正文 20 处均指前者。

> **设计**：示例Harness-F（前端）｜ **日期**：2026-10-09 ｜ **状态**：**示例Harness-E 审阅通过（59 号）；v1.1 并入三条补充，实施中**
> **契约来源**：示例Harness-E 57 号 + 提交 `cd901a6`（隔离实例 18986 实测）；命名规则「第 2 个通道起追加序号」由后端生成，前端不自造名。
> **v1.1 补充（59 号）**：① `since/retired_at/history[].retired_at` 为 **unix 秒 float** → 转本地时间显示；② **不显示绝对路径**——`history[].archived` 只显示条数、`text_path/bridge_path` 只显示文件名；③ `action:"none"` 时**行内状态照响应里的真实 `channel_state` 显示**，不切换成别的状态。

## 0. 三条界面义务（示例Harness-E 57 §三，逐条落）

1. **成员卡显示通道**：`channel.state` ∈ `pending未接入 / active运行中 / retired已停用` + `name`（含序号）+ `seq`；**已停用必须一眼可辨**。
2. **两个按钮**：「停用通道」（二次确认+说明**不删数据、隔间产物保留**）、「新建通道」（名字可留空=平台生成）；互斥显示——active 才能停，非 active 才能建。
3. **失败与如实**：retire 返回 `action:"none"`（没有可停用的）⇒ 显示「当前没有可停用的通道」，**禁止**显示"已停用"；establish 响应里的 `deliver.verified=false` ⇒ 沿用「⚠ 待人工/未核实」（准则⑤）；active 时 establish 被拒 ⇒ **后端中文 `error` 原文**展示。

## 1. 数据源

| 端点 | 用途 | 要点 |
|---|---|---|
| `GET …/members-status`（已有） | 成员项新增 `channel{seq,state,since,retired_at,retired_count,name}` | 状态与名字的**展示源**；随现有 `loadSessionFlow()` 刷新 |
| `GET …/member/{mid}/channels` | current + history（seq/name/retired_at/reason/archived/queue_cleared） | 卡片展开时拉一次；history 只读折叠列表 |
| `POST …/channel/retire` | body `{"reason": …}` | 成功→刷新；`action:"none"` 如实显示 |
| `POST …/channel/establish` | body `{"new_name":"…可空","reason":"…"}` | 成功→返回 `channel_seq/state/name` + **`deliver`（步骤5结果）**；active 拒绝 |

**写操作仅这两个 POST**（在工作间页面，与 FE-08/09 同页共存；hub 说明书零新增请求）。

## 2. 落位与呈现（workshop.html · FE-08 会话流程面板内）

**成员卡内，会话名行之下新增「通道」行**：

```
🔗 通道 [#2 · 运行中]  名：xxx-码农-m1-2        [停用通道]
     （active 绿徽 / pending 灰「未接入」/ retired 红「已停用 ×N」+ 名字仍显示但配色变暗）
▸ 通道历史（点开展开 GET channels.history）
[新建通道]（仅 pending / retired 时显示；名字输入框可空=平台生成）
```

- **停用**：`acModal` 二次确认——「停用该成员当前通道？**不删除任何数据**：桥归档、隔间产物全部保留。」+ reason 下拉（预设：用户不满意 / 上下文老化 / 其他→文本框）。
- **新建**：行内输入框（placeholder「留空则平台按 规则生成（含序号）」）+ 按钮；reason 可选默认「按需新建」。
- **establish 成功后的 `deliver` 结果**：复用 FE-08 结果面板契约（绿自证 / 黄待人工，manual 原样，投递文本可复制）。
- `retired_count>0` → 徽章显示「已停用 ×N」；history 折叠逐条：`#seq 名字 · 时间 · 原因 · archived/queue_cleared`。

## 3. 状态与诚实清单

- `state` 缺失（旧后端/字段未到）→ 该行显示「通道信息未取到」灰字，不装状态；
- 所有按钮请求中禁用（「处理中…」）；失败红条原文；
- **反向断言（验收）**：a) retire `action=none` 的文案不含「已停用」；b) `deliver.verified=false` 的面板无绿色"完成"；c) active 上点新建（罐头拒绝）→ 显示后端 `error` 原文。

## 4. 刷新时机

并入现有 `loadSessionFlow()`（载入/选人/确认/名单同步/会话与送桥动作后）+ 两通道动作成功后立即重拉；**零新轮询**。

## 5. 不做

- `model.md` 相关（老板排序：先通道后建模；57 §四明确先别做）；
- 对话老化自动提醒（老板裁定先不做，只留手动——本稿也无该按钮）；
- hub 说明书不加任何通道操作（说明书速查表保持"通道操作在工作间"）；
- 通道列表管理页、批量通道操作。

## 6. 验收（隔离实例 + AC_FE_BASE + 自建自清）

1. 自建间+成员 → members-status 渲染通道行（pending 灰「未建立通道」）；
2. 真跑 `channel/establish`（名字留空）→ `channel_seq/name` 回显（含序号）、按钮切换为「停用通道」、`deliver` 按 verified 契约显示；
3. 真跑 `channel/retire`（带 reason）→ 红「已停用 ×1」、history 一条、按钮切换为「新建通道」；
4. **罐头**：`action:"none"` retire → 文案「当前没有可停用的通道」且无「已停用」；active establish 拒绝 → 后端 `error` 原文；
5. 三档视口、Console、写请求白名单=仅两通道 POST（+页面既有）；截图进 temp、result 脱敏。
