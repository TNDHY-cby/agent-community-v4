## 2. 编辑器（V32 §3.2，老板已拍板「两种都要」）

- **模式开关**：「五块表单」（默认）⇄「整篇编辑」，同一条接口：
  表单 ⇒ `model:{goal,parts,roles,deps,outputs}`；整篇 ⇒ `model:"整篇 markdown"`。
- **五块**：目标与验收 / 组成（模块·任务分解）/ 分工对应 / 依赖与顺序 / 产物落点
  （键名与后端 `MODEL_SECTIONS` 一致：`goal/parts/roles/deps/outputs`）。
  未建立 ⇒ 预填**骨架提示语**（照 `MODEL_SECTIONS` 的 hint，非空白）。
- **执笔人下拉**：组长（默认）/ 整合者 / 用户 ⇒ `author`；显示「执笔：X」。
- **编辑既有模型**：从 `libData.model.preview`（≤2000 字）按 `## 标题` 拆块预填；
  预览被截断（长度 ≥2000）时编辑器顶部显示**如实警示**（保存前旧版自动备份到 `model.history/`，可回溯）。

## 3. 保存后的表现（准则⑤，失败要说话）

| 情形 | 界面 |
|---|---|
| `model.ok=true` 且 `missing=[]` | 绿「已保存 · vN」 |
| `model.ok=true` 且 `missing` 非空 | 黄「已保存 · 缺 N 块（未完成）」+ 逐名列出 |
| `model.ok=false`（含 `error="未提供 model"`） | 显示后端 `error` 原文，**禁止**出现「已保存」 |
| HTTP 失败 | 显示 `error/detail` 原文（`req()` 已解析） |

保存后立即重拉 `GET …/library`（`version` 递增、`history_count` 增加应可见）；
请求中按钮禁用（「保存中…」）。写请求**仅一条**：`POST /api/workshop/{ws}/library/update`。

## 5. 验收（隔离实例 + `AC_FE_BASE` + 自建自清，`verify/fe13_check.js` 扩写）

1. 未建立 ⇒ 「未建立」灰徽 + 「建立模型」按钮可见；
2. 点开 ⇒ 编辑器出现（五块表单 + 执笔人下拉）；**反向断言**：整篇模式空提交 ⇒ 显示「未提供 model」、**无「已保存」**；
3. 表单填 2 块保存 ⇒ 黄「缺 3 块」+ 执笔 + `version` 递增；
4. 填满 5 块保存 ⇒ 绿「已完成/已保存 · vN」；
5. 已建立时按钮变「编辑」；Console 无红错；写白名单 = 仅 `library/update`；截图进 `temp\验收证据截图\`、`result.json` 脱敏。
