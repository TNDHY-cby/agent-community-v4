## 2. 阶段门控（「不渲染」，不是置灰；`sbOk=false` 时**全部放开**）

| 目标 | 显示条件（`sbOk` 时） |
|---|---|
| `#rosterBlock`（②选定员工的名单+按钮组，本次**新包裹**） | `stage.id==='select'` **或** 本地 `_phase===2`（`endDiscuss` 先于后端状态翻转的窗口期，用本地阶段兜住，避免"面板开了按钮却藏了"） |
| `#harnessBlock`（可用 Harness 列表+标题，本次**新包裹**） | 同上 |
| `#offlinePanel`（FE-09 成员状态） | `stage.id==='working'` 或 `_phase===4` |
| 插话悬浮钮 `#interjectFab` | `stage.id ∈ {discuss2, working, review}` |
| `#sessionFlow`（FE-08 会话流程，**按成员卡为单位**） | **不门控**（白名单表未列；卡内按钮属"每人一个"类，同抢救按钮先例） |
| Agent 列表 / 系统统计 | 不动（全局只读，不计入 5） |

**同屏去重**（`sbOk` 时，避免同一动作两个入口把计数顶破 5）：
`#selectBtn / #addMemberBtn(新加 id) / #saveMembersBtn / #confirmBtn` **只在 `!sbOk` 降级态显示**
（`stage=select` 时由 stageBar 的四条同名主操作接管；名单行、输入框照常可见）。
`#ofScanBtn` **保留不去重**（working 下 3 主操作+扫描+刷新=5，恰好达线且 fe09 依赖它）。

## 5. 对旧验收的**契约性连带改动**（如实说明）

`fe09_check.js`（FE-09 抢救面板）原本在**草稿态**工作间直接断言 `#offlinePanel` 可见 ——
按 FE-17，成员状态面板是 **④ 工作中** 的阶段专属面板，草稿态**按契约就该不渲染**。
⇒ 该脚本补一段 `page.route('**/sidebar', …)` 注入 `working` 阶段样例（其余逻辑不动），
**改的是测试的进入方式，不是放水**：面板渲染与抢救断言仍全部照旧。
其余旧脚本按此核过：`fe08`（sessionFlow 不门控）、`action_notice`/`fe07`（只碰讨论区/指引条）、
`fe12`（sessionFlow 卡片，不门控）**不受影响**。
