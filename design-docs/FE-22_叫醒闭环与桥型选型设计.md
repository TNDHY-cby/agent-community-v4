## 1. 「已注册 Harness」清单加 wake 列（105 §五-1）

| 项 | 内容 |
|---|---|
| 数据 | 每行 `GET /api/harness/{hid}/wake`（与 delivery 列同一次 **20s 节流** 的 extras 刷新） |
| `configured=true` | 绿徽 `📣 已配` + `status_text` 截断显示（全文进 `title`） |
| `configured=false` | 红徽 `📣 未配叫醒` + 后端 `why`/固定人话「不配 ⇒ 消息只会躺在邮箱里，不会自动叫醒」 |
| 404/失败 | **不显示该列**（不猜） |

## 2. 「🧭 桥型选型（你选型 · 你填）」新面板（105 §五-2；置于架桥速查之后）

**单一真相 = `/api/bridge-catalog`，字段一个都不手抄**：

- **第 1 步 你选型**：`GET /api/bridge-catalog` → 4 张卡（`kind`/`label`/`one_liner`/`when`），点选；
- **第 2 步 你填**：`GET /api/bridge-catalog/{kind}` →
  - `fields[]` 中 `provides==='user'` 的逐条渲染：`label`（含后端加粗语义原文）+ `fill` 说明 + `example`（代码样式）；
  - `provides==='platform'` 的合并一行灰字「平台自动填：…」；
  - `verify.text`（怎么自证这一型可行）+ `pitfalls`（常见坑）原文；
- **叫醒命令真填口**（该型 `user_fields` 含 `TRIGGER_CMD` 时出现）：
  选 harness（复用清单数据）+ 一个输入框（**只收一条命令**）→ `POST /api/harness/{hid}/wake {"command":…}`
  → 成功显示返回的 `wrapper_path` + `next` 原文；失败显示 `error` 原文。
  **界面不拼引号、不拼路径。**
- **闭环回跳**：自检灯 `no_reply` 结果底部加锚链「→ 去配叫醒命令（第 2 步·你填）」`#bridgeKindPanel`。

## 3. 不做

- 不改话术段（FE-21/V39 已交）；不做 catalog 第 1 步之外的桥生成/起桥动作；
- **不给 `auto-connect` 传 wake**（后端 105 §五 ⚠️：示例Harness-E 侧待补，补前自检如实 no_reply）。

## 4. 验收（`verify/fe22_check.js`，隔离实例 + 自建自清 + `AC_VERIFY_OUT`）

1. **catalog 真打**：4 卡渲染（kind 集合与真接口一致）→ 点 `file_poll` → spec 渲染出
   user 字段（含 TRIGGER_CMD/INBOX_DIR 的 label）、平台字段行、verify 文本、pitfalls ≥1（**非手抄**：字段名来自响应）；
2. **wake 列**：自建 harness 后清单出现 `📣` 列（已配/未配按真实响应）；
3. **wake POST**：`page.route` 打桩（仅拦 POST）→ 填命令 → 显示返回 `wrapper_path`+`next` 原文；
   **反向断言**：页面不出现"拼好引号的 --trigger 带空格命令"文案模式；
4. **自检 no_reply 回跳**：桩 no_reply ⇒ 出现「去配叫醒命令」锚链；
5. 禁词（真实名/用户目录）0 命中；页面写请求 ⊆ {self-check, wake POST}；Console 0 红错；
   截图进 `temp\验收证据截图\`、`result.json` 脱敏。
