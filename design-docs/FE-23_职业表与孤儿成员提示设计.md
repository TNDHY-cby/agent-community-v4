## 1. 职业候选（选成员步 · `.role-btn` 下拉）

| 项 | 内容 |
|---|---|
| 数据 | `GET /api/role-catalog` 拉一次缓存（`ROLE_CATALOG`）；`makeRosterRow` / `renderRoster` **先等目录再渲染**（`await loadRoleCatalog()`） |
| 下拉结构 | **自由输入行**（文本框，回车/失焦即采用）+ 按 `groups` 分组的推荐项（组名小标头 `.dd-group`）+ 底部 `note` 原文（「只是推荐…不得当白名单拦」） |
| 写死表 | **删除 `POSITIONS=['组长','码农','画师','搜索者']`**；目录拉不到 ⇒ 下拉只剩自由输入 + 「职业目录暂不可用」提示（不伪造候选） |
| 提示行 | `#roleHint`（「② 选定员工」标题下）：`职业自由填 · 候选 N 个（M 组，来自平台职业表）` + `legacy_aliases` 旧叫法提示（如「画师 → 美术」） |

## 2. 孤儿成员（`members-status` 的 `orphan*` 三字段 + `GET …/orphans`）

| 层 | 做法 |
|---|---|
| **成员卡**（会话流 `_sfCard`） | `m.orphan===true` ⇒ 卡头下**红黄警示块**：「⚠ 孤儿成员」+ `orphan_text` + `orphan_advice` **原文** |
| **页面横幅**（`#orphanStrip`，stageBar 下） | `GET …/orphans`：`headline` + 逐条（岗位·名字·text·advice）+ 按钮「去名单移除（选定员工区）」→ 滚动并闪烁 `#rosterBlock`（**不代删**） |
| **刷新时机** | `loadSessionFlow()` 末尾与 `loadWorkshop()` 末尾各拉一次（读接口，无副作用） |
| **与 FE-20 门控的联动** | `orphan_count>0` 时 **名单块 `#rosterBlock` 即使不在 select 阶段也放开**（否则工作阶段连"移除"入口都没有——FE-20 §2 门控加一个 `|| _orphanCount>0`），主操作计数不受影响（名单行/删除是行级操作） |

## 3. 不做

- 不自动清理孤儿（后端故意不级联删，等老板拍板）；不改 `members` 写接口；
- 不动 role 提示词/AI 选人链路（DSH 侧已接 role_catalog）。

## 4. 验收（`verify/fe23_check.js`，隔离实例 + 自建自清 + `AC_VERIFY_OUT`）

1. **职业下拉**（真接口）：打开 roster 行的职业下拉 ⇒ 组标头 + 候选数与 `role-catalog.count` 一致、
   自由输入行存在且**可输入任意职业并被采用**（非白名单）；提示行含 `note` 要点与「画师 → 美术」；
2. **孤儿链路（真造）**：注册 harness → 建间带该成员 → **删 harness** → 打开工作间 ⇒
   会话流卡出现「⚠ 孤儿成员」+ `orphan_text`/`orphan_advice` 原文；`#orphanStrip` 出现 headline；
   点「去名单移除」⇒ `#rosterBlock` 被滚动/闪烁（**且全程无 members 删除请求**——只提示不代删）；
3. 名单在非 select 阶段因孤儿放开（FE-20 联动断言）；
4. 禁词（真实名/用户目录）0；页面写请求白名单不变（members POST 等既有）；Console 0 红错；
   截图进 `temp\验收证据截图\`、`result.json` 脱敏。
