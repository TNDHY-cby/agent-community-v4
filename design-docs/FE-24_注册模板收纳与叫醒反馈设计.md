## 1. 收纳展开（老板验收口径）

| 项 | 内容 |
|---|---|
| 结构 | `#copyAll` 内：提示行 → **`<details id="tplDetails">`（默认不 open）**：`summary`=「📄 展开完整模板…点一下展开，再点收起」，内容包在 `#tplText`（p1 + `#aiPrompt` + p2 + `#jsonTemplate` + p3）→ **details 之外**保留三个按钮 + `#oneClickResult` |
| 默认态 | 只见标题 / 提示 / summary 条 / **按钮区**；模板正文不可见 |

## 2. 叫醒结果反馈（107 §三.1 / 109 §三）

- `bkWakeSave`：POST wake 成功后**再 GET 一次** `…/wake`，把后端 `status_text` 原样显示成
  **「📣 已配：收到任务会执行「…」来叫醒它」**（读接口确认的真话，不是自说自话）；
- `oneClickRegister` 的 `auto-connect` 成功分支：响应带 **`wake_pending_restart:true`** 时追加黄条
  —— 「你配了叫醒命令，但桥已在运行 ⇒ **要等桥重启后才生效**」+ `note` 原文（含两条可行路径）；
  无该标记但有 `note` 时也显示 note（信息不吞）。

## 3. 连带改动（契约性，如实）

`fe21_check.js` 原以 `#aiPrompt` 可见为前置、读其 `innerText` —— 收纳后默认不可见 ⇒
**进入方式改为先展开 `#tplDetails` 再读**（断言全部原样，只改进入方式，同 fe09 先例）。

## 4. 验收（`verify/fe24_check.js`，隔离实例 + 自建自清 + `AC_VERIFY_OUT`）

1. 默认：`tplDetails` 非 open、`#aiPrompt` 不可见、summary 与三按钮可见；
2. 点 summary 展开（aiPrompt 可见、`#tplText.textContent` 取快照）→ 再点收起（不可见），
   **两态快照长度一致**（复制载体不变）；
3. **收起态点复制**（上下文开 clipboard 权限）→ 读取 `navigator.clipboard.readText()`，仅将 Windows 的 CRLF 归一为 LF 后逐字符比较 `#tplText.textContent`
   （展开态再比一次，两态一致；实测源 5407 字符 / 176 个 LF，剪贴板 5583 字符 / 176 个 CRLF）；
4. wake 反馈：打桩 POST/GET `…/wake` ⇒ 写入后出现 `📣 已配：收到任务会执行…`；
5. `wake_pending_restart`：打桩 pre-register/probe-register/auto-connect（`wake_pending_restart:true`）
   ⇒ 一键注册结果出现「等桥重启后才生效」+ note 原文；
6. 禁词 0；写白名单 = {self-check, wake, pre-register, probe-register, auto-connect}（均打桩）；Console 0 红错。
