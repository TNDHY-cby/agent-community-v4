## 2. ★前台第一屏 ＝ 各种功能模块（老板裁定）

**第一眼看到的就是"我们能替你做哪些事"** —— 一屏**功能模块**（卡片/瓦片），每块点进去**当场办**。
不做点名册优先、也不做排障台优先（老板 2026-10-15 晚场明确：「**第一眼是各种功能模块**」）。

### 2a. 功能模块清单（把现有能力摆成柜台业务）

| # | 模块（用户看到的话） | 背后（现有端点） | 现状 |
|---|---|---|---|
| 1 | **登记一位新员工**（你手头有什么给什么，平台自己探） | `pre-register` / `probe-register` / `register` | ✅ 已有 |
| 2 | ★**脚本激活**（填关键词 → 平台去找 → 写好激活脚本） | **本稿新增**（§3） | ❌ 新做 |
| 3 | **员工档案**（harness 列表 ＋ 点「详情」查看/编辑） | `GET /api/harness/list` ＋ **新增详情读写**（§2b） | ⚠️ 列表有、详情要新做 |
| 4 | **建会话 / 送桥**（把岗位和它对上） | `establish-session` / `deliver-bridge` | ✅ 已有 |
| 5 | **批量对接 / 掉线抢救** | `onboard-members` / `recover` / `recover-scan` | ✅ 已有 |
| 6 | **通道停用 · 新建** | `channel/retire` / `channel/establish` | ✅ 已有 |
| 7 | **架桥辅助**（桥路径 / 验证桥 / 自动连接） | `bridge-path` / `bridge-verify` / `auto-connect` | ✅ 已有 |
| 8 | **问前台**（说不清就直接问） | `/api/assistant/chat` | ✅ 已有 |

**前台的气质（老板的比喻就是要求）**：模块**列得出来、点得下去、办完有结果**；
办不成**当场说清为什么、下一步你去哪**（准则⑤）；**不摆一段说明让你自己读**。

### 2b. ★模块 3 · 员工档案（harness 列表 ＋ 「详情」按钮）

**列表**：每个 harness 一行 —— 名字 / `harness_id` / 在线与否 / 桥状态 / **当前激活方式**。
**每行一个「详情」按钮** ⇒ 打开**详情面板**（同一页抽屉，不跳页），**四块内容可查看、可编辑**：

| 详情块 | 编辑什么（**都是 `HarnessInfo` 里真实存在的字段**，不凭空造） |
|---|---|
| **① 框架性能** | `harness_type` / `harness_version` / `transports` / `preferred_transport` / `tools[]` / `ai.capabilities`；<br>**平台算出的档位事实**（只读展示）：`interface_class`、`can_be_woken_by_platform`、`needs_protocol`（来自 `tier_guidance`） |
| **② 适配模型** | `ai.*`：`model_name` / `provider` / `version` / `capabilities` / `max_tokens` / `can_see` / `can_code` / `can_browse` / `can_file_ops`；`waking_models[]` |
| **③ 具体桥模板** | 该 harness 选的桥模板（`platform/bridge_template.py` 那一族）＋ 桥坐标 `bridge_dir` ＋ `bridge_status`（`""未登记 / reported已告知 / tested测试通过`）；「去看模板」用 `list_bridge_templates` |
| **④ 激活方式** | `wakeup_method` ＋ 它那一支的字段：`wakeup_url`（http）/ `wakeup_dir`（file_poll）/ `acp_command`+`acp_cwd`（acp）/ `api_base_url`+`api_message_path`+`api_outbox_dir`（http_api）<br>**＋ 视觉激活脚本本体**（★新增字段 `activation_script`，就是 §3 工作台产出的那份） |

**编辑的纪律**：改完**必须回显平台重新判定的事实**（例如换了 `wakeup_method` ⇒ 档位事实跟着变），
**不许"改了但界面还显示旧档位"**（这是 `tier_guidance` 顶上那条"只写不读"裁定的直接后果）。

**保存方式**：走**新端点**（§5），不复用注册端点（注册会重建会话/桥，语义不同 —— 改档案不该顺手重建）。

## 3. ★脚本激活工作台（本稿核心）

### 3.1 三步（老板定的口径，一步一步来）

```
① 用户填写**具体关键词**  →  ② 让 **agent 去定位**  →  ③ 落成**具体视觉激活脚本**
```

### 3.2 逐屏形态

**屏 1 · 填关键词**
- 一个输入框：**具体关键词**（可多个，用 `|` 分隔）；
- 输入框下面给**候选关键词**（可点即填）——从**现有事实**里推，不让用户干瞪眼：
  该 harness 的 `process_hint` 片段、进程名、已登记的会话名、最近扫到的窗口标题里的字；
- 一句话说清关键词是干嘛的：**"我会拿它去你桌面上找那个窗口/控件"**。

**屏 2 · 让平台去找**（按钮：「让平台去找」）
- 平台 Agent 真的跑工具：列窗口 → 按关键词匹配 → 报告候选；
- 逐条显示：**窗口标题 / 进程 / pid / 能不能被注入（injectable） / 匹配分**；
- **如实说清**：找到几个、哪个最像、**为什么**；一个都没找到时**说清试了什么**、并给"把关键词换宽一点"的建议
  （**不许留"没反应"**）。

**屏 3 · 确认 + 试投**（按钮：「就是这个窗口，试一次」）
- 用户点选候选 → 平台做**一次试投**：送一句**可核对的探针文本**，然后**读回验证**；
- 结果三态（照 `FE-08`/`FE-11` 的既有文案，**原样沿用**）：
  `✓ 已自证`（真送达且读回一致） / `⚠ 未核实`（送出去了但不能确认） / `✗ 失败 + 原因 + 下一步`；
- **绝不显示"完成"**（准则⑤；V51 已把这条写进实现纪律）。

**屏 4 · 成稿：这就是你的视觉激活脚本**
- 显示**脚本正文**（可见、可复制、可手改），并写清它依赖什么：关键词、注入方式（`wmpaste` / `clipboard`）、
  预期回读、失败时人该做什么；
- 按钮：「**保存为该员工的激活方式**」→ 之后这位员工可以**一键脚本激活**（每次跑完**如实回报**三态）；
- 保存的是**可复现的脚本**，不是一次性动作 ⇒ 这就是老板说的"最后写具体视觉激活脚本"。

### 3.3 平台 Agent 的边界（**必须写死**）

| 动作 | 谁能做 |
|---|---|
| 生成候选关键词、跑定位、生成脚本正文、解释为什么 | **平台 Agent 可以自动做** |
| **试投**（真的往窗口里送字） | **必须用户点**（一次一按，结果如实回报） |
| **保存**脚本、把它设为该员工的激活方式 | **必须用户点**（可审计、可回退） |

理由：注入是**动用户桌面的动作**，平台不能"替用户动手"。这条与本项目既有纪律一致（自动兜底默认关）。

### 3.4 ★平台 Agent 有没有这个能力 / 要不要升级（**2026-10-15 实测盘点**，回答老板第 2 问）

**现有工具清单（实测，`platform/tools/`）**：
`list_harness` · `launch_harness` · `bridge_test` · `probe_harness`（harness 运维四件）
＋ `read_file` · `write_file` · `shell_exec` · `generate_bridge` · `list_bridge_templates` · `web_fetch`

| 这一步 | 需要什么 | 平台 Agent 现在 | 结论 |
|---|---|---|---|
| 生成**候选关键词** | 读 harness 记录 ＋ 探本机进程 | ✅ `list_harness` / `probe_harness` ＋ `read_file` | **现成，够用** |
| **定位**（按关键词找窗口） | 列窗口 ＋ 按关键词匹配 | ❌ **没有窗口枚举工具**：`visual_launch.list_windows()` 只存在于后端代码里，**没暴露给 Agent**；Agent 只能 `shell_exec` 拼 PowerShell ⇒ **Windows 专属、拿不到结构化结果、无法跨平台**，也过不了产品化判据 | **★需要升级：加 1 个工具** `find_window(keywords)`（包 `visual_launch`，跨平台、探不到就如实说探不到） |
| **试投 + 读回验证** | 注入 ＋ 回读 | ⚠️ 后端有 `visual_launch.launch()`（verified 三态），**Agent 没有工具** | **按 §3.3 的建议不开给 Agent** —— 试投由**界面按钮**直接调端点（一次一按、可审计）。若老板要放宽，再加 1 个工具 |
| **生成脚本正文** | 会写文件、懂平台自己的 API/模板 | ✅ `write_file` ＋ `generate_bridge` 已是同类先例（平台 Agent 早就会"生成桥脚本"） | **现成，够用** |
| **保存进档案** | 改 harness 记录 | ⚠️ 需要**新端点**（§5），Agent 不宜直接改记录 | 走端点，**用户点保存** |
| **算框架性能** | 档位事实 | ✅ 纯规则（`tier_guidance`），平台自己算，**不需要 Agent** | 现成 |

**一句话结论**：**能力大部分现成**（探进程、读档案、写脚本、算档位都有），
**唯一真缺口是"定位"那一步 —— 需要加 1 个工具 `find_window`**（把已有的 `visual_launch` 能力开放给 Agent，跨平台、如实回报）。
**这属于"小升级、不是重构"**；升级清单＝`find_window`（必须）＋ `try_activate`（可选，取决于老板要不要放宽 §3.3）。

## 4. 关键词从哪来（不让用户卡在第一步）

前台**主动给**候选（可点即填），来源都是**已有事实**、不新增采集：
- 该 harness 注册时的 `process_hint` / `path_hint` / `port_hint` 片段；
- `sysprobe`/`procprobe` 能看到的进程名；
- 该成员已登记的**会话名**（`session_aliases[0]`，V25 要求"脚本不写死名字"）；
- 定位时**真扫到的窗口标题**里的高频词（第二轮起可复用）。

⇒ 用户最省事的路径是：**点一个候选 → 让平台去找 → 点确认**。

## 5. 数据契约（新增尽量少）

**新增只读**
- `POST /api/docking/locate`：`{keywords:[…], harness_id?}` →
  `{candidates:[{title, process, pid, injectable, score}], tried:[…], probe_note}`
  （纯探测，**不改状态**；`injectable` 用平台已有的窗口/注入能力判，探不到就**如实说探不到**）

**新增写（进前台白名单）**
- `POST /api/docking/try-activate`：`{harness_id|member_id, keywords, text?}` →
  `{verified, method, detail, next_step}` —— 内部复用 `visual_launch.launch(...)`，**不另写一套注入**
- **档案详情读写**（模块 3 §2b 用）：
  - `GET /api/docking/harness/{harness_id}` → 档案全文 ＋ 平台算出的档位事实（只读项）；
  - `POST /api/docking/harness/{harness_id}` → 只改 §2b 四块里的**声明白字段**（白名单式，逐字段校验）；
    **语义是"改档案"，不重建会话/桥**（那与"重新注册"是两件事）。
- **激活脚本**（★老板裁定：存进档案，不另建目录）：
  - `HarnessInfo` 新增字段 **`activation_script`**（默认空 ⇒ **向后兼容**，老记录不受影响）；
  - `POST /api/docking/harness/{harness_id}` 带 `activation_script` 即为保存；`GET` 详情时一并回显。

**白名单（页面级契约，验收据此卡）**＝ `FE-11 §1` 那 6 条 **＋** 上面 3 条（`locate` / `try-activate` / 档案读写）；
**`/discuss` 出现即 FAIL** 这条不变。GET 不限。

**落盘**：脚本**跟着 harness 记录走**（老板裁定），落在平台既有的状态存储里 ⇒ **仍认 `AC_DATA_DIR`**（可移植性硬规则不变）。
导出成 `.ps1` 只是**给用户看的副本**，不是第二份真相。

## 8. 验收（本稿的硬判据）

1. **产品化判据**：换目录 + 换端口 + 换数据目录、**不改一行代码**能走通（脚本落盘认 `AC_DATA_DIR`）；
2. **真跑**（隔离实例 + 真 HTTP）：定位**命中**与**不命中**都要有话说；试投 **verified 三态**都要能触发；
   脚本保存 → **重启后还在** → 一键脚本激活成功；
3. **诚实性**：非 Windows / 无注入能力时**如实说不支持**并给人工路径；**任何路径都不许出现"完成"字样**
   除非 `verified=True`（反向断言）；
4. **白名单**：页面非 GET 请求 ⊆ 白名单；`/discuss` 出现即 FAIL；
5. **"只做不讲"**：对接中心正文**不得含说明书特征段落**（守卫按特征词卡：`三步`/`自测`/`怎么验证`/`骨架` 等，
   白名单逐条说明理由）；
6. `check_portability` / `check_productization` / 全量回归 全绿。
