## 1. 要解决的问题（老板口径）

后端 2026-10-23 把「送话」收敛成**一个通用入口**：上层只说
**「把这段话送给这个员工」**，由 `platform/delivery.py` 自己按会话名定位目标、
按 `cdp → native → uia → clipboard` 选通道、每档读回核对。
问题在界面上：**这条能力目前没有任何前台**——用户只能看后端日志或自己调接口。

本稿要做的只有一件事：**把这件事做成界面上一点就能办的动作**，并且
**界面不猜通道、不猜目标**，全部照后端返回说人话。

---

## 2. 后端契约（只认这三个，不重复实现）

| 用途 | 端点 | 关键字段 |
|---|---|---|
| 现在能送到哪儿（只读） | `GET /api/docking/harness/{id}/delivery` | `ok` / `name` / `ws` / `hwnd` / `title` / `source` / `why` |
| 送一段话（写） | `POST /api/docking/harness/{id}/deliver` `{text, prefer?, idx?, enter?}` | `ok` / `channel` / `verified`（`true`/`false`/`null`）/ `attempts[{channel,ok,why}]` / `detail` / `next_step` / `resolved{source,…}` |
| 这个目标能走哪条通道（只读） | `GET /api/docking/delivery/channels?hwnd=&ws=&title=` | `channels[{channel,available,why}]` / `recommended` |

三条硬纪律（后端已用守卫钉住，前端必须照做）：

1. **`verified` 三态如实**：`true`＝读回核对通过；`false`＝投递没成功；`null`＝这档本来不能核实。
   **`null` 永远不许写成「已送达」**——剪贴板档只把内容放好，等人按 `Ctrl+V`。
2. **`prefer` 是排障用的锁档**：锁了就**锁死**，那档失败就如实失败，界面不替它换档。
3. **找不到目标时说原因 + 下一步**：`why`（如「这个 harness 还没有会话名」）原样显示，
   并给出去处（建会话 / 重命名 / 开会话名对应的窗口）。

## 3. 界面方案（两个入口、同一份实现）

同一件事只写一份渲染：`dockDeliverPanelHtml(prefix, hid)` +
`dockDeliverTarget(prefix, hid)`（定位 + 通道）+ `dockDeliverSend(prefix)`（送）。两个入口共用。

### 3.1 入口 A：新瓦片「送话给员工」

- 位置：**「脚本激活」之后、「员工档案」之前**（办事顺序：登记 → 激活 → **送话** → 档案 → 建会话 …）。
- 文案：名 `送话给员工`；副标题 `只说送什么 —— 平台自己找目标窗口/页面，并按能核实的通道先投`；
  `去办 →`。不挂 `CORE` 铭牌（`CORE` 仍只属脚本激活）。
- 瓦片编号由 CSS 计数器自动排（插入不手改 `UNIT-nn`）。
- 弹窗内容：员工选择器 → 目标解析行 → 通道表 → 文本框 + 「送话」。
  **打开即自动解析一次**（否则用户不知道"现在能不能送"）。

### 3.2 入口 B：员工档案详情 ⑦「送话（按员工）」

- 放在 ⑥ 附属记录之后，**默认展开**（它就是"我现在就要跟这个人说话"）。
- 员工固定为该档案的人，**不出现选择器**（避免在 A 的档案里给 B 送话）。
- 其余渲染与入口 A 完全同一份。

### 3.3 面板结构（自上而下，一屏内办完）

```
目标：▸「窗口/页面标题」  来源：记忆（上次成功过的页面）| 按会话名在调试端口里找到页面 | 按会话名找到窗口
      （找不到时）⚠ <why 原话>  → 下一步：去「建会话 / 送桥」把会话名对上
通道：cdp 可用/不可用 · native · uia · clipboard（每档带 why，recommended 标「推荐」）
文本：[____________________________________]  锁档：自动 ▾  ✓ 送完回车(enter)
      [送话]   <状态行>
结果：✓ 已自证（通道 cdp，读回一致） / ⚠ 未核实（投递没成功）/ ⚠ 半自动（内容已放剪贴板，需要你按 Ctrl+V）
      attempts 折叠：cdp 失败——没有页面 ws 地址；native 失败——没有窗口句柄 …
```

- **通道表用「能不能用 + 为什么」两列**，`why` 原样显示（那是给用户看得懂的原因），
  不用红/绿块替代文字。
- **锁档下拉**：`自动`（默认）/ `cdp` / `native` / `uia` / `clipboard`；
  选「半自动」时按钮文案改成「放进剪贴板」——因为那一档不是"送"，是"备好让你粘"。
- **`enter` 勾选**：默认**不勾**（回车会把消息发出去，不能替用户决定）。

### 3.4 三态话术（一处真相，A/B 两个入口共用）

| 后端返回 | 界面写什么 | 绝不许写 |
|---|---|---|
| `verified === true` | `✓ 已自证：话送到了这个目标，且读回一致（通道 X）` | — |
| `verified === false` | `⚠ 未核实：投递没成功（通道 X）` + `detail` + `next_step` | 「已送达」 |
| `verified === null` | `⚠ 半自动：内容已放进剪贴板，需要你到目标窗口按 Ctrl+V；平台不能核实` | 「已送达」「已投递」 |
| `ok === false` 且无 `resolved.ok` | `✗ <detail/why 原话>` + 下一步 | 「没有内容」 |

`source` 一并显示：**用户由此判断平台有没有认错人**（"按会话名找到窗口"≠"记忆"）。

## 7. 不做 / 边界

- **不做**「批量给全员送话」（一次一位，误投代价大；要批量得先有回执台账，另起设计）；
- **不做**发送历史（后端没有这条数据，前端自己存就是两份口径）；
- **不接管**签名/回执：`verified` 只证明"这次读回一致"，不证明"agent 收到了/会处理"（与 V73 口径一致）；
- 非 Windows 上 `native`/`uia` 不可用 ⇒ 通道表由后端 `why` 如实说，界面不写平台专属引导。

## 10. 大厅页（index.html）复核与修正（2026-10-23 第三批）

老板「顺便看看大厅有哪些要改的」⇒ 在隔离实例上真看 + 真量，结论如下。

### 10.1 必修：一处**真 bug**（陌生人首次运行必踩）

| | |
|---|---|
| 现象 | 大厅整页塌成一条：`.main` 只有 **30px** 高，页面中间一片空白 |
| 根因 | `.app{display:grid;grid-template-rows:52px 1fr 30px}` **只写了 3 行**，而 `.app` 现在有 **6 个兄弟**（`#dataHealthBar` / `#credBar` / `#singletonBar` 三条横幅是后加的）。三条横幅**任一可见**时，网格把 `1fr` 那一行给了横幅（实测凭据黄条 **796px** 高），主区被挤进 30px 的固定行 |
| 为什么没人发现 | 老板机器上凭据体检跑过了 ⇒ 黄条不显示；隔离/新装的实例上必现 |
| 修法 | `.app` 改**纵向 flex**（`flex-direction:column`）+ `.main{flex:1;min-height:0}` —— 以后再多几条横幅也只是"多一行"，主区永远占满 |

### 10.2 同批修正（一致性 / 可读性 / 首次上手）

1. **可读性**：`theme-crt.css` 的 `--dim` `#7A4E4E` → `#967C7C`（2.7:1 → 约 5.2:1）；cap 标签 `#FF3527` → `#FF7B7B`（4.49 → 约 6.7）；大厅对比度告警 **14 → 0**。
2. **字号**：`.ac-sw` 10px→12px、`.ac-fw` 10.5px→12px、`.ac-id` 10px→11.5px。
3. **图标**：tab 的 `🏛️/🔧`、回收的 `♻️`、讨论头 `💬`、桥接 `🔗`、工作间行的 `📌📍✏️🗑️`、agent 卡的 `🧩🤖`、协议徽标 `✅⚠️🔒` 全部去 emoji（改用文字或既有圆点）。

### 10.7 大厅广播通知（FE-31，老板点名「大厅还要做广播通知之类的功能」）

**契约（后端 `platform/routers/hall.py`，本轮新增）**

| 端点 | 说明 |
|---|---|
| `POST /api/hall/notice` `{text, level?}` | 发一条广播；`level = info / warn / urgent`；`text` 1~500 字 |
| `GET /api/hall/notices?limit=20` | 读最近 N 条（1~100，越界自动收敛） |

**口径**：一条广播 = **一条大厅消息**（`from_agent=platform`、`to_agent=broadcast`、
`payload.message_type=notice`、`payload.level=…`）⇒ 天然出现在大厅、天然被 WebSocket 推给所有开着的页面，
**不另造一套通知存储**（两套必然打架）。只追加、无已读/撤回；不落盘，重启即清 —— 它是"广播"不是"公告板"。

**界面**：顶部标签行右侧「广播通知」→ 玻璃面板（文本框 + 级别 + 发出）→ 发出后大厅出现
`.hmsg.type-notice`（红边 + 玻璃，标签「广播」）；页面打开时 `GET /api/hall/notices` 把历史广播补进大厅。

**失败要说话**：空内容前端先拦住并给原因；超长/乱级别后端 400 + 中文原因，界面原文显示。

**判据**：`verify/fe31_check.js`（真浏览器 + 真请求：点开面板 → 空内容被拦 → 真发一条 → 大厅出现 + `total` +1）；

## 11. 备选两路（D后端-3 表层交互 / D后端-4 浏览器直连）落地记录

### 11.1 表层交互（`surface`）

| 环节 | 界面 | 纪律 |
|---|---|---|

| 送一句 | `POST /api/docking/try-activate {method:'surface', harness_id, title, text, enter}` | Electron 一律 `verified=null` ⇒ 只说「已按教过的位置点进去并逐字键入，不能确认对方收到了」 |

### 11.2 浏览器直连（CDP）

① `GET /api/docking/web/probe` 找页面（空结果把 `why` 原样显示 = 怎么开调试端口）
② `POST /api/docking/web/editors {ws}` 列输入框，**用户点一个指认**（平台不猜 idx）
③ `POST /api/docking/web-send {ws, text, idx, mode, enter, harness_id}` —— 三档 `insert → paste-event → clipboard`，
每档后读回核对；`tiers` 与 `readback` 都折叠显示；`enter` 默认不勾。

### 11.3 试投文案（`D后端-2` §2 的文案纪律）

- `ok=false` / `need_human=true` / `detail` 含「没有投递」 ⇒ 说 **「✗ 没有投递：<detail>」+ 下一步**（以前一律写成"未核实：送出去了…"，属于把"没投出去"说成"投出去了"，已改）；
