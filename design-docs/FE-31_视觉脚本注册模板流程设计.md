# FE-31 · 视觉脚本注册模板流程（大厅对接中心专用）

> 来源：**老板 2026-10-24 口述规格**（原文见下 §1 摘要）；**本文是方案稿**，等老板拍板后再动代码
> （按 2026-10-24 定的循环：讲清方案 → 老板把关 → 写进项目模型 → 最小成本跑通 → 通用化）。
> **范围**：**只做大厅对接中心里的"注册模板"**；工作间对接中心那一版等老板另给要求。
> 现状（供对照）：`input_regions.py` 目前只存 `input / send / keywords / frame`，
> 只有"试投一句"，**没有**会话列表框、新建会话框、两个测试、固定话术、焦点恢复。

---

## 1. 老板要的场景（一句话）

> 没有高级协议适配的 harness：平台只能靠**视觉脚本**激活 ——
> 注册脚本 → 拉到最前 → 点击输入框 → 粘贴固定话术（提醒检查邮箱）。

两类只能这样办的 harness（老板给的协议分档，原文保留）：

| 档 | 谁 | 能做什么 |
|---|---|---|
| **clipboard（C 档）** | ChatGPT 桌面、Claude 桌面、 Cherry Studio、ChatBox、LM Studio、Jan、Msty、豆包、Kimi、通义、多数纯 GUI 客户端 | 只能**人**粘贴；D 档桥只落盘，**不能自动叫醒** |
| **http（无回调，D 档）** | 只能接收 HTTP 落盘、无回调的简单 webhook/接收端 | 只落盘，**不叫醒** |

⇒ 这两档的"叫醒"必须靠视觉脚本：**点进输入框 → 粘一句固定话术 → 发送**。

## 2. 注册流程（大厅对接中心 · 模板性质）

> 模板**不涉及会话命名**（"会话名取消"）：大厅侧只负责"这套脚本属于哪个窗口"。

### ① 选择 Harness（换掉现在的"让平台去找"）

```
[ 输入一个模糊名，例如 trae        ] [ 确定 ]
   ↓ 下拉出平台探测到的相似窗口（真实标题，可滚动）
   Trae CN
   Trae Helper
   ↓ 点一条
[ Trae CN                          ] [ 确定 ]      ← 真实标题回填输入框
当前已绑定：Trae CN                                ← 小字，点选的同一刻就绑定
```

- 点错想换：**手动清空输入框 → 重新输入 → 再点确定** → 平台重新搜、重新下拉（同一套流程）；
- 点选时立刻 `POST …/bind {hwnd,title}`（**绑定和"选中"是同一个动作**，不留第二步）；
- 下拉里每条显示：真实标题 + 窗口类 + 是否最小化/能否截图（探不到的如实标"截不了"）。

### ② 图样与位置（全部在**同一张截图**上框）

提示语（照抄老板口径）：**框的时候别过分超出目标本身；脚本点击时默认点中间。**

| 要框的东西 | 必填？ | 干什么用 |
|---|---|---|
| **会话列表**（全新，之前没有） | 是 | 判断"新建会话到底成没成"：只比这块区域**前后有没有变化**，不去猜"里面有几条"（见下 §2a） |
| "新建会话"按钮 | 是 | 点它建新会话 |
| 输入框 | 是 | 点它、粘话术 |
| 输入框里的**引导词**（可填多个） | 否 | 窗口大小/界面变化时用来确认"这还是输入框" |
| 发送按钮 | 是 | 点它发送（避免有些聊天框回车是换行） |

#### §2a 会话列表框是**全新**的，现在平台没有

现状必须说清：`input_regions.py` 只存 `input / send / keywords / frame`，
**既没有会话列表，也没有"新建会话"按钮**（截图/试投/送话都只围绕输入框与发送按钮）。
所以这一块是**新契约**，不是把老的东西改个名。

它怎么判断"新建会话成功"（**不承诺 OCR**，也不假装能数条数）：

1. 点「新建会话」之前，先截一张图，把**会话列表那块区域**的像素存下来（`sessions_before`）；
2. 点完再截一张，取同一块区域（`sessions_after`）；
3. 比这块区域的**变化率**（复用后端已有的 `band_diff` / `paste_ratio` 那套）：
   - 变化率 ≥ 阈值 ⇒ 记"像新建出来了"（`sessions_changed=true`）；
   - 变化率 ≈ 0 ⇒ 记"这块没看出变化"（`sessions_changed=false`）；
   - 抓不到图（最小化/被遮挡）⇒ 记 `null`，**不下结论**。

**为什么只对比、不数条数**：列表里是应用自己画的 UI，系统层读不到条数；
硬说"多了 1 条"就是编造（这正是"失败要说话"要避免的）。

**判不了怎么办**：`sessions_changed=null` 或 `false` 时，界面说人话
（"我在你框的那块区域没看出变化 —— 你看到新会话出现了吗？"），并给一个
**「我看到新会话了」** 的人工确认按钮；点了也算通过，但档案里记 `verified_by: "human"`，
**不许写成"平台自动确认"**。

> 工作间那版里，会话列表这块还可能用来**选某个会话**（点列表里某一行）；
> 那时就要多一层"行定位"，本文档（大厅模板）不做。

按钮：`读取剪贴板截图`、`重新读取截图`（全部重来）、`重新框选`（只清框、图不动）。
下方固定放：**截图 + 已画的框**（框上有名字标签，点一下选中、拖拽移动/缩放）。

### ③ 两个测试（都通过才允许保存）

| 测试 | 平台做 | 默认内容 |
|---|---|---|
| 测试新建会话 | 抬到最前 → 点「新建会话」→ **看会话列表变没变** | —— |
| 测试发送消息 | 点输入框 → 粘贴 → 点发送按钮 → 看画面变化/是否回话 | **"你好（请直接回复你好）"** |

- 任一测试失败 ⇒ **保存按钮保持不可点**，并在旁边写清失败原因（原话，不美化）；
- 两个都通过 ⇒ `保存为该 Harness 的脚本激活方式`。

### ④ 通知（模板里固定，工作间落配置）

1. **激活话术文本固定**（一处真相，见 §5 待拍板）；
2. 每次**只做一遍**：点一次输入框 → 粘一次 → 点一次发送（防重复输入出错）；
3. 收尾：**把平台拉回最前，恢复合作社展示**；
4. 若这套脚本**不需要**把目标拉到最前，**尽量后台做**（目标不最小化即可）。

## 4. 后端要补的契约（现在的缺口，明写在前面）

| # | 缺口 | 建议 |
|---|---|---|
| 1 | `regions` 只有 `input/send` | 扩成 `sessions`（会话列表）、`new_session`（新建按钮）两个框；老数据能读（缺的不当有） |
| 2 | 没有"测试新建会话" | `POST …/visual/test {step:"new_session"}` → `{ok, sessions_before, sessions_after, why}` |

| 6 | 收尾没"恢复平台焦点" | 投递/脚本结束时按开关把平台窗口抬回最前（**默认开**，见 §5 Q4） |

## 5. 要老板拍板的四个点（只有你知道）

1. **点击落点**：你说"默认点中间"。但现在后端是"框的上三分之一"（因为用户常把底下那排小按钮一起框进来）。
   我建议：**默认点中间，若框高超过窗口的 8% 就自动取上三分之一**（并在界面写一句）。要不要这样？
2. **固定激活话术**：给我一句原文，我照抄成一处真相（模板默认值），通知时统一用它。
   我拟的是："【生产合作社】有新任务，请回大厅看邮箱。回一句"收到"确认你在。" ——换不换？
3. **"测试通过"的标准**：新建会话＝会话列表真的多了一条？发送＝**看到对方回话**才算过，
   还是 `paste_seen + press_ok` 就算过（看不到回话时让人点一下"我看到回话了"）？
4. **收尾焦点**：脚本跑完把平台拉回最前 —— 所有情况都拉回，还是只在"平台本来在前台"时才拉回？

## 6. 判据（实现后要能跑）

- 输入模糊名 → 确定 → 下拉出现真实窗口标题；点选后输入框被真实标题替换、小字显示"当前已绑定：X"，
  且 `GET …/bind` 真回来了（**点选=绑定**，不是两步）；
- 五个框缺任何一个，保存按钮不可点，且写清缺哪个；
- 测试新建会话后 `sessions_after > sessions_before`；测试发送后目标里真出现那句话；
- 保存后 `GET …/regions` 能读回五块；`GET …/bind` 是那一扇窗；
- 全程**不出现任何具体应用名/路径/端口**（模板对所有 GUI 客户端通用）。
