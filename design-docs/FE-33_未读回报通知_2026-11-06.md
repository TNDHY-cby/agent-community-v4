# FE-33 · 未读回报通知（大厅）

> 老板 2026-11-06：「工作间组长干完活发送消息后，平台检测到**用户不在工作间内**属于未读情况时，**大厅进行对用户的通知**」
> 状态：**已落地**（`6ffd620`）　作者：W前端　影响面：`agent_community/frontend/{index,workshop,v5}.html`

## 1. 口径（先把"未读"定义清楚）

| 概念 | 定义 |
|---|---|
| **已读水位** | `localStorage['ac_read_<ws_id>']` = 用户最后看过的 `seq` |
| **未读** | 该工作间 `discussion` 里 `seq > 水位`、且 **`role !== 'user'`** 的消息条数 |
| **用户不在工作间内** | 用户当前不在 `workshop.html?ws_id=…` / `v5.html?ws=…` 那个间 ⇒ 水位不推进 |
| **基线** | 某工作间**第一次**出现在大厅时，用当前最大 `seq` 初始化水位（否则一开局 19 个全红 = 没通知） |

为什么"不算用户自己发的"：用户在大厅发的任务消息也是 discussion 的一部分，把自己发的那条算成"新回报"是荒谬的。

## 2. 呈现（三处，都在大厅）

1. **左栏工作间项**：右上角红徽标（数字，>99 显示 `99+`），左侧加一条红竖条（`box-shadow: inset 3px 0 0`）；
2. **标题条右侧**：「● N 条新回报」胶囊按钮 —— 点它**跳到第一个未读工作间**，`title` 说明"组长/员工干完活后发的消息，你还没看"；
3. **浏览器标题**：`(N) 外端agent生产合作社`（切换标签页也能看见）。

## 3. 什么时候消掉

`workshop.html?ws_id=` 与 `v5.html?ws=` 页面里各挂一段 IIFE：**进间即把水位推到该间最新 `seq`**，之后每 4s 再推一次。
⇒ 人已经在里面看了，回大厅徽标自然消失（这正是"不在工作间内才算未读"）。

取不到 `/api/workshop/{id}` 时**不推进水位**（宁可多提醒一次，不假装已读）。

## 4. 为什么不加后端接口

`GET /api/workshops` 的 `to_dict()` **已经返回完整 `discussion`**（实测：顶层字段含 `discussion`，每条带 `seq`/`role`/`timestamp`）。
所以"未读"完全可以在前端算，零后端改动、零新端点。

## 5. 已知限制（如实写）

| 限制 | 影响 | 后续 |
|---|---|---|
| 水位在 **localStorage** | 换浏览器/换设备不同步；清缓存会重置（重置后按"基线"处理，不会误报） | 要跨设备 ⇒ 后端加 `user_read_seq`（按 ws 存），端点 `POST /api/workshop/{id}/read`；前端切一行 |
| 多标签页各自水位 | 都进过同一间就一致；同时开两个大厅可能各自计时 | 可加 `storage` 事件同步，P2 |
| 只按"消息条数" | 同一人连发 3 条算 3 条未读（不是"3 个人"） | 需要"按人聚合"再改 |

## 6. 判据（真浏览器全链路，已跑通）

```
伪造未读（水位压到 0）→ 左栏 badges=1、badgeText=1
标题条 sayText=● 1 条新回报；document.title=(1) 外端agent生产合作社
点通知 → 真跳 workshop.html?ws_id=7c797290
工作间页 → 水位被推到 1（waterAfter="1"）
回大厅 → badges=0、通知消失、title 干净
console 错误 0；前端守卫 75 条全绿
```
