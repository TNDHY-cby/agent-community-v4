## 0. 一句话原理

**平台只认一个东西：对端公司有一个能通的 HTTP 地址。**

```
公司 A  ──派活/回查──▶  http://<host>:<port>  ◀── 隧道/直连都行 ──  公司 B 的 a2a 服务
                        ↑
             这个地址怎么弄出来的，平台不管
```

所以"隧道"不是平台的功能，是**你网络环境的事**；平台负责：
① 告诉你该暴露哪个端口 ② 告诉你别暴露什么 ③ 帮你把它登记成"对端公司"并验证通不通。

---

## 1. 先回答三个问题（决定你要不要隧道）

| 问题 | 怎么看 | 结论 |
|---|---|---|
| 两台机器在**同一个局域网/同一台电脑**吗？ | 是 | **不需要隧道**，直接用内网 IP |
| 公司 B 有**公网 IP**、且端口能放行吗？ | 有 | **不需要隧道**，直接 `http://公网IP:端口` |
| 上面两条都不是 | 常见 | **需要隧道**（下面第 3 节任选一种） |

平台也能替你判断一次：

```bash
# 看它怎么判断本机、给出哪几类办法（不联网、不发请求）
Invoke-RestMethod http://127.0.0.1:18920/api/peers/tunnel-advice
```

返回里的三样东西按顺序读：
- `reachable_from_outside`：`likely` / `unlikely` / `unknown`（**平台不猜"已通"**）
- `why`：为什么这么判（比如"只监听回环地址，只有本机能连"）
- `suggest`：**三类办法**（内网直连 / 隧道 / 映射后改一行地址）
- `must_not_expose`：**绝对不能映射出去的东西**

---

## 2. 要暴露的是哪个端口？（**这条最容易做错**）

| 端口 | 是什么 | 该不该暴露 |
|---|---|---|
| **a2a 端口**（默认 `9104`，`AC4_A2A_PORT`） | 对端派活、查回执的入口 | ✅ **只暴露这个** |
| 平台端口（默认 `18920`，`AC_PORT`） | 管理面：改配置、重启、读日志、静态页 | ❌ **不要暴露到公网** |

为什么：平台端口上有 `/api/config`（能看/改 AI 配置）、`/api/admin/restart`（能重启服务）、
`/api/logs/tail`（能读日志）。**把管理面暴露到公网，等于把方向盘交给陌生人**——即使有令牌也不行。

> 平台在 `/api/peers/tunnel-advice` 的 `must_not_expose` 里把这条写死了，别绕过。

## 3. 三类办法（按"最省事"排序，任选其一）

### 办法一：同机 / 同局域网（**不需要隧道**）

1. 公司 B 用**非回环**地址监听 a2a：
   ```powershell
   # 让 a2a 服务监听所有网卡（默认是 127.0.0.1，只有本机能连）
   python -m agent_community.a2a_server --host 0.0.0.0 --port 9104
   ```
   > ⚠️ 改成 `0.0.0.0` 后**必须**有公司令牌（平台 fail-closed：没令牌拒启）。
2. 查公司 B 的内网 IP：`ipconfig`（Windows）/ `ip addr`（Linux），例如 `192.168.1.23`
3. 公司 A 里验证一下能通：
   ```powershell
   Invoke-RestMethod http://192.168.1.23:9104/.well-known/agent-card.json
   ```
   能读到卡片 JSON（含 `name`）就通。
4. **防火墙**：Windows 上第一次会弹"是否允许"，选允许；或在防火墙里放行 9104/TCP。

### 办法二：任意隧道（跨网络、B 没有公网 IP）

**任选一种你手上有的**（平台不推荐也不内置特定服务商）：

- frp：自建 frps，或用任何提供 frp 的服务。本仓库给了客户端配置生成器：
  ```bash
  python tools/gen_frpc.py --check     # 先看缺什么（会逐条告诉你）
  python tools/gen_frpc.py --write     # 生成配置 + 打印启动命令
  ```
  需要的四个值：**frps 地址 / 控制端口 / token / 对外开放端口**（都填进环境变量 `AC_FRP_*`）
- ngrok / cloudflared 之类的反向隧道：把 **9104** 映射出去
- 自有服务器做反向代理：`http://你的域名/` → 公司 B 的 `9104`

> 无论哪种，**最终只要得到两样**：一个**域名或 IP**、一个**端口**。

### 办法三：你自己搞定了，但不知道怎么填（平台只负责登记与验证）

直接跳到第 4 节，把地址填进去，点"验证"。

## 4. 在平台上登记对端公司（A 侧）

```powershell
# 1) 登记（token 是对端在它自己那边签发给你的公司令牌）
Invoke-RestMethod -Method Post http://127.0.0.1:18920/api/peers `
  -ContentType 'application/json' `
  -Body '{"display_name":"公司 B","base_url":"http://<域名或IP>:<端口>","token":"<对端给你的令牌>","note":"经 frp 映射"}'

# 2) 验证能不能通（只读对端的 Agent Card，不需要令牌、不花 AI 费用）
Invoke-RestMethod -Method Post http://127.0.0.1:18920/api/peers/co-b/verify

# 3) 派活
Invoke-RestMethod -Method Post http://127.0.0.1:18920/api/peers/co-b/dispatch `
  -ContentType 'application/json' -Body '{"title":"把登录页的错误提示统一口径"}'

# 4) 查回执
Invoke-RestMethod http://127.0.0.1:18920/api/peers/co-b/tasks/<task_id>
```

**几个空分别填什么**：

| 字段 | 填什么 | 报错时怎么办 |
|---|---|---|
| `display_name` | 界面上显示的名字（随便起） | 空 ⇒ 400 |
| `base_url` | 对端的**根地址**，形如 `http://host:9104` | 带路径 ⇒ 400（提示你改成不带路径）；连不上 ⇒ 验证报 502 并给排查项 |
| `token` | 对端在它那边登记你之后**签发给你**的公司令牌 | 不填 ⇒ 派活时 400 并告诉你先要令牌；填错 ⇒ 派活 502，**且不会写进本地任务索引**（不留假成功） |
| `note` | 备注（比如"经 frp 映射，端口变了要改这里"） | 可空 |

## 5. 怎么自查"真的通了"（三步，别跳）

1. **对端自己活没活**：在公司 B 那台机器上 `curl http://127.0.0.1:9104/.well-known/agent-card.json`
2. **隧道通没通**：在公司 A 那台机器上 `curl http://<映射地址>:<端口>/.well-known/agent-card.json`
   - 通 ⇒ 返回含 `name` 的 JSON
   - 不通 ⇒ 依次查：隧道进程在不在跑 / 端口映射对不对 / 防火墙 / 地址写错没
3. **平台认不认**：`POST /api/peers/co-b/verify` ⇒ `ok=true` 且带回卡片里的名字

> **一条判据**：`tools/cross_company_check.py` 会起两个真实例把整条链跑一遍
> （登记 → 验证 → 派活 → 对端真收到 → 回查 → 停用 → 错令牌如实失败）。**不用隧道也能跑通**，
> 它证明的是"逻辑对不对"；隧道只影响"地址通不通"。

## 6. 常见故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| verify 报 502 `读不到对端` | 隧道没起 / 端口变了 / B 的 a2a 没开 / 地址带路径 | 先手工 curl 一次（第 5 节第 2 步）定位在哪一跳断 |
| dispatch 报 400 `没登记令牌` | 对端还没签发给你 | 让对端在它那边 `/api/companies` 登记你并签发，走安全通道把令牌给你 |
| dispatch 报 502 + `403` | 令牌对不上（过期/被吊销/填错公司） | 对端重新签发；旧令牌被吊销后**立即失效** |
| 隧道断了但 localhost 正常 | 只有外网通道断 | 重起隧道进程；地址不变就不用改平台 |
| 对端地址变了（隧道换端口） | 服务商换了端口/域名 | **只改 `base_url` 这一行**（`POST /api/peers` 同 `peer_id` 覆盖即可），其余不动 |
| 怕把管理面暴露出去 | 有人提议映射 18920 | **不要**。只映射 a2a 端口（9104）；平台 `must_not_expose` 里写着 |

---

## 7. 安全三件套（暴露前必须做到）

1. **令牌必填**：没签发过令牌时，平台 `check_inbound_ready()` 会**拒绝**让你暴露（fail-closed）；
2. **只开 a2a**：管理端点不出公网（见 §2 表）；
3. **可吊销**：对端在它那边吊销后，你这边**立即** 403（不需要改任何代码）。

## 8. 和"对方来连我"的区别（别混）

| 方向 | 端点 | 你要准备什么 |
|---|---|---|
| **别人来连我** | `/api/companies`、`/api/company/token/issue` | 登记对方公司 + **签发**令牌给对方 |
| **我去连别人** | `/api/peers`（本 RUNBOOK） | 对方给我令牌 + 我登记**它的地址** |

一句话：**`/api/companies` 是"谁能进我家"，`/api/peers` 是"我要去谁家"。**
