# RUNBOOK · 没有公网服务器，中转（Hub）怎么办

> 配套 `V66_本地优先与中心中转架构设计.md` §8.3。
> **一句话**：Hub 只需要"别人连得到它"；而"别人连得到"有好几条路，**不必自己有公网 IP、不必买云主机**。

---

## 0. 先分清你要连谁（这决定选哪条路）

| 场景 | 谁需要连 Hub | 推荐 |
|---|---|---|
| **A. 都是你自己的机器**（家里台式 + 笔记本 + 公司电脑 + 手机） | 只有你自己的终端 | **方案一：私有组网**（最省事，零成本） |
| **B. 要让不在你私有网络里的人/公司连** | 外部的人 | **方案二：把 Hub 暴露成一个 https 地址** |

---

## 方案一（推荐）：私有组网 —— Hub 放在你的任意一台机器上

**原理**：先用一层"私有虚拟网络"把你的机器连起来（每台机器都拿到一个互通的固定地址），
Hub 就跑在其中一台上，其他终端用那个**虚拟地址**连它。**这些地址天然跨公网**，不需要公网 IP。

**这类工具都行**（平台不绑定任何一家，下面只是常见选择）：
WireGuard（自建）/ Tailscale / ZeroTier / Netbird / 企业 VPN …

**你要做的三步**（以"每台机器都拿到一个互通地址"为前提，具体怎么装看你选的工具）：

1. 在**每台**要参与协作的机器上装好，登录同一个网络 ⇒ 每台拿到一个虚拟地址（常见形如 `100.x.x.x`）；
2. 挑一台跑 Hub：
   ```bash
   python tools/relay_hub.py --port 9400            # 绑 0.0.0.0，私有网络内可访问
   ```
   记下它的虚拟地址（例：`100.1.2.3`）；
3. 每个终端配三样（在 `.env` 或环境变量里），然后重启平台：
   ```
   AC_HUB_URL=http://100.1.2.3:9400
   AC_HUB_TERMINAL_ID=home-desktop          # 每台起不同的名字
   AC_HUB_TOKEN=<同一个共享密钥>
   ```
   `GET /api/relay/status` 里 `connected=true` 就成了。

**为什么够安全**：流量在你自己的私有网络里已经加密；而且**不用开任何入站端口**给公网。

**自证"不是局域网"**（本仓库的判据就是这么验的）：
```bash
python tools/relay_crossnet_check.py
```
它会拿本机的**非回环地址**（有这类虚拟网卡时优先用 `100.64/10` 段）起 Hub 并真传一条消息；
判据输出里 `Hub 绑非回环地址（100.x）且终端能连上 = OK` 就说明**没靠回环、也不是靠局域网**。

## 方案二：把 Hub 暴露成一个 https 地址（要给外部的人用）

本质只有一句：**让 `https://<某个地址>:端口` 能到你的 Hub**。常见四类做法，任选其一：

| 做法 | 你要准备什么 | 平台侧要改什么 |
|---|---|---|
| **隧道服务**（把你本机 9400 映射出去） | 一个隧道（自建 frp / 任意隧道服务） | `AC_HUB_URL=https://<隧道给你的地址>` |
| **反向代理**（有公网机器的朋友/公司借一台） | 一台能被动连的机器 + 证书 | 同上 |
| **边缘隧道**（Cloudflare Tunnel 之类） | 一个域名（免费域名也行） | 同上 |
| **私有组网的"公网出口"**（某些组网工具自带 Funnel 功能） | 组网工具里开启对外入口 | 同上，地址是它给你的 https |

**共同点**：平台**只认一个地址**，不认是谁提供的。换地址就改 `AC_HUB_URL` 一行。

### 必须做 TLS

Hub 用证书起：
```bash
python tools/relay_hub.py --port 9400 --certfile hub.crt --keyfile hub.key
```
或者前面放一层带证书的反代。
终端侧对**自签证书**用：
```
AC_HUB_CA_FILE=<那张证书的 pem>       # 推荐：自签也能安全校验
# AC_HUB_INSECURE=1                  # 仅自测，跳过校验，风险自负
```

**为什么必须**：跨公网明文传 `Authorization: Bearer` = 把钥匙贴在网上。
Hub 没给证书时启动就会警告这一条。

## 方案三（不推荐）：不要 Hub，直接点对点

如果只是**两台机器**，且两台都能互相访问（例：都在同一个私有网络里），
可以不用 Hub，走仓库里已有的 **a2a 点对点**（`/api/peers`，见 `RUNBOOK_公司间合作_隧道怎么用.md`）。

**为什么不推荐**：
- 没有"一处真相"（谁在线、消息到没到，两边各记一套）；
- 每加一台机器就要两两配置；
- 跨端派活/回执的自动收回（V63）在 Hub 下才自然。

## 一张对照表（照着选）

| 你的情况 | 走哪条 |
|---|---|
| 都是自己的机器，愿意装一个组网工具 | **方案一**（最省，零成本） |
| 要给客户/合作方看或连 | **方案二**（+ TLS） |
| 只有两台，且本来就能互通 | 方案三（a2a），或方案一 |
| 一台都没有、也不想装任何东西 | **暂时不做跨端**：本地平台照常用，`/api/relay/status` 会如实说"没配置中转" |

## 常见问题

**Q：为什么不用隧道把整个平台（18920）开出去？**
A：那是"管理面"整个暴露（能改配置、能重启、能读日志）。跨端只需要**转发消息**，Hub 就够；
平台自己的界面永远只在本机/私有网络里看。

**Q：Hub 挂了会怎样？**
A：**本机一切照常**（工作间、员工、任务都在本地）；只是"跨端"暂不可用，`/api/relay/status` 会说清。
Hub 恢复后终端**自动重连**（判据里有这一格）。

**Q：Hub 里存了我的数据吗？**
A：**不存**。只存"待取消息"（有上限、会过期）；工作间/审计/产物都在各自机器上。

**Q：一定要 TLS 吗？**
A：私有网络的方案一不需要（链路本身加密）；**出公网的方案二必须**。
