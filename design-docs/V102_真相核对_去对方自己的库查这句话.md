## 1. 一句话（大白话）

现在点「测一次」能证明三件事：平台把话发出去了、对方回话了、对方说"我写进会话了"。
但这三件**都是它自己说的**（V101 的真事：它每条都回 `ok/in_session/message_id`，库文件里 12:58 之后一条都没有）。

**真相核对** = 你告诉平台一句「这个应用的消息存在哪个文件」，平台每次测完就**自己**去那个文件里找这次的口令：

| 结果 | 意思 | 界面该显示 |
|---|---|---|
| 有 | 这条消息**真落进它的存储**了 | 绿勾：`✓ 真相核对通过：这句话真在它的库里` |
| 没有 | 它在自报（或者写到了别的地方） | 红字：`✗ 库里没有这句 —— 它只是"说"发出去了` ＋ 库里最近的口令（好让你判断是不是界面把口令截断了） |
| 读不了 | 文件/表/列不对、库被锁死 | 灰字：`核对不了：<真实原因>` —— **不是"没写"，也不是通过** |

## 2. 用户要做的只有两步（对接中心那一行）

1. 点「真相核对」→ 填**库文件路径**（可选：表名 / 正文列 / 时间列 / 会话列，默认按常见 SQLite 结构填好）；
   保存前平台会**真打开一次**：文件在不在、是不是 SQLite、这张表在不在、这几列在不在 —— 不对就当场说清（并列出库里**实际**有哪些表/列）。
2. 点「测一次」→ 平台发完话**自动**跑一次真相核对，结果跟着这次测试一起回来。

不填 = 不跑（默认关），老用法完全不受影响。

## 3. 契约（后端，一处真相在 `platform/session_truth.py`）

### 3.1 `GET /api/docking/harness/{id}/truth-config`

只读，回：
```jsonc
{ "configured": true, "enabled": true,
  "db_path": "<你填的路径>",
  "table": "agent_session_message", "text_col": "data",
  "time_col": "created_at", "session_col": "session_id",
  "defaults": { "table": "…", "text_col": "…", "time_col": "…", "session_col": "…" },
  "last_truth": { …上次核对的结果，没跑过就没有… },
  "hint": "库路径由你填，平台只读不改" }
```
没填过时 `configured=false`，**其他字段都不编**。

### 3.2 `POST /api/docking/harness/{id}/truth-config`

body `{db_path, table?, text_col?, time_col?, session_col?, enabled?}`（空串 = 用默认）。

- 保存前**真验证**（拷副本真打开 + 查表 + 查列）：
  - 找不到文件 → **400** `{error, why, next}`（`next`：这个路径对不对 / 应用是否装在别的用户下）；
  - 不是 SQLite → **400** ＋ "只支持 SQLite（其它存储形态平台如实不支持）"；
  - 表/列不对 → **400** ＋ `库里有这些表：…` / `这张表有这些列：…`；
- 通过 → 写进 harness 档案 `metadata.truth`（**落数据目录，不写源码、不写仓库**）并 `save_state()`，回 3.1 的形状 ＋ `probe`（真读到几条消息、最近一条时间）；
- `{db_path:"", enabled:false}` → **关掉**并回 `{"ok": true, "enabled": false}`（不静默失败）。
- 路径只在**可用性**上校验，不要求必须是某个盘符/某个应用 ⇒ 换任何 SQLite 应用只改填写内容。

### 3.3 `POST /api/docking/harness/{id}/truth-check`

body `{needle?, session?}`。`needle` 不给 → 用**这次/上次测试的口令**（`metadata.last_test.nonce`）；连口令都没有 → **400** ＋ `next: 先点「测一次」，拿到口令再来核对`。

回：
```jsonc
{ "ok": true,            // 只有 code==0 才是 true
  "code": 0,             // 0=库里有 / 1=库里没有 / 2=核对不了（与 tools/verify_session_truth.py 退出码同义）
  "found": true,
  "needle": "收到-8E7F73…",
  "verdict": "这句话真在它的库里",
  "db": "<路径>", "elapsed_ms": 42,
  "matches": [{ "at": "10-25 13:43:44", "session_id": "8d3b2a97", "excerpt": "…" }],
  "tail":    [{ "at": "…", "session_id": "…", "excerpt": "…" }],   // 最近几条（真·界面来源）
  "recent_codes": ["收到-XXXX"]                                     // 找不到时给，便于判断口令被截断
}
```
结果同时写进档案 `metadata.last_truth`（下次打开页面还看得到）。

### 3.4 `POST …/test-now` 增补字段（不改变任何已有字段的语义）

| 字段 | 含义 |
|---|---|
| `truth` | 本次自动跑的真核结果（形状同 3.3；没配就不出现） |
| `truth_verified` | **`true` 只当库里真找到了这次的口令**（配了库才可能为 true；没配就是 `false`，不算通过） |
| `truth_note` | 一句话结论（`✓ 真相核对通过…` / `✗ 库里没有…` / `核对不了：<原因>`） |
| `in_session_verified_scope` | ★V101 §4.1 的限定：`只代表对方的读回工具看到了这句话；不代表它的界面真的显示（对方可能读的是自己的缓存）` |

## 4. 为什么这不是私人定制

| 私人定制的做法 | 这里怎么做 |
|---|---|
| 代码里写死某个应用的库路径 | 路径由**用户填**，存在 harness 档案里（数据目录） |
| 写死表名/列名 | 四个名字都能覆盖；默认值只是"常见 SQLite 结构"，**不是某个应用专属** |
| 只认一个应用 | 只认 **SQLite** 这个存储形态；换任何 SQLite 应用只改填写内容 |
| 悄悄改人家库 | 永远读**拷贝**（库 + `-wal` + `-shm` 三个一起拷到临时目录），原库不碰 |

## 5. 判据（`agent_community/tests/test_session_truth.py`）

1. **真库真 WAL**：`journal_mode=WAL` 下写入、**不 checkpoint**，判断器仍要找得到（只读主库会假阴性 —— 这条是真教训）；
2. 口令不存在 → `code=1` 且**列出库里最近的口令**（防"界面把口令截断"误判）；
3. 库不存在 / 不是 SQLite / 表名错 → `code=2` 且说人话，**不返回 code=0**；
4. 配置端点：真文件才存得下；错表名要**列出实际表**；关掉要真关掉；
5. `test-now` 自动跑：真档案 + 真库 → 口令写进去 ⇒ `truth_verified=true`；把库里的那行删掉 ⇒ 假成功被抓住（`truth_verified=false`）。

## 6. 做不到的（如实说，不假装）

- 只支持 **SQLite**：其它存储（JSON/Postgres/内存）**如实不支持**，界面上说清；
- 读的是**拷贝**：库被应用独占死锁时拷不出来 → 报 `核对不了`（**不能说成"库里没有"**）；
- "界面显示"这件事最终仍以**用户眼睛**为准（V101 第 ② 类证据）；真相核对只覆盖第 ① 类。
