## 0. 这份框架解决什么

## 1. 一页看懂 v5 的骨架

```
                     ┌──────── 大厅（跨项目，权威）────────┐
                     │ harness / template / agent_profile  │
                     │ lead_roster（按方向绑组长）         │
                     └───────────────┬────────────────────┘
                                     │ 读（裁剪后给组长）
  用户 ──粘贴方向──▶ ┌──────────── 工作间（单项目，权威）───────────┐
                     │ workshop_path（前端持有）                  │
                     │ direction → slot[] → member[]              │
                     │ channel_evidence / task / artifact         │
                     └───────┬───────────────────────┬────────────┘
                             │ 写文件 + 激活 + 记账   │ 回执归一化（Receipt）
                             ▼                       ▲
                    <workshop_path>/…            三种适配器
                    分工.md / 任务/ / 产物/        A 协议端点 · B 桥文件 · C 人工粘贴
                             │                       │
                             └──── 组长 / 成员（外端 agent，真干活）────┘
```

**三条不许破的线**（v4 §索引四）：平台不判断；模板不含真实坐标与令牌；文件是执行真源、DB 是镜像。

## 2. 平台职责边界（v4 §16 的施工化）

| 平台**做** | 怎么做 | 判据 |
|---|---|---|
| 拼对接单 | 纯字符串：`workshop_path` + 模板占位 + 岗位名/命名要求 | 同一输入两次拼出**逐字相同**的文本 |
| 校验文件/目录是否真建了 | `stat` / 目录 diff（L0） | 缺就报，不猜 |
| 记账 | 落库 `slot` / `member` / 证据 / 时间戳 | 每条都可回查 |
| 触达（激活） | 写 `_notice` + 按档 wakeup + 记 `activated_at`/`wakeup_result` | 三档三态，`manual` 必须人确认 |
| 解释拦阻 | 409 四要素模板 | 缺谁/缺哪项证据/去哪补 |

| 平台**不做**（明确删掉） | 原因 |
|---|---|
| 讨论、定方向、选组长、选人 | 老板：外部谈、按列表点 |
| 方向体检 / 组长推荐 / 能力评分 | 平台不判断 |
| 把任务正文存 DB 再推送 | 正文只落文件（派活=写文件+激活+记账） |
| 代成员说话、代写它的会话 | `V101`/`V103`/`V105`：代写是假成功 |

## 4. 与现有 v4.37.1 代码的差异面（**只列，不动**）

| # | 现状（v4.37.1） | v5 要的 | 影响面 |
|---|---|---|---|
| 1 | 成员只有一套 `status`（`pending/…/idle`） | **slot + member 双层**，`slot.proposed` 不进闸门 | `workshop.py` 成员模型、`workshop_gate.py`、`workshops_assign/_session` 全组 |
| 2 | 闸门在 `draft/discussing`，靠"成员接上" | 闸门移到 `modeling`（组长级），`discussing` 删除 | `workshop_gate.py` + 前端状态文案 |
| 3 | 工作间状态 `draft→discussing→selecting→division→running→review→done` | `draft→lead_in→modeling→staffing→running→review→integrate→closed` | 状态机权威 + 所有按状态分支的端点 |
| 4 | 派活 = 平台存任务 + 推给成员 | **组长发起**：写任务文件 → 激活 → 记账；正文只在文件里 | 任务链路、`_dispatch_*`、桥梁 |
| 5 | 产物靠成员回报/截图 | `scan-artifacts` 目录 diff（L0） | 新端点 + 归档 |
| 6 | 无 slot、无 `workshop_path`、无 `direction` 双字段 | 全部新增 | 新端点 + 前端 |
| 7 | 外端回报走 HTTP/桥/粘贴三套，各自解析 | **统一 `Receipt`** + 三个适配器 | 新增 `receipt.py` + `intake` 端点 |
| 8 | 组长靠"每次临时选" | `lead_roster` 按方向固定绑定 + `tooling.fs` 硬门槛 | 新表 + 迁移 |
| 9 | 讨论区三级 | 一级删、二级改组长对话框、三级改名讨论区 | 前端 + `discuss` 端点收敛 |

**结论**：这不是"加功能"，是**换模型**。所以本批只出设计；施工顺序见 `V115`（先立判据、再做模型层、最后搬端点）。

## 5. 三个必须一起走的横切（否则又会出现"看着通、其实没通"）

| 横切 | 做法 | 为什么不能省 |
|---|---|---|
| **证据分级**（v4 §15） | L0 平台实做 / L1 它库已有 / L2 平台留痕 / L3 它自报 / L4 人眼 | L3 永不放行；`code=2` 既不算过也不算"没有" |
| **一处真相** | 回执解析器只有一份（`receipt.py`）；目录/文件命名只有一份（`V109`）；闸门判定只有一份（`V112`） | 历史上三套解析各说各话 |
| **失败要说话** | 每个新端点都要有 `error` + `next`（可执行下一步）；批量解析**整单原子** | 409/422 不带下一步＝逼人去猜 |
