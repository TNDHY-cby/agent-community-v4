| 词 | 一句话 | 别混 |

| agent | 壳 + 模型 | 换模型即换 agent |
| `workshop_path` | 工作间根路径 | 唯一真源，前端持有 |

### 三、状态速查

```
工作间 : draft → lead_in → modeling → staffing → running → review → integrate → closed
slot   : proposed → approved → filled / dropped
member : pending → acked → entered → active → blocked / lost
```

### 四、三条不许破的线

1. **平台不判断**：不推荐、不评分、不体检。
2. **模板不含真实坐标、不含令牌**。
3. **文件是执行真源，DB 是镜像**；冲突报警，不自动改。

## §1 三层定义

| 层 | 是什么 | 键 | 归属 |
|---|---|---|---|
| **harness** | 工具壳子：窗口、工具面、叫醒方式、送字落点 | `harness_id` | 大厅 |
| **AI** | 智能本身（大模型） | 模型名 | 不登记，只引用 |
| **agent** | 壳 + 智能的组合体，真正干活的那个 | `(harness_id, model)` | 组合体 |

三条硬结论：

1. **注册的是壳，不是人。** 模板键在 `harness_id`，大厅模板与成员表不得出现"员工""岗位"字样。
2. **能力 = 壳工具面 × 模型智能 × 接入方式。** 同一个壳换模型，就是另一个 agent。
3. **换模型即换 agent。** 成员记录必须留 `model_snapshot`，否则事后解释不了"上次能干这次为什么不行"。

## §3 工作间路径：单一真源，前端持有

```
workshop_path（唯一真源，前端持有、可改）
   ├─▶ 拼组长对接单时读取
   ├─▶ 组长拼员工对接单时读取（+ 自己定的岗位子目录）
   └─▶ 对接中心展示、用户复制时使用
```

三条规则：

1. **模板只写占位符**：`{{workshop_path}}/<slot_dir>/<template_entry>`，例 `{{workshop_path}}/前端组/_inbox/组长`。
2. **路径落库在工作间记录、由前端持有**；平台与组长都不缓存副本，用时向当前工作间取。
3. **拼装权三方分**：`workshop_path` 归用户/前端，`<slot_dir>` 归组长（它才知道拆几个组），`<template_entry>` 归大厅模板。

为什么不能写进后端模板：模板跨工作间复用，写死绝对路径等于换工作间就得换模板；模板带真实盘符也违反"不含真实坐标"的安全边界。

## §3.1 工作间目录结构（文件即介质）

平台不搬运内容，成员之间靠文件夹协作：

```
<workshop_path>/
├─ _meta/            工作间元信息、名单镜像、证据
├─ _lead/            组长工作区（建模文档、分工源文件）
├─ 前端组/
│   ├─ 分工.md        本组职责、交付要求、接口约定
│   ├─ _notice.md     变更通知，每次改动追加一行
│   ├─ 员工01/
│   │   ├─ 任务/       派活只落这里
│   │   └─ 产物/       成员只往这里写
│   └─ 员工02/
└─ 后端组/ ...
```

三条规则：

1. **派活 = 写文件 + 激活 + 记账**，平台不把任务正文存 DB 再推送。
2. **读写边界**：成员读自己目录 + 本组 `分工.md`；跨组只读不写。
3. **产物只写自己 `产物/`**，平台按目录 diff 生成清单（L0），不采信成员自报（L3）。

成员被"激活"时先读 `_notice.md`，再看 `分工.md` 与 `任务/`——这是变更感知的唯一约定。

## §4 界面结构

| 原界面 | 现在 | 说明 |
|---|---|---|
| 一级讨论区 | **删除** | 用户去外部（免费网页版 DeepSeek）谈方向，把结论粘贴进工作间的「任务方向」框 |
| 二级讨论区 | **改为「组长对话框」** | 只做对接：选组长 → 自动填入路径 → 复制 → 粘贴到外端会话。**不承载讨论** |
| 三级讨论区 | **更名「讨论区」** | 接入后的协作区；平台只做消息路由与记账，不生成内容 |

### 四处界面的职责

| 界面 | 用户做什么 | 平台做什么 |
|---|---|---|
| 任务方向框 | 粘贴外部谈好的方向；方向够不够用，自己判断 | 只存文本，**不体检、不校验** |
| **组长对话框** | 自己看组长列表、按方向点一个 → 点「自动填入路径」→ 复制对接单 → 粘贴给外端 → 回来打勾 | 按方向过滤 `lead_roster`、拼装对接单（`workshop_path` + 模板占位）、写 `rename_seen`；**不推荐、不评分、不拦** |
| 对接中心名单 | 逐个复制员工对接单 → 粘贴 → 打勾 | 存 slot / member / 通道证据 |
| **讨论区** | 与已接入成员协作 | 消息路由 + 记账 |

## §5 工作间状态机

```
draft → lead_in → modeling → staffing → running → review → integrate → closed
```

| 状态 | 进入条件 | 说明 |
|---|---|---|
| draft | 新建工作间 | 未填方向 |
| lead_in | 方向已填 + 组长已选 | 等组长接入 |
| modeling | 组长 `active` | 组长建模、出名单 |
| staffing | 名单齐 + 分工落盘 | 逐个接员工 |
| running | ≥1 名成员 `active` | 可派活 |
| review | 任务产出待验收 | — |
| integrate | 验收通过 | 汇总产出 |
| closed | 归档完成 | — |

> 已删两态：`discussing`（无一级讨论）、`selecting`（选人不再是独立阶段）。

## §6 双层成员模型

**slot（岗位行，组长产出）**

```
proposed → approved → filled / dropped
```

**member（工位，slot 填充后才有）**

```
pending → acked → entered → active → blocked / lost
```

**为什么必须拆**：旧模型混用一个 member，把"还没叫进来"（正常，接员工之前本来就没有）和"叫了没进来"（异常，该报警）塞进同一状态。这就是 V104⑤ 的根因——协议型成员永远被判"未接上"，开工闸 409 拦死。拆开后 `slot.proposed` 不参与任何闸门，只有 `member.pending` 参与。

## §7 通道证据与"接上"

```
channel_evidence = { bridge_ok, session_ok, mailbox_ok, paste_seen, rename_seen }
```

`channel_state = active` 需同时满足三条：`entry_state ∈ {acked, entered}`、该档位证据齐备、`verified_scope` 写明覆盖到哪一段。

| 档 | 型 | 所需证据 | 备注 |
|---|---|---|---|
| A | 协议型 | 真发 `tools/list` 或 `GET` 有响应体 | 无桥、无会话，不算残缺 |
| B | 桥型 | 逻辑桥 1 次取件成功 | 只通不取不算 |
| C | 视觉型 | `paste_seen + press_ok + rename_seen` | 粘贴 + 改名双确认 |

未打勾不算接上，最高只记 `acked`。理由：会话没名字，接员工时分不清哪是组长、哪是空会话，一错整链对错人。

### §7.1 回执报文（唯一格式，与通道无关）

外端回平台，只允许一种报文。传输方式不同，报文一样。

```
#回执 v1
类型: 名单            # 名单 / 派活 / 验收 / 状态
工作间: WS-20261026-01
成员: 前端组/员工01
凭据: <A档填 token，B/C档留空>
序号: 12
---
岗位: 前端组/员工01 | harness: h_cursor | model: claude-x | 人数: 1
岗位: 后端组/员工01 | harness: h_trae_cn | model: deepseek-v3 | 人数: 2
---
行数: 2
```

四类体格式（每行一条，`|` 分隔，字段名固定）：

| 类型 | 体行格式 |
|---|---|
| 名单 | `岗位: <slot_dir> \| harness: <id> \| model: <名> \| 人数: <n>` |
| 派活 | `任务: <T-id> \| 派给: <slot_dir> \| 标题: <文本> \| 期限: <时间>` |
| 验收 | `验收: <T-id> \| 结果: 通过/返工/拒收 \| 产物: <n> \| 备注: <文本>` |
| 状态 | `状态: <slot_dir> \| 新: <state> \| 原因: <文本>` |

四条硬规则：

1. 头五行必填，缺一行整单拒收。
2. **整单原子**：任一行解析失败，整单拒绝，报"第 X 行第 Y 字段"，不做部分写入。
3. 未知字段忽略并记录日志；未知类型直接拒收。
4. **任务正文不进球**：派活只传索引，正文由组长写进成员 `任务/` 目录。

### §7.2 三种投递与对应鉴权

| 档 | 投递方式 | 鉴权 | 防重放 | 人的参与 |
|---|---|---|---|---|
| A 协议型 | POST 平台端点 | `session_token`，绑定 workshop+member，TTL 至工作间 closed，可 revoke | 序号单调递增 | 无 |
| B 桥型 | 写文件到 `_meta/_inbox/*.rcpt` | **位置即凭据**：能写进本工作间该目录，即证明是该成员 | 序号 + 文件名带 member_id | 无 |
| C 视觉型 | 用户粘贴进 intake 框 | 无凭据，绑当前上下文（在谁的页面贴就归谁） | 内容哈希去重 | 用户确认（L4） |

取舍说明：

- A 档 token 会落进对接单文本，所以限死三条：只能写本工作间、TTL 短、仅回环地址可用。宁可少一分便利，不让一个 token 换整间数据。
- B 档不发明新凭据，直接拿文件系统权限当凭据——最省，也最符合"平台不判断"。
- C 档承认现实：人工搬运无法验来源，只能靠用户确认，记 L4。

### §7.3 归一化：三个适配器，一个解析器

```
A: POST /intake          ┐
B: 轮询 _inbox/*.rcpt    ├─▶ 归一为 Receipt{type, workshop, member, seq, rows[]} ─▶ intake ─▶ 落库
C: 粘贴框提交             ┘
```

业务侧只认 `Receipt`。三种协议差异全关在适配器里，新增一种 harness 只加一个适配器，不动解析与业务。**复杂度不进核心。**

### §7.4 激活分档

| 档 | 怎么激活 | 记录 |
|---|---|---|
| A | 发 wakeup 请求 | `wakeup_result=ok` |
| B | 写 `_notice.md` + 投唤醒标记文件，对端轮询自取 | `wakeup_result=queued` |
| C | 平台只能标"待唤醒"，用户去说一句，回来打勾 | `wakeup_result=manual` + `verified_by` |

三档都叫"激活已发起"，但只有 `ok` / `queued` 算闭环，`manual` 必须人工确认。

### §7.5 组长门槛（由上述功能反推）

组长要建目录、写分工、写任务、发回执、发起派活，所以必须同时满足两条：**能落文件** + **能把回执送回来**。

| 组合 | 能否当组长 |
|---|---|
| 有 fs + 有协议 | 能（最理想，全自动） |
| 有 fs + 只有桥 | 能（回执走文件） |
| 有协议但无 fs | **不能**——建不了目录 |
| 只有对话 | **不能**——只能当成员 |

`lead_roster` 里 `tooling.fs_write=true` 才进组长候选。

## §8 主流程（11 步）

| # | 步骤 | 谁做 | 平台干什么 | 产物 |
|---|---|---|---|---|
| 1 | 新建工作间 | 用户 | 建记录、落 `workshop_path`、手填项目短名 | `workshop_id` |
| 2 | 粘贴方向 + 下拉校准 | 用户 | 存长文；下拉值用于匹配组长 | `direction` |
| 3 | 选组长 | 用户 | 按方向过滤 `lead_roster`，**只列有 `tooling.fs` 的** | `lead_slot` |
| 4 | 组长对话框 | 平台 | 拼对接单：`workshop_path` + 开局卡 + 命名要求（N+1） | 对接单文本 |
| 5 | 接组长 | 用户 | 记 `paste_seen` / `rename_seen`（A/B 档记桥证据） | `member.active` |
| 6 | 深谈建模 | 用户 × 组长 | 不介入 | 建模文档 |
| 7 | 建目录、写分工 | **组长** | 事后 `verify-dirs` 校验目录存在（L0） | 组目录 + `分工.md` |
| 8 | 回写名单 | **组长** | 有工具面收 API，无则收 intake 粘贴 | `slots[]` |
| 9 | 逐个接成员 | 用户 | 逐条写通道证据 | 成员逐个 `active` |
| 10 | 激活与派活 | **组长**发起，平台执行 | 写任务文件 + 追加 `_notice` + 触发 wakeup + 记账 | `activated_at` + 任务文件 |
| 11 | 干活、验收、归档 | 成员 × 组长 | 扫目录出产物清单（L0）、汇总归档 | 产物 + 任务记录 |

要点：**第 7、8、10 步的发起方都是组长**，平台只做校验、执行、记账，不判断内容好坏。

### 与原 13 句的对应

| 原句 | 处置 |
|---|---|
| 1 开工前与平台AI交流定方向 | 删，降为第 2 步的输入（改由外部模型谈） |
| 2 员工选择 | 删（与"组长选员工"重复；人池为多余约束） |
| 3 开始工作间与外端对接 | 删（空转，无产物） |
| 4 一级讨论 | 删（一级讨论区砍掉） |
| 5 选组长 | **升为第 3 步**，靠列表不靠 AI |
| 6 平台按模板填工作间路径 | 第 4 步，读 `workshop_path` |
| 7 人工复制粘贴接组长 | 第 5 步，加 `rename_seen` |
| 8 与组长深谈建模 | 第 6 步，在外端会话 |
| 9 组长按列表选员工填名单 | 第 8 步，回写 `slots` |
| 10 组长建目录、建模与分工 | 第 7 步 |
| 11 按工作间给员工填真实路径 | 第 7 步，主体是组长 |
| 12 更新名单给用户复制粘贴 | 第 9 步 |
| 13 接入讨论区（原三级） | 第 11 步的协作侧 |

**结构性差别**：旧模型是"选人 → 全员一起接 → 开工"；实际是"**先只接组长一人 → 组长产出名单、分工、员工路径 → 再按名单接员工**"。组长是唯一入口，也是名单与路径的唯一来源。

## §9 组长列表（替代"AI 选组长"）

```json
{
  "lead_roster": [
    { "direction": "编程/后端", "harness_id": "h_trae_cn", "model": "deepseek-v3",
      "orchestration_score": 4.2, "default": true, "note": "长任务稳，能自己建目录" },
    { "direction": "媒体/视频", "harness_id": "h_chatgpt_desktop", "model": "gpt-x",
      "orchestration_score": 3.8, "default": true }
  ]
}
```

交互：

1. 用户粘完方向，平台按方向关键字命中一级/二级方向；
2. 组长对话框只列**命中方向的候选**，按 `orchestration_score` 排序，标 `default`；
3. 用户点一个即可，**平台不参与判断**；
4. 方向未命中时退化为全量列表 + 提示"该方向暂无默认组长"。

**进候选的硬条件**：`tooling.fs_write=true`（见 §7.5）。无 fs 的 harness 不出现在组长列表里，只能当成员。

`lead_roster` 与旧 `lead_binding` 合并为一张表：`default=true` 那条即绑定。同一方向默认复用同一组长，换人是例外，须记 `lead_override_reason`。

## §10 命名规则

组长交付 **N+1 个名字**：

| 数量 | 对象 | 平台能否自改 | 执行方 |
|---|---|---|---|
| 1 | 工作间名 | 能（字段） | 平台改，用户确认 |
| N | 各外端会话名（组长 1 + 员工各 1） | **不能**（闭源 GUI 无接口） | 给建议名，用户手改，回来打勾 |

规则：`<项目短名>-<岗位>-<角色序号>`，例 `合作社-建模-组长`、`合作社-前端-员工01`。

必须组长给：只有它在深谈后才知道这次拆哪些岗位；命名是项目建模的产物，与分工文档同批出。必须同名同规则：两屏靠名字对号，否则在五六个"新对话"里点错人。

## §11 agent 能力档案（含适配方向）

```json
{
  "harness_id": "h_trae_cn", "model": "deepseek-v3",
  "orchestration": { "decompose": 4, "context": 3, "structure": 4,
                     "dispatch": 3, "arbitrate": 2, "selfcheck": 3 },
  "tooling": { "fs": true, "exec": true, "screenshot": true, "paste": true },
  "stability": { "long_session": 3, "window": "128k", "refusal": "低" },
  "fit_directions": [
    { "path": "编程/后端", "level": 4, "evidence": "L4: 三次后端项目主导" },
    { "path": "办公/PPT",  "level": 3 }
  ],
  "lead_eligible": ["编程"],
  "evidence_level": "L4"
}
```

方向树（一级收纳、二级展开）：

```
编程 ├后端 ├前端 ├脚本/自动化 └数据/SQL
媒体 ├视频 ├音频 └图像/设计
办公 ├PPT ├文档 ├表格整理 └公文

数据 ├采集 ├分析 └可视化

```

两处用法不可混用：**选组长**读 `lead_eligible` + 六项编排能力；**组长选员工**读 `fit_directions` 的 `path + level`。`level` 无 `evidence` 一律按 1 分计。

## §14 功能落位（三维四问）

### 三维

| 维度 | 取值 | 回答什么 |
|---|---|---|
| D1 生命周期 | 跨项目 / 单项目 | 换工作间还在不在 |
| D2 权威副本 | 大厅库 / 工作间库 / 前端运行时 / 外端 GUI | 谁是唯一真源、平台能不能写 |
| D3 读权限 | 平台 / 组长 / 员工 / 用户 | 要不要开只读接口、要不要裁剪 |

### 四问

1. 换一个工作间还成立吗？→ 成立归大厅
2. 描述"壳与智能本身"，还是"这次谁在干什么"？→ 前者归大厅
3. 平台能不能自己写？→ 不能（会话标题、剪贴板）就只存证据，判 L4
4. 除平台外还有谁要读？→ 组长要读就开只读接口并裁剪（落点给、令牌不给）

### 落位表

| 功能 | D1 | 权威副本 | 谁读 | 落点 |
|---|---|---|---|---|
| harness / 模板 | 跨项目 | 大厅库 | 平台、组长（裁剪） | 大厅 |
| 能力档案 / 方向树 | 跨项目 | 大厅库 | 平台、组长 | 大厅 |
| 组长列表 | 跨项目 | 大厅库 | 平台、用户 | 大厅 |
| 自检 / 真相核对 | 跨项目 | 大厅库 | 平台 | 大厅（工作间只调用） |
| `workshop_path` | 单项目 | 工作间库 + **前端** | 平台、组长、用户 | 工作间（前端注入） |

## §15 诚实性

| 级 | 含义 | 能判通过 |
|---|---|---|
| L0 | 平台实做（真发请求、真收回执） | 能 |
| L1 | 它库已有（`code=0`） | 能 |
| L2 | 平台留痕（日志、证据文件） | 能 |
| L3 | 它自报（模型说自己做了） | **永不** |
| L4 | 人眼确认（`verified_by=human`） | 能，须留 `who/when/which` |

硬规则：

1. `code=2` 既不算通过，也不许说"库里没有"。
2. **回显 ≠ 回复。**
3. 命名、粘贴这类只能人工完成的动作，一律 L4。
4. L3 永不得作为闸门放行依据。
5. 能力分无证据，按 1 分计。

## §16 平台定位：无 AI，只剩规则

切掉一级讨论、并去掉方向体检后，平台内**没有任何对话型 AI，也不做方向校验**。剩下的两件小事都是纯规则：

| 职能 | 用什么做 | 成本 | 必需 |
|---|---|---|---|
| **对接单拼装**：把路径、模板占位、岗位名拼成可复制的文本 | 纯字符串，不用模型 | 零 | **是** |
| **闸门解释**：把 409 转成人话（缺谁、去哪补） | 模板化文案，不用模型 | 零 | 是 |
| 方向体检 / 组长推荐 / 能力评分 | **不做**（已明确删除） | — | 否 |
| 讨论、定方向、选人 | **不做** | — | 否 |

结论：价值全在"把路径拼对、把名单记准、把证据留全"。方向够不够用、组长选谁，都由老板自己按方向 + 组长列表决定。

## §19 模拟走查（第二版 · 2026-10-26）

### 一、前提修正

上一版推断有误：我把"组长"当成网页版 AI，据此把 `slots` 回写、建目录、多会话占用判成三处硬断链。**组长是已接进来的外端 agent，自带工具面**——能建目录、能读写文件、能调平台功能。网页版只是 harness 之一，且不具备当组长的条件。

据此，真正要问的不是"网页版能不能建目录"，而是"**组长这个 agent 有没有工具面**"，以及"外端产出怎么结构化回到平台"。

### 二、走查（组长 = 有工具面的 harness）

| 步 | 谁做 | 发生什么 | 结论 |
|---|---|---|---|
| 1 | 用户 | 建工作间，`workshop_path` 落盘 | 通 |
| 2 | 用户 | 粘贴方向长文（外部谈好） | 通，方向需下拉校准（H15） |
| 3 | 用户 | 从组长列表点一个有工具面的组长 | 通 |
| 4 | 平台 | 拼对接单：path + 开局卡 + 命名要求（N+1） | 通 |
| 5 | 用户 | 复制 → 粘到外端新会话 → 改名 → 回来打勾 | 通 |
| 6 | 平台 | 证据齐 → `active` → 进 `modeling` | 通 |
| 7 | 用户 × 组长 | 在组长窗口深谈建模 | 通 |
| 8 | 组长 | 在 `workshop_path` 下建组目录、写 `分工.md`、为成员建目录 | 通（前提是组长有 fs） |
| 9 | 组长 | 回写名单 `slots`：有工具面调 API，无则用户粘贴走 intake | **半通：回执格式未定（H02）** |
| 10 | 平台 | `verify-dirs` 校验目录、生成成员对接单 | 通（新增端点） |
| 11 | 用户 | 逐个复制粘成员、打勾 | 通 |
| 12 | 组长 | 调平台派活：写任务文件 + 激活成员 + 记账 | **半通：鉴权未定（H03）** |
| 13 | 成员 | 被激活 → 读 `_notice` + `分工.md` → 干活 → 写 `产物/` | 通 |
| 14 | 组长 | 读目录验收 → 回写状态 | 半通（同 H02） |
| 15 | 平台 | 扫目录生成产物清单、归档 | 通 |

**结论：这条链能通，且平台确实不判断、不搬运。** 剩下的是四类硬问题：组长的工具面门槛、回写格式、调用鉴权、文件与 DB 谁权威。

### 三、关键判断

1. **组长必须过工具面门槛。** 组长要建目录、写分工、派活、验收，全依赖 fs + 调用能力。`lead_roster` 的 `lead_eligible` 不够，须加 `tooling.fs` 硬门槛并拦。网页版可以当成员，不能当组长。
2. **平台的角色是执行器 + 账本，不是编排者。** 派活由组长发起，平台只做三件事：写文件、触达（激活）、记账。
3. **文件是执行真源，DB 是镜像。** 成员只认文件夹里的 `分工.md` 与 `任务/`；平台里的 `slots` 若与文件不一致，以文件为准，平台负责校验与报警。
4. **"激活"是一门独立能力，不是一次 HTTP。** 三步：写任务文件 → 触发 harness 的 wakeup → 记 `activated_at`。叫不醒的档位只能降级为"用户去说一句"，但仍是同一语义。
5. **产物不能靠自报。** 成员说"我写完了"是 L3；平台扫目录 diff 出清单才是 L0。
6. **鉴权与"模板不含令牌"直接冲突。** 组长要调平台功能就得有凭据，而模板里放令牌又违反安全边界，这条必须拍板。

### 四、缺口清单

| 编号 | 级别 | 缺口 | 建议修法 |
|---|---|---|---|
| H01 | **致命** | 组长工具面门槛未定义，选错 harness 第 7 步起全断 | ✅ 已定（§7.5）：`fs_write` 必选，无 fs 不进候选 |
| H02 | **致命** | 外端→平台无固定回执格式 | ✅ 已定（§7.1）：四类统一行式报文，整单原子，解析失败只报错 |
| H03 | 高 | 组长调平台功能的鉴权未定 | ✅ 已定（§7.2）：A 档 token / B 档位置即凭据 / C 档人工确认 |
| H04 | **致命** | 文件与 DB 双真源，谁权威未定 | ✅ 已定：文件为执行真源、DB 为镜像，派活前校验，冲突报警不自动改 |
| H05 | 中 | 组长建完目录，平台不知道建没建 | `verify-dirs` 用 stat 校验（L0），缺目录在 staffing 阶段 warn |
| H06 | 高 | "激活"语义未定义（写文件？叫醒？告知？） | 固定三步并记录 `activated_at` 与 `wakeup_result`；叫不醒降级为人工 |
| H07 | 中 | 文件改了成员不知道 | `_notice.md` 追加行 + 每次激活必须先读，作为唯一约定 |
| H08 | 中 | 成员产物靠自报 | `scan-artifacts` 目录 diff（L0），自报只做提示 |
| H09 | 中 | 网页版成员/组长的降级路径未写 | 明确"无工具面 = 全人工粘贴 + 人工验收"，流程不许判死，只许降档 |
| H10 | 高 | `member` 主键冲突：同 harness 同 model 多工位无法区分 | 主键改 `(workshop_id, member_seq)` |
| H11 | 高 | slot 与 member 的 1:N 未定，一个岗位要两人就冲突 | 定 1:N，`slot_dir` 加序号，`filled` 表示"达到目标人数" |
| H12 | 高 | `review / integrate / closed` 三态无流程支撑 | 补三态动作：组长读目录验收 → 平台汇总 → 归档到 `_meta` |
| H13 | 中 | `workshop_path` 可改，已建目录会全断 | 进 `running` 后锁定；改动须整间降回 `staffing` 重验 |
| H14 | 低 | 命名左半"项目短名"无 AI 无从生成 | 建工作间时手填，设为必填 |
| H15 | 高 | 自由长文方向 → 枚举方向，无 AI 匹配不了 | 方向框双字段：长文备注 + 方向树下拉（必选） |

### 五、要拍的 3 条

1. **组长是否强制要求 fs 工具面？**（建议强制，网页版只能当成员）
2. **文件与 DB 谁是真源？**（建议文件真源、DB 镜像 + 校验）
3. **组长调平台功能怎么鉴权？**（建议一次性 session token，随对接单下发、用后作废）
