# V108 · v5 对象与键（字段级）

> 依据 `V107`；细化老板 v4 §1/§2/§6/§9/§11 的**施工级**定义：每个对象有哪些字段、键是什么、
> 必填/默认/约束、谁写谁读。**状态：P2 已实施**（`platform/v5_roster.py` + `platform/v5_gate.py`；判据 `tools/roster_check.py` **14 格**、`tests/test_v5_roster.py` **12 条**）。
> 一处真相：字段名以本册为准，别处（前端/文档/脚本）一律照抄这里的名字。

---

## 1. harness（工具壳子，大厅）

```jsonc
{
  "harness_id": "h_cursor",            // 键；全局唯一、可读（工具-机器-角色），不随工作间变
  "display_name": "Cursor @ 示例机",
  "kind": "desktop_gui | cli | web | protocol_only",   // 壳的类型（决定默认档位）
  "template_id": "tpl_cursor_a",       // 指向 template；模板只写占位符
  "tooling": {                          // ★组长门槛就是靠这个（v4 §7.5）
    "fs_write": true,                   // 能在 workshop_path 下建目录/写文件
    "protocol_call": true,              // 能调平台端点（A 档）
    "bridge_poll": false,               // 能常驻轮询桥目录（B 档）
    "gui_paste": false                  // 只能人工粘贴（C 档）
  },
  "wakeup": { "method": "mcp|http_api|acp|file_poll|clipboard", "target": "…" },
  "declared_at": "2026-10-26T10:00:00",
  "last_seen_at": "2026-10-26T10:30:00",
  "notes": ""
}
```

规则：
1. **只登记壳**（v4 §1）：不得出现"员工/岗位"字样；
2. `tooling.*` 必须由**平台实测**过才算 `true`（`fs_write` 用临时目录真写一次；`protocol_call` 真打一次）；
   未测过一律 `null`，而 `null` **不进组长候选**；
3. `wakeup` 与 `tooling` 是两件事：能叫醒 ≠ 能写文件。

## 2. template（叫醒方式 / 送字落点 / 桥形态，大厅）

```jsonc
{
  "template_id": "tpl_cursor_a",
  "harness_id": "h_cursor",            // 键：模板绑 harness，不绑工作间（跨项目复用）
  "kind": "a_protocol | b_bridge | c_visual",
  "entry": "_inbox/组长",              // ★只写**相对**落点；绝对路径由 workshop_path 拼
  "notice": "_notice.md",
  "lanes": ["任务", "产物"],
  "naming": { "pattern": "{ws}-{proj}-{role}-{seq}", "example": "WS-…-前端组-01" }
}
```

规则（v4 §3）：
1. **不许出现**盘符、`/mnt/`、`http://`、令牌 —— 模板跨工作间复用，写死即失效；
2. `entry`、`notice`、`lanes` 都是**相对路径**；拼装权三方分：`workshop_path`（用户/前端）、
   `<slot_dir>`（组长）、`<template_entry>`（大厅模板）；
3. `naming.pattern` 里的占位符在拼对接单时用**实际值**替换；拼不出来就报错并说明缺哪个值。

## 3. agent_profile（壳 + 模型的能力档案，大厅）

```jsonc
{
  "harness_id": "h_cursor",
  "model": "claude-x",                 // 键：与 harness_id 一起唯一
  "fit_directions": ["编程/前端", "编程/后端"],   // 方向树（v4 §11）
  "orchestration_score": 4.2,           // 编排能力分（**待拍板第 8 条**：手工 or 累积）
  "evidence": [ {"kind":"L2","ref":"data/…","at":"…"} ],   // 分数凭据；无证据按 1 分（v4 §15）
  "verified_at": "2026-10-26T09:00:00"
}
```

规则：**换模型即换 agent**（v4 §1）⇒ 成员记录必须留 `model_snapshot`，事后才能解释"上次能干这次为什么不行"。

## 4. lead_roster（组长列表，大厅；替代"AI 选组长"）

```jsonc
{
  "direction": "编程/后端",            // 键之一（方向树里的枚举值）
  "harness_id": "h_trae_cn",           // 键之一
  "model": "deepseek-v3",              // 键之一
  "default": true,
  "note": "长任务稳，能自己建目录",
  "lead_eligible": true,               // 由 tooling.fs_write && (protocol_call || bridge_poll) **算出来**，不手填
  "since": "2026-10-20"
}
```

规则：
1. **硬门槛（v4 §7.5）**：`tooling.fs_write == true` 且（`protocol_call` 或 `bridge_poll`）⇒ 才 `lead_eligible`；
   只有对话能力的（如网页版）**不进候选**，可以当成员；
2. `lead_eligible` 由平台按 `harness.tooling` 计算，**不许手填**（手填＝又一处会说谎的真源）；
3. 方向未命中时按**待拍板第 1 条**处理（现留开关：`fallback_all=true` 时退化全量 + 提示）。

## 5. workshop / workshop_path / direction（工作间）

```jsonc
{
  "workshop_id": "WS-20261026-01",     // 键；与短名一起构成人看的名字
  "project_short": "报销系统",          // ★必填（H14）：命名左半，用户手填，平台不生成
  "workshop_path": "D:/coop/报销系统",  // ★前端持有、平台落库；running 后锁定（V109 §6）
  "direction": {
    "brief": "长文：外部谈好的方向原文", // 原文保存，平台不体检
    "enum": ["编程/后端", "编程/前端"]   // 下拉校准（H15）：必选至少一项，用于匹配组长
  },
  "status": "draft | lead_in | modeling | staffing | running | review | integrate | closed",
  "lead": { "harness_id": "h_trae_cn", "model": "deepseek-v3", "member_seq": 0 },
  "created_at": "…", "updated_at": "…"
}
```

规则：
1. `project_short` **必填**（没有 AI 帮你生成，空着就报 400）；
2. `direction.enum` 至少一项，否则匹配不到组长（按第 1 条拍板结果决定是拦还是退化）；
3. `workshop_path` 一旦被写进任何成员的任务文件，平台就**只读**它（改＝整间降回 `staffing` 重验）。

## 6. slot（岗位行，组长产出）与 member（工位）—— **双层，别混**

```jsonc
// slot：组长产出的名单行（可以有岗无人）
{ "workshop_id": "WS-…", "member_seq": 1, "slot_dir": "前端组/员工01",
  "harness_id": "h_cursor", "model": "claude-x", "headcount": 1,
  "state": "proposed | approved | filled | dropped", "source": "receipt|paste|api" }

// member：真占了岗的工位（有人才有）
{ "workshop_id": "WS-…", "member_seq": 1,            // ★主键 (workshop_id, member_seq)（H10）
  "slot_dir": "前端组/员工01", "harness_id": "h_cursor", "model_snapshot": "claude-x",
  "session_label": "WS-…-前端组-01",                 // 同 harness 多会话靠它区分（第 3 条已定）
  "state": "pending | acked | entered | active | blocked | lost",
  "entry_state": "…", "evidence": {"…"},
  "activated_at": "…", "wakeup_result": "ok|queued|manual" }
```

规则：
1. **主键**：`(workshop_id, member_seq)` —— 旧模型"同 harness 同 model 无法区分"（H10）由此解决；
2. **1:N**（H11）：一个 `slot_dir` 可有多人 ⇒ `member_seq` 递增，`slot.state=filled` 表示"达到 `headcount`"；
3. **`slot.proposed` 不进任何闸门**；只有 `member.pending/acked/...` 参与（V112）；
4. `model_snapshot` 落定后不改（要换模型＝新开一个 member）。

## 7. channel_evidence（"接上"的证据，工作间）

```jsonc
{ "workshop_id": "WS-…", "member_seq": 1,
  "bridge_ok": false, "session_ok": false, "mailbox_ok": false,
  "paste_seen": true, "press_ok": false, "rename_seen": true,
  "verified_scope": "C：粘贴+改名，未验证它能回话",
  "who": "human", "at": "2026-10-26T11:00:00" }
```

档位判定（v4 §7）见 `V112` §3；**未打勾不算接上，最高只记 `acked`**。

## 8. task / artifact（文件为真源，DB 镜像）

```jsonc
// DB 里的镜像（不是真源）
{ "workshop_id": "WS-…", "task_seq": 3, "title": "接口对接",
  "assigned_seq": 1, "file_path": "前端组/员工01/任务/T-003.md",   // ★指向真源文件
  "state": "issued | working | delivered | accepted | rework | rejected",
  "issued_by": "lead", "issued_at": "…", "activated_at": "…" }

// artifact：由目录 diff 生成（L0），**不采信成员自报**
{ "workshop_id": "WS-…", "task_seq": 3, "path": "前端组/员工01/产物/api.md",
  "bytes": 1203, "sha256": "…", "scanned_at": "…" }
```

规则：`file_path` 相对 `workshop_path`；平台**只读**它算 sha/大小，不改内容（v4 §3.1）。

## 9. 字段命名禁区（避免又出现两套口径）

| 不许 | 改成 | 原因 |
|---|---|---|
| `member.status` 里混 `discussing` | 工作间状态才有迁移；成员只有 §6 那 6 态 | 旧模型把两件事塞一个字段（V104⑤ 根因） |
| `channel` 叫"协议" | `channel`（会话+桥+邮箱） | v4 §14 禁用词 |
| 桥的 `kind` 叫 `wakeup_method` | `kind`（a_protocol/b_bridge/c_visual） | 两者正交 |
| 工作间里出现"模板注册" | 大厅才谈模板 | v4 §14 禁用词 |
| `candidate_pool`（人池） | 删掉，组长直接按方向取人 | v4 §2 明确删除 |
