## 0. 一页结论

| 问题 | 结论 |
|---|---|
| 现在后端能撑 v4 吗 | **不能**：v4 的 15 个新概念在后端**一个都没有**（实测见 §1） |

## 2. 数据模型（后端怎么存）

### 2.1 三层定义落到字段

| 层 | 后端对象 | 主键 | 存哪 |
|---|---|---|---|
| harness（工具壳子） | `HarnessInfo` | `harness_id` | 大厅（`data/state.json`） |
| AI（模型） | **不登记**，只在 profile 里写 `model` 字符串 | — | — |
| agent（壳+模型） | `agent_profile`（新增） | `(harness_id, model)` | 大厅 |

> `agent_profile` 是 v4 §11 的能力档案：`orchestration{6}` / `tooling{fs,exec,screenshot,paste}` /
> `stability` / `fit_directions[]` / `lead_eligible[]` / `evidence_level`。

### 2.2 工作间：`Workshop` 加字段（不改名）

```python
@dataclass
class Workshop:
    workshop_id: str
    name: str                      # 项目短名（v4 H14：建间时必填）
    workshop_path: str             # ★唯一真源，取代 workspace_dir（保留旧字段做兼容别名）
    direction: dict = {}           # {"text": 长文, "path": "编程/后端", "level2": "后端"}
    status: str = "draft"          # 8 态（§2.4）
    slots: list[dict] = []         # 岗位行（§2.3）
    members: list[WorkshopMember] = []   # 工位（保留，语义收窄）
    lead_binding: dict = {}        # {member_seq, harness_id, model, at, override_reason}
    mirror_fingerprint: dict = {}  # DB↔文件 一致性指纹（§8）
```

- **删**：`discussion` 里的"一级讨论"用法（v4 删该阶段）、`candidate_pool`（从未实现，不再规划）。
- `workspace_dir` 保留为**只读兼容字段**：读时若 `workshop_path` 空，用它补齐并写回。

### 2.3 slot 与 member（解决 v4 H10 / H11）

```python
slot = {
  "slot_id": "s-01",              # 工作间内唯一
  "slot_dir": "前端组/员工01",      # 相对 workshop_path，**组长给**
  "role": "前端开发",               # 显示名
  "group": "前端组",
  "harness_id": "h_cursor",
  "model": "claude-x",
  "headcount": 1,                  # 目标人数
  "state": "proposed",             # proposed → approved → filled / dropped
  "created_by": "lead",            # lead | user
  "at": "2026-10-26T12:00:00"
}
```

- **主键**：`(workshop_id, slot_id)`；`(workshop_id, slot_dir)` 唯一（目录不能撞）。
- **member 主键改为 `(workshop_id, member_seq)`**（v4 H10）：不再用 `harness_id+model` 组合，
  同一 harness 同 model 可占多个工位；`member_seq` 单调递增，从 1 开始。
- **1:N**（v4 H11）：一个 slot 可挂 N 个 member（`headcount>1`），`state=filled` 表示"已达目标人数"。
- `WorkshopMember` 加字段：`member_seq: int` / `slot_id: str` / `slot_dir: str` / `channel_evidence: dict`。

### 2.4 状态机（v4 三套，值就这么定）

| 对象 | 取值 | 迁移器 |
|---|---|---|
| workshop | `draft → lead_in → modeling → staffing → running → review → integrate → closed` | `platform/workflow_v4.py`（新） |
| slot | `proposed → approved → filled / dropped` | 同上 |
| member | `pending → acked → entered → active → blocked / lost` | 同上 |

- 旧值映射（一次性迁移，写进 `state_restore` 兼容层）：`discussing → lead_in`、`selecting → staffing`、
  `division → staffing`、`running → running`、`review → review`、`done → closed`。
- `entry_state`（正交维度）**保留**，但语义收窄为"派发进度"，不再参与 v4 的阶段判定。

## 3. 存储：文件是真源，DB 是镜像

### 3.1 目录布局（平台只按约定读写，不猜）

```
<workshop_path>/                     ← 用户在界面上填，落 workshop 记录（v4 §3）
├─ _meta/
│   ├─ manifest.json                 平台写：{workshop_id, slots[], members[], fingerprints}
│   ├─ evidence/                     平台写：通道证据、回执副本、产物清单
│   └─ _inbox/                       B 档回执投递点（成员写、平台轮询）
├─ _lead/                            组长工作区（建模文档、分工源文件）
├─ <group>/                          组长建（平台只校验存在）
│   ├─ 分工.md                        组长写（执行真源）
│   ├─ _notice.md                    平台**追加**一行（v4 §3.1 唯一变更感知约定）
│   └─ <员工NN>/
│       ├─ 任务/                      平台写（派活落点）
│       └─ 产物/                      成员写（平台只扫不写）
```

### 3.2 谁写哪一格（硬规则）

| 位置 | 平台 | 组长 | 成员 |
|---|---|---|---|
| `_meta/**` | 写 | 只读 | 只读 |
| `_notice.md` | **追加** | 只读 | 只读 |
| `分工.md` | **不写**（只校验/对比） | 写 | 只读 |
| `任务/` | 写 | 只读 | 只读 |
| `产物/` | **不写**（只扫） | 只读 | 写 |

### 3.3 镜像与指纹（§8 校验用）

- `_meta/manifest.json` 与 DB 里的 `slots/members` 是**镜像**；每批写入后算 `sha256(规范化 JSON)` 存 `mirror_fingerprint`。
- 冲突处理：**报警不自动改**（`POST /api/workshop/{id}/verify-dirs` 返回 `diffs[]`，界面呈现）。

## 5. 状态迁移守卫表（谁能推、推时校验什么）

| 迁移 | 触发者 | 前置校验 | 失败码 |
|---|---|---|---|
| `draft → lead_in` | 用户（选组长） | `direction.path` 非空 + `workshop_path` 可写 + 组长在候选里 | 400/409 |
| `lead_in → modeling` | 平台（证据齐） | 组长 `channel_state=active` 且 `rename_seen=true` | 409（四要素） |
| `modeling → staffing` | 组长（回写 slots） | `slots` 非空 + `verify-dirs` 不缺组目录 | 409 |
| `staffing → running` | 用户（点开工） | ≥1 member `active` | 409 |
| `running → review` | 组长/成员（回执 验收） | 任务树无 `running` 子任务 | 409 |
| `review → integrate → closed` | 用户确认 | `scan-artifacts` 有产物 | 409 |

409 四要素（v4 §12）：`{stage, missing[], evidence_missing[], goto}`；`goto` 是深链（组长对话框 / 名单某行）。

## 6. 回执（Receipt）：唯一的对外报文

### 6.1 语法

```
#回执 v1
类型: 名单|派活|验收|状态
工作间: WS-xxxx
成员: <slot_dir>
凭据: <A档 token / B、C 档留空>
序号: <单调递增整数>
---
<体行，每行一条，| 分隔>
---
行数: <n>
```

- 头 5 行必填；`---` 两处分隔；`行数` 必须等于实际行数（防截断）。
- 四种体行格式见 v4 §7.1。

### 6.2 解析器（`platform/receipt.py`，新）

```python
def parse(text: str) -> dict:      # 返回 {"ok":True,"receipt":{...}} 或 {"ok":False,"error":..,"line":i,"field":name}
```
硬规则（与 v4 一致）：
1. **整单原子**：任一行失败 → 全单拒绝，报"第 X 行第 Y 字段"；
2. 未知字段忽略 + 记日志；未知类型直接拒收；
3. `序号` 必须大于该成员已收最大值（防重放），否则 422；
4. 任务正文不进回执（只传索引）。

### 6.3 三个适配器（`platform/intake_adapters.py`，新）

| 档 | 入口 | 归一后 |
|---|---|---|
| A | `POST …/intake`（HTTP，带 token） | `Receipt` |
| B | 轮询 `_meta/_inbox/*.rcpt`（**位置即凭据**） | `Receipt` |
| C | 界面粘贴框 → `POST …/intake`（无凭据，绑上下文） | `Receipt` + `verified_by=human` |

业务侧只认 `Receipt`。

## 7. 鉴权（三档，与投递方式绑定）

| 档 | 凭据 | 生命周期 | 校验点 |
|---|---|---|---|
| A | `session_token`（`secrets.token_urlsafe(24)`） | 绑定 `(workshop, member_seq)`；`closed` 或 revoke 失效；TTL 24h | `intake` / `dispatch-task` 调用方必须是 lead 或该 member |
| B | **无新凭据**：能往 `_meta/_inbox/` 写文件＝该成员 | 文件保留 7 天 | 读取时校验路径在工作间内、文件名含 `member_seq` |
| C | 无 | 一次性 | `verified_by=human` + 内容哈希去重（同内容 5 分钟内拒重） |

- A 档 token **只出现在对接单文本里**（用户复制给组长），**不落模板、不进日志、不进 `_meta`**。
- 现有"对端是否回环"鉴权继续用于**管理面**（保留），与 A 档并存。

## 8. 开工闸（重写 `workshop_gate.py`）

| 阶段 | 强弱 | 判据 | 返回 |
|---|---|---|---|
| `draft` / `lead_in` | none | — | `ok:true` |
| `modeling` | **block（组长级）** | 组长 `member.active` | 409 `{missing:["组长"], goto:"/docking…"}` |
| `staffing` | none | — | `ok:true` |
| `running` | per-member block | 只有 `active` 成员可被派活 | 单条 409 |
| `review` / `integrate` | warn / none | — | 带 `warnings[]` |

⇒ 与现在的差别：**不再拦"讨论"**（v4 删了一级讨论），**block 挪到 `modeling` 且只针对组长**。
这就是老板那条"平台 AI 不回话"的根治（旧闸 `GATED_STAGES` 含 `discussing`）。

## 10. 实施批次（每批独立可验收）

| 批 | 内容 | 判据（真请求） |
|---|---|---|
| **B1** | `agent_profile` + `lead_roster` + `workshop_path` + `direction` + 8 态状态机 + slot 表 + member_seq | 建间→填方向→选组长→读 lead-panel 拼出含真实路径的对接单；`state_restore --verify` 通过 |
| **B2** | `receipt.py` 解析器 + `intake`(A/C) + B 档轮询 + `session_token` + `channel-evidence` | 三种档位各投一份回执：A/C 走 `intake`、B 落 `_inbox` 后轮询入库；坏单 422 且报"第 X 行第 Y 字段"；重放 422 |
