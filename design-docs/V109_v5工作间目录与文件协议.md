## 1. 目录树（唯一形状）

```
<workshop_path>/                        ← 前端持有、平台落库；running 后只读（§6）
├─ _meta/
│   ├─ workshop.json                    ← 工作间镜像（id/短名/方向/状态/关键时间戳）
│   ├─ roster.json                       ← 名单镜像（slot[] 一行一条，便于人看）
│   ├─ evidence/                         ← 证据夹（L2/L4：谁在什么时候确认了什么）
│   │   └─ 20261026-1100-paste-组长.json
│   ├─ _inbox/                           ← ★B 档回执收件夹（位置即凭据，见 V110 §5）
│   │   └─ 0001-mbr0003.rcpt
│   └─ artifacts.json                    ← 目录 diff 生成的产物清单（L0，平台写，成员不写）
├─ _lead/
│   ├─ 建模.md                            ← 组长建模文档（组长写）
│   ├─ 分工源.md                          ← 分工的"源"，各组 分工.md 由它派生
│   └─ 名单.md                            ← 组长的名单（人看用；权威仍是回执/DB）
├─ 前端组/
│   ├─ 分工.md                            ← ★本组执行真源（职责/交付/接口约定）
│   ├─ _notice.md                         ← ★变更通知，只追加（H07）
│   ├─ 员工01/
│   │   ├─ 任务/                           ← 派活只落这里（T-003.md）
│   │   └─ 产物/                           ← 成员只往这里写
│   └─ 员工02/ …
└─ 后端组/ …
```

**三条硬规则**

1. **派活 = 写文件 + 激活 + 记账**：任务正文**只在文件里**（`任务/T-*.md`）；DB 里只存索引与状态（v4 §3.1）。
2. **读写边界**：成员读"自己目录 + 本组 `分工.md` + 本组 `_notice.md`"；跨组**只读不写**；
   `_meta/`、`_lead/` 只有组长与平台写。
3. **产物只写自己 `产物/`**；平台按目录 diff 出清单（L0），**不采信成员自报**（v4 §15 / H08）。

## 2. `分工.md`（本组执行真源）格式

```markdown
# 前端组 · 分工

- 版本: 3
- 更新: 2026-10-26T11:20:00
- 组长: h_trae_cn / deepseek-v3

## 职责
一句话：本组负责什么、不负责什么。

## 交付要求
| 产物 | 位置 | 验收要点 |
|---|---|---|
| api.md | 员工01/产物/ | 每个端点写清请求/响应/错误码 |

## 接口约定
- 与后端组的接口：调用 `/api/xxx`，字段见 `后端组/分工.md` 第 2 节

## 人员
| 岗位 | harness | model | 状态 |
|---|---|---|---|
| 员工01 | h_cursor | claude-x | active |
```

**解析契约**（平台只用三条，别的不猜）：

1. `- 版本: <int>` 单调递增（用于"文件比 DB 新"的判定，§5）；
2. `## 人员` 表格的行 = 名单的**人读副本**；权威仍是 `Receipt`（`V110`）；
3. 平台**不解析**"职责/交付要求"的正文（那是给人看的），只做存在性与版本校验。

## 3. `_notice.md`（变更感知的唯一约定，H07）

```markdown
# 变更通知（只追加，最新在最上面）

- 2026-10-26T11:20 | 分工.md | v3 | 新增"接口约定"一节
- 2026-10-26T10:05 | 任务/T-003.md | 新任务 | 接口对接，期限 26 日 16:00
```

规则：
1. **只追加**，平台不重写历史（重写＝丢失"什么时候告诉过他"）；
2. 每次**激活**（`V114`）必须先追加一行再叫醒；
3. 成员被激活后的第一件事：读 `_notice.md` → 再读 `分工.md` → 再看 `任务/`（顺序写进对接单）。

## 4. 任务文件（`任务/T-<seq>.md`）

```markdown
# T-003 接口对接

- 派给: 前端组/员工01
- 派活人: 组长 h_trae_cn
- 派活时间: 2026-10-26T10:05:00
- 期限: 2026-10-26T16:00:00
- 依赖: T-001（产物 api.md）

## 目标
一句话说清"做完是什么样"。

## 验收要点
1. 每个端点写清请求/响应/错误码；
2. 附一条真请求真响应（不是"我认为"）。

## 边界
不许改别人的目录；产物只写 `产物/`。
```

规则：
1. 文件存在＝任务已派（`task_seq` 由平台发号，写进文件名与 DB）；
2. **正文不改写**：要改就发新任务或写 `_notice`（改了别人读到的是哪版说不清）；
3. 期限过期不自动判死，只在 `review` 里标 `overdue`（平台不判断，只记账）。

## 5. 文件 vs DB：谁是权威（H04 的施工化）

| 事项 | 权威 | 平台动作 |
|---|---|---|
| 任务是否存在/正文 | **文件** | 记账索引；文件不在 ⇒ `task.state=missing` 报警 |
| 名单 `slot[]` | **回执/粘贴**（`Receipt`） | 落 DB + 写 `_meta/roster.json` 镜像 |
| `分工.md` 版本 | **文件**（`- 版本:` 行） | 与 DB `division_version` 比对，不一致 ⇒ **报警不自动改** |
| 产物清单 | **目录 diff**（L0） | 写 `_meta/artifacts.json` |
| 状态（`member.state` 等） | **DB** | 它在文件里没有对应物，不需要比对 |

**冲突处理三步**（不许静默）：
1. 记一条 `conflict` 事件（谁和谁不一致、文件版本 vs DB 版本、时间）；
2. 界面/接口显示"以文件为准，平台未改任何内容"；
3. 给出一条**可执行的下一步**（例：`POST /api/ws/{id}/division/reload` 让平台重读文件后同步 DB）。

## 6. `workshop_path` 锁定（H13）

| 阶段 | 能否改 | 改了会怎样 |
|---|---|---|
| `draft` / `lead_in` / `modeling` | 能改 | 只影响后续拼装的对接单 |
| `staffing` | 能改 | 已发出的成员对接单**全部作废**（要求重发），并记 `path_changed` |
| `running` 及以后 | **只读** | 要改 ⇒ 整间**降回 `staffing`** 重验（必须用户显式确认，含"会重发对接单"的提示） |

判据：改路径后，平台必须能列出"哪几份对接单需要重发"（按 `member_seq` 列），列不出来就是没做对。

## 7. 目录校验（H05：`verify-dirs`）

平台在 `staffing` 阶段做的事（**只 stat，不猜**）：

| 检查 | 通过条件 | 失败提示（四要素） |
|---|---|---|
| 组目录存在 | `<slot_dir>` 是目录 | 谁：组长 h_xxx；缺什么：`前端组/`；去哪补：在 `workshop_path` 下建目录；补完点"重新校验" |
| `分工.md` 存在且可解析 | 有 `- 版本: <int>` | 同上，指名文件 |
| 成员目录齐 | `<slot_dir>/任务/`、`/产物/` 都在 | 同上 |
| `_notice.md` 存在 | 文件在 | 同上 |

输出（给界面直接用）：

```jsonc
{ "ok": false, "checked": 12,
  "missing": [{"member_seq":1,"what":"成员目录","path":"前端组/员工01/产物/"}],
  "next": "让组长在 workshop_path 下补建这 1 个目录，然后点「重新校验」" }
```
