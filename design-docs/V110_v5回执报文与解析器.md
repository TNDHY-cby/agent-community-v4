## 1. 报文文法（人写得出的行式格式）

```
#回执 v1                       ← 版本行：必须第一行，逐字一致
类型: <名单|派活|验收|状态>      ← 头：必填
工作间: <workshop_id>           ← 头：必填
成员: <slot_dir>                ← 头：必填（派活/验收/状态必填；名单可填"组长"）
凭据: <token|空>                ← 头：A 档必填，B/C 档留空（必须写这一行，允许空值）
序号: <int>                     ← 头：必填，单调递增（防重放）
---                             ← 分隔：头结束
<body 1..n>                     ← 体：一行一条，字段 `|` 分隔，字段名固定
---
行数: <n>                       ← 尾：必填，必须等于体行数（防截断）
```

### 四类体（字段名与顺序都固定）

| 类型 | 体行 |
|---|---|
| 名单 | `岗位: <slot_dir> \| harness: <harness_id> \| model: <model> \| 人数: <n>` |
| 派活 | `任务: <T-id> \| 派给: <slot_dir> \| 标题: <文本> \| 期限: <ISO8601 或 空>` |
| 验收 | `验收: <T-id> \| 结果: <通过\|返工\|拒收> \| 产物: <n> \| 备注: <文本>` |
| 状态 | `状态: <slot_dir> \| 新: <state> \| 原因: <文本>` |

## 2. 解析器契约（`agent_community/platform/receipt.py`，唯一一份）

```python
def parse(text: str, *, expect: str | None = None) -> ParseResult
# ParseResult = { ok: bool, receipt: Receipt|None, errors: [Err], raw_hash: str }
# Err = { line: int, field: str, code: str, message: str, fix: str }
```

### 错误码（**每条都必须带 `fix`＝怎么改**）

| code | 含义 | fix 示例 |
|---|---|---|
| `R001` | 首行不是 `#回执 v1` | 首行必须逐字 `#回执 v1`（不能有空格/BOM） |
| `R002` | 头缺行（这 5 行必填） | 补 `序号: <int>` 这一行 |
| `R003` | 类型不认识 | 只能是 名单/派活/验收/状态 |
| `R004` | 体行字段名/顺序不对 | 名单行必须 `岗位: … \| harness: … \| model: … \| 人数: …` |
| `R005` | 行数与 `行数:` 不符 | 你有 3 条体，`行数:` 要写 3 |
| `R006` | 序号 ≤ 上次收到的序号（重放/回退） | 下一次用 `序号: 13` |
| `R007` | 工作间不存在 / 成员不属于它 | 检查 `工作间:` 与 `成员:`（列出该工作间的成员） |
| `R008` | 凭据无效或已 revoke（仅 A 档） | 重新取对接单里的 token（TTL 到工作间 `closed`） |
| `R009` | 体行里出现半角 `\|`（应为全角/转义） | 文本里的竖线写成 `｜` |
| `R010` | 同一 `(工作间, 序号)` 内容不同（内容哈希冲突） | 换新序号重发 |

### 四条硬规则（v4 §7.1）

1. 头 5 行必填，**缺一行整单拒收**；
2. **整单原子**：任一行解析失败 ⇒ 整单拒，报"第 X 行第 Y 字段"，**不做部分写入**；
3. 未知字段忽略并记日志；未知类型直接拒（`R003`）；
4. **任务正文不进球**：派活只传索引（`T-id`/标题/期限），正文在 `任务/T-*.md`。

## 3. `Receipt` 对象（归一化后的唯一形态）

```python
Receipt = {
  "type": "roster|dispatch|accept|state",
  "workshop_id": "WS-…",
  "member": "前端组/员工01",
  "seq": 12,
  "rows": [ {...}, ... ],        # 按类型解析出的结构化行
  "source": "A|B|C",             # 哪个适配器送进来的
  "raw_hash": "sha256:…",
  "received_at": "…",
}
```

业务侧（`intake` 之后的落库）**只认这个对象**；三种投递的差异全关在适配器里（`V114`）。

## 4. 幂等与去重

| 场景 | 规则 |
|---|---|
| 同 `(workshop, member, seq)` 重发、内容哈希相同 | **幂等接受**，返回 `duplicate: true`，不重复落库 |
| 同 `(workshop, member, seq)`、内容哈希不同 | 拒（`R010`） |
| `seq` 小于已收到 | 拒（`R006`），并回"上次到 12，下一次用 13" |
| C 档粘贴同一段文本两次 | 按内容哈希判重（不算新回执） |

判据：同一份回执连发 3 次 ⇒ 库里只 1 条，第 2/3 次回 `duplicate: true`。

## 5. 三档投递与鉴权（v4 §7.2 的施工化）

| 档 | 投递 | 鉴权 | 防重放 | 人的参与 | 平台怎么证明"是它" |
|---|---|---|---|---|---|
| **A 协议** | `POST /api/ws/{id}/intake` | `Authorization: Bearer <session_token>`；token 绑 `(workshop, member)`，TTL 到 `closed`，可 revoke | `seq` 单调 | 无 | 校验 token == HMAC(secret, workshop+member) 且未 revoke |
| **B 桥** | 写 `<workshop_path>/_meta/_inbox/<seq>-mbr<member_seq>.rcpt` | **位置即凭据** | `seq` + 文件名带 `member_seq` | 无 | 只能由本机文件系统写进该目录；平台扫描时记录文件 sha 与写入者（尽力） |
| **C 人工** | 界面粘贴框 → `POST /api/ws/{id}/intake?source=C` | 无凭据，绑当前上下文（在谁的页面贴就归谁） | 内容哈希 | **用户确认**（L4） | 记 `verified_by=human` + `who/when` |

**A 档 token 的三条限死**（v4 §7.2 取舍）：

1. 只能写**本工作间**（token 里带 `workshop_id`，越界 403）；
2. TTL 到工作间 `closed`，且 `revoke` 立刻失效；
3. **仅回环地址可用**（非回环要求 TLS，见 `PORTABILITY.md`）。

> 模板不含令牌（铁律）⇒ token **不进模板**，而是**拼对接单时现签**、只出现在那一份对接单文本里。

## 6. 落点与留痕

| 事 | 落点 |
|---|---|
| 收到的原始报文 | `AC_DATA_DIR/receipts/<workshop>/<seq>-<hash8>.rcpt`（保留原文，便于追"当时到底写了啥"） |
| 解析结果 | DB：`receipts` 表（type/seq/hash/source/member/result/errors） |
| 拒收 | 也要落（`result=rejected` + 全部 `Err`），**不许只回 400 不留痕** |
| 人读镜像 | `_meta/roster.json`（名单类）、`_meta/evidence/*.json`（C 档确认） |
