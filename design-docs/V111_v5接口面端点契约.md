## 4. 鉴权与令牌（`V110` §5 的端点侧）

| 端点 | 谁能调 | 凭据 |
|---|---|---|
| 大厅读（harnesses/profiles/lead-roster） | 用户、前端 | 平台令牌（既有机制） |
| 工作间写（PATCH/slots/dispatch/…) | 用户、前端 | 平台令牌 |
| `intake`（A 档） | 组长/成员 agent | **`session_token`**（绑 workshop+member，TTL 到 closed，可 revoke） |
| `intake`（B 档） | 桥进程 | 位置即凭据（文件系统） |
| `intake`（C 档） | 用户 | 平台令牌 + 前端"我确认"打勾（L4） |

`session_token` 签发：`POST /api/workshop/{id}/members/{seq}/token`（仅回环、仅用户）→ 立刻拼进那一份对接单；
**不写模板、不落库明文**（库里只存 `token_fingerprint`）。

## 5. 错误码与响应形状（统一）

```jsonc
// 失败
{ "ok": false, "code": "WS_PATH_LOCKED", "error": "工作间已 running，路径只读",
  "next": "要改路径请先 POST /api/workshop/{id}/rollback?to=staffing（会要求重发成员对接单）",
  "detail": {"who": "h_trae_cn", "missing": "…", "where": "…"} }
```

| HTTP | code 举例 | 何时 |
|---|---|---|
| 400 | `BAD_REQUEST` / `RECEIPT_R002` | 参数/回执格式错（带 `next`） |
| 401 | `TOKEN_MISSING` | A 档没带 token |
| 403 | `TOKEN_SCOPE` | token 越界（别的成员/别的间） |
| 404 | `NO_SUCH_WORKSHOP` / `NO_SUCH_MEMBER` | 查不到（列出可用的） |
| 409 | `GATE_BLOCKED` | 闸门拦住（四要素，`V112` §4） |
| 422 | `RECEIPT_ATOMIC_FAIL` | 回执有一行不合法（整单拒，附全部 `errors[]`） |
| 429 | `TOO_MANY_*` | 上限保护（任务/回执/成员） |

**闸门 409 的四要素**（v4 §16）：`who`（缺谁）、`what`（缺哪项/哪条证据）、`where`（去哪个界面补）、`how`（一句话动作）。

## 6. 分批冻结（施工用，见 `V115`）

| 批 | 冻结什么 | 为什么先冻它 |
|---|---|---|
| P1 | `Receipt` 与 `intake` 三档 + 拒收留痕 | 所有回报都走它，早冻早稳 |
| P2 | `slot/member` 双层 + 主键 + `evidence` | 闸门与成员表都建在上面 |
| P3 | `dispatch`（写文件+notice+激活） | 派活是主流程的心跳 |
| P4 | `verify-dirs` / `verify-artifacts` / `review` / `integrate` | 收尾三段 |
| P5 | `lead-roster` + `lead-kit` + 命名 | 入口 |
| P6 | 讨论区（等第 7 条） | 唯一大分叉 |
