## 1. 工作间状态机（8 态）

```
draft ──(方向+短名齐)──▶ lead_in ──(组长 member.active)──▶ modeling
  ▲                         │                                 │
  │                         │                                 │(名单落库+分工落盘+verify-dirs 全绿)
  │                         │                                 ▼
  │                         │                              staffing
  │                         │                                 │(≥1 成员 active)
  │                         │                                 ▼
  │                         │                              running
  │                         │                                 │(组长给验收结论)
  │                         │                                 ▼
  │                         │                              review ──(全部通过)──▶ integrate ──▶ closed
  └──(改方向/改路径，整间降级)┘                                 │
                                                  (有返工) ────┘→ running
```

| 状态 | 进入条件（**必须可判**） | 退出（谁触发） | 允许的动作 |
|---|---|---|---|
| `draft` | 建间成功 | 用户填方向+短名 → `lead_in` | 改路径/短名/方向 |
| `lead_in` | 方向`enum`非空 + 短名非空 + `workshop_path` 非空 | 组长 `member.active` → `modeling` | 拼组长对接单、记证据 |
| `modeling` | 组长 active | 名单落库 + `分工.md` 存在且可解析 + `verify-dirs` 全绿 → `staffing` | 组长建模、深谈（外端） |
| `staffing` | 见左 | ≥1 成员 `active` → `running` | 逐个接成员、拼成员对接单 |
| `running` | 见左 | 组长发起验收 → `review` | 派活/干活/改分工（走 `_notice`） |
| `review` | 有空 `delivered` 任务 | 全部 `accepted` → `integrate`；有 `rework` → 回 `running` | 验收、返工 |
| `integrate` | 见左 | 用户点归档 → `closed` | 汇总（`_meta/`） |
| `closed` | 见左 | 终态（只读） | 只读、导出 |

**已删**：`discussing`（无一级讨论）、`selecting`（选人不是独立阶段）、旧 `division`（并入 `staffing` 的"分工落盘"条件）。

## 2. slot / member 状态机

```
slot  : proposed ──▶ approved ──▶ filled
                        └───────▶ dropped

member: pending ──▶ acked ──▶ entered ──▶ active ──▶ blocked
                                              └────▶ lost
```

| 迁移 | 触发（谁） | 条件 | 记账 |
|---|---|---|---|
| `pending→acked` | 平台 | 收到成员对接单的"已粘贴"证据（`paste_seen` 或 A/B 档对等物） | `acked_at` |
| `acked→entered` | 平台 | 会话名对上了（`rename_seen`）或 A 档首次调通 | `entered_at` |
| `entered→active` | 平台 | **该档位的证据齐备**（§3）且 `verified_scope` 写明覆盖到哪 | `active_at` |
| `active→blocked` | 用户/组长 | 明确报"卡住"（缺凭据/调不通），带原因 | `blocked_reason` |
| 任意→`lost` | 平台 | 连续 N 次触达失败（`wakeup_result=failed`）或用户标"它没了" | 吊销 token |

**关键**：`slot.proposed` **不参与任何闸门**（V104⑤ 根因就在这），只有 `member.*` 参与。

## 3. 通道证据 → 档位（判"接上"）

| 档 | 判据（全部满足才算 `active`） | `verified_scope` 必须写到 |
|---|---|---|
| **A 协议** | 真发一次 `tools/list` 或 `GET` 有响应体（L0），且 `session_token` 校验通过 | "能调平台：已真调 tools/list，回 N 个工具" |
| **B 桥** | 逻辑桥**取件成功 1 次**（真把文件取走，`_notice` 或任务文件） | "桥能取件：已取走 T-00x" |
| **C 视觉** | `paste_seen` + `press_ok` + `rename_seen`（三项，缺一不算） | "粘贴+回车+改名已确认，**未**验证它能回话" |

**未打勾不算接上**，最高只记 `acked`（v4 §7）。
**第 5 条待拍板**：若定"必须 `full_chain`"，则 B 档要加"有回执"才算；现稿按"桥通无回执只记 `acked`"留位。

## 4. 闸门（谁在什么状态拦什么）

| 闸 | 在哪个状态 | 拦什么 | 判据 | 409 四要素 |
|---|---|---|---|---|
| G1 方向 | `draft→lead_in` | 方向`enum`为空 / 短名为空 | 字段非空 | who=用户；what=`direction.enum`；where=工作间首页；how=选下拉 |
| G2 组长 | `lead_in→modeling` | 组长未 `active` | `member(seq=0).state==active` | who=组长 h_xxx；what=A/B/C 档证据缺哪项；where=组长对话框；how=复制对接单→粘贴→打勾 |
| G3 名单+目录 | `modeling→staffing` | 名单没落 / `分工.md` 缺或少版本行 / 目录缺 | `V109` §7 `verify-dirs.ok` | who=组长；what=缺 `前端组/员工01/产物/`；where=组长窗口；how=让组长补建后点"重新校验" |
| G4 成员 | `staffing→running` | 一个 `active` 成员都没有 | `count(member.active)>=1` | who=用户；what=成员证据缺项；where=对接中心；how=逐个打勾 |
| G5 派活 | 任何写派活时 | 目标成员非 `active` / 任务正文没落文件 | 文件存在 + 成员 active | who=组长；what=`任务/T-003.md` 不存在；where=`workshop_path/…`；how=让组长先写文件 |
| G6 路径锁 | `running+` 改路径 | —— | `V109` §6 | who=用户；what=路径已锁；where=工作间设置；how=降回 staffing（会重发对接单） |

**闸门实现要求**：**单一函数**返回 `(ok, code, four_elements)`；端点只负责把它拼进 409（别在 10 个端点里各写一遍）。

## 5. H12：`review / integrate / closed` 三态的动作（原来"没有流程支撑"）

| 状态 | 谁做 | 做什么（可执行动作） | 产物/记账 |
|---|---|---|---|
| `review` | 组长（外端） | 读 `产物/` → 出结论 → 发 `Receipt(验收)` | 任务 `state`: `accepted/rework/rejected`；`_meta/evidence/accept-*.json` |
| `review` | 平台 | `verify-artifacts` 扫目录、比对派活单与产物清单 | `_meta/artifacts.json`（L0）+ 差异清单 |
| `integrate` | 平台 | 汇总：产物清单 + 验收结论 + 冲突项 + 未交付项 | `_meta/integrate.json`（人读） |
| `integrate` | 用户 | 点"归档" | 目录原样保留；写 `_meta/closed.json` |
| `closed` | 平台 | 只读；吊销所有 `session_token` | `closed_at`；`receipts` 不再接收（新回执拒 `R007`） |

**归档不搬内容**：`integrate` 只写清单与索引，**不动** `产物/` 里的文件（v4 §3.1 文件即介质）。

## 6. 降级路径（H09：无工具面也能走，只是全人工）

| 缺什么 | 谁受影响 | 怎么降 | 判据 |
|---|---|---|---|
| 无 `fs_write` | 不能当组长（H01 已定） | 只能当成员 | `lead_roster` 里根本不出现 |
| 无 `protocol_call`、有 `bridge_poll` | 组长可用（B 档） | 回执走 `_meta/_inbox/*.rcpt` | 桥取件 1 次 = 证据 |
| 两者都无（纯 GUI） | 只能当成员，且全人工 | 平台标"待唤醒"，用户去说一句、回来打勾（L4） | `wakeup_result=manual` + `verified_by=human` |
| 叫不醒 | 同上 | 不判死：`member.state` 留 `acked`，界面红字"叫不醒，需人工去说一句" | 允许继续，但派活时 G5 会提示 |

## 7. 判据（施工时先立这些，再改代码）

1. `slot.proposed` 存在时，**任何**闸门都不该拦（用真请求验：建间→落一条 proposed slot→G4 只看 member）；
2. 三档各走一遍 `entered→active`：A 真打 tools/list、B 真取件、C 真三项打勾；
3. 六个闸各造一次失败，检查 409 **四要素齐全且 `how` 可执行**；
4. `running` 后改路径 ⇒ `WS_PATH_LOCKED` + 返回"需重发清单"；
5. `review→integrate→closed` 走一遍：产物清单由目录 diff 生成（**不采信自报**），归档不动产物内容。
