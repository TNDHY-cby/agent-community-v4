## 术语速查（最容易混的十二个）

| 词 | 一句话 | 别混 |
|---|---|---|
| harness | 工具壳子：窗口、工具面、叫醒方式、落字点 | ≠ AI，≠ 人 |
| AI | 模型本身 | 不登记，只引用 |
| agent | 壳 + 模型；**换模型即换 agent** | 成员要留 `model_snapshot` |
| **根A `agent_mind_path`** | **永久心智根**（宪章/基模/记忆索引/memories/日志/死胡同） | 不随工作区销毁 |
| **根B `workshop_path`** | **一次性工作区**（manifest/分工/任务/产物） | 可整根归档 |
| slot | 岗位行（组长产出，**可有岗无人**） | 不参与闸门 |

| channel | 会话 + 桥 + 邮箱 | 不叫"协议" |
| 回执 | 外端 → 平台的结构化报文 | 与投递方式无关（三档归一） |
| 激活 | 写任务 + 追加 notice + 触达 | ≠ 派活已完成 |
| `manifest.json` | 根B 的入口地图（G0 必检） | 不是模板，也不含令牌 |
| `分工.md` | 执行真源 | DB 只是镜像 |

## 状态速查

```
工作间: draft → lead_in → modeling → staffing → running → review → integrate → closed
slot  : proposed → approved → filled / dropped
member: pending → acked → entered → active → blocked / lost
```

## 三条不许破的线

1. **平台不判断**：不推荐、不评分、不体检。
2. **模板不含真实坐标、不含令牌**（令牌拼对接单时现签）。
3. **文件是执行真源、DB 是镜像**；冲突报警，**不自动改**。

## §0 不变量清单（**改动前先看这 12 条；与本册任何一处冲突，以本清单为准**）

| # | 不变量 | 违反的后果 |
|---|---|---|
| 1 | `lead_in` **不要求** manifest（只要方向 `enum` + 短名 + 路径） | 会把"还没建模"卡死在第二步 |
| 2 | **G0（manifest 合法性）必检于两处**：`modeling→staffing` 之前、`dispatch` 之前 | 派活写进一个没清单的工作区 |
| 3 | `running+` **路径与配置不可改**；但受控区域**可追加**（白名单见 §3.4） | 要么把派活堵死，要么把"锁"变成空话 |
| 4 | **L3（大模型自报）永不采信**（`R011` 直接拒） | 把"它说做完了"当证据 |
| 5 | `mind_path` **不得落在工作区内**（`M005`） | 工作区一归档，记忆跟着丢 |
| 6 | **文件是真源、DB 只是镜像**；文件↔DB 冲突**报警不自动改** | 平台替人做决定 |
| 7 | B 档"位置即凭据" **只用于可信本机/可信桥**；跨机不要用 | 谁都能写收件夹 ⇒ 可伪造回执 |
| 8 | **批准 ≠ 落地**：`approve` 只记审批，`apply` 才改写基模（且必须人拍板 + 校验改前 hash） | 人点了同意，认知却悄悄变了 / 或永远变不了 |
| 9 | **平台不判断、不代写、不评分**：验收只记结论与证据等级 | 平台变成"审稿人"，红线和 10-25 事故重演 |
| 10 | 任何"看起来成功"的状态都不许留：失败要给 `code` + `why` + `next`（闸门给四要素） | 用户把"坏了"当"正常" |
| 11 | **员工名单以「组长回执落库的那份 v5 名单」为准**；界面手动加人写**同一份**（`source=manual`），旧 `WorkshopMember` 只是**投影**（老板 2026-10-30 SOP，见 §8.1） | 两本账各写各的 ⇒ 加了人却「没有成员」、派活派不出去 |
| 12 | **产物目录真扫到 0 个文件时只允许 `L4`**；`L1` 必须带 `evidence_ref` 凭据（没凭据按 `L4` 算）（老板 2026-10-31 拍板，见 §15.1） | 只看"它说做完了"/一纸回执就判通过 ⇒ 2026-10-25「对方说通了不算」的事故重演 |

## §1 三层定义

| 层 | 是什么 | 键 | 归属 |
|---|---|---|---|
| **harness** | 工具壳子：窗口、工具面、叫醒方式、送字落点 | `harness_id` | 大厅 |
| **AI** | 智能本身 | 模型名 | 不登记，只引用 |
| **agent** | 壳 + 智能 | `(harness_id, model)` | 组合体（v5 起还带一份**心智根**） |

> 结构上还有一层：**Cell**（§22）—— 工作间只是 Cell 的一个特例；未开发，见 §22。

硬结论：注册的是**壳**；能力 = 壳工具面 × 模型 × 接入方式；换模型即换 agent（留 `model_snapshot`）。

### 1.1 协议不是一条高低线，而是**四层**（老板 2026-10-28 更正）

> 老板原话：「**我不认为 MCP 是最好的协议，它只是调用了对象的工具和技能**」。
> ⇒ 纠正：不能拿"自动化程度"当协议高低。按**协作语义深度**分四层：

| 层 | 回答什么 | 谁在做 | 典型协议/实现 | 缺了它会怎样 |
|---|---|---|---|---|
| **① 身份与意图** | 谁让谁干、谁承担、谁验收 | **平台**（roster / member / lead / direction） | ——（A2A 的 AgentCard 只给"我是谁"，不给"谁负责"） | 谁都能说，没人担责 |
| **② 任务契约** | 派活→回报→验收→证据 | **平台自研**（`Receipt` 四类 + 任务账本 + 证据 L0~L4 + 409 四要素） | 回执报文（`V110`） | "它说做完了"就当完了（V101 的坑） |
| **③ 传输与调用** | 消息怎么送到、工具怎么被调 | 适配器（各自独立进程） | **MCP＝工具面**（它调我的工具/技能）· HTTP/gRPC＝通道 · A2A＝对等任务语义 · ACP＝会话轮次 · 桥＝文件 · WS＝事件流 | 送不到就全是空转 |
| **④ 触达** | 怎么把它叫起来 | 三档（协议 / 桥标记 / 人工） | `wakeup` | 派了活没人干 |

**四条由此得出的硬话（不许再写反）**：

1. **MCP 只是第 ③ 层的"工具面"**：它让 agent **调用平台的工具与技能**（14 个工具），
   它**不表达**身份、任务归属、验收责任，也**不能**让平台反过来驱动它的模型；
2. **"最好的协议"这个问题本身要拆**：要**对等协作语义**看 A2A/ACP；要**调工具省事**看 MCP；
   要**跨机可靠**看 gRPC/HTTP；要**没有网络条件也能干**看桥/人工。它们在**不同层**，不是同一把尺子；
3. **协作语义在我们自己手里**：`Receipt` + 任务账本 + 证据阶梯 + 闸门四要素 —— 这部分**任何现成协议都不给**，
   所以我们把它做进平台（这也是 P1~P4 的实质）；
4. **文档口径统一**：任何"按协议排名"的写法一律改成"**按层说能力**"。

## §2 对象与权威副本

> 泛化视角：`workshop` ＝ 一个 **Cell**（§22.5）；`slot/member` 是它的叶子成员。本节的键与权威副本**不变**。

| 对象 | 键 | 权威副本 | 备注 |
|---|---|---|---|
| `harness` | `harness_id` | 大厅 | `tooling.fs_write` 必须**实测**过才算 true |
| `template` | `(harness_id, kind)` | 大厅 | 只写占位符/相对落点 |
| `agent_profile` | `(harness_id, model)` | 大厅 | 含 `fit_directions`、能力分 + `evidence` |
| `lead_roster` | `(direction, harness_id, model)` | 大厅 | `lead_eligible` **算出来**，不手填 |
| **`agent_mind`（根A）** | `agent_key` | **心智根目录** | 宪章/基模/索引/memories/日志/死胡同；**只增不改** |
| `workshop` | `workshop_id` | 工作间 | 含 `project_short`（必填）、`direction{brief,enum[]}` |
| `workshop_path`（根B） | —— | 工作间记录 + **前端持有** | 建间时可指定；`running` 后锁 |
| **`library_path`（资料库指向）** | —— | 工作间记录 | **可指向工作区之外的目录**（用户自己新建的文件夹）；组长把「项目建模 + 分工明细」放进去；不填 ⇒ 默认 `<根B>/library/` |
| **`manifest`** | `(workshop_id)` | **根B 的 `manifest.json`** | G0 必检；hash 由平台记账（不写回文件） |
| `slot` / `member` | `(workshop_id, member_seq)` | 工作间 | 双层；1:N（headcount） |
| `channel_evidence` | `(workshop_id, member_seq)` | 工作间 | 判"接上"的唯一依据 |
| `task` / `artifact` | `(workshop_id, task_seq)` / 路径 | **文件（根B）** | DB 只镜像索引 |

明确删除：**人池**（`candidate_pool`）。

## §3 路径与目录

> 团队资产也落在根A 下（`asset/…`，见 §23）—— **不新增第二套记忆体系**。

### 3.0 双根（2026-10-27 新增，**这是 v5 与 v4 最大的结构差别**）

```
根A 心智根（永久，跨工作间）                根B 工作区（一次性，可整根归档）
<AC_MIND_ROOT>/<agent_key>/                <workshop_path>/
├─ 00_宪章.md        身份与规矩             ├─ manifest.json   ←★存在性 = 闸门 G0
├─ 00_核心基模.md    当前认知（审忆员改）    ├─ _meta/ workshop.json · roster.json · _inbox/
├─ 01_记忆索引表.md  触发词 → 记忆           ├─ _lead/ 建模.md · 分工源.md          ← 组长深谈后写的建模
│  （资料库 = `library_path`：可以是**工作区之外的文件夹**）
├─ memories/         一条一文件（按需读）    ├─ 前端组/ 分工.md · _notice.md
├─ 02_任务日志/      日结写这里              │   └─ 员工01/{任务/,产物/}
├─ 06_死胡同/        走错的路 + 为什么       └─ 后端组/ …
└─ _meta/mind.json   机器读
```

| 规则 | 内容 |
|---|---|
| **R1 只增不改** | `memories/`、`02_任务日志/`、`06_死胡同/` 只追加；同一天重跑**只追加，不覆盖** |
| **R2 根B 可整根丢** | `manifest.mind_path` 指向根A ⇒ 工作区归档后记忆仍在 |
| **R3 不许互相嵌套** | `mind_path` 落在工作区内 ⇒ **G0 直接拒**（`M005`：归档就丢记忆） |
| **R4 认知与实体分离** | 根A **只存认知**；`任务/`、`产物/` 永远在根B（对方 2026-10-27 答案 3） |

`AC_MIND_ROOT` 未设 ⇒ 默认 `<AC_DATA_DIR>/minds`（换数据目录跟着走）。

### 3.1 单一真源

`workshop_path` 由前端持有、平台落库（建间时可由调用方指定：绝对路径 + 真写一次探测）；拼对接单时读取；**平台不留第二份副本**。

### 3.3 三个文件格式（要点）

- `manifest.json`：见 §3.5；
- `分工.md`：`- 版本: <int>` 单调递增 + `## 人员` 表格（人读）；平台只校验存在性与版本；
- `_notice.md`：**只追加**（`时间 | 文件 | 版本 | 一句话`），每次激活前必须追加一行（Boot Protocol 注入也会留痕）；
- `任务/T-<seq>.md`：目标 / 验收要点 / 边界；**正文只在文件里**，DB 不存。

### 3.4 文件 vs DB 与路径锁

| 事项 | 权威 | 冲突处理 |
|---|---|---|
| 任务存在与正文 | 文件 | 文件不在 ⇒ `task.state=missing` 报警 |
| 名单 `slot[]` | 回执/粘贴 | 落 DB + 写 `_meta/roster.json` 镜像 |
| `分工.md` 版本 | 文件 | 与 DB 不一致 ⇒ **报警不自动改**，给"重新读取"动作 |
| 产物清单 | 目录 diff（L0） | 写 `_meta/artifacts.json` |

**`workshop_path` 锁**（只锁路径与配置，**不是把工作区变只读**）：
- `draft / lead_in / modeling`：路径可改；
- `staffing`：改则已发对接单作废（要重发）；
- `running+`：**路径与配置不可改**（要改整间降回 `staffing`，并列出需重发的对接单）；
- `running+` **受控区域仍可追加写**（平台与组长都要写）：`<slot>/任务/`、`<组>/_notice.md`、`manifest.active_tasks`、`_meta/artifacts.json`、`_meta/integrate.json`、`_meta/_inbox/`（B 档收件夹）。**白名单之外不许写**。

### 3.5 `manifest.json`（**已实现**，`platform/manifest.py` 是字段唯一真源）

```jsonc
{
  "manifest_version": "coop.workshop.manifest/1",
  "workshop_id": "WS-20261027-01",
  "mind_path": "<AC_MIND_ROOT>/示例agent-01",   // 必填，且不许在工作区之内
  "entry_points": ["_lead/建模.md", "前端组/分工.md"],   // 非空 + 每条真实存在
  "active_tasks": ["前端组/员工01/任务/T-001.md"],
  "ignore_zones": ["_meta/evidence/", "前端组/员工01/产物/"],  // Boot Prompt 的黑名单
  "task_focus": "当前阶段：接口联调与自测"
}
```

**G0 四检**（`POST/GET …/manifest` 都跑）：版本匹配（`M003`）· `mind_path` 不在工作区内（`M005`）·
`entry_points` 非空（`M006`）且每条真实存在（`M007`）· `ignore_zones` 只做黑名单（允许暂不存在）。
`hash` 由平台记账（`sha256:` 规范化 JSON），**不写回文件**（避免自指）。

### 3.6 Boot Protocol（激活时注入，**两个根写死**）

```
【系统启动协议（Boot Protocol）】
1. 身份声明：你是 Agent [A-01]。当前激活的动态工作区（根B）为 `<workshop_path>`。你的永久心智根（根A）为 `<mind_path>`。
2. 强制挂载：只读根A的 `00_核心基模.md` 与 `01_记忆索引表.md`，挂载你的核心记忆与规则。
3. 加载上下文：读取根B的 `manifest.json`，认知当前任务焦点（task_focus：…）。
4. 沙盒红线：禁止使用任何工具对根B进行全盘扫描；严禁读取 `manifest.json` 中的 `ignore_zones`（…）。
5. 按需唤醒：根据当前任务关键词，在 `01_记忆索引表` 中匹配，仅且只读取匹配成功的 1-3 个 memories 文件。
6. 开始执行：结合以上上下文，开始今日工作。
```

模板唯一真源：`platform/boot_prompt.py`；判据会去 `stat` 两个根，**占位符一律红**。

### 3.7 日结（把教训写回根A）

`POST /api/workshop/{id}/daily-close`：把当天"做完了 / 卡住了"写进 `<mind>/02_任务日志/<日期>.md`
与 `<mind>/06_死胡同/<日期>.md`（**模板拼接，不用 AI**；同一天追加不覆盖）。
**平台不判断哪条重要** —— 压缩成 3 行、重写索引是夜间审忆员的活（P4）。

## §5 状态机

| 状态 | 进入条件（可判） | 谁触发 |
|---|---|---|

## §6 通道证据与"接上"

| 档 | 所需证据（全齐 + `verified_scope` 非空才算 `active`） | 谁验的 | 备注 |
|---|---|---|---|
| A 协议型 | **答得出对接单第 6b 节的一次性回话口令**（`protocol_ok`） | **平台自己**（`platform-observed` + 时间戳） | 无桥无会话，不算残缺 |
| B 桥型 | 桥**真取件 1 次**（`bridge_ok` / `mailbox_ok`） | **平台自己**（写测试消息 + 看它进 `delivered/`，`platform-observed` + 时间戳）—— 见 §6.2 | 只通不取不算 |
| C 视觉型 | `paste_seen + press_ok + rename_seen`（三项） | **用户打勾**（`user-check`） | 粘贴 + 回车 + 改名；平台看不见 |

**未打勾不算接上**，最高只记 `acked`（并说清缺哪项）。P4 起再加**认知证据** `evidence_level`（见 §15）。

> ⚠️ **B 档的边界（2026-10-31 补 §6.2 时写明）**：走 `/members/{seq}/evidence` 直接申报
> `bridge_ok` 的路径**仍然存在**——那种情况账上照旧记 `user-check`（与人打勾同类），
> 界面必须分开显示。**只有走 §6.2 的 `bridge-probe` 才记 `platform-observed`**。

### 6.1 每项证据必须记「谁验的」（2026-10-31 老板追问后改的）

> 老板原话：「A 档改成平台自己观测，会不会有人随便发一次请求就算『接上了』？这一块你怎么卡的？」

**原来的问题（真事，不是推测）**：`protocol_ok` / `bridge_ok` / `mailbox_ok` 三个标志**全是调用方传进来的**
（前端勾一下、接口喂一下就算），平台自己从不观测。于是"随便发一次请求"或"自己点个勾"都能记成接上 ——
评委一问「你怎么知道它接上了」，诚实答案是"因为有人打了勾"，这句话站不住。

**现在的做法：A 档改成"平台自验"，五道卡**（判据 `tests/test_v5_handshake.py` 8 条真跑）：

1. **一次性口令**：拼成员对接单时现生成（`XXXX-XXXX`），**库里只存 sha256 指纹**；口令写进单子第 6b 节；
2. **必须答对口令**：错一个字符 ⇒ `HANDSHAKE_MISMATCH`（随便编不算）；
3. **必须有该工位的 A 档凭据**：没有 ⇒ 401；凭据属于别的工位/别的工作间 ⇒ 403 `TOKEN_SCOPE`
   （"拿别人的单子来刷"进不来）；
4. **一次性、防重放**：用过就作废 ⇒ 再发同一口令 `HANDSHAKE_ALREADY_USED`；
5. **重拼对接单 ⇒ 旧口令立刻失效**（保证"口令只属于那一张单子"）。

成功后平台**自己**写 `evidence._sources["protocol_ok"]="platform-observed"` + `protocol_ok_at` 时间戳，
并自动补 `verified_scope`（"它答出了口令"就是它能覆盖到的那一段）。

**账上必须区分来源**（同一件事两种口径 = 假账）：

| `evidence_sources` | 含义 | 界面怎么显示 |
|---|---|---|
| `platform-observed` | 平台自己看到的（口令回话 / 看见桥取件） | 「平台验的」+ 时间戳 |
| `user-check` | 用户在界面上打的勾 | 「你打的勾」——**不许**显示成"已验证" |

⚠️ **单看时间戳分不出来**：打勾也留 `*_at`。区分点是 `evidence_sources`，界面上两者必须长得不一样。

**诚实边界（写在这里，别在汇报里吹）**：这套只防「**没接上却记成接上**」。
**防不了用户自己拿单子里的凭据 + 口令 curl 一次**（那等于用户伪造自己的账）。
要做到"伪造也做不到"，就得让平台判断回应内容像不像真的 —— 那违反「平台零 AI」，所以不做。

⚠️ **一条副作用（别当 bug 修）**：**成员对接单不再逐字可重复** —— 每拼一次都现生成新口令，
所以两份文本必然不同（旧口令同时作废）。**组长对接单仍然逐字相同**（组长不走口令）。
判据 `p5_check` ⑤ 测的是**组长**单，13 格仍全绿；成员单的"可重复"由"口令一次性"这个**安全要求**覆盖掉。

### 6.2 B 档也做成「平台自验」：平台自己写测试消息、自己看它被取走（2026-10-31 老板拍板后做）

> 老板拍板原话（选项 A）：「B 档也做成自验，别只嘴上说」。
> 起因：上一版 §6 表格把 B 档写成「平台看得见文件从有到无」是**过度声明** ——
> 当时 `bridge_ok` / `mailbox_ok` 只能由调用方申报（账上 `user-check`）。

**做法（复用 `platform/bridge_selfcheck`，不发明新协议、不写死路径）**：

```
POST /api/workshop/{id}/members/{seq}/bridge-probe
body: {inbox_dir?: "该工位邮箱目录", probe_id?: "上次那条", wait?: 秒}
```

1. 平台往该工位邮箱写一条 `task_<probe_id>.json`（**平台自己写的**，与桥的 `task_*.json` 约定一致）；
2. 平台看两处磁盘事实：
   - 文件进了 `inbox/delivered/` ⇒ **桥真取走了** ⇒ `bridge_ok` 记 `platform-observed` + `bridge_ok_at`；
   - `inbox/replies/` 里出现 `reply_<probe_id>.json` ⇒ **它真回话了** ⇒ 再加 `mailbox_ok`（同样 `platform-observed`）；
3. **没取走 ⇒ 一个字都不许记进证据**（`PROBE_NOT_PICKED` 409），并给出 `probe_id` 让用户"等会儿再看同一条"；
4. 取件成立时**自动补 `verified_scope`**（"平台观测：它取走了平台写进邮箱的测试消息（probe_xxx）"），
   不逼用户再补一句废话；没有 tier 时默认记 `b_bridge`。

**路径怎么来（真实边界，别假装精确）**：`inbox_dir` 不给就按 `compartment.mailbox_dir()`
约定推导成 `<工作间>/<岗位>_<成员>/inbox`，并在响应里标 **`inbox_guessed: true` + 一句提示**——
因为 v5 名单的 `slot_dir` 是**岗位名**，同一岗位多人时它们**共用同一个邮箱**，取件分不出是谁。
要精确到人就在 `inbox_dir` 里显式给（这也是 `bridge_selfcheck` 的既定原则：不写死任何路径）。

**与 A 档的对称**：A 档 = 平台发口令、它答对；B 档 = 平台写消息、它取走。两档都是
「平台做的动作 + 平台看见的事实」，所以都能记 `platform-observed`。C 档（视觉）平台看不见，永远 `user-check`。

**仍然防不了什么（如实）**：用户自己也能往同一个邮箱塞文件/删文件，从而骗出一次"取件"。
这套防的是「**没接上却记成接上**」的**无心错记**（勾错、以为接上了），不是防有意伪造成本。
判据：`tests/test_v5_bridge_probe.py` **7 条**（真目录真文件，测试自己扮演"桥"把文件移进 `delivered/`）。

### 7.1 文法

四类体：名单 `岗位|harness|model|人数`；派活 `任务|派给|标题|期限`；验收 `验收|结果|产物|备注`；状态 `状态|新|原因`。
**P3 已加（可选）**：验收体第 5 列 `证据: L0|L1|L2|L4` —— **`L3`（大模型自报）直接拒 `R011`**；不写这一列仍收（向后兼容），但 `review→integrate` 起会要求每个任务至少 `L1`（P4 落闸）。

**证据阶梯的判定口径**（`L1` 原来写得含糊，2026-10-30 收紧）：

| 级 | 谁做的 | **可复现的判定**（不是「我觉得」） |
|---|---|---|
| `L0` | 平台自己 | 平台自己的目录 diff / 记账（`_meta/artifacts.json` 有这一条，带 sha256） |
| `L1` | 平台的**可复现查询** | 必须写清「哪条查询、谁跑、期望什么」：<br>① 产物类 ⇒ `POST …/verify-artifacts` 返回该文件在清单里；<br>② 任务类 ⇒ `GET …/tasks` 该任务状态与账本一致；<br>③ 对端库类 ⇒ `python tools/verify_session_truth.py --db <库> --needle <口令>` **exit 0**（对方应用自己的库里真有）。<br>**写不出「哪条查询」的，就不许记 L1。** |
| `L2` | 平台留痕 | trace / 审计 / 桥产物在中转目录里（不等于内容正确） |
| `L4` | 人的眼睛 | 用户自己看过并签字（平台只记账） |

**每类任务的最低等级（P4 起强制）**：产物类 ≥`L1`；接口/契约类 ≥`L1`；文档类 ≥`L2`（有 `L1` 更好）；**任何任务都不许用 `L3`**。

### 7.1b B 档（位置即凭据）的威胁模型（2026-10-30 补）

B 档用"把回执文件放进 `_meta/_inbox/`"来代表"这个成员确实送来了回执"。**但工作区是成员可写的**，
所以必须认账：**谁能写那个目录，谁就能伪造/覆盖/重放一份回执**。已有的缓解：

1. **原子写**：先写临时文件再 `rename` 进位（半截文件不会被当成回执）；
2. **去重**：按 `(workdir, member, seq)` + **内容哈希**判重 —— 同一份重放只会记一次；序号回跳报 `R006`；
3. **坏单留痕**：解析失败的文件移进 `_fail/` 并写 `.err`，原文不丢。

**边界（写死）**：B 档**只用于可信本机 / 可信桥**（同一台机器、同一个操作者）；
**跨机、跨公司不要用 B 档** —— 跨机走 A 档（token）或经中转（`/api/relay/*`）。
平台**不**把 B 档回执当成"防伪凭据"，它只是"位置＝这个成员的口子被谁用过"的记账。

### 8.0 名单与实到对不上怎么办（老板 2026-10-31 拍板；**已落地**）

> 老板原话：「名单上写了五个员工，实际只拉进来三个；或者拉进来的人换了名字 ——
> 平台是发现差一个就拦住不让往下走，还是先接着干、以后再补？」

**口径一 · 人数不齐 ⇒ 先接着干，缺的那个在他被用到时才拦**（不拦开工）：

- 名单回执写 `人数: 5` ⇒ 平台**真建 5 个工位**（`pending`），不是只记一个数字；
- 只接上 3 个 ⇒ **开工放行**（G4 只要 `≥1 active`，见 `v5_gate.check`）。**这是刻意设计**：
  一个 agent 抽风没接上，不该把整间活儿停掉；
- **给"没接上"的工位派活才拦**：409 `GATE_G5` + 四要素（谁=`成员 #N` / 缺什么=`它还在 pending` /
  去哪补=`对接中心` / 照做=`先把它接上再派活`）；
- **必须给一句人话**（本条此前只在模型里写了「明写还有 N 人未接上」，实现里没有 ⇒ 2026-10-31 补上）：
  `GET …/roster` 与 `GET /api/workshop/{id}` 都带 **`roster_summary`**
  （例：`名单 5 人，已接上 3 人，还差 2 个（前端组#4、前端组#5）—— 空工位不能派活`），
  界面直接显示这一句，别让用户自己数状态数字。

**口径二 · 名字对不上 ⇒ 平台核不出来，只能"你填了就比"**（老板选 A：可不填，填了就比）：

- 平台给每个工位生成**身份名** `session_label`（`工作间-岗位-序号`），名单落库时写死，**这才是账上的身份**；
- 用户在自己那边的应用里给 agent 起的名字，平台**看不到**（除非该 harness 配了 `rename_session` 脚本且回读成功）；
- 因此：接人时**可选**填一句 **「它现在实际叫什么」**（字段 `actual_name`，从那个应用的会话标题抄）；
  - 填了 ⇒ 与 `session_label` 比，不一致就**提醒**（「名单上叫 X，你说它叫 Y —— 是同一个 agent 改名，还是换了一个？」），
    **不拦**（改名很常见，拦死就成了"改个名就派不出活"）；
  - 没填 ⇒ 按现状，但界面**如实标**「这个名字是你给它的，平台没核过它真实叫什么」；
- **为什么只提醒不拦**：拦死会造死局；不提醒又会让活儿记在错的人名下（`2026-10-25`「谁干的记错了」同类）。

**证据三档（谁也不能「嘴上说通了」）**

| 档 | 判据（平台自己看到的） | 最高状态 |
|---|---|---|
| **A 协议型** | 真收到它的请求（`GET` / `tools/list` 等） | `active` |

## §15 诚实性

| 级 | 含义 | 能判通过 |
|---|---|---|
| L0 | 平台实做（真发请求、真收文件/回执、`stat`/目录 diff） | 能（**但盘上真扫到 0 个文件时不能**，见下） |
| L1 | 它库已有（`code=0`） | 能 —— **必须带 `evidence_ref` 凭据**（老板 2026-10-31 拍板） |
| L2 | 平台留痕 | 能（**产物目录空时不能**，见下） |
| L3 | 它自报（大模型说自己做了） | **永不**（P4 起验收回执里出现 `L3` 直接拒 `R011`） |
| L4 | 人眼确认（`verified_by=human`） | 能，须留 who/when/which；**唯一不受"产物空"限制的档** |

硬规则：`code=2` 既不算通过也不许说"没有"；**回显 ≠ 回复**；命名/粘贴只能 L4；能力分无证据按 1 分。

### 15.1 两条 2026-10-31 拍板的硬规则（**新会话按这两条判，别再凭印象**）

**规则一 · `L1` 必须带凭据**（老板选定 B 方案，设计稿 `V121 §3.3`）：

- `evidence_level=L1` 而未给 `evidence_ref`（谁核的 / 核的什么 / 用什么工具或命令核的）⇒ 拒，错误码 `L1_NEEDS_PROOF`；
- **没凭据的 `L1` 一律降级按 `L4` 算**（你说"它库里有"，但拿不出凭据 ⇒ 只能当人眼确认）；
- 有凭据的 `L1` 照过，但账本记 `evidence_ref` + `evidence_ref_is_manual=true`，**界面必须标「L1（人工凭据，平台未核对）」**，
  不许显示成"平台已验证"——平台确实没去查那个库。

**规则二 · 产物空只许 `L4`**：

- 平台真扫该工位 `产物/` 得到 **0 个文件**时，`L0`/`L1`/`L2` **一律拒**（`ARTIFACTS_EMPTY`），只有 `L4`（人眼确认）能过；
- 理由：`L2` 只是"留痕"，`L1` 只是"别人说库里有"，都不证明产物真在；`L0` 却与扫描结果自相矛盾时要**说清这层矛盾**，
  别让用户以为"平台坏了"；
- 判"有没有交东西"**只看盘上现状**（`total_files` / `files_now`），**不看"这一轮 diff 出的 `new`"**——
  先点过「扫描产物」再验收时 `new` 会是空数组，而文件明明在（实测抓到的看反坑，见 `V121 §2.2`）。

> 依据：`V121`（设计稿，已拍板）、老板 2026-10-31 口答；判据 `tests/test_v5_review_view.py` + `tools/p4_check.py`。

### 15.2 跨组织：**采信态四值**（2026-11-04 老板拍板；`V130`，2026-11-05 已实施）

`L0~L4` 回答的是"**结果能不能被独立复核**"；它**不回答**"复核结论算不算数、谁说了算、两方不一致怎么办"。
后者由账本 `external.peer_accepted` 记，四值（**只在大模型自报以外再加一层准入，不是评分**）：

| 值 | 含义 | 界面怎么说 | 能进验收 |
|---|---|---|---|
| `accepted_self` | 只有交付方自证 | 「**未复核**：只有它自己说」 | **不能** |
| `accepted_peer` | 接收方独立重算通过 | 「已复核：本侧重算一致」 | 能 |
| `disputed` | 有争议且未决 | 「**有争议，不采信**」 | 不能（冻结待裁） |
| `refuted` | 已被证据证伪 | 「**已证伪**」 | 不能（可直接降级） |

**硬规则（唯一后果）**：**跨组织任务（账本里有 `external` 段）通过验收，必须 `accepted_peer`**；
`accepted_self` / `disputed` / `refuted` 一律拒（`PEER_NOT_REVIEWED` / `DISPUTE_OPEN` / `PEER_REFUTED`）。

**复核只认可重算/可指向的东西**：逐文件比 `sha256`（含字节数）；`L1` 的 `evidence_ref` 若像本机路径，
平台真 `stat` 一次，指向的东西不存在 ⇒ `L1_PROOF_MISSING`、按 `L4` 算（`V130` §4 规则二）。

```
        ↑ 日常流转
第一层：日常自治（Worker 自己改，事后知情，写"修正记录"）
常设：审忆员（独立于指挥链；只检查、只报告、只建议暂停）
```

### 24.1 危急度五级（**落到回执里，不另起报文**）

| 级 | 代号 | 时限 | 处理层级 | 本项目的载体 |
|---|---|---|---|---|
| L1 | `OBSERVE` | 无 | 组级看板观察区 | 看板追加（L0 留痕） |
| L2 | `GROUP` | 24h | 组长裁决 | 回执 `类型: 状态` + 任务账本 |
| L3 | `CROSS` | 8h | 团长（＝最近共同祖先）仲裁 | 回执 + `manifest_ref` 指涉事任务 |
| L4 | `URGENT` | 2h | 用户直接介入 | 回执 + `_pending`（等拍板） |
| L5 | `CRISIS` | 立即 | 用户 + 审忆员 | 同上 + 冻结 |

触发：超管辖权 / 资源竞争 / 规则冲突 / 组内重试 ≥3 / 价值观取舍不一致。
**超时未处理 ⇒ 自动升一级 + 审忆员记"超时未决"**（这是状态机，不是文案）。

### 24.2 阶段大会（只议事、不改拓扑）

| 大会 | 参与 | 周期 | 表决 |
|---|---|---|---|
| 组级 | 组长 + Worker | 2 周 | 简单多数 |
| 团级 | 团长 + 组长 | 每月 | 简单多数，用户可否决 |
| 全体 | 用户 + 团长 + 组长代表 + 审忆员 | 季度 / 里程碑 | 2/3 多数，用户可否决 |

- 弃权**不计入分母**；允许"保留意见"入档；
- **载体**：AILP 2.0 四类消息承载**发言**（§13 `/ailp`，已实施）；**投票 / 计票 / 否决 / 决议归档**
  协议里没有 ⇒ **平台必须自己做**（缺口见 §21 G2）。

### 24.3 审忆员扩面（现状 → 目标）

| 现在（已实现 `tools/mind_reviewer.py`） | 扩面后（未开发） |
|---|---|
| 归档原文 → 压缩 → 重写索引 → 核心基模只进 `_pending` | 再加三项检查：**拓扑合法性**（C001~C005）、**资产与拓扑一致**（迁移后路径是否同步）、**联合体是否越权**（是否写了成员内部看板） |

权力边界（写死）：**检查权 / 报告权 / 暂停建议权**；**无指挥权、无惩罚权**；报告不经中间层过滤。

### 24.4 与协议的边界（一条硬话）

> 危急度是**回执的一个类型**、大会发言是**AILP 的四类之一**、投票计票是**平台自己的状态机** ——
> 三者都不需要新协议；`A2A`/`MCP` 只是把它们**送过去**（§1.1 第③层）。
