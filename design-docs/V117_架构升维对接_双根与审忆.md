## 1. 改造点① 双根分离：怎么落到我这套对象上

### 1.1 现状（必须说清，否则会以为要重写）

```
<workshop_path>/                      ← 工作区（根B 的雏形）
├─ _meta/ _lead/ 前端组/…
└─ <职位>_<成员id>/{input,output,temp}  ← 「隔间」：成员唯一可写区（platform/compartment.py）
```

隔间有三条既有口径（`V23` §9，别推翻）：
1. **归属 = 岗位（成员），不是会话** ⇒ **跨会话存活**（换会话复用同一隔间）；
2. 创建时机 = **架起具体桥那一步**（不是建工作间就建）；
3. 唯一真源 = 后端 `compartment.py`，前端不许自己拼路径。

**但隔间现在长在工作区里** ⇒ 工作区一销毁，记忆就跟着没了。这正是建议书要解决的问题。

### 1.2 改法：把隔间升级成「心智根」，并搬出工作区

```
根A 心智根 agent_mind_path（永久，跨工作间）       根B 工作区 workshop_path（一次性，可归档）
<AC_MIND_ROOT>/<agent_key>/                       <workshop_path>/
├─ 00_宪章.md            ← 它的身份与规矩           ├─ manifest.json      ← ★存在性 = 闸门G0
├─ 00_核心基模.md        ← 当前认知（可被审忆员改） ├─ _meta/ _lead/
├─ 01_记忆索引.md        ← 触发词 → 记忆文件        ├─ 前端组/分工.md · _notice.md
├─ memories/             ← 一条一文件（按需读）     │   └─ 员工01/{任务/,产物/}
├─ 02_任务日志/          ← 日结写这里（按日一份）   └─ …
├─ 06_死胡同/            ← 走错的路 + 为什么
└─ _meta/mind.json       ← 机器读：agent_key/宪章版本/索引版本
```

| 事项 | 归属 | 谁写 | 谁读 |
|---|---|---|---|
| `00_宪章` / `00_核心基模` / `01_记忆索引` | 根A | **审忆员**（重大修正走待审队列） | agent（只读） |
| `memories/*` | 根A | 审忆员 / agent 自己（append-only） | agent（**按索引按需读**） |
| `02_任务日志/<日期>.md` | 根A | **日结接口**（平台执行、组长触发） | 审忆员 |
| `06_死胡同` | 根A | 日结接口 / agent 报 `kind=block` 时 | 审忆员、人 |
| `manifest.json` / `分工.md` / `任务/` / `产物/` | 根B | 组长 / 成员 / 平台（记账） | 全组 |

### 1.3 三条硬规则（防止"双根"变成"两个都乱")

1. **根A 只增不改**：`memories/`、`02_任务日志/`、`06_死胡同/` 只追加；改`00_核心基模`只能由审忆员
   且必须留 `diff + 理由 + 谁批的`（§4）。
2. **根B 可以整根丢**：`manifest.json` 里写明 `mind_path`（指向根A），所以工作区归档后仍能找回记忆。
3. **不许把根A 塞进根B**（也不许反向）：`manifest.json` 必须有 `mind_path` 且**不得位于工作区之内**，
   平台启动/挂载时校验，违反即 409（否则"双根"名存实亡）。

### 1.4 接口影响（新增/改造）

| 接口 | 变什么 |
|---|---|
| `POST /api/workshop/{id}/members/{seq}/evidence` | 增加 `mind_path_ok` 证据（该成员根A 真存在且非空壳） |
| `POST /api/workshop/{id}/intake` | 回执头可带 `心智: <agent_key>`（可选，用于把回执归到某个心智） |
| **新** `POST /api/workshop/{id}/daily-close` | **日结接口**：把当天的任务/教训写进根A（§1.5） |
| **新** `GET /api/mind/{agent_key}` · `GET /api/mind/{agent_key}/index` | 只读：看它的宪章/基模/索引（给人看） |
| **新** `POST /api/mind/{agent_key}/memories` | agent 自己追加一条记忆（**append-only**） |

### 1.5 日结接口（这是"根B 可销毁"的前提）

```
POST /api/workshop/{id}/daily-close
→ 组长触发（或用户点）；平台执行：
  ① 收集当天：任务清单（文件 diff）、验收结论（回执）、卡住项（kind=block）
  ② 生成 3~5 行「今天学到什么」草稿（**模板拼接，不用 AI**）
  ③ 追加到根A/02_任务日志/<日期>.md
  ④ 走错的写根A/06_死胡同/<日期>.md
  ⑤ 返回 {written:[...], mind_path, next:"审忆员夜间会把它压成 3 行"}
```

**不做**：平台不判断"哪条重要"（那是审忆员的活）；**不写** `00_核心基模`（只有审忆员写）。

## 2. 改造点② Manifest 强校验 + Boot Prompt

### 2.1 `manifest.json` 草案（**请对方把他们的 Schema 发回来，我按他们的为准**）

```jsonc
{
  "schema": "coop.workshop.manifest/1",
  "workshop_id": "WS-20261027-01",
  "project_short": "报销系统",
  "direction": {"brief_id": "dir-01", "enum": ["编程/后端"]},
  "mind_path": "<AC_MIND_ROOT>/示例agent-01",     // ★必填，且不许在工作区之内
  "workshop_path": "<workshop_path>",
  "lead": {"harness_id": "h_trae_cn", "model": "deepseek-v3", "member_seq": 0},
  "slots": [{"slot_dir": "前端组/员工01", "harness_id": "h_cursor", "model": "claude-x",
             "headcount": 1, "members": [3]}],
  "files": {"分工": "前端组/分工.md", "notice": "前端组/_notice.md", "tasks": "员工*/任务/"},
  "budget": {"tokens": null, "deadline": null},
  "created_at": "2026-10-27T10:00:00",
  "manifest_hash": "sha256:…"                      // 平台写；任何改动都要重算 → 闸门比对
}
```

### 2.2 闸门 G0（新增，排在所有闸之前）

| 检查 | 通过条件 | 失败（409，四要素） |
|---|---|---|
| `manifest.json` 存在 | 是文件、能解析、`schema` 对 | 组长 / 工作区缺 `manifest.json` / `<workshop_path>` / 让组长按模板写一份（给模板文本） |
| `mind_path` 合法 | 非空、**不在工作区内**、目录存在、有 `00_宪章.md` | 组长 / 心智根不对（缺失/被放进工作区）/ 该 agent 的根A / 先建根A（给命令） |
| `manifest_hash` 一致 | 与平台记账一致 | 用户 / manifest 被改过 / 工作间设置 / 点"重新校验"（平台重读并**报警不自动改**） |

### 2.3 Boot Prompt（激活时注入，平台给骨架，**不代它说话**）

```
【只做两件事，别全盘扫描】
1) 读你的心智根（只读）：<mind_path>/00_宪章.md、<mind_path>/00_核心基模.md、<mind_path>/01_记忆索引.md
2) 读工作区（只读）：<workshop_path>/manifest.json
然后按任务关键词去 01_记忆索引.md 找对应记忆文件，按需只读那几个文件。
禁止：递归遍历整个根A或根B；禁止读别人的 memories/。

你现在的工作间：<workshop_id>（<project_short>）
你的岗位：<slot_dir>；任务在 <slot_dir>/任务/，产物只写 <slot_dir>/产物/
变更先看 <slot_dir>/_notice.md（每次激活前会追加一行）
```

注入方式：写进 `<slot_dir>/_notice.md` 顶部区（人也能看到）+ 激活请求体里的 `boot_prompt` 字段（A 档）。
C 档只给可复制文本。**判据**：Boot Prompt 里出现的路径**必须**是真实存在的两个根（不许是占位符）。

## 3. 改造点③ 认知证据 `evidence_level`（**我这已经有 L0~L4，只需接线**）

现状：`V116` §15 已定义 L0~L4 并写进纪律（L3 永不放行）；P2 的闸门已经返回四要素。
要补的只有两件：

1. **验收回执（`类型: 验收`）加一列** `证据: L0|L1|L2|L4`（**L3 直接拒：`R011`**）；
   - 缺省规则：`产物` 数与目录 diff 一致 ⇒ 平台自动判 `L0`；人工打勾 ⇒ `L4`；其余按声明但不放行；
2. **任务报告**（`Receipt(验收)` 落库）记 `evidence_level`，并在 `review → integrate` 的闸门里要求
   **每个任务至少 L1**（L0 最优），**L3 一律拦**。

示例（建议书给的那条我照抄，字段名对齐我这套）：

```json
{"who": "员工#02", "what": "未达 L4 确认", "where": "对接中心", "how": "请人工打勾「我确认它能回话」"}
```

> 我这边的 409 已经是这个形状（`v5_gate._four`），所以这条**不用改结构**，只加 `evidence_level` 一路。

## 4. 改造点④ 夜间审忆员（P4 扩展；**默认关**）

### 4.1 形态

`tools/mind_reviewer.py`（**标准库、可 cron**；不常驻、不监听端口）

```
python tools/mind_reviewer.py --mind-root <AC_MIND_ROOT> --dry-run   # 看会改什么
python tools/mind_reviewer.py --mind-root <AC_MIND_ROOT> --apply     # 真写（默认关，要显式 --apply）
```

### 4.2 步骤（严格只读根 A，绝不碰根 B）

1. 扫 `<mind>/**/02_任务日志/<昨天>.md` 与 `06_死胡同/`；
2. **主动遗忘**：把大段正文替换为「3 行结论 + 指向原始日志的指针」；
   **删除前先留档**：原文整体移到 `_archive/<日期>/`（谁也不能把记忆真删掉）；
3. **索引重写**：更新 `01_记忆索引.md`（`触发词 → 文件`），保留旧版本 `01_记忆索引.<ver>.md`；
4. **核心基模**：只有"重大认知修正"才动，且**进待审队列** `_pending/00_核心基模.<日期>.diff`，
   等「法 AI 或用户」拍板；**平台不自己拍**；
5. 全部动作写 `_meta/reviewer-log.jsonl`（做了几条、删了什么、待审几条）。

### 4.3 红线（我加的四条，防"审忆员变成第二个会说谎的平台"）

1. **默认关**（老板既定：自动兜底默认关），要 `--apply` 才写；
2. **只读根 A**：路径白名单校验，出现 `<workshop_path>` 直接拒（防它把工作区当真源）；
3. **不可真删**：一律先 `_archive/` 再改索引，任何人能回溯；
4. **重大修改必须人/AI 拍板**：`_pending/` 里的 diff 不自动生效；生效时记 `approved_by`。

## 8. 判据草案（施工时先立这些，红就不许往下走）

### 双根（8 格）
D-R1 `manifest.json` 缺 ⇒ 闸门 G0 拦（409，四要素齐）；D-R2 `mind_path` 在工作区内 ⇒ 拦；
D-R3 `mind_path` 不存在或 `00_宪章.md` 缺 ⇒ 拦；D-R4 `manifest_hash` 被改 ⇒ 报警且**不自动改**；
D-R5 `compartment` 根切换后，老工作间的隔间**还能读**（迁移脚本真跑一遍）；
D-R6 `/daily-close` 真写 `02_任务日志/<日期>.md`（读回内容一致）；D-R7 死胡同真落 `06_死胡同`；
D-R8 Boot Prompt 里两个路径**真实存在**（不是占位符）。

### 认知证据（4 格）
C-E1 验收回执 `证据: L3` ⇒ 拒（`R011`）；C-E2 产物数 = 目录 diff ⇒ 自动 `L0`；
C-E3 `review→integrate` 有任务低于 L1 ⇒ 拦；C-E4 `evidence_level` 落库可在任务详情回查。

### 审忆员（5 格）
M-R1 不带 `--apply` ⇒ 一个文件都不改；M-R2 只读根A：给它一个含根B 的路径 ⇒ 拒绝；
M-R3 遗忘前 `_archive/` 有原文（可回溯）；M-R4 核心基模改动**不自动生效**，进 `_pending/`；
M-R5 重跑幂等：同一天跑两次不产生第二份日志。
