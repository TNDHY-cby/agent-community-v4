## §1 一句话

> 把「工厂—车间—工作间—隔间」还原成一个通用单元 **Cell**：
> **纵向嵌套＝分级**、**横向 peers＝拼接**；每个 Cell **带着自己的资产走**；
> 组织内部的**日常自治 / 紧急上报 / 阶段大会 / 独立校准**按 Cell 层级对齐，但**大会不改拓扑**。

## §2 Cell：唯一的结构单元

**硬约束（与 `V116` §1.1 的第①层同一件事：身份与意图）**

| 约束 | 内容 | 违背时 |
|---|---|---|
| **无环** | 父子链不许成环 | 拒（`C001`） |
| **单亲** | 一个 Cell 只能有一个直接上级 | 拒（`C002`） |
| **跨度** | 直接下级默认 ≤ `max_span`(5)，可配 | 警告 + 需显式确认（`C003`） |
| **深度** | 向下默认 ≤ `max_depth`(5) | 警告 + 需显式确认（`C004`） |
| **可验证产物** | 每个 Cell 必须声明"产物怎么验" | 拒（`C005`，防空壳） |

```yaml
cell:
  id: "车间A-工作间1"         # 全局唯一；与工位 `slot_dir` 的关系见 §7
  type: "工作间"               # **纯标签**，系统只认结构，不认"工作间"三个字
  parent: "车间A"              # 纵向唯一上级（根 Cell 为 null）
  children: ["隔间1-1", "隔间1-2"]
  peers: ["工作间2"]           # 横向拼接（联合体成员）
  role: "负责前端组件重构"
  capabilities: ["react", "typescript"]
  policies:
    max_span: 5
    max_depth: 3
    escalate_on: ["跨组冲突", "资源竞争"]
  board_path: "组织/车间A/工作间1/看板.md"     # 只写自己的看板
  heartbeat_path: "组织/车间A/工作间1/心跳/"
  verify:                                   # ★可验证产物（必填）
    how: "产物目录 diff + 清单 sha256"
    where: "产物/"
  asset:                                    # 团队资产（§4）
    style_fingerprint: "fp_7a3c…"
    team_memory_path: "资产/车间A-工作间1/团队记忆.md"
    style_guide_path: "资产/车间A-工作间1/风格指南.md"
    case_library_path: "资产/车间A-工作间1/经典案例/"
    failure_library_path: "资产/车间A-工作间1/失败教训.md"
    cohesion_score: 0.87
  current_task: "电商后台重构"               # 可变；任务结束清空，**asset 不清空**
```

> **唯一真源**：`组织拓扑.md`（一份文件描述整棵树）。
> **一处真相**：Cell 的合法性只看这一份 + 校验器，不许别处再存一份"父子关系"。

## §3 拼接：横向联合体（不是新的行政上级）

```yaml
cell:
  id: "联合体-接口契约"
  type: "联合体"
  children: ["工作间1", "工作间3"]
  peers: []
  role: "统一协调前后端接口契约"
```

| 规则 | 内容 |
|---|---|
| 联合体有**自己的联合看板**，只记跨组冲突与聚合摘要 | 不复制成员内部细节 |
| 成员**内部自治不变** | 联合体不改父子关系、不接管调度 |
| 跨成员协调**只走联合看板** | 不许点对点私聊绕过（否则无法追责） |
| 解散即删联合体节点 | 成员拓扑不受影响 |

## §4 团队资产：拓扑可变，资产随团队走

| 原则 | 落到本项目的具体位置 |
|---|---|
| 资产**积累性**、拓扑位置**任务性** | 资产落**根A（心智根）**：`<AC_MIND_ROOT>/<cell_key>/…`；工作区（根B）可整根丢（`V116` §5 R2） |
| 迁移**搬资产、不搬工作区** | `relocate` = 改根A 的归属 + 归档旧看板；工作区按新位置重建 |
| **不自动稀释** | 子集派遣/联合体借用**只带风格快照（只读）**；写回父团队必须显式"风格合并"并被记账 |
| 风格漂移可检测 | 五维指纹（代码审美/协作节奏/风险偏好/验证严格度/沟通密度）存根A `风格指南.md` 头部 |
| 资产腐化可体检 | 僵化/默契退化/案例陈旧/教训遗忘四类信号 → 建议（**平台只报事实，不评分**） |

**与既有机制的接口**：

- 根A 已有的 `00_宪章 / 00_核心基模 / 01_记忆索引表 / memories/ / 02_任务日志 / 06_死胡同` **就是 asset 的骨架**，
  只需补 `asset/风格指南.md`、`asset/经典案例/`、`asset/失败教训.md` 三个位置（**不新增第二套记忆体系**）；
- `00_核心基模` 的修改仍**只进 `_pending` 等拍板**（`V117` §9）——这就是"不自动稀释"的执行机制；
- 审忆员（`tools/mind_reviewer.py`）已能做归档/压缩/索引重写，**扩面即可**（见 §6）。

## §5 分层协商：四层 + 审忆员

```
第三层：阶段大会（组级 2 周 / 团级 每月 / 全体 季度或里程碑）→ 只校准方向
        ↑ 决议下发
第二层：危急度上报（组长 → 团长 → 用户；按时限自动升级）
        ↑ 日常流转
第一层：日常自治（Worker 自己改，事后知情，写"修正记录"）
常设：审忆员（独立于指挥链；只检查、只报告、只建议暂停）
```

### 5.1 危急度五级（**落到回执里，不另起一套报文**）

| 级 | 代号 | 定义 | 时限 | 处理层级 | 在本项目的载体 |
|---|---|---|---|---|---|
| L1 | `OBSERVE` | 不影响产出，值得记 | 无 | 组级看板观察区 | 看板追加（L0 留痕） |
| L2 | `GROUP` | 影响组内，组内可解 | 24h | 组长裁决 | 回执 `类型: 状态` + 账本 |
| L3 | `CROSS` | 影响多组/资源竞争 | 8h | 团长（=最近共同祖先）仲裁 | 回执 + `manifest_ref` 指向涉事任务 |
| L4 | `URGENT` | 影响稳定/价值观冲突 | 2h | 用户直接介入 | 回执 + `_pending`（等拍板） |
| L5 | `CRISIS` | 不可逆损害/信任破裂 | 立即 | 用户 + 审忆员 | 同上 + 冻结（§5.3） |

升级触发：超管辖权、资源竞争、规则冲突、组内重试 ≥3、价值观取舍不一致。
**超时未处理 ⇒ 自动升一级 + 审忆员记"超时未决"**（这是状态机，不是文案）。

### 5.2 阶段大会（只议事、不改拓扑）

| 大会 | 参与 | 周期 | 表决 |
|---|---|---|---|
| 组级 | 组长 + Worker | 2 周 | 简单多数 |
| 团级 | 团长 + 组长 | 每月 | 简单多数，用户可否决 |
| 全体 | 用户 + 团长 + 组长代表 + 审忆员 | 季度/里程碑 | 2/3 多数，用户可否决 |

- 弃权**不计入分母**；允许"保留意见"入档；
- **载体**：AILP 2.0 的 `PROPOSE / CHALLENGE / REFINE / CONTEXT_ECHO` 承载**发言**（`V117` §7-5 已实施）；
  但**投票、计票、否决、决议归档**协议里没有 ⇒ **平台必须自己做**（见 §8 缺口 G2）。

### 5.3 六原语（拓扑操作）

| 原语 | 作用 | 副作用（必须同时做） |
|---|---|---|
| 创建 | 新建 Cell 挂到父节点 | 校验 5 条硬约束 + 建看板/心跳路径 + 版本化 `组织拓扑.md` |
| 挂接 | 把已有 Cell 移到另一父节点 | 同上（重点查环与深度） |
| 拼接 | 多个 Cell 标 `peers` 生成联合体 | 建联合看板 |
| 分裂 | 一个 Cell 拆两子，原 Cell 升协调层 | 资产按策略拆/复制（**显式**） |
| 合并 | 两个低负载 Cell 合并 | 资产**显式合并**（指纹加权或用户指定；教训去重） |
| 冻结 | 暂停该 Cell 及全部子 Cell | 资产保留不更新；解冻需健康检查 |

**每次操作后固定四件事**：① 校验 ② 生/改看板与心跳路径 ③ 版本化备份 ④ 通知受影响 Cell 热加载。

## §6 审忆员扩面（现状 → 目标）

| 现在（已实现） | 扩面后（本稿设计，**未开发**） |
|---|---|
| 归档原文 → 压缩 → 重写索引 → 核心基模只进 `_pending` | 再加三项检查：**拓扑合法性**（无环/单亲/跨度/深度/产物）、**资产与拓扑一致**（迁移后资产路径是否同步）、**联合体是否越权**（是否写了成员内部看板） |
| 只管根A 一个 agent | 按 Cell 逐级巡检；报告**逐条给证据路径**，不给评分 |

权力边界（写死）：**检查权 / 报告权 / 暂停建议权**；**无指挥权、无惩罚权**；报告不经中间层过滤。

## §7 与现有对象的关系（不许另起一套）

| 现有（`V116`） | 在本稿里的位置 |
|---|---|
| `workshop`（工作间） | 就是**一个 Cell**（`type` 可为"工作间"）；`workshop_path` = 该 Cell 的根B |
| `slot` / `member`（工位/成员） | 是该 Cell 的**叶子成员**，不是 Cell（Cell 才可嵌套；成员不嵌套） |
| `manifest.json` | **每 Cell 一份**（`entry_points` / `active_tasks` / `ignore_zones` / `task_focus`），`组织拓扑.md` 只存结构与资产指针 |
| 回执 `Receipt` | 危急度上报**复用**它（`类型: 状态`），不新增报文类型 |
| AILP 2.0 | 承载大会发言与跨组提案；`manifest_ref` 强校验 = "指得回真实条目" |
| 根A / 根B | 资产在根A，工作区在根B；`relocate` 只动根A 归属 |

## §10 一句话结论

> **Cell 是唯一结构单元**（纵向嵌套＝分级、横向 peers＝拼接）；
> **资产随团队走**（根A 承载、拓扑可变、显式才合并）；
> **治理四层对齐层级但不改拓扑**（危急度复用回执，大会复用 AILP，投票是平台的活）。
> 这三块**全在"身份 + 契约"两层**，与协议等级无关 —— 协议只负责把消息送到。
