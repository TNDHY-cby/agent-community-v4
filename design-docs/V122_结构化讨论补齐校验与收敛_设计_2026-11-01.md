## 0. 一句话结论

**同意"四格不够"**，但要注意一个坑：补"裁决/关闭"时，**平台只能记裁决、不能自己裁**
（`V116` §16：平台不判断、不评分）。否则就从"记账平台"变成"AI 裁判"，那是我方定位的自我否定。

所以本稿的核心口径是：**平台记状态、验迁移、验引用；采哪个方案永远由人/组长决定。**

## 3. 先修这两处（**不需拍板**，这是"文档承诺、代码没做"）

### 3.1 `REFINE.target_id` 没有校验（规则写了，代码没写）

`GET /api/ailp/types` 的 `rules` 第 4 条明确写着「`REFINE` 要指向一条真实 msg_id（`target_id`）」，
但 `ailp.validate()` 里**根本没有这段代码**。

⇒ 现在可以随手 `REFINE` 一个不存在的 `target_id`，平台照收。**规则与实现不一致（规则20）**。

**修法**：`validate` 加一步——`REFINE` 的 `target_id` 必须能在该工作间的消息日志里找到；找不到 ⇒ `A013 TARGET_NOT_FOUND`，并列出最近 5 条可用 msg_id。

### 3.2 正常 `POST …/ailp` 不查重，只有 `/ailp/replay` 查

同一条消息（同 `msg_id`）连发两次，会**入账两次**（只在 replay 端点才判重）。

**修法**：`POST` 时也按 `msg_id` 查重；已存在 ⇒ 返回 `duplicate: true`（幂等，不重复入账）。
判重依据用 `fingerprint`（已有）或 `msg_id`，二者一致才判重。

> 这两条属于"守卫该抓却没人写"的类型，先补上；判据见 §6。

## 4. 建议的实施（分三批，**前两批需要你点头**）

### 批 1 · 补齐"发言协议"（低风险，只加不改）

**① 新增两类消息**（四类 → 六类，老四类不变）

| 新类型 | 干什么 | 必填 | 平台校验什么 |
|---|---|---|---|
| `CLARIFY`（提问/澄清） | 卡在"我没听懂"时的正当出口 | `question`、`to_ref`（针对哪条） | `to_ref` 必须存在 |
| `ACT`（行动项） | 把"接下来谁干什么"变成可追踪的一条 | `task_ref`（**必须指向任务账本里真实任务号**）、`owner`、`due?` | `task_ref` 真实存在（查 `task_ledger`）；`owner` 在该工作间名单里 |

**② 给每条消息加"可验证证据"**（补他第 ③ 条）

- `basis_ids` / `evidence_ids` **每一项**从"任意字符串"升级成：**必须能在该工作间找到**；
- **合法目标只限「账本内实体」三类**（老板拍板的口径，避免为外部证据写通用解析器最后只能校验非空）：
  1. **`msg_id`** —— 查该工作间的 AILP 消息日志；
  2. **`task_id`** —— 查任务账本（`T-001` 这种）；
  3. **`manifest_ref`** —— 查该工作间 `manifest.json` 的 `entry_points` / `active_tasks`；
- **外部证据（URL / 文件 / 实验）不直接当 id 用**：先用 `POST …/evidence/register` 登记
  （`url` + `sha256` + `kind` + `note`），拿到一个 `ev-xxxx` 编号，之后才能被 `basis_ids` 引用。
  没登记就想引用 ⇒ `EVIDENCE_NOT_REGISTERED`（并给登记入口）。
- 找不到 ⇒ `EVIDENCE_NOT_FOUND`，并列出"我能找到的这些"（近 5 条 msg_id / task_id / manifest_ref）；
- 保留旧数据兼容：**老消息不回溯校验**，只对新消息生效。

**③ 置信度留痕**（补第 ④ 条，按老板口径）

- `PROPOSE.confidence` 不变（0~1）；
- `REFINE` **必须**带 `reason`（为什么改）＋ `new_confidence`；
  这条 `REFINE` 存成**新消息**，**原消息的 `confidence` 一个字都不改**（append-only 不能破）；
- 置信度轨道 = 查询按 `target_id` 把 `PROPOSE → REFINE → REFINE …` 串起来；
- 平台**不判断哪个置信度对**，只让"改了几次、每次凭什么、从多少改到多少"可查。

### 批 1 的三个定义（老板要求：先定，否则返工）

1. **证据合法目标** = 上面 ② 的三类账本内实体 + 已登记的 `ev-xxxx`；**不解析外部 URL**。
2. **正常 POST 的查重键** = `sender` + `msg_type` + `target`（或 `target_id`）+ `fingerprint` 四者同 ⇒ 判重。
   命中时**返回已有的 `msg_id`（`duplicate: true`）而不是报错** —— 客户端重试才是安全的；
   只比 fingerprint 会把"相似但合法"的重复发言误杀。
3. **置信度只追加不改**（见上 ③）：`REFINE` 是新消息，原消息不动。

### 批 2 · 补"收敛机制"（**已拍板：组长 + 用户裁决；agent 只能 RECOMMEND**）

**④ 消息状态机（用「投影」，不原地改）**

```
OPEN（刚提出）
  ├─ CHALLENGED（被质疑过，仍有分歧）
  ├─ REVISED（被 REFINE 改过，看最新版本）
  ├─ DECIDED（有人裁定采纳/否掉）→ 记 by / at / rationale
  └─ CLOSED（搁置/作废）→ 必须给 reason
```

- **状态怎么来**：由 `CHALLENGE` / `REFINE` / `DECIDE` / `CLOSE` 事件**计算得出**（投影），
  原消息一个字节不改 ⇒ append-only 存储不用动，审计链干净（老板口径）；
- **谁能推进状态**：`DECIDE` / `CLOSE` 只能由**组长或用户**；**`sender` 必须来自令牌，不接受 body 声明**
  （最小身份绑定，见下 ⚙️）；
- 每条要有：`owner`（谁负责推动）、`version`（REFINE 一次 +1）、`supersedes`（改的是哪条）、`due?`；
- **`DECIDE` 必须指到一条真实 msg_id**，且记 `rationale`（为什么）；
- ⚠️ **平台不做的事**：不判断"这条方案对不对"、不算"哪条票数多"、不生成结论摘要。

**⚙️ 批 2 的前置（老板点破的耦合，必须一起做）**：批 3 才做完整身份绑定，
但"只允许组长或用户裁决"在 `sender` 可信之前是**纸糊的**（body 里写谁是组长谁就是组长）。
⇒ **裁决类消息（`DECIDE`/`CLOSE`）的 `sender` 必须来自令牌**（A 档凭据），不带令牌 ⇒
`403 NEED_VERIFIED_DECIDER`；其它消息的规范化留到批 3。


**⑤ 一条提案的"收敛视图"**（补第 ⑧ 条的一半）
- `GET …/ailp/proposals`：按提案列出——提出者、当前状态、被质疑几次、改了几版、最新置信度、是否已裁决；
- `GET …/ailp/open`：**未收敛的**（`OPEN`/`CHALLENGED`/`REVISED`）——这就是"我们还欠哪个决定"；
- `GET …/ailp/by_me?who=`：某人被质疑的、指派给他的。
- **摘要由查询生成、不是 AI 生成**（正合他的第 8 条）。

### 批 3 · 沙箱区与身份（**已拍板：沙箱做；三条边界机械写死**）

**⑥ 双区（沙箱）**

- `POST …/sandbox`：**自由聊**（不收结构化），写独立文件 `_sandbox/<workshop>.jsonl`；
- **三条边界（机械保证，不靠自觉）**：
  1. **不可作证据**：沙箱消息**不能**直接当 `basis_ids` / `evidence_ids` 的合法目标（§4.1 的三类里没有它）；
  2. **不进正式账本、不参与状态机、不计入统计**：`GET …/ailp` 一条都不返回，`GET …/ailp/proposals` 也不算它；
  3. **提升必须显式**：要把沙箱里的话变成正式条目 ⇒ **新建一条正式消息**（`PROPOSE` 等），
     并在 payload 里标 `source_type="sandbox"` + `source_ref=<沙箱条目 id>`；
     **原沙箱条目只作为来源链接保留，不能原地转正**。
- **查询要能筛**：`GET …/ailp/proposals?source=sandbox` 能列出"引用了非正式来源"的正式条目
  ⇒ 评审别人时一眼看出"这条结论是从草稿捞上来的"。

**⑦ 身份绑定**

- 讨论端点接 **A 档凭据**（`intake_token` 已有）：带令牌的 `sender` **由令牌决定**，不信 body 里写的；
- 不带令牌（人从界面发）⇒ 记 `by=user`；
- 这样"谁说的"不再靠自觉。
  （批 2 已先把**裁决类**消息的这一条做完，这里扩展到全部消息。）

## 5. 明确**不做**的（免得越做越像"AI 裁判"）

| 不做 | 为什么 |
|---|---|
| 平台自动裁决 / 自动选方案 | 违反 `V116` §16；平台一旦选，就不再中立 |
| 平台算"支持率/票数" | 那是判断；要投票就记**每人一条 `PROPOSE`/`CHALLENGE`**，人自己看 |
| 平台生成讨论摘要 | 他的第 8 条说得对：**摘要应由查询生成**（按状态过滤），不是让模型写 |
| 在讨论层再造"任务/产物的账" | 一处真相：任务在 `task_ledger`、产物在 `artifacts`，讨论层只引用 |
| 给老消息回溯校验 | 会一夜之间把历史全判红；只对新消息生效 |

## 7. 拍板结果（2026-11-01 老板已定，**本节即施工依据**）

| 事项 | 拍板 | 落地要点 |
|---|---|---|
| **谁能裁决** | **组长 + 用户**；**不授权 agent 终态裁决** | 理由（老板补的三条比我原话硬）：① **责任稀释**——agent 裁决后追责链变成"平台记了、agent 判了、没人负责"；② **权限自证循环**——agent 身份在批 3 前不可信，等于用不可信身份授予终态权力；③ **账本通胀**——多个 agent 都能 `DECIDE` 会出现同一议题多个终态、互相覆盖，状态机失去意义 |
| **agent 的收敛贡献** | 新增 **`RECOMMEND`**（推荐采纳哪条 + 理由 + 置信度） | **非终态**：不产生 `DECIDED`、不改状态机，只作为人或组长裁决时的参考。放在**批 1**（纯加类型，不涉权限） |
| **沙箱区** | **做，放批 3**，边界**机械写死**（见 §4 批 3 的三条） | 不做的话早期发散只有两个出路：不聊，或把半成品硬塞进正式账本 ⇒ 反而污染账本 |
| **批 1** | **现在动**；但先定三个定义（§4.1） | 否则批 1 会返工 |
| **两个 bug** | **立即修，无讨论空间** | 见 §3 |
| **批 2 前置** | **最小身份绑定提前到批 2**：`DECIDE`/`CLOSE` 的 `sender` **必须来自令牌**，不接受 body 声明 | 否则"只允许组长或用户裁决"建在不可信身份上 = 纸糊（老板点破的耦合，我原稿漏了） |

**另外三条技术口径（老板给的，照做）**：

1. **状态机用「投影」，不原地改**：`OPEN→CHALLENGED→REVISED→DECIDED/CLOSED` 由
   `CHALLENGE`/`REFINE`/`DECIDE`/`CLOSE` 事件**计算得出**，原消息一个字节不改，查询视图负责投影
   ⇒ append-only 存储不用动，审计链干净。
2. **`ACT` 的权威归属**：`ACT` 入讨论账本，**只表示"这条讨论关联/提议了哪个任务"**；
   **任务本体与完成状态一律以任务账本（`task_ledger`）为准**。要新建任务 ⇒ **先调任务账本 API 拿到 `task_id` 再发 `ACT`**，讨论层不许自己编任务号。
3. **置信度只追加、不原地改**：`REFINE` 带 `reason` + `new_confidence` 存成**新消息**，
   原消息的 `confidence` 字段**不动**；轨道由查询按 `target_id` 链起来。原地改会破坏 append-only，留痕就假了。

## 8. 一句话

他说的"**校验 + 收敛 + 裁决 + 查询**决定成败"我同意；我只改一处——
**裁决那一步的"裁"必须由人做，平台只负责让"谁在何时因为什么采纳了哪条"变成不可篡改的一行。**
