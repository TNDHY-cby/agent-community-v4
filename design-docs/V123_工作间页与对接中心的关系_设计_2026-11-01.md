# V123 · 工作间页与对接中心：两套流程并存，用户不知道自己在哪

> **状态：待老板拍板**（2026-11-01）
> **起因**：老板截图指出三条——① 工作间对接中心很乱很复杂，不符合"一眼就懂"；② 工作间里还残留"一级讨论"的线；③ 用户只能选员工，选不到组长。
> 前两条里 **1 条是旧页面（缓存）**、**2 条是真的**，但**真正的病根是第四条：两个界面 = 两套流程**。

- `workshop.html` 的步骤条把用户带到"02 选人"，但**选组长**这件事只在前者之外；
- `workshop.html` 里又有一句文案把用户推去"本间对接中心"选组长（自相矛盾：既然这里也有步骤条，为什么要去别处？）。

⇒ 用户感受就是老板说的：**"很乱很复杂，不知道点哪"**。

## 3. 三个方案（要老板选）

### 方案 A：**分工明确**（推荐）——工作间页只管"干活与验收"，前两步整块摘掉

```
【大厅】发布任务
   ↓
【v5.html 本间对接中心】定方向 → 选组长 → 组长对接单 → 接组长 → 深谈建模
   → 资料库指向 → 名单回执 → 逐个拉人 → 派活
   ↓（点「进入工作间」）
【workshop.html 工作间】看进度 / 组长对话框 / 讨论区 / 隔间与桥 → 验收 → 归档
```

- 工作间页的步骤条从 5 步改成 **3 步：03 干活 → 04 验收 → 05 归档**（只留它在干的事）；
- 顶部给一条**永远可见的路标**：「前两步（定方向 / 选组长 / 拉人）在 **本间对接中心** →」；
- 好处：**一个界面只干一件事**，用户永远知道"我现在缺的是哪一步、去哪补"；
- 代价：改 `workshop.html` 的步骤条与首屏卡片（改动中等，不动后端）。

### 方案 B：**合并成一个界面**——把 v5 十一步搬进工作间页

- 好处：只有一个页面；
- 代价：`workshop.html` 已经 4550 行，再塞十一步会更乱；且改动大、回归面广。

### 方案 C：只统一话术，结构不动

- 好处：最省事；
- 代价：**"乱"解决不了**——两套步骤条还在，用户还是不知道该看哪个。

## 4. 我建议方案 A，理由

1. 现有代码里其实**已经有这个意图**（工作间页的文案就写着"对接与资料走「本间对接中心」"），只是步骤条没跟上，自相矛盾；
2. 老板要"一眼就懂"——**一个页面只承担一个阶段**是最省认知的；
3. 改动集中在 `workshop.html` 的步骤条 + 首屏提示，**不动后端**，风险低。
