# V124 · 工作间右侧列表简化（设计稿，2026-11-01）

> 老板原话：「工作间右侧列表复杂化了，用户看不懂怎么操作」
> 状态：**待拍板**（下面"明显错误"三项我可以立刻改；"要你选"的那一项等你定）

## 一、我实际看到的（真机截图，1440×900，不是推测）

右侧那一栏从上到下是这样的：

```
┌─ 员工名单 ──────────────────── [对接中心] ─┐
│ ② 名单                    [本间对接中心]    │
│ 职业自由填（候选来自平台职业表，加载中…）      │
│ [+ 添加职位 / harness]                      │
│ 可用 Harness（能力）                        │
│   （空）                                    │
└────────────────────────────────────────────┘
系统统计
  工作间数   18
  在线Agent   6
Agent 列表  共 6 · 在线 6   ▾
```

## 二、三个**明显错误**（不是设计选择，是错了）

### 错误 1：两个"对接中心"，名字几乎一样、功能完全不同 ★最要命

| 现在的名字 | 点进去是 | 实际干什么 |
|---|---|---|
| **对接中心** | `/docking.html` | **接入新 agent**：注册、检测、生成模板、架桥 |
| **本间对接中心** | `/v5.html` | **这间的活**：定方向、选组长、派活、看产物、验收 |

用户根本分不清这两个。更糟的是页内还有话术写着
「对接与资料走『本间对接中心』」——**指的却是另一个页面**，口径自相矛盾。

**改法（名字说了就懂）**：
- 对接中心 → **「接入 Agent」**
- 本间对接中心 → **「本工作间」**

### 错误 2：同一个意思，两个标题叠着

「员工名单」和「② 名单」两行标题说的是同一件事。

**改法**：只留一行（`② 名单`），上面那行去掉。

### 错误 3：空的东西占着地方，无关的信息挤着

- 「可用 Harness（能力）」——**空的**，还占一块
- 「系统统计：工作间数 18 / 在线Agent 6」——**全局信息**，跟"这间怎么操作"没关系
- 「Agent 列表 共6·在线6」——同上
- 「职业自由填（候选来自平台职业表，加载中…）」——**技术话术**，而且一直停在"加载中…"

**改法**：空的直接隐藏；系统统计与 Agent 列表移到底部**折叠**；
"职业自由填"改成一句人话（例：`这一栏填岗位名，平台会提示常见的`）。

## 三、**要你选**的一件事（这是设计取向，只有你能定）

右侧要不要**只显示"当前这一步该做的"**？

### 方案 A：固定 4 块，「当前那步」展开、其余折成一行

```
▸ ① 定方向
▾ ② 选组长        ← 当前，展开
     [候选人列表 + 为什么不能当]
▸ ③ 名单
▸ ④ 派活
```

- **好处**：结构稳定；随时能回头改上一步
- **代价**：折叠标题还占 4 行；屏幕上信息量仍然不小

### 方案 B：右侧**只显示当前这一步**

```
02 选组长
从下面挑一个能当组长的（灰的是不能当，原因已写）

[候选人 1]  能写文件 ✓  有协议通道 ✓   [选它]
[候选人 2]  缺写文件 ✗  —— 去接入 Agent 补
```

- **好处**：屏幕最干净，一眼一个动作 —— 最接近"一眼就会"
- **代价**：想改上一步要回步骤条点（步骤条本来就能点）

**我建议 B**。因为你的原则是"一眼就会"，A 只是把混乱藏了一半，点开还是乱。

## 四、两个方案都要加的一样东西

右侧顶部一行**大字**，随状态变的那句话：

> **现在该做：选一个组长** →（点它直接做）

用户不用自己判断"我在哪、下一步干什么"，界面直接说。

## 五、不做什么（避免又搞复杂）

- **不新增按钮**：只减不增；
- **不动中间那块**（工作内容/讨论区）；
- **不动左侧工作间列表**（这轮只管右侧）。
