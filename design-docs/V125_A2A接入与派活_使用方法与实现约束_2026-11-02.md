# V125 · A2A 接入与派活：使用方法与实现约束

> 状态：**已实施**（2026-11-02）
> 适用：把一个 **A2A agent**（对等任务语义）接进本平台，并让它能派活、能回执、能对话。
> 本文是**唯一口径**：界面话术、`protocol_tree` 卡片、错误提示都从这里取；改一处要全改（规则 20）。
> ⚠️ 全文**不含任何真实机器坐标**（端口 / 路径 / 真实 agent 名）—— 那些是使用者自己的事。

---

## 1. 它是什么 / 不是什么

| | 是什么 | 不是什么 |
|---|---|---|
| **A2A** | **对等任务语义**：Agent Card 发现 → `tasks/send` 派活 → `tasks/get` 回查 → 产物回传 | **不是**"工具面"（那是 MCP）；**不是**"平台拉起子进程"（那是 ACP） |
| 平台的定位 | 按地址发任务、按任务号回查、把结果记进账本；**不代它干活** | 不点它的窗口、不替它写库、不把它的自报当验收 |

**一句话**：A2A 是"平台**直接调用**它对等任务接口"，所以它**没有桥、没有拉起命令、不需要人工粘贴**。

## 2. 接进来（三步，全部由平台做）

### 2.1 注册

```http
POST /api/harness/register
{
  "harness_id":   "示例-A2A-01",
  "harness_name": "示例 A2A Agent",
  "wakeup_method": "a2a",
  "transports":    ["a2a"],            // 可省；省略也能认（注册只填 wakeup_method 是合法的）
  "api_base_url":  "<它的 A2A 端点基址>", // ★必填，没有就当场 400
  "ai": {"model_name": "..."}
}
```

**为什么 `api_base_url` 必填**：A2A 是"平台主动连它"。没有地址 = **无处派活**，
注册成功也是白的 ⇒ 平台**当场拒**，而不是先返回 200 + S 档、等到自检才说缺地址。

**地址填什么**：它的 **A2A 端点基址**（能拼出 Agent Card 与 JSON-RPC 的那个前缀）。
不同实现的形态不同，实测遇到过三种：

| 形态 | 例子（虚拟名） | 说明 |
|---|---|---|
| 标准 | `http://host:port` | 卡在 `/.well-known/agent-card.json` |
| 旧版 | `http://host:port` | 卡在 `/.well-known/agent.json`（v0.2） |
| **挂在端点基址上** | `http://host:port/a2a/<实例id>` | 卡在 `<基址>/agent-card.json`（**不套 `.well-known`**） |

平台**三条路径都会试**，使用者不用自己选。

### 2.2 检测

```http
POST /api/docking/harness/{harness_id}/test-now
```

做两件事，**都要做**：

1. **读 Agent Card** —— 读到 = 它确实是 A2A 且活着；
2. **真发一条探针任务** —— 这条会在**对端自己的会话**里出现，所以使用者能在客户端里
   "看见平台来过"。探针**不传 `contextId`** ⇒ 对端新开一个上下文，**不污染正式会话**；
   发出后尽量 `CancelTask` 撤回。

> ⚠️ 别只读卡就宣告"通了"：卡能读 ≠ 端点受理任务。

### 2.3 生成并保存「具体模板」

```http
POST /api/harness/{harness_id}/template      # 生成 / 重建（幂等）
GET  /api/harness/{harness_id}/template      # 读回
```

模板（L2）存的是**与工作间无关**的东西：

```
template="a2a"   artifact_kind="contract"
params: API_BASE_URL / CARD_NAME / CARD_SKILLS / MODEL_NAME / PLATFORM_URL
        DISPATCH_PROTOCOL="a2a-jsonrpc:tasks/send"
        QUERY_PROTOCOL="a2a-jsonrpc:tasks/get"
        SESSION_FIELD="message.contextId"
        REPORT_PATH="/api/harness/task-result"
required: HARNESS_ID / API_BASE_URL / MODEL_NAME   → 缺地址时 missing=["API_BASE_URL"]
```

**它不包含**工作间目录、工位、任务文件、会话号 —— 那些是**建间期才有的**。

## 3. 拉进工作间（模板 + 实时路径）

### 3.1 原则

> **同一个 harness 可以进多个工作间、多个工位**，每个组合的路径与会话都不一样。
> 所以**不能复用注册时那套固定值**，必须"模板 + 这次的工作间坐标"现算。

实现：`bridge_template.render_for_workshop(info, workshop_id=…, workshop_dir=…, slot_dir=…,
member_seq=…, task_seq=…, task_rel=…, context_id=…)` → L3 落地参数（端点 / 协议 / 会话 / 回报 body）。

### 3.2 对接单：按「它怎么被派活」分流

| 它的接入形态 | 对接单里给什么 |
|---|---|
| **A2A / MCP / http_api**（契约型） | **派活契约**：端点、协议、会话字段、回报地址 + 本次 `workshop_id`/`member_id` |
| ACP / file_poll（桥型） | 桥参数（模板 + `HARNESS_ID`/`WORK_DIR`/`PLATFORM_URL`） |
| clipboard（人工） | 激活提示词 |

**A2A 的对接单不长这样**：~~`WORK_DIR`~~、~~`POST /api/bridge/generate`~~ —— 它没有桥。
给了桥参数是**误导**（2026-11-01 真机踩过：一个能用的 A2A 被报"桥没配好"）。

### 3.3 「平台自己接它进来」（A 档平台自验）

```http
POST /api/workshop/{ws_id}/members/{member_seq}/protocol-probe
body: {"wait": 20}        # 等它做完的秒数（3–60）
```

平台**自己发**一条探针、**自己按 `tasks/get` 轮询到终态**；只有 `completed` 才算"它真做完了"，
然后**由端点内部**记 `protocol_ok`，来源写 **`platform-observed`** 并盖时间戳。

> ⚠️ **铁律**：`platform-observed` 只能平台自己记。前端传 `who=platform` 不算数 ——
> 否则"打勾"换个马甲就能冒充"平台自己验的"，账就是假的（2026-10-25 教训）。

**只有 A2A 支持这一步**（它能自己发、自己看回执）。别的接入如实返回 `PROBE_NOT_SUPPORTED` + 指路。

## 4. 派活（平台 → 它）

```http
POST /api/workshop/{ws_id}/dispatch   # 或按你们的派活入口
```

平台做的是 **JSON-RPC `tasks/send`**（不是普通 HTTP POST）：

```json
{"jsonrpc":"2.0","id":"…","method":"tasks/send",
 "params":{"message":{"role":"user","parts":[{"text":"<任务正文 + 回报契约>"}],
                      "contextId":"<本工位当前会话>"}}}
```

**兼容处理（三个真机踩出来的）**：

1. **方法名按错误码回退**：先发 v0.2 `tasks/send`；**只在**明确"方法不认识"
   （`-32601` / `-32600` / `-32004`）时改发 v1.0 `SendMessage`，并翻参数（`taskId→id`）；
2. **端点容忍尾斜杠**：先试基址，404 再试基址 + `/`；两个都 404 时把**试过哪些地址**写进异常；
3. **回报契约随任务下发**：正文里给"干完往哪 POST 回执"（含本次 `workshop_id` / `member_id`）。

## 5. 拿结果（两条腿，谁先到算谁）

| 腿 | 机制 | 何时用 |
|---|---|---|
| **平台回查**（主） | `a2a_result_poll` 按 `tasks/get` 轮询，**终态**就写进任务账本 | 平台派出去的活 |
| **它主动回执**（辅） | 它 `POST <平台>/api/harness/task-result` | 它愿意配合时 |

**账本只推进到 `delivered`**（回执留痕）；`accepted` / `rejected` **只能由人给** ——
不把对方自报当验收。

**解析必须按真机形状**（`platform/a2a_result_poll.parse_task`，一处真相）：

- `status` 是**对象**：`{"state":"TASK_STATE_WORKING","timestamp":…}` —— 不能直接 `str()`；
- 枚举带 `TASK_STATE_` 前缀 ⇒ 归一化；
- 文本优先级 **artifacts（产物）→ status.message（附言）→ 顶层字段**；
- artifact 内 `parts` 是**逐词片段** ⇒ 必须 `""` 直拼（用 `\n` 会碎句）；
- **只认终态**（`completed/failed/canceled/rejected/error`）—— 对端报 `working` 又挂占位产物时，
  不能提前写回（会假完成）。

## 6. 跟它说话（送话 + 取回复）

```http
POST /api/docking/harness/{harness_id}/deliver        body: {"text":"…"}
     → {ok, channel:"a2a", task_id, note}
GET  /api/docking/harness/{harness_id}/a2a-task/{task_id}
     → {ok, state, terminal, text, artifacts, context_id}
```

**A2A 的送话 = 按协议发一条消息**（给了 `task_id` 走 `message/send` 挂到既有任务，否则 `tasks/send`
新任务）—— **不是点窗口、不是 session_post**。

**必须配套"取回复"**：A2A 的回复**只回到平台**（它没有"往自己会话里说话"这类工具）。
平台不去问就永远拿不到 ⇒ 界面就是"发出去了、没下文"（2026-11-01 真机踩过）。
取回复靠轮询 `a2a-task`，**终态才算最终回复**。

## 7. 会话（`contextId`）

### 7.1 语义

`contextId` 是 A2A 的**会话/上下文标识**：

| 做法 | 对端行为（实测） |
|---|---|
| 不传 | 对端**自己生成**一个 ⇒ 每次新上下文 |
| 传同一个 | 回显同一个 ⇒ 协议上算"同一上下文" |
| 传新的 | 新上下文 |

⚠️ **边界**：它控的是"A2A 上下文标识"；**是否映射到客户端同一个会话窗口**取决于对端实现
（实测：同一 `contextId` 的两条任务，各自 `history` 仍互不交叉）。界面上**不要宣称**"一定同一个窗口"。

### 7.2 我们的策略：一员工一当前会话，老化换新

```
(harness, 工作间, 工位)  →  一个 active 会话(context_id + seq)
                           老化 ⇒ seq+1，旧的进 retired[] 留痕（只追加不删）
```

- **老化判据是平台自己数**（默认 20 条活 / 6 万字，可配）—— **不是**读对端的"压缩次数"
  （那是对方客户端内部的事，A2A 不暴露）；
- 对端也可在回复里带 `[NEED_NEW_CONTEXT]` **主动要求换新**（只是触发信号，不进验收）；
- `context_id` 必须**纯 ASCII**，且带 `harness-工作间-工位-序号-时间后缀` ⇒ **保证唯一**
  （同一实例里两个不同的东西用了同一个 `contextId`，会挤进同一个会话）。

### 7.3 隔离性（核实过，不是假设）

查了实现与文件：`@hanphone/dsh-a2a` 的 `ContextSessionPool` 是 **per-context** 的
（每 `contextId` 一个 live agent、一个独立会话 id、一个会话文件），会话绑定还带实例命名空间
（`<serverId>:<contextId>`）⇒ **不同 contextId 之间是隔离的**。

但它**不保证**"命名撞了也不串"：`sessionIdFor` 只拼 `<ns>-<contextId>` ——
**所以唯一性由我们这边负责**。

## 8. 失败要说话（这一节的每一条都是真机踩出来的）

| 现象 | 平台怎么说 | 不许做什么 |
|---|---|---|
| 注册没给地址 | 当场 400 + "没有这个地址，注册成功也是白的" | 不许先绿再在自检时说缺地址 |
| 端点连不上 | 报真实原因 + **"客户端刚重启过，端口可能变了，去确认地址"** | 不许把它当成"它离线了" |
| 发出去了但没做完 | 报最后状态 + "可能它在忙 / 不接这个任务；再验一次或走人工" | 不许记成成功 |
| 做完了但没回话 | "它做完了但没有文字回复" | 不许编一段回复 |
| 等满超时没终态 | "没等到最终回复（最后状态：working）；去对端会话看" | 不许静默 |
| 非 A2A 走平台自验 | `PROBE_NOT_SUPPORTED` + 指路 | 不许假装验过 |

---

## 9. 通用性约束（**这条是老板点名的**）

1. **不写死任何机器坐标**：端口、路径、真实 agent 名一律不进代码与对外文档；
   地址只从 `api_base_url` 来，平台地址只经 `platform_address.base_url()` 解析；
2. **不预设"只有某个客户端才有"的行为**：三条卡片路径、尾斜杠、方法名回退，
   都是"多试一次"而不是"按某个实现写死"；
3. **换一个目录 + 换一个端口 + 换一个 agent 名，不改一行代码就能走通** —— 这是验收判据；
4. **一处真相**：解析逻辑（`parse_task`）、找组长、会话命名，都只该有一个入口
   （同一个错写两遍，已经吃过两次亏）。

## 10. 验收清单（照着打勾就能确认"这个 A2A 真接上了"）

```bash
# 1) 注册（缺地址必须 400）
curl -sX POST $BASE/api/harness/register -H 'Content-Type: application/json' \
  -d '{"harness_id":"示例-A2A-01","harness_name":"示例","wakeup_method":"a2a","ai":{"model_name":"x"}}'
#   → 期望 400，且 error 里说清"必须给 api_base_url"

# 2) 带地址再注册 → 200；模板完整
curl -s $BASE/api/harness/示例-A2A-01/template | jq '.template.complete, .template.missing'
#   → 期望 true, []

# 3) 检测（读卡 + 真发探针）
curl -sX POST $BASE/api/docking/harness/示例-A2A-01/test-now
#   → 期望 ok=true；detail 里同时有"读到 Agent Card"和"探针任务 <号>"

# 4) 派活 → 账本
#   派完之后查任务账本：state 应到 delivered，external.result 是它的原话

# 5) 送话 → 取回复
curl -sX POST $BASE/api/docking/harness/示例-A2A-01/deliver \
  -H 'Content-Type: application/json' -d '{"text":"你好"}'
#   → 拿 task_id；再 GET …/a2a-task/<task_id> 轮询，terminal=true 时 text 是它的回复
```

**四条都过，才算"这个 A2A 是通的"** —— 只过 1、2 条只能说明"它活着"，不能说明"能派活"。
