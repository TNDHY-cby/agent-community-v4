# V126 · 一键清空「接入」（大厅 · 对接中心）

> 状态：**待拍板 → 实施中**（2026-11-02 老板原话：「做一个功能让用户可以一键清理掉接入的agent，包括注册的模板，放在大厅对接中心里」）
> 位置：**大厅 → 接入 Agent（`docking.html`）**，不是工作间的员工对接。

---

## 1. 为什么要它

现在要清掉接入，只能：

- 一个个删（`DELETE /api/harness/{id}`），五个就要点五次，还得自己记住删了哪些；
- 或者 `tools/reset_platform_data.py` 把**工作间也一起清掉**（那不是用户想要的）。

用户真实场景：「**这批接入都作废了，我要从空白重新接**」——
agent 注册和模板要清，**工作间和账不能动**（那里有它的历史）。

---

## 2. 清什么 / 不清什么（**唯一口径**）

### 清（= 一个 harness 的全部痕迹）

| 项 | 位置 | 说明 |
|---|---|---|
| **agent 注册 + 注册的模板** | `harnesses.json` 的每一条（`metadata.bridge_template` 就在里面） | **主目标**；删了它就等于"这个接入不存在了" |
| 工具面探测记录 | `harness_tooling.json` | `fs_write` 等实测结果 |
| 拉起日志 | `harness_launch_log.json` | |
| 会话引用 | `sessions.json` / `session_notes.json` | |
| 签发的令牌 | `keys/` | 吊销即失效 |
| **内存态** | `agents` / `pending_activations` / `pending_tasks` / `pending_bridge_tests` | 光删文件内存里还在 = 假清 |

### 不清（明确保留，界面上要说）

| 项 | 为什么留 |
|---|---|
| **工作间**（`workshops.json` / `workshops/` 工作区 / 产物） | 那是用户的活和历史，不是"接入" |
| **v5 名单**（`v5_roster.json`） | 名单是名单，接入是接入 |
| 任务账本（`task_ledger.json`）、任务、回执 | 历史证据，删了就说不清"谁干过什么" |
| 日志、备份、`policy.json`、`plugins.json`、`local_ai.json` | |

### ⚠️ 清完会发生的副作用（必须告诉用户，不许静默）

工作间里**引用过**这些 agent 的成员会变成 **孤儿成员**（harness 不在了）。
平台**不自动删成员**（那是另一件事，得人决定）。

⇒ 清完的响应里带上：**"这 N 个工作间有 M 个成员引用了已删的 agent"** + 指路
（工作间 → 名单 → 移除，或重新接入同名 agent 顶回来）。

## 3. 安全设计（这一节是重点）

老板刚经历过一次误删（我自己也是事故方），所以**不许只做一个红按钮**：

1. **默认先预览**（dry-run）：列出「会删 N 个 agent（名字逐条）」＋「受影响的 M 个工作间」；
2. **真清要打确认词**：前端要用户输入 `清空接入` 四个字，body 里带 `confirm:"清空接入"`
   —— 端点**自己校验**，不只靠界面（界面能绕过）；
3. **删前自动备份**：`<data>/backups/pre-reset-agents-<时间戳>/`，备份失败就**中止，一个字节都不删**；
4. **回滚办法**写进响应：把备份目录拷回 `data/` 即可；
5. **失败要说话**：任何一项删不掉都如实报（不许"部分成功还说成功"）；
6. **不需要停服务**（这跟 `reset_platform_data` 不同）：端点自己清内存 + 存盘，
   清完立即生效。但**正在跑的任务**会失去归属 → 响应里如实提示。

## 4. 接口

```http
GET  /api/docking/agents-reset/preview
→ {ok, agents:[{harness_id, harness_name, template, workrooms:[...]}],
   count, affected_workrooms:[{workshop_id, name, orphan_members:[...]}], will_delete:[...]}
   # 只读，不改任何东西

POST /api/docking/agents-reset
body: {"confirm": "清空接入"}
→ {ok, deleted:[harness_id...], backup:"backups/pre-reset-agents-<时间戳>",
   affected_workrooms:[...], note, next, rollback}
# confirm 不对 → 400，什么都不删
```

## 6. 判据（真机）

1. **预览是真的**：预览列的 agent 数 == 实际注册数；受影响工作间 == 真引用过它们的；
2. **确认词拦得住**：`confirm` 不对 ⇒ 400，且**一个 agent 都没少**；
3. **真清干净**：清完 `harnesses.json` 里 0 条、`/api/harness/list` 0 条、
   内存态 0（连发一次派活应报"没有这个 agent"）；
4. **备份可回滚**：把备份拷回后 agent 全回来（含模板）；
5. **不误伤**：清完工作间数量、账本条数、产物文件**前后一致**。

**判据一律在临时数据目录里跑**（`AC_DATA_DIR` 指向临时目录），**不动真实数据**。
