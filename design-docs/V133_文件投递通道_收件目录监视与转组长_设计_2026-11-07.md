# V133 · 文件投递通道：成员把文件放进一个文件夹，平台自动发现并转给组长

> 状态：**已落地（2026-11-07）** —— 收件目录沿用 `<工位>/产物/`（唯一被验收/采信认的落点），
> 另允许档案 `artifact_inbox_dir` 指外部导出目录；落地物与判据见 §7。
> 性质：设计稿 + 落地记录。**先讲清"用哪个文件夹"，再写码**。

---

## 〇、先回答"看看之前"：现在到底有哪些目录约定（实测，别再造第五个）

| 现成的 | 是什么 | 方向 | 谁在用 |
|---|---|---|---|
| `<工作间>/<工位>/产物/` | **成员产物目录**（`artifacts.snapshot()` 扫它，算 sha256、出 `_meta/artifacts.json`，验收/采信只看这份盘上清单） | **入站**（成员写，平台读） | `artifacts.py` / P4 验收 / V130 采信 |
| `<工作间>/library/` | 心智根（`model.md`、记忆、日志） | 双向 | 组长执笔（V29） |
| `<工作间>/<工位>/_notice.md` | 变更通知（只追加，最新在上） | 平台 → 成员 | `dispatch.append_notice` |
| 桥的 `INBOX_DIR`（`wakeup_dir`） | **平台 → 成员**的任务邮箱（桥搬件） | **出站** | `bridge_*` |
| `ws.resources`（`/api/workshop/{id}/resources`） | 资源库**登记**（名字/路径/备注），不扫盘、不监视 | 人工登记 | `workshops_task.py` |
| 隔间继承 `inherit` | 跨隔间**显式**搬产物（人点一下） | 人工触发 | `inherit.py` |

**结论（这就是"特定文件夹"的答案）**：**入站投递目录沿用 `<工位>/产物/`**——它是唯一已经被
"产物清单 / 验收 / 采信"认的落点，再造一个就变成第五套口径。
唯一的补充：桌面型 agent 常常只能"另存为"到它自己的导出目录 ⇒ 允许在档案里配一个**外部收件目录**
（`artifact_inbox_dir`），平台按同一套规则扫它；不配就扫 `产物/`。

**明确不做**：不把资源库当投放口（它是登记表，不是目录）；不动桥的 `INBOX_DIR` 语义（那是出站）。

## 一、要做的事（一条链）

```
成员（视觉脚本那类）把文件另存/导出到收件目录
        ↓ 平台小型监视器（后台线程，默认 20s 一轮；也可手动 POST 扫一次）
扫盘：文件名 + 字节数 + sha256
        ↓ 与"已上报表"对比（AC_DATA_DIR/artifact_inbox.json）
新增 / 内容变了 → 生成一条**投递事件**
        ↓ 上报平台
① 事件流（`AC_DATA_DIR/inbox_events.jsonl`，上限 500，追加写）
② 组长的 `_lead/_notice.md` 追加一行（时间 / 工位 / 文件 / 大小 / sha 前 8 位）
        ↓ 转给组长
③ 界面：`GET …/inbox-events`（只读）；④（可选，默认关）视觉投递提醒组长
```

**为什么"扫盘 + sha256"而不是让成员调接口**：视觉脚本成员没有回执协议（上一轮 `V132` 已确认
"能投话、读不到回复"）。文件是它唯一可靠说得出的话——**盘上有就是有，没有就是没有**，
这正是本项目 `L0` 口径。

## 二、口径（一条一条钉死）

| # | 口径 | 说明 |
|---|---|---|
| 1 | **只认盘上真文件** | 事件里必须有 `sha256` + `bytes`；读不到就记 `error`（不是"没有文件"） |
| 2 | **去重按内容** | 键 `(目录, 相对路径)`，值是 `sha256`：同 sha 不重复上报；sha 变了算一次"更新"（`changed`） |
| 3 | **只扫两层** | 与 `artifacts.snapshot()` 一致：目录本身 + 一层子目录；不跟符号链接、跳过 `.` 开头的 |
| 4 | **目录不存在就说清** | 「目录不存在 —— 平台**不替你建**（它会替你建就等于替成员决定落点）」+ 怎么改 |
| 5 | **不报重复不报空** | 首次见到一个已有目录里的一堆老文件，**不整批上报**（记基线，见 §4） |
| 6 | **一次扫描要有上限** | 单轮最多 200 个新事件（超出标 `truncated` 并说清"还有 N 个没报"） |
| 7 | **转组长不等于打扰** | 默认只写 `_lead/_notice.md`（不会抢焦点）；视觉提醒是**开关**，默认关 |
| 8 | **监视器挂了要说话** | 状态端点显示 `running/enabled/interval/last_run/last_error`；线程异常每进程喊一次 |
| 9 | **落点跟 `AC_DATA_DIR` 走** | 已上报表与事件流都在数据目录，换目录就跟着走，不进仓库 |
| 10 | **不写成员的文件** | 扫描只 `stat` + 读字节算 hash，绝不改/删/移动（"搬进资料库"是另一个动作，不做） |

**基线（第 5 条的落地）**：第一次扫某个目录时，把盘上现有文件**全部记进"已上报表"但不发事件**，
并回一句「首次见到该目录，已记基线 N 个文件（不当作新增）」。这样不会一开监视器就刷一屏历史文件。

## 三、配置与入口

| 项 | 是什么 | 默认 |
|---|---|---|
| 成员的 `artifact_inbox_dir` | 可选：外部收件目录（不配就用 `<工位>/产物/`） | 空 |
| `AC_ARTIFACT_WATCH_SEC` | 后台扫描间隔（秒）；`0` = 关（只能手动扫） | `20` |
| `POST /api/workshop/{id}/scan-inbox` | **手动扫一次**（立即返回本轮 `new/changed/baseline/errors`） | — |
| `GET /api/workshop/{id}/inbox-events?limit=` | 只读事件流（倒序） | 50 |
| `GET /api/workshop/{id}/inbox-status` | 监视器状态（是否在跑、上次扫的是谁、上次错误） | — |

## 四、失败与降级（全都要说人话）

| 情况 | 用户看到 | 平台做什么 |
|---|---|---|
| 收件目录不存在 | 「收件目录不存在：`…`；平台不会替你建」+ 给"改档案"的办法 | 记 `errors`，不生成事件 |
| 目录不可读（权限） | 「读不进去：`WinError 5`」 | 同上，每进程喊一次 |
| 文件太大（>64MB） | 事件里 `sha256=null` + `too_big: true` + 字节数 | 仍上报（**名字与大小是真的**），不假装算过 hash |
| 单轮超 200 个 | 事件表标 `truncated` + 「还有 N 个下轮再报」 | 剩下的留到下一轮（不丢） |
| 监视线程异常 | 状态端点 `last_error` + 日志一行 | 不静默：每进程喊一次，线程继续下一轮 |
| 工作间已归档/关闭 | 不扫（省事），状态里说明 | 只扫 `active/lead_in` 之类在用状态 |

## 五、判据（`tools/artifact_inbox_check.py`，12 格，真跑）

| # | 格 | 断言 |
|---|---|---|
| ① | 建工作间 + 工位，往 `产物/` 放 1 个文件 | 手动扫 ⇒ `new` 里有它，带真 `sha256`/`bytes` |
| ② | 再扫一次 | `new` 为空（**去重**） |
| ③ | 改文件内容 | 报 `changed`（sha 变） |
| ④ | 首次见到已有文件的目录 | 回 `baseline=N`，且 `new` 不含那些老文件 |
| ⑤ | 组长的 `_lead/_notice.md` | 真有一行（时间/工位/文件名/大小） |
| ⑥ | 事件流端点 | 倒序、带 `source=platform_observed` / `judge=verified` |
| ⑦ | 目录不存在 | `errors` 里有人话 + 不生成事件 |
| ⑧ | 配置外部收件目录 | 用它而不是 `产物/`（两者都在时以配置为准） |
| ⑨ | 只读 | 扫描前后产物文件 sha256 不变、mtime 不变 |
| ⑩ | 不跟符号链接 / 跳过 `.` 开头 | 真造一个软链与一个 `.hidden`，都不上报 |
| ⑪ | 上限 | 一次放 210 个文件 ⇒ `truncated=true` 且说清"还有 N 个" |
| ⑫ | 监视器开关 | `AC_ARTIFACT_WATCH_SEC=0` ⇒ 状态显示 `enabled=false`（不偷偷跑） |

## 六、不改什么

- 不动 `artifacts.snapshot/scan` 的语义（产物清单仍由验收动作触发；本方案只**多一条"发现"入口**）；
- 不动桥的 `INBOX_DIR`（出站）；
- 不动资源库（登记表，不改成收件箱）；
- 不动"隔间继承"（显式搬运）；
- 不搬/删成员文件（只读扫描）。

### 踩到的两个真坑（写下来，防重犯）

1. **循环导入**：`routers/artifact_inbox.py` 在模块级 `from .. import server` ⇒ `server` 导入本模块时炸
   （`ImportError: cannot import name 'router' ... partially initialized`），**服务直接起不来**。
   修法：`server` 只在函数体内惰性导入（与本项目其它 router 的既有做法一致）。
2. **判据工具里 URL 带中文**（`harness_id` 是"示例Harness-A"）⇒ `urllib` 不做 URL 编码，
   抛 `UnicodeEncodeError`。修法：工具里统一 `urllib.parse.quote(path, safe="/?=&:,...")`。
   浏览器/前端会自动编码，所以这不是接口问题。
