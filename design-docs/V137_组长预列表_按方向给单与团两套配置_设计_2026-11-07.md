# V137 · 组长**预**列表：按方向给「单 / 团」两套配置

> 状态：**按最优解实现**（老板 2026-11-07：「为了做出组长预列表，各个组长（单/团）适合不同方向/任务」）
> 前置：`V134`（能力面）、`V135`（适配度/团队）、`V136`（算法两条路 + 组长列表）。

---

## 〇、预列表与组长列表的区别

| | 什么时候看 | 依据 |
|---|---|---|
| **组长列表**（`/api/lead-roster`，`V136 §8`） | 已经有一个工作间、要选人 | 全部候选的能力面 |
| **组长预列表**（本节，`/api/lead-preliminary`） | **还没建工作间**，先看"这个方向该用谁" | 候选的**方向** × 算法（单/团） |

所以预列表的键是**方向**（外加可选的任务关键词），值是**该方向下的两套配置**（单 / 团）。

---

## 一、方向从哪来（不编）

- **唯一来源**：接入档案里**自己报**的方向树 `fit_directions`（`HarnessInfo.fit_directions`，
  `lead_roster._directions_of()` 已经在读它；旧字段 `directions` 也认）。
- **没报方向的不归任何方向组** ⇒ 单独进 `no_direction`，并写清
  「它没报 `fit_directions`，平台不替它编方向」。
- `?task=<关键词>`：在该方向树里做**包含匹配**（`前端页面开发` 命中 `前端`）；
  命中不了就**如实说没匹配到**，并列出实际存在的方向（不猜、不退化到"随便给一个"）。

---

## 二、每个方向给两套配置（单 / 团）

对每个方向 D：

1. 候选集 = 方向 D 的接入（能力面由 `V134` 算）；
2. 跑 `V136` 的算法 `plan(candidates)`；
3. 输出：
   - `solo`：该方向**单**的能力（`feasible` + `lead` + `covers`），不可行也如实标 `feasible=false` + `reason`；
   - `team`：**团**（主组长 + 助手 + 每个助手 `adds`），不可行标 `feasible=false` + `missing`；
   - `blocked`：两套都不可行时的缺口与三条出路；
   - `candidates[]`：该方向候选的 `protocol_fit/covers/solo_feasible/needs_helpers`（与组长列表同一套字段）。

**助手不限定方向**：补的是"能力缺口"（能读/能收回执/能唤醒），跨方向借人是对的——
但预列表里会标 `from_direction`（这个助手属于哪个方向），让人知道"借了谁"。

---

## 三、顶层还有一个「按模式看」的总览

```
by_mode.solo[]  = [{direction, harness_id, protocol_count}]   # 哪些方向能一个组长包下来
by_mode.team[]  = [{direction, lead, helpers:[...], missing}] # 哪些方向必须搭
by_mode.blocked[] = [{direction, missing, next}]              # 哪些方向现在没人能接
```

界面可以按"单 / 团 / 还不行"三段渲染，也可以按方向渲染（每方向两行：单、团）。

---

## 四、纪律（一条都不破）

- **不打分、不排名**：方向内按 `harness_id` 字典序；`sort_note` 明写"不是推荐度"；
- **不编方向**：没报方向的接入不进任何方向组；
- **不假装可行**：`feasible=false` 一定有 `reason`/`missing`；`blocked` 一定给三条出路；
- **只读**：纯函数 + 只读端点，不落库。

### 落地时踩的一个小坑（记下）

判据工具里 `?task=` 用了 `urllib.parse.quote(...)`，而 `_http()` 内部**已经**对 path 做过 quote
⇒ **双重编码**，服务端收到的是字面 `%E5%89%8D...` ⇒ 关键词永远匹配不上（⑨ 红）。
修法：**工具层只 quote 一次**（`_http` 里统一做，调用方直接传中文）。

## 八、优化版（2026-11-07 午间，老板：「优化组长预列表设计」）

原版能用但**要读字段才懂**。这一版加了三件"让人一眼看懂"的东西，口径一条没松：

| 加的东西 | 解决什么问题 |
|---|---|
| **`headline`（一行结论）** | 每个方向第一句就是人话：「**一个人就够** —— 示例Harness-A（2 种协议，四件事全包）」/「**得搭团** —— A 当组长，借 测试 的 B（补 能看产物）」/「**现在没人能接** —— 缺 能看产物」 |
| **`solo.alternatives`（梯队）** | 同一方向如果还有别的能一个人干的人，列在后面（协议数降序、名字）—— **不是推荐，是"还有谁"** |
| **`task_card`（任务卡）** | `?task=` 命中给「关键词 → 方向 → 一行结论」；**没命中给换词建议 + 现有方向清单**，并明说"方向只认接入自己报的" |
| **`guidance`（三条引导）** | 空池怎么补方向 / 全 blocked 怎么修 / 部分可行时怎么按方向各配各的 |

**为什么不是"加评分"**：老板要的是**看得懂**，不是"给个分数替我决定"。
所以优化只动**表达**（一句话、梯队、任务卡、引导），不动"不排分、不推荐"的纪律 ——
`sort_note` 仍然明写"技术性稳定，不是推荐度"。

**判据**：`tools/lead_prelist_check.py` **15 格**（新增 ⑬ 一行结论 / ⑭ 梯队 / ⑮ 任务卡命中与未命中）；
`tests/test_lead_prelist.py` **16 条**（新增 4 条覆盖 headline/alternatives/task_card/guidance）。
