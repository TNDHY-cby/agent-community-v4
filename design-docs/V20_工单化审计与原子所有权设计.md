## 三、设计 A：审计埋点（工单化审计）

### A1 埋点位置
`platform/task_state_machine.py` 的状态变更出口，共 4 处：
- `set_state()` —— 正常流程推进（created→assigned→…→done）
- `on_event()` —— 异常 / 回报路径（stuck / block / timeout / report / resume / resolve / complete / drop）
- `remove()` —— 回收退出状态机
- `tick()` —— 兜底超时（其内部就是调 `on_event`，**不重复埋点**，避免一条迁移两条审计）

### A2 事件结构
统一 `event = "task.transition"`：

| 字段 | 取值 |
|---|---|
| `actor` | 优先取 ctx 里的 `member_id` / `by` / `leader`；缺省 `"system"`（`tick` 走这条） |
| `target` | 状态机 key（= `ws_id`，即工单号） |
| `detail` | `{event}: {from}→{to} action={action} note={note}` |
| `ts` | 由 `audit_log.record` 自带 |

### A3 不阻塞 + 可测试（守住本模块既定原则）
`task_state_machine.py` 文首写明「纯函数 + 依赖注入：**不 import 主模块全局单例**」。因此：
- 新增模块级 `_audit_sink: Callable[[str, str, str], None] | None = None` 与 `set_audit_sink(fn)`；
- 构造参数 `TaskStateMachine(..., auditor=None)` **优先**于模块级 sink；
- 两者都没有时，**在函数体内惰性** `from .audit import audit_log`（与 `policy.py:446`、`ai_verify.py:152` 同一既有范式），导入期不碰全局单例；
- 整条埋点路径 `try/except Exception` 全包 + `print` 一行，**绝不阻塞主流程、失败不炸**（与 audit.py / experience_v2 同原则）；
- `audit_log` 的 ring buffer 语义（`AUDIT_MAX = 500`）不动。

### A4 工单化查询
- `AuditLog.query()` 增 `target: Optional[str] = None` 过滤（默认 None，向后兼容）。
- `GET /api/audit` 增 `target` 参数；沿用本端点既有约定——声明为 `str` 再手工夹紧，**不引入 422**。

## 四、设计 B：原子所有权（防抢单）

### B1 新模块 `platform/task_ownership.py`

```python
@dataclass
class Lease:                      # 票据
    key: str; owner: str; token: str
    acquired_at: float; ttl: float
    def expired(self, now: float | None = None) -> bool: ...

class OwnershipRegistry:
    def __init__(self, default_ttl: float = 300.0): ...
    async def acquire(self, key, owner, *, ttl=None) -> Lease | None   # 拿不到返回 None
    async def release(self, key, owner, token=None) -> bool
    def owner_of(self, key) -> str | None      # 只读；已过期视为无主
    def snapshot(self) -> dict                 # 只读快照，供 /api 展示
    async def reap_expired(self) -> list[str]  # 回收过期票据（给 示例Harness-C 的 stranded 回收留钩子）

ownership = OwnershipRegistry()                # 模块级单例（与 audit_log / policy 同约定）
```

**语义**（全部在 `asyncio.Lock` 临界区内 check-and-set；事件循环单线程 ⇒ 真原子，无需数据库）：

1. 无主 **或** 已过期 → 授予，返回 `Lease`；
2. **同一 owner 重入 → 续租**并返回新票据（容忍审查回退后的重试、兜底层的二次 acquire）；
3. 不同 owner 且未过期 → **返回 `None`（拒绝）**；
4. `release` 校验 `token`，非持有者不可释放；已过期票据的 release 是 no-op。

**key 命名约定**：`task:{task_id}`（任务领取）、`delegation:{delegation_id}`（交付单元执行）。

### B2 接入点（一处主、一处兜底）

**主：`discussion_engine.execute_layers`** —— 锁粒度 = **delegation**（交付单元）：
- 派发前 `await ownership.acquire(f"delegation:{d.id}", owner)`；
- 拿不到 → 该单元**不进 `gather`**，直接产出 `ok=False` 的 `ExecutionResult`（`error="已被 <owner> 领取，拒绝重复执行"`）；
- 执行 + 审查循环内的重试沿用同一 owner（走 B1 第 2 条续租）；
- `finally` 释放。
- ⚠️ **本稿对 47 号原文的必要细化**：原文写「同一 task_id 同一时间只允许一个 agent 领取/执行」，但 `execute_layers` 的层内并行（`asyncio.gather`）本就是「同一 task_id 下多个 agent 同时干不同子任务」。若按 task_id 加锁，层内并行会被整体串行化、任务链性能腰斩。故拆成两级：`task:{id}` 管**领取**、`delegation:{id}` 管**执行**。
- 新增可选参数 `owner: str = ""`（缺省回落到 `task_id`），**旧调用方零改动**（`orchestrator.py:361` 不用改）。

**兜底：`harness_adapter.execute_subtask` / `_manual_execute_subtask`** 入口再 acquire 一次同一 delegation key（同 owner 重入 ⇒ 不冲突），堵住绕过 `execute_layers` 的直接派发。

### B3 状态注入（守 V-13 双副本规则）
单例落 `platform/state.py`（`ownership = OwnershipRegistry()`），与 `task_state_machine` 并列；`_CLEARABLE` / `reset()` / `snapshot()` 按对象型状态各自处理（手动 reset，与 `TaskStateMachine` 同待遇）。

## 九、V-20.1 修订（2026-10-07）

> 本稿为 V-20 的**增量修订**：不改动原有设计决策，只追加接口增强与一处实现时发现的缺陷修复。
> 触发：前端（FE-01 运维看板）经协作通道提交两条 `[接口变更申请]`。

### 1. 审计事件增**结构化明细字段**（申请 #1）

- `AuditLog.record()` 增可选 `extra` 参数；`task.transition` 事件随之携带
  `event_name` / `from` / `to` / `action` / `note` 五个字段，使前端不必正则解析 `detail`。
- **纯新增**：`extra` 为空时事件键与 V-20 完全一致（有硬断言测试钉住）。
- `detail` **永久保留**；`extra` **不可覆盖** `ts`/`event`/`actor`/`target`/`detail` 五个身份字段。
- 审计出口 sink 签名由 `(actor, target, detail)` 扩为 `(actor, target, detail, extra)`。
- ⚠️ 老记录没有这些字段（ring buffer 重启不清空）⇒ **前端必须三段式渲染**：
  结构化字段 → 冻结正则解析 `detail` → 降级显示原文。

### 2. `GET /api/audit` 顶层增 `total`（申请 #2）

- 新增 `AuditLog.query_page()`，返回 `(当页事件, 截断前命中总数)`。
- `query()` 与 `query_page()` 共用 `_filtered()`，保证"列表与计数"口径一致（有测试断言）。
- 路由返回 `{"events": [...], "total": N}`。`total` 的意义：区分"只有这么多"与"被 limit 截断"
  （ring buffer 上限 500，仅凭返回条数无法判断）。

### 3. 修复 `set_state` 新建记录时的**无意义迁移**（实现申请 #1 时发现）

- 原实现 `ensure(key, initial=state)` 使新建 key 的 `from_state` **恒等于** `to_state`，
  于是审计第一条迁移是 `X→X`（例 `executing→executing`）——对工单时间线毫无信息量。
- 改为：**新建 key 时先在 `created` 建账，再置到目标状态**。
  **终点状态、`ctx`、时间戳完全不变**，仅 `from_state` 变正确（`created→X`，
  与 `on_event` 新建 key 时的行为对齐）。
- 改动前已核对全仓：**无任何调用方或测试依赖旧的 `from_state` 取值**。
