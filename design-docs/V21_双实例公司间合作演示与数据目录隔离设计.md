## 一、问题（全部实测，非引用文档）

| # | 事实 | 证据 |
|---|---|---|
| 1 | **本机无法跑第二个实例** | `DATA_DIR` 在 **7 处硬编码**、全部由 `__file__` 推导，且**无任何环境变量出口**：`server.DATA_DIR`、`server.WORKSHOP_BASE`、`audit.DEFAULT_DATA_DIR`、`policy.DEFAULT_DATA_DIR`、`session_registry.DEFAULT_DATA_DIR`、`harness_launcher.DATA_DIR`、`tools/watchdog.DATA_DIR`。实测脚本打印：设 `AC_PORT=18931` 后七个路径**全部仍指向同一个 `agent_community\data`**；全文检索 `AC_DATA_DIR` 命中 0。⇒ 两个实例会写同一份 `workshops.json`/`tasks.json`，**必然互相覆盖**。 |
| 2 | 项目的环境变量约定**早已存在** | `AC_PORT` / `AC_AI_*` / `AC_BUDGET_*` / `AC4_BASE_URL` / `AC4_TOKEN` / `AC4_COMPANY_ID` 遍布各模块 ⇒ 补一个 `AC_DATA_DIR` 是**顺着既有约定**，不是新造机制。 |
| 3 | **Tailscale 其实是装好并可用的** | 交接清单写「本机 Tailscale 未装、真实组网未实施」——**实测证伪**：`Tailscale` 服务 Running、`tailscaled`/`tailscale-ipn` 进程在跑、`100.68.55.71` 是本机真实接口、9104 在它上面可连而 `127.0.0.1:9104` 正确拒连（fail-closed 生效）。 |
| 4 | A2A 边缘已 fail-loud | 9104 入站请求体按声明 charset 严格解码，编码不符 400 / 未知 charset 415（提交 `09e2a61`）。**跨公司送中文不再可能被静默污染**。 |
| 5 | 公司间访客凭据链路齐备 | `deploy/issue_token.py` 签发、`agent_community/a2a_client.py` 已有 `card`/`send`/`get`/`msg` 四个子命令、`deploy/合作方接入文档.md` 与 `管理员手册.md` 在册。 |

## 二、目标与非目标

**目标**
1. 本机可同时运行**两个完整实例**（公司 A / 公司 B），数据、日志、公司注册表**互不可见**。
2. 经 **A2A 标准协议**（9104/9106）完成一次真实任务往返：B 发中文任务书 → A 建工作间并回执 → B 回查结果。
3. 全过程**一条命令可复现**，适合录屏；不依赖外部人、外部机器、任何付费额度。
4. 缺省行为**逐字节不变**：不设 `AC_DATA_DIR` 时，与今天完全一致。

**非目标（明确不做）**
- 不改 `publish_acv4.ps1`、不动 oss 副本。
- 不新装任何软件、不改 Tailscale 配置、不改系统 ACL/防火墙。
- 不做多公司（>2）编排、不做公网暴露。
- 不实现「会话/进程级也隔离」（`~/.agent_community/config.json` 仍全局共用一份——两实例共用同一 AI Key 与预算；**本稿显式接受该共享**，理由见 §五风险 R2）。
- Tailscale **不作为必需项**：本机双实例走回环即可；Tailscale 只留作「真远程加分项」。

## 三、设计 A：数据根可配置（`AC_DATA_DIR`）

### A1 改法
7 处逐点改为「环境变量优先、缺省回落原路径」：

```python
DATA_DIR = Path(os.environ.get("AC_DATA_DIR") or (Path(__file__).parent.parent / "data"))
```

- **必须在模块 import 时求值**（这 7 处本来就是模块级常量），保持「同进程内路径恒定」的现有语义。
- `WORKSHOP_BASE` 必须**从 `DATA_DIR` 派生**，不得各自独立读环境变量（否则两处口径可能不一致）。
- 环境变量为空串时按未设置处理（`or` 天然满足）。

### A2 必须一起处理的连带点
| 连带点 | 处理 |
|---|---|
| `agent_community/tests/conftest.py` 的两层守卫 | `guard_real_data_dir` 比对的是 `_PKG_ROOT/data`。加了环境变量后**必须确认守卫仍拦得住**新入口：新增一条断言——测试期间若 `AC_DATA_DIR` 被设成真实目录，直接 fail。 |
| `data/logs/` | 随之隔离（日志在 `DATA_DIR` 下），两实例日志天然分开；**权威日志路径**不变（`DATA_DIR/logs/...`）。 |
| `tools/watchdog.py` 的 `DATA_DIR`/`PROJECT_ROOT` | 看门狗要守护第二个实例，就必须能指向第二个数据根 ⇒ 与 `--port` 同样按环境变量或参数传入。 |
| `a2a_server` / `a2a_relay` / `grpc_gateway` / `mcp_server` | 它们**不直接用 `DATA_DIR`**，只通过 `AC4_BASE_URL` 指向对应平台的端口 ⇒ 无需改，但**启动脚本必须显式给 `AC4_BASE_URL`**（否则第二实例的 A2A 会去戳第一实例的平台，这是本稿最容易踩的坑）。 |

### A3 备份与回滚
7 个文件改动前一律留 `.bak_v21`；回滚 = 恢复 7 个 `.bak_v21`（无数据格式变更，无迁移）。

## 四、设计 B：双实例编排（一条命令）

### B1 端口与数据根分配
| | 公司 A | 公司 B |
|---|---|---|
| 平台 | `18920`（现状不动） | `18930` |
| A2A 边缘 | `9104`（Tailscale IP，现状不动） | `9106`（**回环**） |
| 数据根 | `agent_community/data`（现状不动） | `<工作区>\demo\company-b-data` |
| `AC4_BASE_URL` | `http://127.0.0.1:18920` | `http://127.0.0.1:18930` |
| 公司身份 | `co-local-a`（`self`） | `co-remote-b`（`peer`） |

> 公司 A 一律**沿用现状**（端口/数据根/`AC4_*` 一个都不变），保证演示脚本不改变生产行为。

### B2 脚本 `demo\two_companies.ps1`（新增，纯 ASCII + BOM）
子命令：
- `start`：按上表起两个实例（B 实例注入 `AC_DATA_DIR`/`AC_PORT`/`AC4_BASE_URL`），等健康检查通过；
- `stop`：按 pid 文件停止两实例；
- `status`：打印两个平台的 `/api/status`、两个 A2A 的 `/health` 与 Agent Card；
- `selfcheck`：见设计 C。

### B3 演示动线（录屏脚本，写进 `demo\DEMO.md`）
1. `start` → `status` 显示 A、B 各自独立、互不可见（B 的 `workshops.json` 为空）。
2. 在 A 的工作间界面走正常流程（建工作间 → 分工 → 执行 → 三级讨论）。
3. **B 侧发任务**：`python -m agent_community.a2a_client send "把接口文档整理成中文 Markdown" --url http://127.0.0.1:9104 --company co-remote-b --token <B 的公司 token>`
4. **A 侧**自动建工作间（名称=任务前 20 字，中文完整、无污染）并回执。
5. **B 侧回查**：`a2a_client get <task_id>` → 拿到 A 侧状态与产物。
6. 收尾：`stop`。

> 关键：第 3/4 步的中文往返，是提交 `09e2a61` 之后**才**保证不被静默污染的那条链。

### B4 凭据（不用手工传）
`deploy/issue_token.py` 在 A 侧签发 `co-remote-b` 的公司 token，脚本**同机**把它作为环境变量交给 B 侧客户端即可（演示场景下不涉及真实交付风险）；文档里出现的一切 token 一律写 `sk-your-key` 形态的虚拟值（守铁律 6）。

## 五、风险与对策

| # | 风险 | 对策 |
|---|---|---|
| R1 | 第二实例误连第一实例的平台（`AC4_BASE_URL` 没给） | 脚本**强制**注入 `AC4_BASE_URL`；`status` 子命令把两个平台的实际 URL 打出来核对。 |
| R2 | 两实例共用 `~/.agent_community/config.json` ⇒ 共用同一 AI Key 与**同一份预算熔断** | **明确接受并写进文档**：演示只用一次真实 AI 调用或不调用（`AC_FAKE_REPLY` 可兜底）。若要真隔离需再拆配置根，**本稿不做**（避免把「会话级隔离」也拖进来）。 |
| R3 | 改动 7 处路径影响面 | 缺省行为逐字节不变；回归必须跑两套全量测试 + 「不设环境变量时 `/api/status` 与数据文件位置与改前一致」的对照断言。 |
| R4 | 演示期间公司 A 仍是**正在用的生产实例**（18920 老板在用） | 脚本**只读**公司 A（除正常演示动作）；`stop` 只停 B（A 的 pid 不进 pid 文件）。 |
| R5 | Windows `SO_REUSEADDR` 造成同端口双绑定（本次已踩） | `start` 子命令在起服务后**用 `netstat` 断言该端口只有一个 LISTENING pid**，否则报错停下。 |

## 六、验收标准

| # | 验收项 | 证据形式 |
|---|---|---|
| 1 | 数据根可隔离且缺省不变 | 不设 `AC_DATA_DIR` 时 7 处路径与改前逐字节一致（脚本对照）；设了则全部改到新根 |
| 2 | 两实例互不可见 | B 的 `workshops.json` / `tasks.json` 与 A 的是不同文件；同一时刻各自 `GET /api/workshops` 内容不同 |
| 3 | 跨实例中文往返零污染 | B 发中文任务 → A 侧工作间名与 `hall_content` 中文完整（逐字比对，`decode('utf-8')` 判定，不信 PowerShell 显示） |
| 4 | 一条命令可复现 | `demo\two_companies.ps1 start` → `selfcheck` 全绿 → `stop`，全流程无手工步骤 |
| 5 | 全量回归不破 | `agent_community/tests` 与根 `tests` 计数对照（当前 **742 passed / 10 xfailed** + **66 passed**） |
| 6 | 零 push、oss 只读、无新装软件 | `git log` 只在 dev；`git status` 干净 |
