## 一、问题（实测，含复现方式）

### 1.1 入站断头：外部任务落成「死工作间」

一次真实 A2A `tasks/send`（`POST 9104/` JSON-RPC，带公司 token）建出工作间后，实测：

```
status     = draft      ← 停在草稿，协作流程不启动
members    = 0          ← 没有任何成员
discussion = 0          ← 讨论区空的
```

⇒ **外部送来的任务没有任何人来接**，工作间就此搁置。

历史与根因：
- 此前由 `a2a_relay` 插件写一条**合成的 user 回执**把它推进 `discussing`，但该插件已随 Marvis 退役停用（本仓 `ee5dd08`）。
- **但即便恢复回执也不够**：`members=0` 时**没有人可以协作**，回执只是把状态从 `draft` 挪到 `discussing` —— 那本来就是半截方案。
- 根因：`POST /api/workshop` 的成员**只能由调用方显式传入**，而 A2A 入站路径没有传。

### 1.2 出站无兜底：三件设施互不连线

| 设施 | 能力 | 状态 |
|---|---|---|
| `platform/heartbeat.py` | **agent 级**存活（`stale()`，阈值 = `interval × timeout_scale`） | ✅ 已有（V-20 修通端点） |
| `GET /api/tasks/stale` ＋ `POST /api/tasks/recover-stale` | **任务级**卡死判定与回收（基于 `updated_at` 超时；`resume`/`archive` 两种动作） | ✅ 已有（V-18） |
| `platform/task_ownership.py` | 交付单元锁 + `reap_expired()` 过期回收钩子 | ✅ 已有（V-20） |
| **「agent 失联 ⇒ 它手上的活被回收/重派」** | —— | ❌ **缺失** |

两点具体缺失：
1. **没有连接**：`heartbeat.stale()` 只告诉你"谁死了"；`/api/tasks/stale` 只告诉你"哪些任务卡了"。**没有任何东西把前者变成后者。**
2. **没有自动触发**：现有回收**纯手动**（需人调端点）。无人工值守时，崩溃 worker 的遗留任务会一直挂着。

## 二、目标与非目标

**目标**
1. 外部任务进来 ⇒ **自动组队**并进入协作流程（不再出现 `members=0 && status=draft` 的死工作间）。
2. agent 失联 ⇒ 其名下在办交付单元**自动进入回收**，按规则重派或升级。
3. 全过程**可审计**（复用 V-20.1 的 `task.transition` 结构化字段）、**可急停**（一个开关）。
4. 缺省行为不变：不开启时与今天逐字节一致。

**非目标（明确不做）**
- ❌ 不做「两个 agent 自动互相对话」的循环（老板已搁置 A2A 协议方向）。
- ❌ **不自动重派需要人决策的事**（L2 一律升级）。
- ❌ 不改前端。只出接口；是否加「孤儿/回收队列」面板由前端自行决定（`ops.html` 已有时间线与失联看板，是天然的落点）。
- ❌ 不新起线程/进程（挂到既有巡检路径上）。

## 三、设计 A：入站闭环（外部任务 → 组队 → 进协作）

**现状**：`POST /api/workshop` 的成员由调用方传入；A2A 入站没传 ⇒ `members=0`。

| 选项 | 做法 | 评价 |
|---|---|---|
| **A1（推荐）** | 入站按**能力自动组队**：复用既有 `harness_manager` 的在线会话 + `/api/agents` 的 `capabilities`，挑 N 个在线 harness 作为成员 | 真正闭环；失败时有明确语义 |
| A2 | 入站未带成员则**拒绝创建**并返回 409 + 原因 | 最小改动，但把问题推回给调用方 |
| A3 | 只补回执、把状态推到 `discussing` | **不采纳**：治标不治本（见 §1.1） |

**建议 A1，且组队为空时按 A2 明确失败**（宁可不建，也不留死工作间）。

**接口（新增，向后兼容）**——二选一：
- 给 `POST /api/workshop` 增可选参数 `auto_team: bool` + `team_size: int`；或
- 新增专用入口 `POST /api/workshop/from-task`（语义更清楚，不污染既有端点）。

**组队规则（纯规则、零 token）**：能力匹配 → 在线优先 → 排满即止；不足 N 人时**如实减少并在响应里说明**，不要假装组满了。

## 四、设计 B：出站兜底（失联 → 孤儿回收）

**规则（三选一，纯规则零 token）**：

| 情形 | 动作 |
|---|---|
| 锁**未过期**（可能只是网络抖动） | **只标记**"疑似孤儿"，进人工队列，**不动任何状态** |
| 锁**已过期** ＋ 任务非终态 | 释放锁 + 写审计 + 沿用 V-18 既有语义把任务置 `resume` |
| 任务**已终态** | 只释放锁（幂等，不留痕升级） |

**触发**：挂在既有心跳巡检路径上（复用 `task_state_machine.tick()` 那一路的兜底循环），**不新起线程**。

**安全阀（本稿重点，缺一不可）**
1. **单次回收上限**（防雪崩式批量回收）。
2. **幂等**：同一交付单元**只自动回收一次**（幂等键）。
3. **人在环上**：需要授权/判断的一律 **L2 升级**，**绝不自动重派**。
4. **急停开关**：一个配置项可整体关闭自动回收（默认**关**？默认**开**？见 §六.3）。
5. **保留既有手动路径**：`/api/tasks/recover-stale` 不动，人工仍可用。

## 五、验收

| # | 验收项 | 证据 |
|---|---|---|
| 1 | 入站不再产生死工作间 | 再造一次 A2A `tasks/send`：**要么**工作间有成员且进入协作流程，**要么**明确 409 + 原因；`members=0 && status=draft` 这一组合**不再出现** |
| 2 | 失联 → 孤儿回收 | 造一个失联 agent ＋ 一个过期锁，跑一次巡检：锁被释放、任务置 `resume`、审计出现回收记录 |
| 3 | 幂等 | 同一孤儿连跑两次巡检，**只回收一次** |
| 4 | 急停有效 | 关掉开关后巡检不再改动任何状态 |
| 5 | 零回归 | 两套测试计数对照（当前 **752 passed / 10 xfailed** ＋ 根 **66 passed**） |

**§1 两个问题的复现方式**（供拍板后复验）：
- 入站：用 Python 发 A2A `tasks/send`（公司 token）→ 查 `GET /api/workshops` 的 `status`/`members`/`discussion`
- 失联：`POST /api/heartbeat`（需**已注册** harness，未注册返 403 是正确行为）→ 等 >60s → `GET /api/heartbeat/stale`

## 六、待老板拍板

1. **入站**取 **A1（自动组队）** 还是 **A2（明确拒绝）**？我建议 A1 + 组不到队时按 A2 失败。
2. **出站自动动作的范围**：只「释放过期锁 + 置 `resume`」，还是也允许**自动重派给另一在线 agent**？
   我建议**只做前者**，重派先留人工——重派错了会造成**双份工作**，而防双份正是 V-20 原子所有权要解决的事，两者不该互相拆台。
3. **自动回收默认开还是默认关**？我建议**默认关**（设开关才开），与「先观测、后行动」的一贯做法一致；你若要无人值守，就默认开 + 上限。
4. **与 V21 的先后**：V21（数据目录隔离 / 双实例演示）是初赛 DEMO 的硬前置；V22 是协作层。**你要哪个先？**（两个都已成稿待拍板，可以一次批。）
