## 0. 三句话说完

1. **不装任何开机自启**（撤掉现在已有的计划任务与启动文件夹项）；
2. **一条快捷启动**：双击一个图标 ⇒ 起平台 + A2A + grpc + **一套**看门狗，**只起没在跑的**，窗口里逐步显示状态；
3. **平台内一个「退出并关闭」**：点它 ⇒ 把**看门狗和服务全部停掉**（先停看门狗，否则它会把服务又拉起来）。

---

## 1. 为什么要"先停看门狗"（这是本设计最容易做错的一步）

看门狗的职责就是"服务不在就拉起来"。如果关停顺序是 `platform → A2A → grpc → 看门狗`，
那么每停一个服务，看门狗都会**立刻把它拉回来** ⇒ 用户看到"点了退出，服务还在"，
**典型的"看起来成功"死状态**（违反准则⑤）。

⇒ 正确顺序：**看门狗 → A2A → grpc → platform（最后）**，并且**每一步都核对端口真的不再监听**，
没停掉的**如实报出来**（"grpc(9105) 未关掉：拒绝访问"），**不许显示成"已全部关闭"**。

## 2. 一条快捷启动（叫什么、放哪、点了做什么）

**产物**：`启动合作社.cmd`（仓库根一份；**另外放一个快捷方式到桌面**，指向它，图标可自定义）

**双击后的动作（全部幂等）**：

| 步 | 动作 | 已在跑时 |
|---|---|---|
1 | 读 `deploy/.env`（缺则从 `.env.example` 复制）、缺 token 则生成并写回 | 已有则跳过 |
2 | **选择解释器**：`AC4_PYTHON` → 否则逐个试候选，**挑第一个能 `import fastapi` 的** | 都不行则打印"怎么修"并停 |
3 | 起 **platform**（默认 18920，带 token） | 端口在听 ⇒ 跳过 |
4 | 起 **A2A**（默认 9104） | 同上 |
5 | 起 **grpc**（默认 9105） | 同上 |
6 | 起**一套**看门狗（覆盖 18920 + 9104 + 9105） | 已在跑 ⇒ 跳过（**不重复起**） |
7 | 逐项健康检查并打印汇总（平台 / A2A / grpc） | —— |

- **窗口不自动关**：留着让人看见状态；关掉窗口**不影响**服务（服务是独立进程，这正是"退出要走平台按钮"的原因）。
- **绝不写自启项**（默认行为；`-Ensure` 那种开关从快捷启动里**去掉**）。
- **失败要说话**：任一步失败 ⇒ 明确说哪一步、为什么、怎么修；**不打印"启动成功"**。

## 3. 平台内「退出并关闭」

**位置**：界面右上角「系统」菜单里（与"设置/关于"同级），文案 **「退出并关闭」**。
**二次确认**：「将关闭平台、A2A、grpc 与看门狗（**不会删除任何数据**）。确定？」

**后端**：`POST /api/system/shutdown`（**仅本机或持 token 可调**）

**动作顺序（关键）**：
```
① 停看门狗（并确认它真的不在了——否则它会把后面的服务再拉起来）
② 停 A2A(9104) → ③ 停 grpc(9105) → ④ 最后停 platform(18920)
⑤ 逐项核对"端口已不再监听"，返回真实结果
```
**返回形状（诚实优先）**：
```jsonc
{ "success": true,                     // 只要发起关停就 true（动作做了）
  "stopped": ["watchdog", "a2a", "grpc", "platform"],
  "still_running": [],                 // ★没关掉的必须出现在这里，界面如实显示
  "detail": { "watchdog": "pid 8664 已退出", ... } }
```
**界面**：关停后显示「**已关闭。可以关掉这个页面了。**」+ `still_running` 非空时显示
「⚠ 未关掉：grpc(9105)：拒绝访问 —— 需要管理员」。**不自称"全部关闭"**。

**边界（不做的事）**：
- **不删数据**、不动工作间、不停外端 harness 的会话（那是别人的东西）；
- **不能替用户关浏览器标签页**（浏览器不允许）⇒ 用"可以关掉这个页面了"的提示替代（**不假装能关**）。

## 3.1 「关闭口令」是干什么的（老板 2026-10-09 问「加什么口令？」）

**它不是那个很长的平台访问 token，而是你自己定的一小串**（例如 4~6 位数字，或一句你记得住的短语），
写在 `deploy/.env` 里：

```ini
# 关停平台时需要输入的口令（留空 = 只做二次确认，不校验口令）
AC4_SHUTDOWN_PIN=<你自己定，别写进仓库>
```

**为什么值得加**（不是形式主义，是实测口径）：
- 平台的认证规则是「**本机访问免 token，非本机才要 token**」——这是为了让界面不用登录就能用（`_auth_check`）；
- 而平台**没有 Origin/Referer 校验**（全库搜不到）⇒ 你浏览器里**任何一个网页**都能朝
  `http://127.0.0.1:18920/api/system/shutdown` 发一个**普通表单 POST**：
  这类请求属于浏览器的「简单请求」，**不触发预检、CORS 挡不住**（跨域只挡"读响应"，不挡"发出去"）。
- ⇒ 有人放个钓鱼页/广告页在页脚塞个隐形表单，就能把你的平台关掉。**加口令是把这道门关上**。

**双保险（建议两条都做）**：
1. **口令**：`POST /api/system/shutdown` 必须带 `X-Shutdown-Pin`，与 `.env` 里的一致才执行；
2. **来源校验**：同时校验 `Origin`/`Referer` —— 只接受**本机来源**（`http://127.0.0.1:*` / `http://localhost:*` / 无 Origin 的本机命令行调用），
   其它来源一律 403（这条成本很低，且对"网页乱调"更直接）。
   与 1 并存时：**本机来源 + 口令** 才放行；没设口令则退化为"仅本机来源 + 界面二次确认"。
