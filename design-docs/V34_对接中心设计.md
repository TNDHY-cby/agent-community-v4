## 0. 一句话

**对接中心 = 把"外部 Agent 接进平台、并让它跟工作间对上"这件事，收成一个入口、一个页面。**

它**只做接入与激活**（RUNBOOK §12 的边界不变）；**讨论与工作仍在工作间**。
自本次起，它的用户可见名字就叫「**对接中心**」——与「**流程说明**」（只讲不做的说明书）是两个东西，别混。

---

## 1. ★两个入口、两种范围（老板刚定的，本稿的核心）

| 入口 | 位置 | 范围 | 能干什么 |
|---|---|---|---|
| **大厅（总控）** | 大厅首页新入口 | **全局**（所有工作间） | ① 注册/管理 Harness；② **跨工作间**看"谁接进了哪个工作间、对上哪个岗位"；③ 选任意工作间后做对接操作 |
| **工作间** | 工作间右上入口（现在那个胶囊指向"流程说明"） | **只这一个工作间** | 看并操作**本工作间**的成员对接（建会话/送桥/抢救/批量）；**不出工作间选择器** |

**设计要点**：两个入口进的是**同一个页面**（同一份 HTML），用 URL 参数区分范围：
`/docking.html`（总控）与 `/docking.html?ws=<工作间id>`（锁死单间）。
⇒ 好处：一处实现、两处复用，不会出现"两个页面行为不一致"；且与后端端点的**工作间作用域**天然对齐
（激活类端点本来就是 `/api/workshop/{ws}/…`，总控只是"先替你选好 ws"）。

**总控里"工作间"只是筛选维度，不是第二套实现**——这条是防止把界面做成两套的分界线。

## 2. 边界（照 RUNBOOK §12 原样，不新增不削减）

**归对接中心（把外部东西接进来 / 唤醒起来）：**
- **接入**：注册 Harness（`pre-register` / `probe-register` / `register` / `list` / `action-scripts` / `DELETE`）
- **激活**：`establish-session`、`deliver-bridge`、`onboard-members`、`recover`、`recover-scan`
- **通道生命周期**（V28 已实现）：`channel/retire`、`channel/establish`
- **为上述服务的只读**：`members-status`、`offline-report`、`compartments`、`channels`、`library`（只读视图）
- **架桥辅助（现 `register.html` 有，须一并迁入）**：`bridge-path`、`bridge-verify`、`bridge-templates`、`auto-connect`

**不归对接中心（留在工作间）：**
- 讨论（`discuss` / `review`）、选人（`select-members` / `members` / `confirm-members`）
- **开工** `POST /api/workshop/{ws}/start`（它虽触发激活，但语义是"开始工作"的决策）
- 资料库**写**（`library/update`）、阶段整合（`integrate`）、收尾（`complete`）

**一句话自检**：在把外部东西接进来 / 唤醒起来吗？→ 对接中心；在讨论或推进工作吗？→ 工作间。

## 4. 接口契约

### 4.1 新增：对接总览（只读）★这是唯一确定要新加的后端

```
GET /api/docking/overview            # 总控用：全局
GET /api/docking/overview?ws=<wsid>  # 单间用：只回该间
```

**为什么需要**：现在 `GET /api/harness/list` 只给"已注册的 harness"，**不含它接进了哪个工作间**；
而工作间侧的 `members-status` 只给一个间。⇒ 没有任何端点能回答"**这个 harness 现在接在哪个工作间、哪个岗位**"。
总控要的正是这个视图。

**返回（形状提案，实现期可微调）**：
```jsonc
{
  "scope": {"type": "global", "ws": null},
  "harnesses": [                    // 来自 harness_manager.list_sessions() 现有字段
    {"harness_id": "...", "harness_name": "...", "harness_type": "...",
     "online": true, "access_tier": "...", "has_template": true,
     "bindings": [                  // ★新增：该 harness 接进了哪些工作间/岗位
       {"ws_id": "...", "ws_name": "...", "role": "...", "member_id": "...",
        "channel_state": "active|retired|none", "channel_seq": 2,
        "session_name": "...", "since": "..."}
     ]}
  ],
  "workshops": [                    // 供总控的工作间选择器
    {"ws_id": "...", "name": "...", "member_count": 5,
     "docked": 3, "pending": 1, "offline": 1}
  ],
  "generated_at": "..."
}
```
- **`bindings` 怎么算**：由"工作间成员里记录的 `harness_id` + 通道状态"反查（成员侧已有 `channel{seq,state,…}` 与 harness 关联），
  **不新建存储**；实现时逐工作间扫成员表聚合（工作间数量级小，可接受；若大再加索引）。
- **只读、无副作用**：不得触发激活、不得改状态（对齐 V17 的教训——只读端点别偷偷收敛状态）。

### 4.2 沿用（不新增）

`POST /api/workshop/{ws}/member/{mid}/establish-session`、
`POST /api/workshop/{ws}/member/{mid}/deliver-bridge`、
`POST /api/workshop/{ws}/onboard-members`、
`POST /api/workshop/{ws}/member/{mid}/recover`、
`POST /api/workshop/{ws}/recover-scan`、
`POST /api/workshop/{ws}/member/{mid}/channel/retire|establish`、
`GET  /api/workshop/{ws}/member/{mid}/channels`。

## 5. `register.html` 的"取代"怎么做（分两步，避免一次动太大）

老板定的是**取代**，不是并存。但该页有 1231 行、8 个区块、还被大厅直接链着，
**一步删掉会打断现有用法**（有人正靠它注册）。⇒ 建议**两步**：

- **第 1 步（本次）**：对接中心**能力追平**——注册 + 架桥辅助 + 激活 + 通道，全部可用；
  大厅入口改为**对接中心**；`register.html` 暂留可达（旧链接不 404），但**不再从大厅主入口导向**。
- **第 2 步（追平并验收后）**：把 `register.html` 的**教程/模板/速查类只读内容**并入对接中心，
  该页**下线**（重定向到对接中心，或留只读镜像）。

**必须迁走、不能丢的现有内容**（`register.html` 实测区块）：
`📖 接入教程 + 注册模板`、`🌉 架桥速查`、`🔌 协议接入方式`、`🚀 平台协助架桥`、
`💬 平台 Agent 直聊`、`🔁 平台 Agent ↔ 外端对象 传讯`、`已注册 Harness`。
⚠️ 其中「平台 Agent 直聊 / 传讯」用到 `POST /api/assistant/chat` —— 它是**写**但不是"对接动作"，
**要不要进对接中心白名单，请老板拍板**（我倾向：**进**，因为它是"协助架桥"的一部分；但它在白名单外，必须显式登记）。

## 7. 权限、审计、失败语义（对齐既有规矩）

1. **不做服务端 ACL**（与 V29 同一结论）：不做"只有谁能进对接中心"的判定，
   而是**记录执笔人/操作者**；老板要卡权限时再单独出稿。
2. **每个写动作落审计**：注册/建会话/送桥/批量/抢救/停用/新建 都要进审计，带 `ws_id` / `member_id` / `channel_seq`。
   ⚠️ **但注意 `audit.record()` 单次约 5.75ms**（全量重写 500 条）——**别放进轮询/热路径**；
   这些是**用户点击级**动作，安全。
3. **失败要说话**（产品化准则⑤）：
   - 逐项返回真实结果，**批量操作必须分栏**（`auto_ok` / `need_human`、`still_running`），不合并、不"美化"；
   - `verified=false` **一律显示"⚠ 待人工/未核实"，绝不显示"完成"**（沿用 FE-08 契约）；
   - 不得出现"看起来成功"的死状态（这正是本次要修的 `healthcheck` 那类问题的同源要求）。
4. **不得打扰用户**（老板 2026-10-08 产品级要求）：对接中心为 `foreground: required` 的动作
   （如需要抢占桌面的激活）**必须显式提示**，默认不抢前台。

## 9. 验收（隔离实例 + 自建自清，按规则 11/16）

1. **隔离实例**上跑（`test_instance.ps1 start -Port 18930`），**不用在用的 18920 当试验台**；

5. **白名单卡口**：脚本记录全部非 GET，断言 ⊆ §4.3；**`/discuss` 出现即 FAIL**；
6. **总控范围断言**：总控可选任意工作间；**单间入口不得出现工作间选择器**（且不得越权操作别的间）；
7. **`GET /api/docking/overview` 无副作用**：调用前后 `workshops.json` 指纹不变（对齐 V17 审计教训）；
8. 截图进 `temp\验收证据截图\`（**不入库**），`result.json` 脱敏；
