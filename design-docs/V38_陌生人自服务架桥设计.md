## 1. 先承认问题：我前几轮做的是"私人定制"

| 我做的（✗） | 别人需要的（✓） |
|---|---|
我把 示例Harness-B 的桥在我这台机器上调通 | 陌生人在**他自己的机器**上，把自己的 agent 接通 |
我知道路径（`agent_community\bridges\<hid>\bridge.py`）、知道命令、知道目录名 | 他**什么都不知道**，而且**没有我** |
我测的是"**我这条**路通不通" | 要测的是"**任何一条**路能不能被他自己调通" |
我告诉你要开哪条命令行 | 平台/文档必须让他**自己推出**该做什么 |

**根因（一句话）**：
> 我**替用户填了答案**；而产品要做的是**帮用户找到他自己的答案**。

⇒ **判据**：设计是否合格，看我**是否预设了任何"我这台机器才有的东西"**：
我的路径、我的 harness 名、示例Harness-B 特有的操作、某个固定端口……**有一条就算没做成**。

---

## 2. 关键认识：桥的"形态"只有四种，agent 侧的动作永远由用户提供

平台**不可能知道**别人的 agent 怎么被叫醒、怎么回话 —— 这是**接入方自己的知识**。
但平台**知道**"唤醒/回话"这件事在工程上**只有几种形态**。所以：

```
平台给：桥的【骨架】+【该填什么】+【怎么自己验证通了没】
用户给：他自己 agent 的【一句话命令 / 一个地址 / 一个目录】
```

**四种桥型（覆盖绝大多数 agent）**：

| 桥型 | 适用什么样的 agent | 用户要提供 | 平台做什么 |
|---|---|---|---|
**① 命令行唤醒（ACP/CLI）** | 能被一条命令拉起来的（CLI agent、无头模式） | **一条命令行** + 工作目录 | 生成"收到消息 → 调这条命令 → 收结果"的脚本 |
**② 文件轮询（file_poll）** | 有"监听目录"能力的（多数桌面/IDE agent 可挂 watcher） | **一个目录** | 生成"往这个目录写任务文件"的桥 + 收 `replies` |
**③ HTTP/API（http_api）** | 自带 HTTP 接口的 | **一个 URL**（+ 消息路径） | 生成连接契约 JSON（0 进程）+ 回执格式 |
**④ 人工中转（clipboard）** | 只能人肉贴的（如只开 GUI 的） | **无**（平台给可复制文本） | 生成激活提示词 + 复制按钮；**明说这是人工模式** |

⚠️ **四种之外不硬撑**：若用户说"我的 agent 只能用 X 方式"，平台**如实说"当前不支持"**并给最近的一型的改造建议 —— **不假装能接**（准则⑤）。

## 3. "陌生人怎么架桥"：三步选型 + 一次自检

**核心机制：平台不猜，让用户选 + 让平台**自检**。**

```
第 1 步  你选：你的 agent 怎么被叫醒？
         ○ 我用一条命令能把它拉起来        → 桥型①
         ○ 它能盯着一个文件夹看新文件      → 桥型②
         ○ 它自己开了个网页接口            → 桥型③
         ○ 它只能我自己手动贴              → 桥型④
        （选完，平台只问这一型需要的那两三样东西 —— 不再问别的）

第 2 步  你填：平台给【带占位符的骨架】+【每个占位符填什么】+【照抄示例】
         · 每个字段旁边给"最小示例"（可一键填入）
         · **填错不报术语**，用人话说"这一行要的是一个能执行的文件路径"

第 3 步  自检（★这一条最要紧）：平台发一条测试消息，然后盯着
         ✅ 桥取走了  → ✅ 你的 agent 回话了     ⇒ 接入成功，绿灯
         🔴 桥没取走  ⇒ 告诉你去哪看、为什么（桥没跑/目录写不进去）
         🔴 取走了没回话 ⇒ 告诉你是 agent 侧的事，并给出**你能自己查的两处**
         （全程**不出现** harness_id / channel_seq / bridge.py 这类词）
```

**要点**：第 3 步是**平台做的自动判定**，不是让用户读日志。他只需要看**灯**。

---

## 4. 别人怎么知道"我的 agent 到底能不能被这样叫醒"（给可自证的方法，不给结论）

平台**不能替他判断**，但可以给他**照着做的两步自证**（文档里已有精神，这里做成界面上的例子）：

| 桥型 | 让用户自己验证（平台给可复制的例子） |
|---|---|
① 命令行 | 「先**手动跑一次**这条命令，看它能不能起来」。能起来 ⇒ 桥型①可行 |
② 文件轮询 | 「往那个目录**丢一个空文件**，看你 agent 有没有反应」 |
③ HTTP | 「浏览器打开这个地址，看它回不回 JSON」 |
④ 人工 | 不用验证（本身就是人肉） |

⇒ **平台给的是"举手之劳的验证动作"，不是"帮他把环境探好"**。这才是可复制的。

## 5. 反面清单：这些**一律不许**出现在实现里（否则又成私人定制）

| 不许 | 为什么 |
|---|---|
❌ 写死我这台机器的路径（含中文的 `D:\<私有工作区>\...`） | 别人机器上不存在（准则①） |
❌ 内置"示例Harness-B 专用"分支或任何**真实 harness 名** | 铁律 6：对外文档与示例一律虚拟名 |
❌ 假设某个固定端口/固定目录存在 | 别人环境不同 |
❌ 要求用户"先读一遍协议文档"才能动手 | 违反"不读文档也能完成"（V37 指标 A） |
❌ 桥脚本里出现"只有我能解释"的注释 | 别人的注释要能自己看懂 |
❌ 把"平台探测不到"当成"用户环境有问题" | 平台要**如实说"我探不到，请你按这个自证"** |

**可复制的判据（放进验收）**：把仓库换到**另一个目录**、用一个**完全不同的 agent 名字**，
按界面从头接入一遍 —— **不改任何代码**就能走通。
