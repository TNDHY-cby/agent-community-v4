## 1. 现话术的三处硬伤（都实测证实）

| # | 现话术写的 | 实测事实 |
|---|---|---|
1 | 「平台会**自动探测**补齐 `wakeup_method`…」＋「**不要向用户问技术细节**」 | ★**平台探测不出"怎么叫醒 agent"**。实测后果：生成桥里 `TRIGGER_CMD` **是空的** ⇒ **只落盘、不叫醒** ⇒ 老板遇到"唤不醒" |
2 | 「自动架桥…**不用手动跑桥命令**」 | 一半对：`auto-connect` 确实会起桥进程；但**起了桥 ≠ 能叫醒 agent**（缺 #1 那一项），页面没说这个区别 |
3 | 叫人跑 `--trigger "D:\...\app.exe"` 这类**带空格的命令行** | ★**实测会挂**：路径含空格被拆成多个参数 ⇒ argparse 报 `unrecognized arguments` ⇒ **桥根本起不来** |

## 2. 实测到的三个硬事实（话术必须反映）

1. **叫醒必须显式配置**：平台**不该猜、也猜不到**你的 agent 怎么被拉起。不配 ⇒ 消息静静躺在邮箱里。
2. **触发命令要包一层**：直接填带空格的命令会被拆坏（我本人踩了）。⇒ 让用户填**一个包装脚本的路径**。
3. **桥脚本在中文 Windows 上有编码坑**：它打印 `✗` 会撞 GBK（`'gbk' codec can't encode`）。
   ⇒ 启动时给环境变量 **`PYTHONIOENCODING=utf-8`**（把这条写进给用户的启动命令里）。
   ⚠️ 已记为本项目的**代码缺陷**（`bridge.py.tmpl` 应只用 ASCII 或显式设编码），待修。

## 3. 建议的新话术（可直接替换 `register.html` 里那段）

**① 把「不要问技术细节」改成「只问一问」**（这是第 1 步的关键）

```
【收集信息的方式（重要）】
用户是平台的拥有者，不是 harness 本身。大多数字段请你自己探测/推断，不要问用户。
但有一件事**只有用户或你知道、平台猜不到**，必须问清：

    ★ 你的 agent 怎么被「叫醒」？（四选一）
      A. 我用一条命令能把它拉起来        → 桥型 cli_acp
      B. 它能盯着一个文件夹看新文件      → 桥型 file_poll
      C. 它自己开了个网页接口            → 桥型 http_api
      D. 它只能我自己手动贴              → 桥型 clipboard（人工模式）

如果选 A/B，还要问一个：**收到任务后，要执行哪条命令去叫醒它？**
（答不上来也能先接入，但那样消息只会落在邮箱里、不会自动叫醒它 —— 平台会如实告诉你这一点）
```

**② 把「注册完就自动化」改成「三步，每步都有自检」**

```
【注册完成后：三步接入（每步都能自己验证）】

第 1 步 注册（就是上面这份 JSON）
第 2 步 起桥：POST /api/harness/auto-connect  body: {"harness_id":"我的唯一标识"}
        · status=connected/ready ⇒ 桥已起来
        · status=manual ⇒ 看返回里的 note（人工模式，不阻塞）
第 3 步 ★自检：POST /api/workshop/{工作间}/member/{成员}/self-check  body: {"wait":8}
        平台会**发一条测试消息**并给出结论（都是人话）：
          state=ok          通了（桥取走了 + 你的 agent 回话了）
          state=no_reply    桥取走了，但**你的 agent 没回话** ⇒ 多半是没配「叫醒命令」
          state=not_picked  消息还躺在邮箱里 ⇒ **桥没在运行**
          state=not_set_up  还没架桥（没有邮箱）
        ⇒ 拿到 no_reply/not_picked 时，按返回的 advice 做，再重跑自检。
```

**③ 把「手动跑桥命令」改对**（含编码坑与包装脚本）

```
【如果第 3 步自检说"桥没在运行"：这样起桥】
  · 起点：平台生成的桥脚本在**该成员的隔间目录**里（路径以平台返回的 compartment 为准，
    不要自己拼）：
        set PYTHONIOENCODING=utf-8
        <python.exe> -u "<隔间目录>\bridge.py"
    （★PYTHONIOENCODING=utf-8 必加：桥打印里有非 GBK 字符，不加会报
      `'gbk' codec can't encode`）
  · 要"叫醒"你的 agent：别把带空格的命令直接写进参数（会被拆坏，实测报
    `unrecognized arguments`）。**写一个包装脚本**，然后填它的路径：
        例（Windows）：新建 wake.cmd，内容：
            @echo off
            "<你的 agent 完整路径>" <参数>
        然后把 --trigger 指向这个 wake.cmd
```
