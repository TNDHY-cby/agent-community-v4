## 0. 一句话结论

> **平台让用户在"还没有任何 agent"的时候就建好了工作间，然后把用户丢在一个走不下去的岔口。**

顺序错了：**先要 agent，才能建工作间**。而现在反了。

## 2. ★结构性缺口（这才是"整体"的问题）

### 缺口一：平台允许"零 agent 开工"，却不在开工前拦一下
大厅的输入框只说「输入指令，例如：写一首关于秋天的诗」——
**它把这件事说成了聊天**，用户完全不会想到"我得先接一个 agent"。
平台**不检查**就建了工作间，把用户带进一条**注定走不通**的路。

### 缺口二：AI 选人失败时**沉默**（连"为什么"都不说）
实测：点「让平台 AI 选定员工」→ 名单 0 行、界面不动、Console 无报错。
真实原因大概率是"没有可用的 harness"（旁边那行小字是唯一线索，在另一个区块里）。
⇒ 用户唯一能得到的解释是**角落里一行灰字**。这违反老板定的**准则⑤「失败要说话」**，
也是他最初那句「**唤不醒、不回话**」的同一种病：**平台不说，用户只能猜**。

### 缺口三：界面**把后面几步的东西全摊在前面**
一级讨论阶段（用户只需要"聊"和"结束讨论"）时，右侧就摆着：
「📋 组长检查员工状态」「⬆️ 登记到资源库」「提交插话」「组长工作台」「插话栏」「Token 消耗…」
—— 这正是老板原话「**有一些按不了，我不知道怎么按**」的来源。
（我此前做的 `sidebar` 收敛**只落了后端**，右边栏这些**还没真收敛**。）

### 缺口四：阶段指示器**没跟着走**
点了「结束讨论」之后，标题仍显示「**一级讨论** · 10/11 15:59」，左侧也仍高亮 `01 一级讨论`，
而下一步条已经进入"选定员工"。⇒ 用户会怀疑"我到底走到哪一步了"。

## 3. 我判断的**优先级**（按"能不能用"排，不按好听排）

| 优先 | 做什么 | 为什么排这个 |
|---|---|---|
**P0** | **开工前先检查"有没有 agent"，没有就地引导（就地注册/接入）+ 说清"没有 agent 会怎样"** | 这是**路能不能走通**的问题；不解决，后面全是空中楼阁 |
**P0** | **AI 选人失败必须说话**：把后端真实原因（如"没有任何可用 harness"）显示在**点击处**，并给"去注册"按钮 | 准则⑤；也是老板最初抱怨的同一个病 |
**P1** | **右侧栏按阶段真收敛**（后端判据我已做好 `sidebar`，界面要接） | 直接对应「有一些按不了，我不知道怎么按」 |
**P1** | **阶段指示器跟着状态走**（结束讨论后标题/高亮应立刻变） | 用户判断"我在哪"全靠它 |
**P2** | 大厅文案：把"输入指令，例如：写一首秋天的诗"改成**说清这是"派活给 agent 团队"** | 消解"这是聊天框"的误解 |

## 4. 我接下来怎么做（不重复"机械"）

1. **先做 P0 两件**（能不能走通 > 好不好看），每件都按"陌生人走一遍"验收（真浏览器截图）；
2. 做之前**先跟老板对齐一句**：P0 第一件的做法有两种味道——
   **① 拦**（没 agent 就不让发布，先引导接入）/ **② 放行但明说**（允许建间，但显著提示"现在没人能干，先去接入"）。
   我倾向 **①+② 合起来**：**允许发布（不打断想法），但立刻在显眼处引导"先接入一个 agent，否则到选人这步会停住"**。
3. **不再用"模块+端点+测试"的老套路去套**：这次先改**用户看得见的那条路**，
   后端只在"必须由后端说清"的地方加（如选人失败的原因）。
