# V45 按接口引导（不同接口不同引导）· 契约

> **作者**：示例Harness-E ｜ **日期**：2026-10-13 ｜ **状态**：**已实施**（老板 2026-10-13 拍板原话：「可以，**不同接口不同引导**」）
> **来源**：`V44` #15 —— 五个真机回执暴露出「所有接口拿到同一套五步话术」会直接导致误读。
> **一处真相**：`agent_community/platform/interface_guidance.py`。后端响应、界面话术、文档都从它取（规则 20）。

## 1. 要解决的问题（不是"文案不好看"，是"会让人做错"）

| 实测现象（V44） | 后果 |
|---|---|
| `http_api` 的 harness（平台直推，**根本不需要桥**）被引导走完了桥的 3/4/5 步 | 白折腾；而且第 4 步的"已验证"会被读成"这条链路通了" |
| 第 4 步验的是 `pending_poll` 桥、第 5 步实际在跑 `file_poll` 桥 | **验的和跑的不是同一型**，`verified` 语义被污染 |
| `clipboard` 的 harness 被问"你的叫醒命令是什么" | 它根本没有这条命令（`mode:manual` 才是正常）—— 会让人以为接入失败了 |
| `http`（兜底）的 harness 以为"接上了" | 平台**只会落盘、不会叫醒**；没人轮询就永远躺着 |

## 2. 契约：每个叫醒方式各自的五步

`interface_guidance.BY_WAKEUP` 是唯一定义处。五步 = 注册 / 配叫醒 / 起桥 / 自检 / 持久跑桥。

| `wakeup_method` | 档位话术 | 第 2 步 | 第 3 步 | 第 5 步 | 桥型 | 活怎么到它面前 |
|---|---|---|---|---|---|---|
| `acp` | A 档·命令行 | **需要** | **需要** | **需要** | `cli_acp` | 进待取队列，桥用命令拉起会话去取 |
| `file_poll` | B 档·盯目录 | **需要** | **需要** | **需要** | `file_poll` | 写进它的目录，桥搬件与收回报 |
| `http_api` | C 档·常驻 HTTP | 不适用 | 不适用 | 不适用 | 无 | **平台直推**它的 HTTP 地址（不过桥） |
| `mcp` | B 档·MCP | 不适用 | 不适用 | 不适用 | 无 | 平台作为 MCP 客户端直调它的工具 |
| `http` | E 档·测不出来 | 不适用 | **需要** | **需要** | `pending_poll` | **只落盘、不叫醒**（没人轮询就一直躺着） |
| `clipboard` | D 档·人工中转 | 不适用 | 可选 | 可选 | `pending_poll` | 落盘 + **等人粘贴**（"敲门"得人来） |
| （未声明 / 不认识） | 未知 | 可选 | 可选 | 可选 | 无 | 如实说"平台不知道该叫醒它"，并给自测四项 |

每一步还各带四段"说人话"：
`what_to_fill_in_step2`（第 2 步填什么）、`how_tasks_arrive`（活怎么到）、
`how_to_keep_running`（怎么让它一直活着）、`platform_can` / `platform_cannot`（**平台能做到/做不到**，准则⑤）。

## 3. 接口面（两处，都是加字段，不破坏既有契约）

1. `POST /api/harness/register` 响应新增：
   - `interface_guidance`：结构版（`steps` / `step_labels` / `where_tasks_go` / `platform_can|_cannot` …）
   - `next_steps_text`：同一份的**纯文本版**（给"复制给 AI"的话术用，与结构版同源）
2. `POST /api/harness/{hid}/bridge/generate` 响应新增：
   - `wakeup_method` + `kind_warning`：**桥型与声明的接口对不上时说人话**（空串 = 匹配；**不禁止**，只提醒）

## 4. 界面（规则 20：一次全改）

`frontend/register.html` 的"一键复制给 AI"话术里，第 5 步的桥型选择由"三种都列"改为
**按接口分行的六行引导**，并写明"桥型与接口对不上时响应里会带 `kind_warning`，那不是报错"。

## 5. 守卫（防回退）

`agent_community/tests/test_v44_batch1_fixes.py`：
- `test_guidance_steps_differ_by_interface`：**逐个接口**断言"哪几步要做"（有牙：改回统一话术即红）
- `test_guidance_unknown_is_honest`：不认识的方式必须说"不知道"
- `test_guidance_flow_text_shares_one_truth`：文本版与结构版同源
- `test_kind_warning_speaks_on_mismatch`：不匹配要说话、**匹配时不许瞎告警**（防 alert fatigue）
- `test_register_response_carries_interface_guidance` / `test_bridge_generate_response_carries_kind_warning`：端点契约

**变异验证**：`temp/v44_mutation_check.py` 7 个定点变异 **7/7 KILLED**
（含"把 #15 的告警去掉"这条）。

## 6. 明确不做的

- **不改档位判定**（`tier_guidance.py` 的 A/B/C/D 是另一套老口径，本稿只做"按 `wakeup_method` 分引导"）；
  两套档位词表**并存**这件事本身是个待清理的口径债，见 §7。
- **不禁止**桥型与接口不匹配（用户可能有自己的理由），只**说话**。

## 7. 遗留（如实）

   五份回执里两种"档"都出现过 ⇒ 待老板定：**合并成一套**还是**明确分成两个概念**（本稿不擅自合并）。
2. `#16`（老进程 + 新模板无提醒）未做：`/api/status` 还没带"进程启动时间 vs 代码 mtime"。
