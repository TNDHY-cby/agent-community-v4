## 2. 等级判据（**写在代码里，可查可辩**）

四项：**是否全自动**（任务到 agent 面前要不要人）· **端到端延迟** · **常驻开销** · **链路环节数**。

| 等级 | 接口 | 该配的桥 | 延迟 / 开销 | 判据说明 |
|---|---|---|---|---|
| **S** | `http_api` | **不需要桥** | 秒级 / 无 | 平台直接 POST 到它的 HTTP 地址：环节最少、无落盘、无额外进程 |
| **S** | `mcp` | **不需要桥** | 秒级 / 无 | 平台作为 MCP 客户端直调工具 |
| **A** | `acp` | `cli_acp` | 5~15s / 一个常驻桥 | 全自动，但每次要拉起会话；多一个进程 |
| **B** | `file_poll` | `file_poll`（首选）<br>`pending_poll`（可用） | 2~5s / 桥 + 目录监听 | 桥投文件到目录，**多一环"你自己那份监听得活着"** |
| **C** | `clipboard` | `pending_poll` | 不可估 / 低 | 半自动：桥送得到门口，**"敲门"得人来** |
| **D** | `http` | `pending_poll` | 不可估 / 中 | 平台只落盘、**不叫醒**；没人轮询就一直躺着 |

> 为什么 `http_api` / `mcp` 比 `acp` 高一档：**它们根本不需要桥**。桥是"多一个常驻进程 + 多一环转发"，
> 也就是多一个故障面（V44 那批缺陷里，凡是桥相关的都出在这条链上）。

## 3. 接口 ↔ 桥型匹配（`bridge_fit` 五态）

| 结论 | 含义 | 谁会说这句话 |
|---|---|---|
| `best` | 就是首选 | 无告警（`kind_warning` 空串） |
| `ok` | 可用，但**非首选** | 给"提示："（不拦） |
| `redundant` | 该接口**本来不需要桥**（多一条多余链路） | 明说"能跑，但白多一个进程与故障面" |
| `mismatch` | 不是这一型该配的桥 | ⚠️ 提醒"**第 4 步验的和第 5 步跑的可能不是同一型**，`verified` 不能当链路通了" |
| `unknown` | 平台不认识这个接口 | 如实说不知道，请先确认叫醒方式 |

**原则：不禁止任何组合**（用户可能有自己的理由），但**必须说话**（准则⑤）。
