# V47 口径唯一化：接口 / 档位 / 等级，只留一套字母

> **作者**：示例Harness-E ｜ **日期**：2026-10-13 ｜ **状态**：**已实施**
> **来源**：老板 2026-10-13 一句「**最优解**」——批准我把上一轮挂出来的"三套词并存"这条口径债按最优方式解掉。
> **一句话裁定**：**字母只留给"接口适配等级"一套（S/A/B/C/D）**；"档位"这个词从系统里退休。

## 1. 病根（不是"文案不好看"，是同一个词指三个东西）

同一个"挡位"概念，系统里有**三份互相独立**的定义：

| 出处 | 那套字母 | 例子 | 实际含义 |
|---|---|---|---|
| `platform/tier_guidance.py` | **A/B/C/D** | "B 档 · MCP 工具补偿" | 老 V-15 的**接入路径分类**（ACP / MCP / 自建 / 插件市场）|
| `frontend/register.html` 自测题 | **A~E** | "选 **B**（盯文件夹）" | 只是"**你属于哪种接口**"的**问答编号** |
| `platform/bridge_catalog.py`（V46） | **S/A/B/C/D** | "`acp` = A 档" | **适配性 / 高效性**等级 |

后果实例：回执里那句「`http_api` 是 C 档，却走了桥的 3/4/5 步」——
"档"在同一份材料里既能指"接口类别"又能指"质量等级"，读的人只能猜。

## 2. 最优解（四条，一次改完）

1. **`wakeup_method` 是唯一的接口身份**（6 个值：`acp` / `file_poll` / `http_api` / `mcp` / `clipboard` / `http`）。
2. **老档位 A/B/C/D 降级为「事实判断」**（`tier_guidance.py`）：
   - `interface_class`：`has_command` / `watches_dir` / `has_http_api` / `manual_only` / `unknown`（**说事实，不造字母**）
   - `can_be_woken_by_platform`：**平台能不能自动叫醒它**（取代"X 档"的那句判断）
   - `needs_protocol`：要不要它自己补"能被接进来"的能力（插件引导仍保留）
   - `access_tier` 仅作**老落盘字段名**保留（只写不读、**不进任何文案**）
3. **自测选项 A~E → Q1~Q5**：它关心的是"你属于哪种接口"，不该占用字母；
   模板里明确写一句「**Q 编号不是等级**，等级只有 S/A/B/C/D 一套」。
4. **字母只留给适配等级**：`bridge_catalog.GRADES = ("S","A","B","C","D")`，
   判据仍是"是否全自动 / 延迟 / 常驻开销 / 链路环节数"。

| 注册模板 `register.html` | 自测四项改 **Q1~Q5**；五步话术里的"X 档"全改「（适配等级 X）」；索引块标注"只有这一套用字母"；加一句"Q 编号不是等级" |

## 5. 现在三套词的关系（一句话讲清）

> **接口**用 `wakeup_method`（6 个值）说；**能不能自动叫醒**用 `can_be_woken_by_platform` 说；
> **好不好、该配哪只桥**用适配等级 **S/A/B/C/D** 说。**"X 档"这个词不再出现。**

## 6. 遗留（如实）

1. `tier_guidance.py` 的**文件名**仍是老名字（内容已改口径）——保留是为了不动 import 面与老测试；
   真要改名是一次纯机械重构，等有别的理由时一起做。
2. `protocol.py` 里 `WakeupMethod` 的枚举值仍带**旧的示例注释**（拿某个真实 harness 的轮询目录举例），
   属**代码注释级**存量，清理属"全清"工作，不影响对外表达。
3. `harness_probe` 探到 `wakeup_method=http`（兜底）时，界面仍会说"先落盘、暂不叫醒"——
   这是**事实**，保留（不是档位词）。
