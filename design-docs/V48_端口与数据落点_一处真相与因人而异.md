# V48 端口与数据落点：一处真相 + 因人而异

> **作者**：示例Harness-E ｜ **日期**：2026-10-13/14 ｜ **状态**：**已实施**
> **来源**：老板 2026-10-13 两句话 ——
> 「**本地网址不应该引入**」（别把本机地址写进对外的东西里）
> 「**本地端口因人而异**」（端口是每个用户自己的事，产品不该焊死）。
> **一处真相**：`agent_community/platform_address.py`。

## 1. 病根（"同一件事六处各写一套"，规则 20 的又一例）

| 位置 | 原来怎么取默认端口 |
|---|---|
| `cli.py` | `DEFAULT_PORT = 9103` |
| `platform/server.py`（argparse） | `AC_PORT` 默认 **9103** |
| `platform/server.py::_platform_base_url()` | `AC_PORT` 默认 **18920** ← **同一个文件里两套** |
| `platform/bridge_template.py::_platform_url()` | 硬编码 `127.0.0.1:18920` 兜底 |
| `platform/verify_sandbox.py::_platform_url()` | 硬编码 `127.0.0.1:18920` 兜底 |
| `platform/protocol_catalog.py` / `gui.py` / `tools/watchdog.py` | 各自写 18920 |

后果：**用户换一个端口，平台自己生成的东西就全错** ——
桥模板里的示例命令、验证间的提示、目录里的端点示例、README 的 curl、
`hub.html` 的 5 个页内跳转（写死 `127.0.0.1:18920` ⇒ 点开 404）。

**同一族的第二个病**：数据落点。5 个模块（`memory` / `ai_external` / `local_ai` /
`bridge_wake` 兜底 / `identity`×4）把落点写死在包内 `data/`，不认 `AC_DATA_DIR`
⇒ 换目录或多实例时**运行数据被写回仓库**（实测：换了目录、设了 `AC_DATA_DIR`，
`agent_community/data/memory/` 照样长出来）。

## 2. 裁定

1. **端口只有一处解析**：`platform_address.resolve_port(explicit)`＝命令行 > `AC_PORT` > `DEFAULT_PORT`；
   越界/坏值退回默认（不崩）。六处调用点**全部委托**它（原函数名/常量名保留，不动调用方）。
2. **对外不许出现本机地址**：
   - 界面 → **相对路径**（`hub.html`）或 `location.origin`（`hub.js`）；
   - 文档 → `$PORT` / `<你的端口>` 占位；
   - 代码里的"示例端点" → **运行时**由 `base_url()` 生成。
3. **数据落点必须认 `AC_DATA_DIR`**：全部改为 `AC_DATA_DIR` 优先、回落包内 `data`；
   **老实例的数据位置不变**（没设环境变量时行为与之前一致）⇒ 无迁移。
4. **桥模板**：`--url` 默认值改 `_platform_url_default()`（跟随 `AC_PORT`）；
   持久桥的真实地址仍由平台在 `launch_hint` 里注入。

## 3. 实测验收（换目录 + 换端口，规则 19 的姿势）

```text
复制仓库 → D:\Temp\friend_sim3\agent-community
AC_PORT=34567  AC_DATA_DIR=D:\Temp\friend_sim3\acdata
python -m agent_community.platform.server
→ running v4.7.0
→ GET /api/protocols 的 http 端点 = http://127.0.0.1:34567/api   （跟着端口走 ✓）
→ 仓库内**不再生成** data/                                      （数据不落仓库 ✓）
→ memory / policy.json 落在 AC_DATA_DIR                          （隔离生效 ✓）
```

## 4. 守卫（全部验证过有牙）

`tests/test_v44_batch1_fixes.py` 新增：
- 端口三级优先级 + 坏值/越界退回默认；
- **默认端口只有一处定义**（防再冒出第二套）；
- 平台地址解析点**不许**硬编码本机兜底；
- 用户可见面（README / `hub.html` / `hub.js`）**不许写死端口**；
- 每个数据落点都要认 `AC_DATA_DIR`，**不许**再写死包内 `data/`。

`tests/test_protocol_catalog.py`：原断言写死 `"127.0.0.1:18920" in …`，改为
"等于解析出来的地址" + 新增"`AC_PORT` 一变端点就得跟着变"。

**变异验证**：`temp/port_mutation_check2.py` **6/6 KILLED**
（含"README 端口写回去""hub.html 写回 127.0.0.1""解析器给错值""兜底又硬编码"）。

## 5. 一条环境纪律（顺手记下来）

跑**全量** pytest 时，**在用的 18920 实例要停掉**（或用隔离实例）：
`agent_community/tests/conftest.py` 的 `guard_real_data_dir` 会比对真实 `data/` 指纹，
而在用实例会持续重写 `data/memory/task_memory.json`（大小不变、mtime 变）⇒
表现为"数据被污染"的**误报**（实测 2026-10-13：干净跑 `tests/` = 0 变化 exit 0；
带着在用实例跑全量 = 该文件 mtime 变 ⇒ 守卫报红）。**守卫本身没错，别为它放水。**

## 6. 遗留（如实）

- `bridge_templates/*/bridge.py.tmpl` 里仍保留 `os.environ.get("AC_PORT") or "18920"` 这一处兜底
  （脚本会被复制出包外运行，不能依赖包内解析器）——它有守卫约束（只允许出现在
  `_platform_url_default` 里）。
- `tests/` 下若干**测试内部**仍用 18920 当一次性端口（测试自带实例，不外露，属可接受用途）。
- `hub.js` 的页脚现在显示**本实例端口**（`location.port`），不再点名数字。
