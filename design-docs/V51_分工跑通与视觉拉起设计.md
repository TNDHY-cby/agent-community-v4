## 4. 判据与守卫（**按真结果写**）

> ### ★4.0 实现期用真机跑出来的三条**硬事实**（先看这个，它改了两处设计）
>
> ① **`-Verify` 必须在默认路径上**（判据从"我们送出了"升级为"读回来核对过"）。
>    实测：脚本打印了 `[inject] WM_PASTE -> class=… (15 chars)`（看起来成功），
>    而**受控靶子窗口自报文本框 `len=0`** —— **文本根本没落进去**。
>    ⇒ `launch(verify=...)` **默认 True**；`verified` 三态：`True` 读回一致 / `False` 读回不一致（`ok=False`）/
>    `None` 没能自证（目标无标准文本框，或调用方明确不要核对）—— 且 `detail` 会**明说"没有读回核对"**。
> ② **别解析人类可读的对齐格式**。`-List` 的列是 `{2,-28}` 宽度对齐，而 WinForms/Electron 的类名
>    **超过 28 字符** ⇒ 列间只剩**一个空格**；我第一版按"两个空格"切分，`class` 把 ` title=` 一起吃掉、
>    **title 解析成 None** ⇒ `options()` 永远报"0 个候选窗口"（界面显示没有可注入的窗口，实际有），
>    而 `launch()` 因为把 `-TitleLike` 交给脚本、不解析文本，照样能用 —— **两个结论打架**才发现。
>    ⇒ 改成正则解析，并用**当时那一行原文**做守卫。
> ③ **本 harness 进程树里合成输入到不了目标窗口**（`WM_PASTE` / `sendkeys` / `clipboard+CtrlV`
>    三种都"报成功、靶子 `len=0`"；同一窗口 `-List` 在 pwsh 起的进程里看得到、经 Python 起的看不到）。
>    ⇒ 这是**环境属性**（窗口站/完整性隔离），不是产品缺陷；它的价值是：**平台必须如实报失败**，
>    而这正是 §4.0① 保证的。端到端诚实性判据见 `temp/visual_launch_e2e.py`
>    （**报成功但内容没到 = FAIL**；如实失败 = PASS —— 所以两种机器上都能给结论）。

1. `options()` 在**没有会话名的成员**上必须**如实说"还没命名"**，不做任何注入尝试；
2. `launch(method="wmpaste")` 在**非 Windows** 上必须 `ok=False` + 文案含"不支持"（**不假装成功**）；
3. `launch(method="clipboard")` 必须**真的把载荷写进剪贴板**（真读回来比对），且 `need_human=True`；
   ⚠️这条顺带修掉一个**静默送垃圾**的老缺陷（见 §4.1）；
4. **找不到匹配窗口**时 `wmpaste` 必须 `ok=False` 且 detail 说明"没找到标题匹配的窗口"（不能返回成功）；
5. `GET visual-options` 必须**无副作用**（调用前后 `workshops.json` 指纹不变 —— 对齐 V17 审计教训）；
6. Windows 上：真起窗口 → `launch` → **读回核对**；无桌面环境**如实 skip 并说明**（见 `temp/visual_launch_e2e.py`）；
7. 突变检验：把"找不到窗口"改成就返回成功 ⇒ 守卫必须变红。

### 4.1 顺带修掉的**条 E**：剪贴板把中文写坏（旧的"剪贴板型唤醒"一直在送垃圾）

实测（2026-10-15）：`wakeup_bridge._set_clipboard("中文标记")` 之后，
剪贴板里是 `涓\ue15f枃鏍囪\ue187` —— **UTF-8 字节被按 GBK 解**的典型。
根因：Windows 分支用 `Set-Clipboard -Value $input` 把文本走 **stdin**，
而 **PS 5.1 按控制台输入码页解码 stdin**（中文 Windows = cp936）。
**而函数照常返回成功** ⇒ 中文 Windows 上「剪贴板型唤醒」（`V25` §5 那个"永远可用"的兜底档 f）
一直在送垃圾。修法：**不经 stdin**，把文本 base64 嵌进命令（命令全 ASCII），
在 PowerShell 里解回 UTF-8 再 `Set-Clipboard`；超长文本走临时文件。
（`tools/inject_window.ps1` 那条路走**命令行参数**，Windows 用 UTF-16 传递，**不受影响** —— 同一台机器上两条路的对照。）
