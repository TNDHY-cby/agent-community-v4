---

## 0. 为什么不是"投票"（照抄修订稿的核心结论，一字不改其实质）

- 多数投票有效的经典前提是 **Condorcet 陪审团定理**：投票者**相互独立**、且各自正确率 > 50%。
  我们的 agent 常常**共享同一批数据源 / 同构模型 / 相似检索路径** ⇒ 误差**高度相关** ⇒ 前提不成立；
  此时"多数"不是纠错，是**互相强化**。
- 无证据锚定时，辩论会退化成"我对/你错"的往复，**轮次越多越放大初始错误**。
- ⇒ 本设计的判定对象**不是"答案"**，而是**证据**（修订稿 §三）。
  这样每一步都**可计算、可审计**，且**不需要预先知道正确答案**。

## 1. 落在哪、怎么开（可开可关）

| 项 | 决定 |
|---|---|
| 位置 | **只在三级讨论（`ws.status == "review"`）**；一级/二级讨论**不出现** |
| 开关 | 工作间级 **`debate_enabled`**，**默认 `False`**（对齐老板既定优先级「自动兜底默认关」） |
| 谁来开 | 用户显式开（界面/API）；**平台不会自己开** |
| 开了之后 | 只在**触发阈值成立**时才真跑（§4）——开关是"允许"，阈值是"该不该" |
| 裁决落哪 | 作为一条 **`orchestrator`（平台 AI 身份）消息**写进 **zone=3**；**不改任何人的原话**、不删任何发言 |

## 2. 三个机制（修订稿 §二：缺一不可）

1. **论点独立性校验**：按**证据来源集合**算重叠度，同源者**合并降权**（见 §3）。
2. **证据驱动的迭代修正**：每轮强制「**观点 → 证据 → 推理**」三段；**无证据的断言不参与计分**；
   分歧点触发**新证据/工具调用**，而不是重复表态；收敛目标 **2–3 轮**。
3. **非共识决策**：不要求达成一致；用**轨迹评分**（评估整个过程）替代末轮多数投票。
   ⚠️ 修订稿的警告照单全收：**轨迹评分本身是新的黑箱** ——
   若评分只看"逻辑连贯/说服力"，**自洽的错误答案会套利**（把"票多者胜"换成"说得漂亮者胜"）。
   ⇒ 本设计的评分**只由可执行/可核对的东西构成**（见 §3.3），**没有"文采分"**。

---

## 3. 判定程序（修订稿 §三，落成可执行）

### 3.1 证据集与同源度

- 每条陈述带证据项 `{"kind": "url|doc|tool|file", "ref": "..."}`；归一成身份串 `kind:ref`
  （小写、去 `#fragment`、去尾部 `/`）后去重成集合 `E_i`。
- 两两重叠度用 **Jaccard**：`J(E_i,E_j) = |E_i∩E_j| / |E_i∪E_j|`（两边都空 ⇒ 视为 **不重叠**，
  因为"都没有证据"不该被当成"互相印证"）。
- `J ≥ 阈值`（默认 **0.5**）⇒ 判**同源**，合并成一个**簇**。

### 3.2 权重（同源降权）

- **一个簇的总权重 = 1**（两个同源 agent 同错，合并后总权重仍是 1，**不是 2**）；
- 证据互相独立的簇**各自保留权重 1**；
- **无任何证据**的陈述：权重 **0**（进 `unsupported` 计数，**不进结论候选**）；
- **与外部校验器冲突**的陈述（工具/计算返回与它互斥）：**直接扣分**，且**不进结论候选**。

### 3.3 评分（只有可核对的东西，没有文采分）

```
cluster_score = 可验证证据项数 − 与已有证据冲突项数 − 无证据断言数
```

- "可验证证据项"＝该簇证据里**被外部校验器/检索凭证确认过**的条数（`verified=True`）；
- 结论候选按 `cluster_score` 排序；**同分不出胜负时如实并列**（不硬选一个）。

### 3.4 置信度（**标注为启发式、待标定**）

```
evidence_share = 该簇去重证据数 / 全部去重证据数        （0 若全无证据）
score_share    = 该簇分 / 各簇正分之和                  （无正分则 0）
confidence     = clamp01(0.5 * evidence_share + 0.5 * score_share)
```

⚠️ **明确标注**：这是**启发式的、需要按场景标定的示意值**（修订稿对评分函数也是这个口径），
不许当成"概率"对外宣称。

### 3.5 终止条件（满足任一即收口）

| 条件 | 判据 |
|---|---|
| 证据链闭环 | 只剩一个簇，且它**没有**未解冲突 |
| 无新信息进入 | 本轮新增去重证据数 = 0 |
| 边际增益不足 | 新增可验证证据项 < `MIN_GAIN`（默认 1）|
| 轮次上限 | 轮次 ≥ **3**（修订稿：2–3 轮内闭环）|

### 3.6 输出（**四件套**，缺一不可）

`结论` + `置信度` + `关键证据` + `分歧点`（非共识也是合法结论）。

## 4. 触发阈值（成本闸门；修订稿 §四）

| 信号 | 是否触发了辩论 |
|---|---|
| 同模型多次采样答案分歧大 | 触发 |
| 多路检索结果互相冲突 | 触发 |
| 工具/计算返回与模型结论互斥 | 触发 |
| 错误代价高（金额/安全/不可逆）| 触发 |
| 简单事实查询、纯主观偏好 | **不触发** |

**成本（照抄，别装作免费）**：`总成本 ≈ N_agent × R_round × 单次上下文成本 + 检索成本`；
`N=3, R=3` 时仅生成 token 就 ≥ 单模型的 9 倍 —— 这正是**默认关**的原因。

## 5. 数据契约

### 5.1 陈述（成员回报里可带，缺省即"没有证据"）

```jsonc
{
  "claim": "一句话结论",
  "evidence": [{"kind": "url|doc|tool|file", "ref": "...", "verified": true}],
  "reasoning": "为什么这些证据支持这个结论"
}
```
⚠️ **不带 `evidence` 的发言仍然会被记录进讨论区，但计分权重为 0** —— 界面必须**如实显示"无证据"**，
不许把它显示成"参与裁决"。

### 5.2 裁决结果（写进 zone=3 的那条消息的结构部分）

```jsonc
{
  "round": 2, "threshold": 0.5,
  "triggered": true, "trigger_reason": "多路结论互斥",
  "clusters": [{"weight": 1, "speakers": ["..."], "score": 3, "evidence": ["url:..."]}],
  "ranking": [{"speaker": "...", "claim": "...", "score": 3, "verified": 2, "conflict": 0, "unsupported": 0}],
  "output": {"conclusion": "...", "confidence": 0.62,
             "key_evidence": ["url:..."], "disagreements": ["A 与 B 的证据集不相交且结论互斥"]},
  "stop": {"stop": true, "reason": "只剩一个簇且无未解冲突"},
  "notes": ["置信度是启发式示意值，需按场景标定"]
}
```

## 6. 判据与守卫（**按真结果写**）

1. **同源合并**：两人证据完全相同 ⇒ **一个簇、总权重 1**（不是 2）；
2. **独立保留**：证据不相交 ⇒ 两个簇、各权重 1；
3. **无证据 ⇒ 权重 0**，且进 `unsupported`，**不进结论候选**；
4. **与校验器冲突 ⇒ 扣分且不进候选**；
5. ★**这条最要紧**：**"多数但无证据"必须输给"少数但有独立证据"**（否则又回到投票定对错）；
6. 触发阈值：无分歧且低代价 ⇒ **不触发**；有互斥结论 ⇒ 触发；
7. 终止：轮次上限 / 无新证据 / 边际增益不足，三种都要能停；
8. 输出四件套齐全；
9. 证据身份归一：同一 URL 带不同 `#fragment` / 大小写不同 ⇒ **视为同一来源**；
10. 两边证据集都空 ⇒ **不算同源**（"都没有证据"不是"互相印证"）。

突变检验：把"同源合并"去掉、把"无证据权重 0"改成 1、把"冲突扣分"去掉 ⇒ 守卫**必须变红**。

---

## 7. 不做（防范围蔓延）

- ❌ 不做 OCR/CV、不做新模型接入；
- ❌ **不判"谁对"**（无 ground truth 时只按证据质量加权并**如实并列**）；
- ❌ 不自动开启（默认关）；不在轮次上不设上限；
- ❌ 不改任何人的原话、不删任何发言（裁决是**追加**一条消息）；
- ❌ 不引入第三方依赖（纯标准库，和 `procprobe` 同一条纪律）。

- ⚠️ **词汇对齐（规则 20）**：平台**已有**一套 `claim + evidence` 的既有词汇 ——
  `platform/handover.py` 的**完成声明**用 `{claim, evidence:{commit, file, test}}`。
  两者**不是同一件事、也不该合并**：
  | | 完成声明（handover） | 辩论陈述（debate） |
  |---|---|---|
  | 证据的用途 | 证明"这件事做完了" | 算**来源重叠度**（同源降权） |
  | 证据形状 | `{commit, file, test}`（做了什么） | `{kind, ref, verified}`（**来源身份**） |
  ⇒ 桥接方式：`kind` 是**自由文本**，所以直接把完成声明的 `file`/`commit` 当 `ref` 传进来即可
  （例如 `{"kind":"file","ref":"agent_community/platform/debate.py","verified":true}`），
  **不新增第二套字段名**。
