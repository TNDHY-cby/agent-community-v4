> 为什么没搬**都要**如实**写在继任者自己的隔间里 —— 不是"自动变聪明"，是"**交接不留黑洞**"。

## 0. 现状（都是源码事实，不是印象）

| 事实 | 出处 |
|---|---|
| 隔间目录名＝`<工作间目录>/<职位>_<成员id>/`（两段都过 `safe_part`：非法字符替换、去首尾点空格、单段 ≤48 字符） | `compartment.py::compartment_dir` / `safe_part` |
| 隔间里的**三个工作分区**＝`input/ output/ temp/`；另有两个**邮箱** `inbox/ replies/`（邮箱与分区**分开维护**：前者是寻址契约，后者是前端已知字段） | `compartment.py` 顶部常量 |
| **磁盘实况**的唯一事实源＝`inspect_compartment()`（只读、失败不抛），对前端暴露在 `GET /api/workshop/{ws_id}/compartments` | `compartment.py::inspect_compartment` |

⇒ 所以"继承"必须**新做**：要么把旧隔间的东西**移交给**继任者，要么允许显式指定"继承哪一个隔间"。

## 1. 选定方案（三选一，附理由）

| 方案 | 做法 | 结论 |
|---|---|---|
| A. **显式继承** | 替换/新增成员时给 `inherit_from=<旧成员id>`，平台把旧隔间产物**复制**进新隔间 | ★**选定（主路径）** |
| B. 自动继承 | 同职位新成员自动继承"最近一任同职位" | **本次不做**（见理由） |
| C. 只写交接文 | 只生成一份 `legacy.md`，不搬产物 | **并入 A**（A 里必生成 `legacy.md`，作为"搬了什么/没搬什么"的索引） |

**为什么不做 B（自动）**：
1. "最近一任同职位"是**猜**——工作间里同职位可能有多人（多员工并行），猜错就是**把别人的产物给了你**；
2. 与老板既定优先级「**自动兜底默认关**」一致：能由人一句话说清的事，不要平台替他决定；
3. 猜错的代价不对称：漏继承＝继任者手上没有上下文（可见、可补），错继承＝**他的隔间里混进别人的东西**（隐性污染，难发现）。
> 将来若要做 B：必须是**工作间级开关 + 显式确认**，且 `legacy.md` 要把"这是自动挑的来源"写在第一行。

**为什么用"复制"而不是"移动/软链"**：
- 隔间是成员**唯一可写**目录、且**跨通道存活**；移动会破坏"旧成员的历史原样可追溯"（审计要它）；
- 硬链接/符号链接跨平台不可靠（Windows / WSL / DrvFs 三种语义），而我们坚持不引第三方依赖 —— 复制是唯一"三平台同语义"的做法。

---

## 2. 口径（必须钉死的五条）

1. **继承是"追加"，不是"接管"**：新隔间的 `input/output/temp` 归属新成员；继承**只往里放东西**，
   **绝不删旧隔间**、**绝不改**旧成员的产物。
2. **来源必须留在继任者的隔间里**：新隔间根下写一份 **`legacy.md`**（继承文），写明
   "从谁继承 / 什么时候 / 搬了哪些 / 跳过了哪些与原因 / 哪些只是列了清单没搬"。
3. **搬完必须核对**（不是"我搬过了"）：逐文件核对**新隔间里存在且字节一致**；核对通过才算 `verified=true`。
4. **跳过要说原因**：超限 / 二进制 / 名字非法 / 读写失败 —— 每一条都进 `legacy.md` 的**未搬项**，
   并在接口返回里逐条列出（**不许静默丢**）。
5. **跨工作间禁止**：隔间属于工作间（`<ws_dir>/…`），`inherit_from` 指向别的间的成员一律**拒绝**并说明。

## 3. 落地点（数据与接口）

### 3.1 成员字段（落盘，重启不丢）

```python
# platform/workshop.py · WorkshopMember（追加字段，不动既有字段名/语义）
inherited_from: str = ""     # 继承来源的 member_id（空＝没有继承过）
inherited_at: float = 0.0    # 继承发生时间（epoch 秒）
inherit_note: str = ""       # 一句话小结（如「搬 12 项 / 跳过 2 项（超 5MiB）」）
```
`to_dict()` / `from_dict()` 同步（老数据缺字段⇒默认值，向后兼容；与 `debate_enabled` 同样的做法）。

### 3.2 继承文 `legacy.md`（写在**新**隔间根）

```markdown
# 继承文（隔间移交索引）

- 来源成员：`<旧 member_id>`（职位：<职位>，显示名：<名字>）
- 继承时间：2026-10-17 01:5x（+08:00）
- 由谁触发：用户（工作间 <ws_id>）
- 核对结论：**已搬运 12 项 / 跳过 2 项**（verified=true）

## 已搬运（逐项核对：存在且字节一致）
| 相对路径 | 字节 |
|---|---|
| output/plan.md | 1337 |
| library/assignment.md | 842 |

## 未搬运（如实列原因）
| 相对路径 | 原因 |
|---|---|
| temp/dump.bin | 超过单文件上限（5 MiB） |
| input/大表.csv | 超过总量上限（50 MiB） |

## 说明
- 本次**只复制**，旧隔间**原样保留**（`<旧隔间绝对路径>`），可随时回查。
- 本文件是**交接索引**，不是"完成声明"（那套词汇在 `platform/handover.py`），也不是辩论陈述（`platform/debate.py`）。
```

> ⚠️ **与 `V33` 的路径差异（规则 20：不留两套记忆结构）**：`V33` 建议继承文写
> `library/<agent名>-<职位>/legacy.md`。但本项目的真实结构里**没有工作间级的 `library/` 根** ——
> 成员的产物就在**他自己的隔间**里（`<ws_dir>/<职位>_<成员id>/`），
> 所以本稿把继承文落在**隔间根 `legacy.md`**，并**不新起** `gene_bank/`、也不新起 `library/` 根
> （否则"谁是真的记忆"立刻变成第二个口径）。

### 3.3 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/workshop/{ws_id}/member/{mid}/inherit` | body：`{"from_member_id": "...", "max_file_mb": 5, "max_total_mb": 50}` |
| `GET` | `/api/workshop/{ws_id}/member/{mid}/inherit` | 只读：`inherited_from` / `inherited_at` / `inherit_note` / `legacy.md` 是否存在与全文（≤ 32 KiB 截断并如实标注） |

`POST` 返回（**三态如实**）：

```jsonc
{"success": true, "verified": true,
 "from_member_id": "m_old", "to_member_id": "m_new",
 "moved": [{"path": "output/plan.md", "bytes": 1337}],
 "skipped": [{"path": "temp/dump.bin", "reason": "超过单文件上限（5 MiB）"}],
 "legacy_path": "<新隔间>/legacy.md",
 "note": "已搬运 12 项 / 跳过 2 项（详见 legacy.md）"}
```

失败也要说话：来源不存在 ⇒ `404` + `reason="工作间里没有这个成员"`；
跨工作间 ⇒ `400` + `reason="隔间属于各自的工作间，不能跨间继承"`；
磁盘错误 ⇒ `success=false` + `reason`（不抛栈）。
**`max_file_mb` / `max_total_mb` 是操作参数（可选），不是部署差异** ⇒
不做环境变量、不登记 `env_spec`（少一个只在特殊场景才改的旋钮，就少一份"我这台才有的配置"）。

审计：`_audit_log.record("workshop.member_inherit", actor="user", target=ws_id, detail=..., extra=...)`。

## 5. 判据（**按真结果写**，拍板后做成守卫）

| # | 判据（真跑） |
|---|---|
| 1 | 不传 `inherit_from` ⇒ 不搬、**不写** `legacy.md`、返回如实说"没有指定来源" |
| 2 | 指定存在的旧成员 ⇒ 每个产物在**新**隔间里**存在且字节一致**（逐项核对，`verified=true`） |
| 3 | `legacy.md` **必含**：来源 id、时间、已搬运清单、未搬运清单与原因 |
| 4 | **旧隔间原样保留**（继承前后，旧隔间的文件列表与字节完全不变） |
| 5 | 超单文件上限 ⇒ 进"未搬运"且原因可读；**不许**静默丢、不许让整体失败 |
| 6 | 超总量上限 ⇒ 同上（且**已搬的保留**，不是回滚——回滚会连"搬了一半"都看不见） |
| 7 | 指名不存在的来源 ⇒ `404` + 原因（**不**静默成功） |
| 8 | 跨工作间 ⇒ 拒绝 + 原因 |
| 9 | 幂等：对同一来源二次继承 ⇒ 已存在且字节一致的文件**不再重复堆叠**（如实报"已存在，跳过"） |
| 10 | 旧成员已被删除（harness 没了）但隔间还在 ⇒ **仍可继承**（隔间跨通道存活） |
| 11 | 端点只读版不写盘（`GET` 前后隔间文件列表与 mtime 不变） |

**突变检验（拍板后照 §6 做）**：去掉"逐项核对"（直接报 verified=true）、
把"跳过项"改成静默忽略、去掉"跨工作间拒绝" ⇒ 守卫**必须变红**（三处，逐一验收）。

## 6. 不做（防范围蔓延）

- ❌ 不做"自动挑继任者"（B 方案，见 §1 理由）；
- ❌ 不删旧隔间、不改别人的产物、不动 `input/output/temp` 的既有语义（`FE-03` 已按它渲染）；
- ❌ 不新起 `gene_bank/` 或工作间级 `library/` 根（一份记忆结构，见 §3.2 的 ⚠️）；
- ❌ 不引入第三方依赖（复制 + 哈希核对用标准库 `hashlib`/`shutil`）；
- ❌ 不做"隔间内容的语义摘要"（那是另一个功能：要不要让平台总结旧隔间，**等老板另外说**）。
