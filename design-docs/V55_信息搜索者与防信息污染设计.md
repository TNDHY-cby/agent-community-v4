# V55 · 信息搜索者与「防信息污染」设计

> **设计**：示例Harness-E（DSH 侧）｜ **日期**：2026-10-17 ｜ **状态**：**已拍板（老板 2026-10-17「最优解」＝按本稿建议的三点定稿）并已落地 v4.8.47**
> **老板 2026-10-17 口径**：「忘记这个（DSH 网页版），这个不太好。**依旧是 agent 去搜索吧**」
> ⇒ 平台**不内置搜索**，搜索这件事**交给 agent 成员**；平台只管**委派、收证据、收敛、再分发、留痕**。

---

## 0. 一句话

**搜索由 agent 做，平台不做爬虫**；平台把"一个 agent 搜回来的东西"变成**对别人无害的信息卡**：
有断言、有来源、有时效、有分档、有争议标记、**且不许把大段原文灌进别人的上下文**。

## 1. 现状核实（真源码，2026-10-17）

| 已有 | 在哪 |
|---|---|
| 派活 → 领活 → 回报 | `POST /api/workshop/{ws_id}/leader/assign`（派）／`POST /api/harness/pending-tasks`（领）／`POST /api/harness/task-result`（回） |
| **资源库（可复用）** | `ws.resources` + `POST/GET/DELETE /api/workshop/{ws_id}/resources`；字段 `{rid,name,kind(file/dir/link),path,note,uploader,task_node,created_at}`；`write_resources_manifest(ws)` 落盘；登记时**自动广播 notice**（zone=3） |
| 任务树挂载 | `node_id` ⇒ `node["resources"] += [rid]`（双向关联） |
| 陈述/证据契约 | `GET /api/protocol-brief` 的 `debate_statements`（V52，带 `evidence` 要求） |
| 审计 | `_audit_log.record("workshop.resource.add", …)` |

**缺的**：① 没有"检索委派"的任务形态（现在的 task 就是"干活"，没说"给我带证据回来"）；② 没有来源质量/去重/冲突的概念；③ 资源 `kind` 只有 `file/dir/link`；④ 无"限量再分发"约束。

## 2. 定位与边界（先说清不做什么）

**做**：委派检索 → 收**信息卡** → 收敛（去重/冲突/分档）→ 限量分发 → 留痕。
**不做**：不内置爬虫/搜索引擎；不做全网索引；**不做内容审核与改写**（不改用户与 agent 的原话）；**不做信誉分**（信誉机制仍暂停）；不替 agent 判断"谁对"（只把矛盾并列出来）。

## 3. 数据：信息卡＝**复用资源库**，不新造一张表

`ws.resources` 里的 `kind` 增一档 **`evidence`**，其余字段沿用，另加 `evidence` 子对象：

```jsonc
{
  "rid": "a1b2c3d4",
  "name": "CUDA 12.4 是否支持 sm_90a",          // 卡片标题（≤60 字）
  "kind": "evidence",                            // ★新增档
  "path": "",                                    // evidence 档不用路径（留空）
  "note": "一句话结论：支持，但需 12.4.1 补丁",   // 断言（≤120 字）
  "uploader": "m3",                              // ＝搜索者 member_id（谁带回来的）
  "task_node": "n_17",                           // 挂到哪个任务节点
  "created_at": "2026-10-17T18:00:00+08:00",
  "evidence": {
    "as_of": "2026-10-17",                       // 证据时效（必填）
    "confidence": "medium",                      // high / medium / low（自评，必填）
    "limits": "没查到 12.4.0 的官方说明",          // 没覆盖什么（必填，不许空）
    "sources": [
      {"url": "https://…", "title": "…", "publisher": "…",
       "quoted_at": "2026-10-17", "quote": "≤200 字摘录",
       "primary": true,                          // 一手/二手
       "paywall": false}
    ]
  }
}
```

**硬约束**：`sources` 至少 1 条、每条 `url` + `quote` 必填；`quote` **≤200 字**；整卡 `note+quotes` **≤1200 字**（超了平台**拒收**并说清怎么改）。这是"防污染"的第一道闸。

## 4. 防信息污染：平台只做**四件标注**，不改写内容

| # | 机制 | 规则（可机器判） |
|---|---|---|
| ① | **去重归并** | 同 `host` + 同 `title`（或 `quote` 相似度 > 0.9）⇒ 归并成一个来源组，卡片上显示「3 家转载同一稿」而不是 3 条"独立证据" |
| ② | **冲突标记** | 同一 `note`（同话题键）下，若两张卡的 `note` 互斥（搜索者自己标 `contradicts: [rid]`，或平台按关键词判到"支持/不支持"两种）⇒ 两张卡都挂 `disputed: true` 并互相链接 |
| ③ | **质量分档** | 每条来源按规则打分：`primary`（官方文档/一手发布）/`secondary`（媒体报道）/`marketing`（厂商营销页）/`anon`（无署名无日期）⇒ 卡片给**综合档**；只有 `marketing`/`anon` 的卡片，`confidence` 最高只能 `low` |
| ④ | **限量再分发** | 默认只把**卡片摘要**发给工作间（`note` + 来源标题列表 + rid）；**原文/摘录不广播**，谁要谁取 `GET /api/workshop/{ws_id}/resources?rid=` |

**不做的事（写死）**：不因"营销稿"就拒收，只**标档**；不因"有争议"就删卡，只**并列并标**；不改 agent 的原话。

## 5. 委派：检索任务的形态（复用现有 task，不新造状态机）

派活时 `payload` 增一个可选块（老成员不认也没关系）：

```jsonc
"payload": {
  "kind": "search_request",              // ★ 检索委派
  "question": "CUDA 12.4 支持 sm_90a 吗",  // 要回答什么（必填）
  "must_cover": ["官方文档", "发布日期"],   // 必须覆盖的方面（可选）
  "deadline_minutes": 30,                 // 超时就如实报"没搜完"
  "output": "evidence"                    // 要求交信息卡（不是散文）
}
```

**回报**：走现有 `POST /api/harness/task-result`，`result` 里放卡片字段（`name/note/evidence`），平台据此建 `evidence` 资源并广播摘要。

**失败要说话**：搜不到 ⇒ 回报 `status: "not_found"` + `tried`（搜了什么/哪里）+ `next`（放宽什么关键词/换哪个信息源）；
**不许**用"暂无相关信息"糊过去（沿用对接中心那七条手感项的同一口径）。

## 6. 端点草案（写码时才建，这里只定契约）

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/workshop/{ws_id}/search-request` | 委派检索（派给某个成员；带 question/must_cover/deadline） |
| POST | `/api/workshop/{ws_id}/evidence` | 交信息卡（校验 §3 硬约束 + §4 归并/冲突/分档，然后落 `ws.resources`） |
| GET | `/api/workshop/{ws_id}/evidence?node_id=&topic=` | 取卡片摘要列表（默认只给摘要，`?full=1` 才带摘录） |

> 都挂在 `workshops*` 端点组下（聚合器只做 `router.routes.extend`），审计沿用 `_audit_log`。

## 7. 判据（怎么证明它真做到了）

1. **换名换目录能跑**：换一个 `member_id`（搜索者）+ 换 `AC_DATA_DIR` ⇒ 卡片照样能建、能挂任务树（不写死）。
2. **三条污染样例必须被标出来**（这是本设计的核心判据，做成守卫）：
   - 样例 A「3 家转载同一稿」⇒ 归并成 1 个来源组，卡上写"3 家转载"；
   - 样例 B「两张卡互相矛盾」⇒ 两张都 `disputed=true` 且互链；
   - 样例 C「营销稿冒充一手」⇒ 综合档 `marketing`，`confidence` 被压到 `low`。
3. **限量再分发**：广播出去的 notice 里**不含 `quote` 原文**（守卫按真 notice 文本判，不查源码）。
4. **失败要说话**：`not_found` 回报必须带 `tried` + `next`，缺一即红。

## 8. 待老板拍板的三点

1. **要不要这层"信息卡"**（我建议要；不然搜回来的东西会以大段原文灌进工作间，就是"污染"本身）；
2. **`confidence` 谁来给**：搜索者自评（我建议）+ 平台按来源档位**压低上限**（不允许营销稿自评 high）；
3. **卡片要不要给"人"看**：我建议进对接中心/工作间的资源列表（复用现有资源 UI），**不为它单独做新页面**。

### 三条硬数字（落地时定死，改一处要跑守卫）

`quote ≤ 200` 字 / 整卡 `≤ 1200` 字 / 标题 `≤ 60`、结论 `≤ 120` 字；`sources` 至少 1 条且每条必须 `url`+`quote`；
`as_of`（时效）与 `limits`（没覆盖什么）**必填**。

### 四条标注（平台只标，不改写）

1. **去重归并**：同 host + 同标题（或摘录高相似）⇒ 一个来源组，卡上「N 家转载同一稿」（实测：3 家 ⇒ `source_groups=1`）；
2. **冲突标记**：`contradicts: [rid]` ⇒ 两卡都 `disputed=true` **互链**（实测互链 rid 正确）；
3. **质量分档**：`primary/secondary/marketing/anon`；只有营销/无署名时 `confidence` **被压到 low 并说明原因**
   （实测：自评 high → 生效 low，理由「来源里没有够硬的档位」）；
4. **限量再分发**：广播只有摘要（断言 + 来源组标题 + 置信 + rid），**不含摘录原文**（守卫按真广播文本判）。

### 实施期发现的一条真口径（原稿没写）

**`POST /api/workshop` 会把成员 id 生成成 `m0/m1…`**（传入的 `member_id` 被忽略）——
委派检索时要用返回后的真实 id，否则 404。这条以后写进 `design-docs/项目完整模型.md` 的端点说明里。

### 老板拍板的那三点（我的建议即定稿）

① 要这层信息卡；② `confidence` 由搜索者自评 + 平台按来源档位**压低上限**（不许营销稿自评 high）；
③ 卡片进**现有资源列表**，不为它单独做新页面。
