# V56 · 巡逻员：派人到现场看，别让用户先跑来

> **设计**：示例Harness-E（DSH 侧）｜ **日期**：2026-10-17 ｜ **状态**：**已拍板（老板 2026-10-17「按你的来」＝按本稿建议三点定稿）并已落地 v4.8.48**
> **来由**：`design-docs/项目完整模型.md` §11 最后一格欠账 ——「**巡逻员**（检测不到员工→前往查看维修）」**未实现**；
> 现在只有平台侧的「掉线抢救」，**没有"派人到现场"这一层**。

---

## 0. 一句话

现在链条是「平台自己试着调起 → 不行就**通知用户**」；缺的一环是中间那步：
**平台试过还不行 ⇒ 派一个"巡逻员"成员到现场看看到底怎么了，能修就修，修不了带证据回来再说。**

## 1. 现状核实（真源码，2026-10-17）

`platform/routers/workshops_recover.py`（253 行）+ `platform/member_offline.py`（纯逻辑）已经做到：

| 现有环节 | 实现 |
|---|---|
| 判定掉线 | 心跳口径；**没记录返回 `None`＝"无数据，不据此判掉线"**（不误伤） |
| 通知组长 | 讨论区 notice +（组长有 harness 时）派一条消息 |
| 尝试调起 | 重新派激活 `_activate_single` + **鼠标控制调起** `_activate_windows_by_pids` |
| 成功判据 | **不采信"我发出去了"**：只有**掉线判据真的消失**才算成功（准则⑤，这条要保留） |
| 通知用户 | notice + `entry_state=needs_human` |

**缺的**：平台试过仍不行时，**没有人去"看现场"**——它为什么起不来？（窗口没开／进程在但卡死／桥配置错／磁盘满／权限没了）
这些**只有能看本机事实的 agent 才答得出**，而平台自己只会"再试一次调起"。

## 2. 定位与边界

**巡逻员＝一个角色**（`role="巡逻员"`，需要 computer 工具丰富的成员），**不是一个常驻服务**——
避免又一套后台循环（后台循环是"看起来在跑、其实没人看"的温床）。

**允许它做的（只有三类动作）**：
1. 重新拉起窗口（复用 `visual_launch.launch`，含 `verified` 三态）；
2. 重启该成员的桥（复用既有桥命令与 `harness_bridge` 的状态口径）；
3. 重新派一次激活（复用 `_activate_single`）。

**不许做**：改代码、删数据、动别的机器、改别人的配置；
**做不到就说"我看不了"**（没 computer 工具/不是 Windows 的窗口相关项），不许猜。

## 3. 链条改动（在原链条里插一级，不改原有顺序）

```
员工掉线（判据为真）
  └─ ① 通知组长（不变）
  └─ ② 平台尝试调起（不变；成功即止，判据＝掉线消失）
  └─ ③ ★新增：派**巡逻员**到现场（平台试过仍不行且工作间里有巡逻员）
         · 现场检查单（只读优先）→ 允许的三类维修 → **复验** → 带证据回报
         · 巡逻员修好了 ⇒ 结束（判据同样是"掉线判据消失"，不是"它说修好了"）
         · 巡逻员修不了 ⇒ 把"为什么"写清楚，交回链条
  └─ ④ 通知用户（不变；③ 的 `still_broken_reason` 会附上，用户一上来就知道发生了什么）
```

**工作间里没有巡逻员** ⇒ 跳过 ③，**如实说明"这间没有巡逻员，只能 ②④"**（不假装派了人）。

## 4. 派活的形态（复用现有 dispatch，不新造状态机）

`payload.kind = "patrol"`：

```jsonc
{
  "kind": "patrol",
  "workshop_id": "…",
  "target_member_id": "m2",            // 掉线的那个员工
  "target_harness_id": "hid_…",
  "symptom": {"heartbeat": "stale 12m", "bridge": "running", "window": "未探测"},
  "allowed_actions": ["relaunch_window", "restart_bridge", "reactivate"],
  "report_endpoint": "/api/harness/task-result",
  "checklist": ["窗口在不在（标题含会话名）", "进程在不在（pid/命令行）",
                "桥心跳多久没动", "compartment 日志尾巴有没有报错", "磁盘/权限有没有明显问题"]
}
```

## 5. 回报契约（与信息卡同精神：**没有复验就等于没修**）

```jsonc
{
  "checked": [{"what": "窗口", "how": "visual_launch.list_windows", "result": "未找到标题含 ws-m2 的窗口"}],
  "found": "窗口根本没开，进程也不在；桥心跳停在 12 分钟前",
  "tried": [{"action": "relaunch_window", "result": "ok", "verified": true},
            {"action": "restart_bridge", "result": "failed", "why": "端口被占用"}],
  "fixed": true,                  // true / false / null（null＝**没自证**，必须配 why_no_proof）
  "why_no_proof": "…",
  "still_broken_reason": "…",     // fixed≠true 时必填
  "need_human": false,            // true 时附一句"用户要做什么"
  "evidence": {"after": {"heartbeat": "fresh", "window": "找到 1 个"}}
}
```

**平台侧判据**：`fixed=true` 但**掉线判据没消失** ⇒ 平台把这次标成 **`claimed_but_not_verified`** 并照旧升级到 ④，
审计里记明（**"它说修好了"不算修好"**，与现有"调起成功不采信我发出去了"同一口径）。

## 6. 端点草案

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/workshop/{ws_id}/patrol` | 手动派巡逻员（带 `target_member_id`、可选 `symptom`）；链条 ③ 内部也走它 |
| GET | `/api/workshop/{ws_id}/patrols?target_member_id=` | 看历史巡逻（每条带结论与证据） |

审计：`workshop.patrol.dispatch` / `workshop.patrol.result`（含 `claimed_but_not_verified`）。

## 7. 判据（写码时变成守卫）

1. **换名换目录能跑**：换巡逻员 `member_id`、换 `AC_DATA_DIR` ⇒ 照样能派、能回报；
2. **链条顺序不许乱**：①→②（成功即止）→③→④；**没有巡逻员时跳过 ③ 并如实说明**；
3. **不许"看起来修好了"**：`fixed=true` + 掉线判据仍真 ⇒ 必标 `claimed_but_not_verified` 且如实升级；
4. **没有电脑工具的巡逻员**：如实回报 `checked` 里写"看不了（无工具）"，`fixed=null`；
5. **只许三类动作**：`allowed_actions` 之外的动议（改代码/删数据）**拒收并回报**（守卫按真回报判）。

## 8. 待老板拍板的三点（我给了建议）

1. **巡逻员是"角色"还是"平台自动兜底"**？我建议**角色**（派活；平台只判定"什么时候该派"），
   这样能力/权限留在 agent 侧，平台不偷偷在别人机器上动手；
2. **什么时候派**？我建议**平台自己试过一次仍不行**才派（别一掉线就派人，省得刷屏）；
3. **修不了要不要让用户看细节**？我建议**给一句人话 + 可展开的 `still_broken_reason`**（用户不用读日志也能决定怎么办）。

### 落地时定死的口径（改一处要跑守卫）

1. **只许三类动作**：`relaunch_window` / `restart_bridge` / `reactivate`；别的动议**拒收**（422 说清）；
2. **三态如实**：`fixed` = true / false / **null（没自证，必须写 `why_no_proof`）**；`false` 必须写 `still_broken_reason`；
   `need_human` 必须写 `user_action`（"要你处理什么"）；
3. **"它说修好了"不算修好**：平台拿**自己的掉线判据**复核；`fixed=true` 但判据仍真 ⇒ `claimed_but_not_verified`，
   照样把 `entry_state=needs_human` 并给人话（实测：真 HTTP 上复核结果为 `claimed_but_not_verified`，**没被放过**）；
4. **只派一次 + 宽限期**：派出后 180 秒内 `action="awaiting_patrol"`，**不叫用户**——等它带回"为什么"；
5. **没有巡逻员就如实跳过**：`patrol.skipped=true` + 原因，照旧走原链条（409 端点同理，附 `how_to_fix`）。

### 老板拍板的三点（我的建议即定稿）

① 巡逻员当**角色**（派活），不是平台自动兜底；② **平台自己试过一次仍不行**才派；③ 修不了给**一句人话 + 可展开原因**。
