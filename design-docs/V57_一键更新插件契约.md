# V57 · 一键更新插件契约（给「宋」，2026-10-18）

> **状态：待老板拍板**（老板 2026-10-18 原话：「我让宋去做一个一键更新的插件出来，到时候别人就可以一键更新了，不用跑到仓库来部署」）
> 本稿只定**平台这一侧提供什么**＋**插件那一侧必须怎么做**，避免两边各自猜。

## 1. 目标（用户视角）

用户**不进仓库、不敲 git**：在自己装的平台上点一下（或跑一条命令），就升到最新版；
**数据不能丢**，升级失败要**明确报错并能退回**。

## 2. 职责切分（一条界线）

| 谁 | 负责 |
|---|---|
| **平台（本仓库，DSH）** | 如实回答"我现在是哪版、装在哪、数据在哪、更新该动哪里、要不要重启"；提供**受控重启**（待拍板） |
| **插件（宋）** | 去 Gitee 查最新 tag、下载、替换**安装目录**、重启、校验版本、失败回滚 |
| **不做的事** | 平台**不自己联网、不自己改自己的文件**（本地自部署平台给自己打补丁＝高危；出事也没人兜） |

## 3. 平台已提供：`GET /api/version`（只读、不联网）

```json
{
  "current": "4.8.61",
  "latest": null,                  // ★平台不猜远端：要 latest 由插件按 channel 自己查
  "update_available": null,        // ★没有 latest 就没有判断，如实给 null
  "channel": {
    "repo": "https://gitee.com/TNDHY-cby/external-agents-community",
    "releases_api": "https://gitee.com/api/v5/repos/TNDHY-cby/external-agents-community/releases/latest",
    "release_tarball_tpl": "https://gitee.com/TNDHY-cby/external-agents-community/repository/archive/{tag}.tar.gz",
    "tags_ref": "refs/tags/vX.Y.Z"
  },
  "install_dir": "<安装目录绝对路径>",
  "data_dir": "<数据目录绝对路径>",
  "update_safety": {
    "replace_install_dir_only": true,
    "keep_data_dir": true,
    "restart_required": true,
    "restart_endpoint": null        // 受控重启端点尚未提供（第 5 节，待拍板）
  },
  "notes": []
}
```

**契约要点**（插件必须遵守）

1. `current` 是**唯一版本真相**（等于 `agent_community.__version__`，与 CHANGELOG 最新条目由守卫锁定）；
2. `latest` / `update_available` 为 `null` 时**不许**当成"已是最新"，必须自己去查 `channel.releases_api`；
3. **只替换 `install_dir`**；`data_dir` 一律不动（用户的 harness、工作间、桥、日志都在里面）；
4. `install_dir == data_dir` 时（本机没分离）**必须先提示用户**再动 —— 否则升级＝删数据；
5. 判据：升级后 `current` 必须等于目标 tag，否则**回滚并明确报错**（不许"看起来成功"）。

## 4. 插件那侧的最小流程（建议）

```
1) GET http://127.0.0.1:<AC_PORT>/api/version          → current / install_dir / data_dir
2) GET channel.releases_api                            → 最新 tag（如 v4.8.62）
3) tag 比 current 新？否则"已是最新"并结束
4) 下载 channel.release_tarball_tpl.format(tag=tag) 解包到临时目录
   · 保留原 install_dir 的一份备份（或 git 里已有远端可拉回）
5) 停服务（看门狗会重拉 → 见第 5 节，先停看门狗或让看门狗重启后自动生效）
6) 用临时目录内容替换 install_dir（**排除 data_dir**；若 data_dir 在 install_dir 内，先提示）
7) 重启（受控端点或按平台文档的方式）
8) 再次 GET /api/version：current == tag ⇒ 成功；否则回滚到第 4 步备份，报错退出
```

## 5. 平台侧**还缺**的一件事（请老板拍板）

**受控重启端点**：`POST /api/admin/restart`（只有本机 + 已有 `AC_SERVER_TOKEN` 才能调；返回"已安排重启"，
由看门狗/启动器把它拉起来）。**为什么必须拍板**：这是唯一能让平台"停自己"的入口，属于安全面变更；
且重启方式与部署形态有关（前台进程 / 看门狗 / 计划任务）。

- 现状可用的替代：`GET /api/system/lifecycle` + `POST /api/system/shutdown`（已有，用于退出并关闭），
  重启＝退出后由 `tools/autostart.py` 装的看门狗/启动器拉起。
- 若拍板做 `POST /api/admin/restart`：我会把它做成**本地 + Token 双条件**，并在 `PRODUCTIZATION.md` 记一条安全说明。

## 7. 给宋的两个提醒（都是本仓库真踩过的坑）

1. **不要用 `.cmd` 写中文路径的重定向**（会静默失败）：本仓库的启动器因此改用 **PowerShell `.ps1` + UTF-8 BOM**；

   现在发布脚本里有版本闸门；插件也应照这个标准校验。
