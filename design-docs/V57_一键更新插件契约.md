## 1. 目标（用户视角）

用户**不进仓库、不敲 git**：在自己装的平台上点一下（或跑一条命令），就升到最新版；
**数据不能丢**，升级失败要**明确报错并能退回**。

## 2. 职责切分（一条界线）

| 谁 | 负责 |
|---|---|
| **平台（本仓库，DSH）** | 如实回答"我现在是哪版、装在哪、数据在哪、更新该动哪里、要不要重启"；提供**受控重启**（待拍板） |
| **插件（宋）** | 去 Gitee 查最新 tag、下载、替换**安装目录**、重启、校验版本、失败回滚 |
| **不做的事** | 平台**不自己联网、不自己改自己的文件**（本地自部署平台给自己打补丁＝高危；出事也没人兜） |

## 3. 平台已提供：`GET /api/version`（只读、不联网）

```json
{
  "current": "4.8.61",
  "latest": null,                  // ★平台不猜远端：要 latest 由插件按 channel 自己查
  "update_available": null,        // ★没有 latest 就没有判断，如实给 null
  "channel": {
    "repo": "https://gitee.com/TNDHY-cby/external-agents-community",
    "releases_api": "https://gitee.com/api/v5/repos/TNDHY-cby/external-agents-community/releases/latest",
    "release_tarball_tpl": "https://gitee.com/TNDHY-cby/external-agents-community/repository/archive/{tag}.tar.gz",
    "tags_ref": "refs/tags/vX.Y.Z"
  },
  "install_dir": "<安装目录绝对路径>",
  "data_dir": "<数据目录绝对路径>",
  "update_safety": {
    "replace_install_dir_only": true,
    "keep_data_dir": true,
    "restart_required": true,
    "restart_endpoint": null        // 受控重启端点尚未提供（第 5 节，待拍板）
  },
  "notes": []
}
```

**契约要点**（插件必须遵守）

1. `current` 是**唯一版本真相**（等于 `agent_community.__version__`，与 CHANGELOG 最新条目由守卫锁定）；
2. `latest` / `update_available` 为 `null` 时**不许**当成"已是最新"，必须自己去查 `channel.releases_api`；
3. **只替换 `install_dir`**；`data_dir` 一律不动（用户的 harness、工作间、桥、日志都在里面）；
4. `install_dir == data_dir` 时（本机没分离）**必须先提示用户**再动 —— 否则升级＝删数据；
5. 判据：升级后 `current` 必须等于目标 tag，否则**回滚并明确报错**（不许"看起来成功"）。

## 4. 插件那侧的最小流程（建议）

```
1) GET http://127.0.0.1:<AC_PORT>/api/version          → current / install_dir / data_dir
2) GET channel.releases_api                            → 最新 tag（如 v4.8.62）
3) tag 比 current 新？否则"已是最新"并结束
4) 下载 channel.release_tarball_tpl.format(tag=tag) 解包到临时目录
   · 保留原 install_dir 的一份备份（或 git 里已有远端可拉回）
5) 停服务（看门狗会重拉 → 见第 5 节，先停看门狗或让看门狗重启后自动生效）
6) 用临时目录内容替换 install_dir（**排除 data_dir**；若 data_dir 在 install_dir 内，先提示）
7) 重启（受控端点或按平台文档的方式）
8) 再次 GET /api/version：current == tag ⇒ 成功；否则回滚到第 4 步备份，报错退出
```

## 8. 我们（DSH）是怎么做的 —— **可直接借用，不必重写**

### 8.1 四步流程（动作在命令行，不在平台内部）

```
① 查版本    git ls-remote --tags（取 tag 真名）或 Gitee Releases API
            ↓ 比大小；查不到就**如实说**，不猜
② 记备份点  git rev-parse HEAD → 写 <AC_DATA_DIR>/update_state.json
③ 快进      git fetch --tags --force → git merge --ff-only vX.Y.Z
            ↓ 不是 fast-forward ⇒ **保持原状**并说清"强更要你自己决定"
④ 验版本    从**磁盘**读 agent_community/__init__.py；≠ 目标 tag ⇒ git reset --hard 回备份点
⑤ 重启（可选） 杀监听进程 → 看门狗 20~30s 拉回；没装看门狗则明说"现在跑的还是旧代码"
```

**为什么动作不放在 HTTP 端点里**：本地自部署平台给自己打补丁是高危动作，必须**用户在自己机器上主动执行**
（可回滚、可查看）。平台只回答版本事实（`GET /api/version`、`GET /api/version/latest`）。

### 8.2 五条不变量（每条都有真事垫底，建议插件照抄）

| 不变量 | 为什么 |
|---|---|
| **先备份点，再动手** | 没有备份点就没有回滚，失败只能重装 |
| **只走能回滚的路** | 不做"下载压缩包覆盖安装目录"（不可回滚）；只接受 git fast-forward |
| **数据目录一律不动** | 默认数据目录可能**就在安装目录之内**，覆盖式更新＝删用户数据 |
| **更新后必须验版本，不符自动回滚** | 否则"以为更新了其实没有"是最坏的假成功（本工具真踩过：读进程内模块缓存 ⇒ 刚成功却被判失败） |
| **工作树脏就不更新** | 用户的改动会被卷进冲突；宁可拒绝并说清怎么处理 |

### 8.3 插件调用契约：`tools/update.py --json`（v4.8.70 起）

```bash
python tools/update.py --check --json
# {"action":"check","current":"4.8.70","latest":"4.8.70","update_available":false,
#  "error":null,"safe":false,
#  "problems":["数据目录在**安装目录之内**（…）⇒ 更新会连带删掉数据；…"]}

python tools/update.py --apply --json
# 另加：applied / rolled_back / backup_head / restarted / steps[] / new_version / error

python tools/update.py --rollback --json
```

**退出码语义**（三态，别自己发明）：`0`＝做了/正常；`1`＝不行（安全闸或失败，`problems`/`error` 有原因）；
`2`＝查不到最新版（**不许当成"已是最新"**）。

**三条边界**：
1. **直接调** `tools/update.py`，**别在插件里重写下载/覆盖** —— 那会丢掉"可回滚"这个性质；
2. UI 上把 `problems` **原样显示**（尤其"数据目录在安装目录之内"，照做 apply 会删数据）；
3. 别给平台加"自己改自己"的 HTTP 端点；要重启就用 `--restart`（杀进程 → 看门狗拉回）。
