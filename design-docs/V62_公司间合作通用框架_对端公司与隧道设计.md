# V62 · 公司间合作通用框架：对端公司 + 隧道（不绑定任何穿透服务商）（2026-10-20）

> 老板 2026-10-20：「**把公司隧道合作的功能完善成通用框架，附带隧道使用方法教程到流程说明**」。
> 前情：V61 定了「frp 穿透 + 数据目录隔离」，P1（单机双实例 A2A 真投）已通、九格判据全绿。
> 本稿把"能投一次"升级成**可管理的通用能力**，并把"隧道怎么弄"写成**任何人照做都行**的教程。

## 1. 先把两半说清（避免又出现两套口径）

| 视角 | 语义 | 现有 | 本稿 |
|---|---|---|---|
| **别人来连我** | 我签发公司令牌给对方、登记对方公司、可吊销（吊销即刻入站 403） | ✅ 已有 `/api/companies`、`/api/company/token/*`（`routers/company_admin.py`） | 不动 |
| **我去连别人** | 我保存"对端公司"的名字 / **隧道地址** / 令牌；然后能验证、能派活、能查回执、能停用 | ❌ 只有环境变量 `AC4_PEER_URL` + 命令行 | ✅ **新增 `/api/peers`** |

> 一句话：**`/api/companies` 是"谁能进我家"，`/api/peers` 是"我要去谁家"。**

## 2. **隧道不是框架的一部分**（这是"通用"的关键）

框架只认一件事：**对端公司有一个 HTTP 地址**。

```
对端地址 = http://<host>:<port>        ← 只要这个能通，用什么方式弄出来的都行
             ↑
     直连公网 IP ／ frp ／ ngrok ／ 自建反代 ／ 内网同机 ／ …
```

- 平台**不内置**任何穿透客户端、**不保存**任何服务商的账号或地址；
- 平台提供的是**判断**与**说法**：你这台能不能被对端直接访问？不能就建议一种隧道方式，并告诉你"最后要给我什么"；
- 隧道挂了、地址变了 ⇒ **只改这一行的地址**，其余不动（这是"可移植"的判据）。

## 3. 对端公司数据模型（`<AC_DATA_DIR>/peers.json`）

```json
{
  "peers": {
    "co-b": {
      "peer_id": "co-b",
      "display_name": "公司 B（示例）",
      "base_url": "http://127.0.0.1:9104",
      "token_enc": "<加密后的令牌，落盘不回显>",
      "token_masked": "abcd…wxyz",
      "note": "同机第二个实例，跑在 9104",
      "created_at": "2026-10-20T09:00:00",
      "last_verify": {"at": "…", "ok": true, "detail": "读到 Agent Card：示例Harness-B公司"},
      "enabled": true,
      "tasks": {"<task_id>": {"title": "…", "sent_at": "…", "status": "working"}}
    }
  }
}
```

- 令牌**加密落盘**（复用 `platform/core/security` 的 DPAPI；非 Windows 明文回退并**如实告警**）；
- 列表接口**只回 `token_masked`**，任何接口都不回明文；
- 派过的任务在本地留一条索引（对端回执按需回查），**不在本地复制对端数据**。

## 4. 端点（新 `routers/peer_companies.py`）

| 端点 | 作用 | 关键约束 |
|---|---|---|
| `GET /api/peers` | 列出对端公司（含"上次验证结论"） | 只回打码令牌 |
| `POST /api/peers` | 登记对端：`{display_name, base_url, token?, note}` | `base_url` 必须是 http(s)、**不许带路径尾巴**；同 `peer_id` 幂等更新 |
| `POST /api/peers/{id}/verify` | **探活**：读对端 `/.well-known/agent-card.json` | **不需要令牌也能读卡**（A2A 规范）⇒ 验证不烧 token；返回"卡片里是谁" |
| `POST /api/peers/{id}/dispatch` | **派活**：`{title, task_id?}` ⇒ 对端 `tasks/send` | 令牌缺失/对端不可达 ⇒ **4xx 说清**；成功把 task_id 记进本地索引 |
| `GET /api/peers/{id}/tasks/{task_id}` | 查回执/状态 | 对端不可达时**如实报不可达**（不返回假的"进行中"） |
| `POST /api/peers/{id}/enabled` | 停用/启用 | 停用后**派活直接被拒**（403 + 怎么说） |
| `DELETE /api/peers/{id}` | 删除登记 | 只删本地登记，不影响对端 |

全部只接受**本机来源**（复用 `origin_allowed()`），并记审计 `peer.*`。

## 5. 隧道"该怎么办"的判断（`platform/tunnel.py`，纯建议，不动网络）

`advise(local_port, peer_url=None)` 返回：

```json
{
  "local_port": 9104,
  "reachable_from_outside": "unknown" | "likely" | "unlikely",
  "why": "本机监听在 127.0.0.1（只有本机能连）" / "监听在 0.0.0.0 但仍可能在 NAT 后面",
  "suggest": ["同机/同局域网：直接用 http://<这台机内网IP>:9104",
              "跨网络：任选一种隧道（frp / ngrok / 自建反代），把 9104 映射出去，得到 http://<域名或IP>:<端口>",
              "映射好后：A 侧只改 /api/peers 里的 base_url 一行"],
  "must_not_expose": ["平台管理端口（/api/config、/api/admin/*、/api/logs/*）", "静态管理页"]
}
```

判断依据只用**本机事实**（绑定地址、端口是否回环），**不探测外网、不发请求**。

## 6. 判据（扩 `tools/cross_company_check.py`）

在 P1 的九格之上，新增走**平台业务端点**的链（仍是两个真实例、不需任何隧道）：

| 格 | 判据 |
|---|---|
| ⑨ | `POST /api/peers` 登记 B（地址=本机 a2a）⇒ 列表里**只见打码令牌** |
| ⑩ | `POST /api/peers/{id}/verify` ⇒ `ok=true` 且带回"卡片里是谁"（不烧 token） |
| ⑪ | `POST /api/peers/{id}/dispatch` ⇒ 返回 task_id，且**B 侧真出现工作间** |
| ⑫ | `GET /api/peers/{id}/tasks/{task_id}` 能查到状态 |
| ⑬ | **停用后派活被拒**（403 且说明） |
| ⑭ | 错误令牌登记后派活 ⇒ **401/403 如实报**，本地索引**不写成功** |
| ⑮ | `tunnel.advise()` 对回环地址给出"只有本机能连"并给出三种建议；**不暴露管理端口**的提醒在列 |

## 8. 明确不做

- 不内置 frp/ngrok 客户端，不代管任何服务商账号；
- 不做"自动打洞"（NAT 穿透有可靠性代价，且会引入新依赖）；
- 不把对端公司伪装成本地员工（它就是"外部公司"，界面上分开显示）。
