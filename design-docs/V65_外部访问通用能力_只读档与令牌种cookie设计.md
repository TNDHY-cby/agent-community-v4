# V65 · 外部访问的通用能力：只读档 + 令牌种 cookie + 引导（2026-10-20）

> 起因：老板把平台经免费 HTTP 隧道开到了公网，外网 403（「服务未配置访问 Token」）。
> 技术定位见交接单，**但我要按"反私人定制"重写这件事的问题定义**：
> 这不是"老板那台机器的隧道怎么修"，而是**平台缺了三件通用能力**。

## 0. 纪律前置（这一条决定后面所有设计）

- **不认**任何域名、服务商、隧道名、机器路径（`agentcomm.owo.lat` / ChmlFrp / `D:\MCServer\frp-agent` **一律不出现在代码与判据里**）；
- **判据**：换一台机器、换一个端口、换一个域名、换一种穿透方式（frp / ngrok / 反代 / 直连公网），
  **不改一行代码** 走通；
- 只新增**环境变量**（登记 `env_spec`），不新增"某机器专用分支"。

## 1. 现在有什么、缺什么

| 已有（通用） | 缺 |
|---|---|
| `AC4_TOKEN`（`--token` 或环境变量，任选）+ `Authorization: Bearer` / `X-API-Key` / `?token=` | **"只给人看"这一档**：现在要么全开（能改配置/重启），要么全关 |
| `_is_localhost()` 放行本机、非本地必须带令牌 | **页面自己带令牌**：浏览器打开页面后，`/api/*` 请求不带令牌 ⇒ 一片 401（"能连上但用不了"） |
| `env_spec` 校验 + 文档生成 | **对外访问的引导**：怎么开、开哪档、https 怎么考虑、别暴露什么 |

## 2. 只读外部档：`AC_EXTERNAL_READONLY=1`

开启后，**非本地**请求：

| 类别 | 处理 |
|---|---|
| `GET` / `HEAD` 且路径在**只读白名单**里 | 放行（仍需令牌） |
| 任何写方法（`POST`/`PUT`/`PATCH`/`DELETE`） | **403** + `{"error":"外部只读模式：写操作已关闭", "how_to_fix":"…"}` |
| 只读白名单**之外**的 GET | **403** + 说清"这个端点不对外" |

**只读白名单（明确列举，不靠前缀猜）**：
`/api/status`、`/api/workshops`、`/api/workshop/*`（GET 详情）、`/api/peer-tasks`、`/api/peers`（GET）、
`/api/sessions`、`/api/audit`、静态页（`/`、`/index.html`、`/workshop.html`、`/docking.html`、`/hub.html`、`/ops.html`、`/booths.html`、`/handover.html` 与其 `.js/.css`）。

**明确不在白名单**（即使 GET 也不给）：
`/api/config`（含 AI 密钥的打码值也不该外露）、`/api/admin/*`、`/api/logs/*`、`/api/plugins`、`/api/policy`。

> 为什么用**列举**而不是"排除法"：新增端点时**默认不对外**（fail-closed），而不是默认对外。

## 3. 令牌种 cookie（解决"页面能开但用不了"）

浏览器打不开自定义头，所以：

- 外部访问时用 `https://<域名>/?token=<令牌>` 打开一次 ⇒ 服务端校验通过后**种一个同源 HttpOnly cookie**
  （名字 `ac_ext_token`，`SameSite=Lax`，`Secure` 仅当请求是 https）；
- 之后页面里的 `/api/*` 请求由浏览器**自动带**这个 cookie ⇒ `_auth_check` 也认它；
- **只对"校验通过的令牌"种**；令牌错误 ⇒ 401 且**不种**；
- 退出：访问 `/?token=` 空或 `DELETE /api/auth/logout`（新端点）清 cookie；
- **cookie 只是"携带方式"**，不是新凭据体系：值就是令牌本身，改令牌即失效。

**安全边界**：
- `HttpOnly`（JS 读不到）+ `SameSite=Lax`（跨站表单不自动带）；
- 走 https 时加 `Secure`；
- **日志与响应里绝不回显** cookie 值。

## 4. 引导（文档 + 界面话术）

- `PORTABILITY.md` 现有"对外访问"段落补一页流程：① 设 `AC4_TOKEN` ② 决定开哪档（默认只本机 / 只读对外 / 可写对外）
  ③ 隧道怎么弄（不推荐服务商，只说"最后给我一个 http(s) 地址"）④ **https 强烈建议** ⑤ 别暴露什么；
- **界面**：外部访问且未带令牌时，页面显示「需要访问令牌」输入框（前端负责），提交后走 `?token=` 种 cookie 的同一逻辑；
- 流程说明（V30）加一句指针。

## 5. 判据（`tools/external_access_check.py`，新）

| 格 | 判据 |
|---|---|
| ① | 未设 `AC4_TOKEN` + 非本地来源 ⇒ **403 且说清"服务未配置访问令牌"**（现状保留） |
| ② | 设了令牌、**外部来源**、带正确 `Authorization` / `X-API-Key` / `?token=` ⇒ 均 **200** |
| ③ | 令牌错 ⇒ **401**（与 403 区分：403=没配，401=配了但不对） |
| ④ | `AC_EXTERNAL_READONLY=1` + 外部来源 + 正确令牌 + **POST** ⇒ **403** 且 `how_to_fix` |
| ⑤ | 同上 + GET 白名单内（`/api/status`）⇒ **200** |
| ⑥ | 同上 + GET **白名单外**（`/api/config`）⇒ **403**（**不被令牌绕过**） |
| ⑦ | 本机来源 ⇒ **一切照旧**（只读档不影响本机） |
| ⑧ | `?token=` 正确 ⇒ 响应**种 cookie**（`Set-Cookie` 含 `ac_ext_token`）；令牌错 ⇒ **不种** |
| ⑨ | **通用性**：上面全部用随机端口 + 临时数据目录跑，代码里 grep 不到任何域名/服务商/机器路径 |

## 6. 明确不做

- 不做"某域名白名单"、"某服务商专用逻辑"、写死任何隧道地址；
- 不做"自动把管理面开到公网"的开关（那是用户自己的部署决定，平台只提供**档位与提示**）；
- 不把 https 交给平台解决（证书是部署方的事；平台只**建议**并检查 `Secure` cookie 的种法）。
