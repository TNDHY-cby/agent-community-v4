# V66 · 本地优先 + 中心中转（Local-first Hub）：每端都有完整平台，远程内容走服务器（2026-10-20）

> 老板 2026-10-20 的方向（原话）：
> 「**隧道镜像没啥用，最好还是像大厂做 APP 一样每个终端都有平台，需要远程内容通过服务器**」。
>
> 本稿把这句话落成架构与可验证的最小闭环，并明确它**替代**了 V61 里"用 frp 把平台映射到公网"那条路。

## 1. 一句话

**每个终端都跑一个完整的本地平台**（全功能、本机直接访问），
**只有当内容要跨终端/跨公司时才走"服务器"**——而**终端一律主动出站连服务器**。

```
┌───────────── 终端 A（家里那台）─────────────┐
│ 完整平台（18920，只监听内网/回环）           │
│   ├─ 工作间/员工/任务/隔间/审计（全功能）     │
│   └─ 中转客户端 ── 出站 ──┐                 │
└──────────────────────────┼──────────────────┘
                           ▼
              ┌──────── 中转服务器（Hub）────────┐
              │ 只做三件事：                     │
              │  ① 终端登记与在线状态            │
              │  ② 消息/任务转发（按终端 ID 投递）│
              │  ③ 暂存"待取"内容（有上限、会过期）│
              └──────────────┬──────────────────┘
                             ▲
┌───────────── 终端 B（公司/另一台）──────────┐
│ 完整平台（同版本，独立数据目录）            │
│   └─ 中转客户端 ── 出站 ──┘                 │
└─────────────────────────────────────────────┘
```

## 2. 为什么这比"隧道镜像"优（老板的判断是对的）

| 维度 | 隧道镜像（把 18920 映射出去） | 每端有平台 + 中转（本稿） |
|---|---|---|
| 开端口/公网 IP | 需要（或依赖第三方穿透服务） | **不需要**：终端只**出站** |
| 依赖 | 绑一个穿透服务商、依赖它的节点与域名 | 只需一台能被动连的机器（自己一台云主机即可） |
| 安全面 | 把**管理面**暴露给外网（我们已用只读档缓解，但仍是隐患） | 管理面**永不出网**；出网只有中转协议 |
| 断线表现 | 隧道挂了，页面打不开 | 本地平台**照常用**；只是"跨端"暂不可用 |
| 数据在哪 | 别人在打开你机器上的平台 | 数据在自己机器；Hub 只转发不存储私有数据 |
| 多端体验 | 一个实例被多人看（像"远程桌面"） | 每端各有完整实例（像 App：本地优先，云做同步） |

## 3. 三个角色与边界（**这条决定架构干净不干净**）

| 角色 | 住哪 | 干什么 | **不干什么** |
|---|---|---|---|
| **终端（Terminal）** | 用户自己机器 | 跑完整平台；主动连 Hub；收件箱落本地；发件走 Hub | 不监听公网端口；不需要公网 IP；不需要隧道 |
| **Hub（中转）** | 一台能被动连的机器（云/内网服务器） | 终端登记、在线状态、点对点转发、有限暂存 | **不存**工作间/审计等私有数据；**不执行**任务；**不代理**管理面 |
| **对端公司（Peer）** | 另一套终端+Hub | 与我们同构 | 同上 |

**Hub 的存储边界**：只存"待取消息队列"（`AC_HUB_QUEUE_MAX` 条 / `AC_HUB_TTL` 秒，默认 200 条 / 24h），
过期即丢；**不落业务数据**。要审计就审计"转发过多少条"，不审计内容本身。

## 4. 协议（最小可用，标准库即可实现）

终端 → Hub：**出站 HTTP(S)**，四个动作（都是终端发起的请求，Hub 从不主动连终端）：

| 动作 | 用途 |
|---|---|
| `POST /hub/register` | 登记：`{terminal_id, name, token}` ⇒ 上线 + 拿 `next_poll` 间隔 |
| `POST /hub/heartbeat` | 心跳（带 `since` 游标）⇒ 回 `{messages:[…]}`（**长轮询**，最多挂 25s） |
| `POST /hub/send` | 发一条：`{to_terminal, kind, payload}` ⇒ 进对方队列 |
| `GET  /hub/terminals` | 看有哪些终端在线（只给 ID/名字/最后在线，不给地址） |

- **身份**：`terminal_id`（用户起名，如 `home-desktop`）+ `AC_HUB_TOKEN`（共享密钥）；
- **传输**：JSON；长轮询（25s）比 WebSocket 更容易穿代理、更少依赖；
- **不做**"Hub 主动连终端"——那等于又开了一条入站通道。

## 5. 与已有能力的关系（别造两套）

| 已有 | 在 V66 里的位置 |
|---|---|
| 公司间合作 a2a（V61/V62/V63/V64，**点对点**） | **保留**：适合"两边都愿意暴露一个地址"的场景 |
| **V66 中转** | **新增主路径**：终端不出网也能跨端协作（经 Hub） |
| 外部访问只读档（V65） | **降级为可选**：有人就想给人看页面时才用；**不再是对外协作的推荐路径** |
| `AC_FRP_*` / `gen_frpc.py` | **标注为可选工具**（自建 frps 的人用），**不再是文档主推** |

> 一条铁律：**同一个"跨端派活"，只走一条路**——有 Hub 就走 Hub；没有 Hub 且双方都有可达地址才走 a2a。
> 界面上要显示"这条消息是怎么到对端的"（`via: hub` / `via: a2a`），不许含糊。

## 6. 分期（本轮做 M1，能自证）

| 期 | 内容 | 判据 |
|---|---|---|
| **M1（本轮）** | Hub 服务 + 终端中转客户端（注册/心跳/发/收）+ 本地收件箱 | `tools/relay_check.py`：**起 1 个 Hub + 2 个终端** ⇒ A 发 → Hub 转 → **B 真收到**；**终端侧零入站**（断言终端没有为跨端开监听）；Hub 重启后终端自动重连；错 token 401 |
| M2 | 把"派活/回执"跑在中转上（对外任务改走 Hub） | 与 V63 的外部任务打通，界面上标注 `via: hub` |
| M3 | 多公司路由（一个 Hub 下多家公司，按 company_id 隔离） | 公司间隔离判据 |

## 7. 判据（M1 九格）

| 格 | 判据 |
|---|---|
| ① | Hub 起来（随机端口 + 临时目录），`GET /hub/terminals` 返回 200 |
| ② | 终端 A 注册 ⇒ `GET /hub/terminals` 里出现 A（在线） |
| ③ | 终端 B 注册 ⇒ 两个终端都在 |
| ④ | **A 发给 B**：`POST /hub/send` ⇒ B 的长轮询**收到那条消息**（内容一致） |
| ⑤ | **终端侧零入站**：两个终端**都没有**为跨端监听任何端口（断言只做出站连接） |
| ⑥ | 错 token ⇒ 401（不许裸奔） |
| ⑦ | 发给**不存在的终端** ⇒ 明确 `queued_for_offline` 或 4xx（不假装送达） |
| ⑧ | Hub 重启 ⇒ 终端在下一轮心跳里**自动重连**（不需要人工干预） |
| ⑨ | Hub 暂存**有上限**（超上限按最旧丢）且**会过期**（判据用短 TTL 验证） |

## 8. 跨网络与 TLS（2026-10-20 补，老板：「不能只是局域网」）

**老板这句话点得准**：M1 判据全在 `127.0.0.1` 上跑，只证明了"逻辑对"，**证明不了跨网络**。
补了两件事：

### 8.1 跨网络可用性怎么验证（`tools/relay_crossnet_check.py`）

| 格 | 怎么验 |
|---|---|
| ① | Hub 绑**非回环地址**（优先 **Tailscale `100.x`**——那是真正穿透公网的 overlay 地址；没有则用内网 IP） |
| ② | 经该地址投递，内容逐字一致 |
| ③ | **WSL 侧当"另一台机器"**（不同网络栈）来注册 + 互达 —— 比同机回环强一档 |
| ④ | **TLS**：Hub 用 `--certfile/--keyfile` 起 HTTPS；**本机没有 openssl 时如实 SKIP**（不假绿） |

> ④ 那条写进判据的原因：**没见过真跨网络就别说"支持跨网络"**。没有证书就汇报"未验证"。

### 8.2 跨公网必须 TLS（代码已支持）

- Hub：`--certfile <pem> --keyfile <pem>`（或 env `AC_HUB_TLS_CERT/KEY`）⇒ 起 HTTPS；
  没给证书时**启动就打印警告**："当前是明文 HTTP，只适合内网/本机自测；跨公网请开 HTTPS 或前面放带证书的反代"。
- 终端：`https://` 地址默认**严格校验证书**；两种补充：
  - `AC_HUB_CA_FILE=<pem>`（推荐：自签证书也能安全校验）
  - `AC_HUB_INSECURE=1`（**只给自签自测**，跳过校验，风险自负）
- **为什么必须**：跨公网明文传 `Authorization: Bearer` 等于把钥匙贴在网上。

### 8.3 真跨公网怎么跑（部署三步，与具体服务商无关）

1. 找一台**能被公网连到**的机器（云主机/有公网 IP 的服务器）跑 Hub：
   `python tools/relay_hub.py --port 9400 --certfile hub.crt --keyfile hub.key`；
2. 各终端在自己机器上设三样：`AC_HUB_URL=https://<那台机器的域名或IP>:9400`、
   `AC_HUB_TERMINAL_ID=<自己起的名>`、`AC_HUB_TOKEN=<同一个密钥>`（自签证书再加 `AC_HUB_CA_FILE`）；
3. 重启终端平台 ⇒ `/api/relay/status` 里 `connected=true`。

**终端的网络环境不需要任何改动**：不需要公网 IP、不需要开入站端口、不需要隧道。

## 9. 明确不做

- 不做"Hub 主动连终端"（那是在 Hub 上开入站，问题原样搬过去）；
- 不做"Hub 存业务数据"（它不是云备份；要备份是另一件事）；
- 不做"自动选路"（有 Hub 用 Hub、没有才 a2a，规则写死，界面上标出来）；
- 不绑任何具体服务商（Hub 就是一份能跑在任何人机器上的代码）。
