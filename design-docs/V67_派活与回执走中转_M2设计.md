# V67 · 派活与回执走中转（M2）（2026-10-20）

> 承接 V66：中转（Hub）已经能"两台终端互发消息"。
> 但**派活**还走点对点 a2a（`/api/peers/*/dispatch`，要求对方地址可达）。
> 本稿把"派活/回执"也搬到中转上——**从此跨端协作不需要隧道、不需要对方可达**。

## 1. 用户要办的事

1. 在**对接中心**登记一个"外部公司/另一台终端"（只需要它在 Hub 上的 `terminal_id`，**不需要地址**）；
2. 点「派活」⇒ 内容经 Hub 送到对端；
3. 对端**真的建成一个工作间**（不是只收到一条消息）；
4. 对端干完/状态变了 ⇒ 回执经 Hub 回到本侧，**本侧那条外部任务自动更新**。

## 2. 两条消息（协议就这两个，别再加）

| `kind` | 方向 | payload | 对端怎么处理 |
|---|---|---|---|
| `task.assign` | 发起方 → 执行方 | `{title, workshop_id?, pt_id, from_terminal, from_name}` | **建工作间**（等同"接到一趟外来的活"）+ 回一条 `task.ack` |
| `task.result` | 执行方 → 发起方 | `{pt_id, status, detail, artifacts?}` | 更新本侧外部任务记录（状态/时间线/产物清单） |

- **`pt_id` 是发起方生成的外部任务号**，随消息走一趟往返 ⇒ 回执能**精确对上**本地那条记录；
- 只有这两条 + M1 已实现的纯文本（`kind=text`）；**不做**第三次握手的复杂协议。

## 3. 关键设计：**收到就要办，不能只落收件箱**

M1 的收件箱是"存下来给人看"。派活不一样——**收到就要执行**。
所以给终端客户端加一个**消息处理钩子**：

```
relay_client 收到消息
  ├─ kind=text        → 只落收件箱（人看）
  ├─ kind=task.assign → ① 建工作间 ② 落收件箱 ③ 回 task.ack
  └─ kind=task.result → ① 更新本侧外部任务 ② 落收件箱
```

- 钩子在**平台进程内**注册（`platform/relay_handler.py`），**串行执行**（避免并发建间打架）；
- **处理失败必须说话**：把失败写进收件箱该条消息的 `handled` 字段（`ok/failed + 原因`），
  并在审计里记 `relay.handle.failed`；**不许静默吞掉**（否则发起方以为派成了）。

## 4. 端点（在 `/api/relay` 那组里扩）

| 端点 | 作用 |
|---|---|
| `POST /api/relay/dispatch` | **经中转派活**：`{to_terminal, title, workshop_id?}` ⇒ 生成 `pt_id`、建本地外部任务（`via=hub`）、发 `task.assign` |
| `GET  /api/relay/inbox` | 已有（加 `handled` 字段显示处理结果） |

- `via` 字段：`hub` / `a2a`——**界面必须显示**这条活儿是怎么走的（V66 §5 的口径）；
- 派活成功后本地立刻有一条 `status=sent, via=hub` 的外部任务（复用 `peer_tasks`，不另造一套）。

## 5. 与点对点 a2a 的关系（别造两套）

| 场景 | 走哪条 |
|---|---|
| 对端在同一个 Hub 上 | **走中转**（`/api/relay/dispatch`）——不需要对方地址 |
| 对端没有 Hub、但给了可达地址 | 走 a2a（`/api/peers/*/dispatch`） |
| 两边都行 | **优先中转**（一条链路、一处真相） |

两条路都写进同一张外部任务表（`peer_tasks`），只差 `via` 字段 —— 界面/看板不用写两套。

## 6. 判据（`tools/relay_dispatch_check.py`，八格）

| 格 | 判据 |
|---|---|
| ① | 两个终端 + 一个 Hub 起来，都 `connected=true` |
| ② | A `POST /api/relay/dispatch` → 本地立刻有外部任务（`status=sent, via=hub`） |
| ③ | **B 侧真建出工作间**（标题一致），且 B 回了一条 `task.ack` |
| ④ | 本侧收件箱里能看到这两条消息（`text`/`ack`），且 `handled.ok=true` |
| ⑤ | 模拟 B 完成后发 `task.result(status=done)` ⇒ **A 侧那条外部任务自动变 `done`**（不用点刷新回执） |
| ⑥ | 给**不存在的终端**派活 ⇒ 如实 `online=false` + 本地任务仍标 `sent`（**不标成功**） |
| ⑦ | 处理钩子失败时**有痕迹**：故意发一条坏 `task.assign`（缺 title）⇒ 收件箱该项 `handled.ok=false` + 审计有 `relay.handle.failed` |
| ⑧ | 全过程中**两个终端都没有对外监听**（复用 M1 的口径：只绑回环也行） |

## 7. 明确不做

- 不做"重试/补偿队列"（Hub 已有队列上限与过期；失败就如实标，不做隐形重试）；
- 不做"派活给公司内的员工"（那是工作间内部流程，与中转无关）；
- 不把中转当成"能保证送达"的通道（它只保证"进了队列"，界面文案要照这个说）。
