# V72 · 双击到大厅：启动器（先播过场 · 并行加载 · 自动进大厅）设计

> 状态：**待老板拍板**（2026-10-21 起草）。老板原话：
> 「双击后没有反应，我要双击后**先播放动画**，**同步加载进程**，然后**自动弹出平台大厅**」。

---

## 1. 现在是什么、为什么"没反应"（先说事实）

**桌面快捷方式** `D:\Desktop\启动合作社.lnk`（2026-10-17 建）指向：
`…\external-agents-community\启动合作社.cmd`（**另一个副本**，1115 字节）——**不是**开发副本。

〔实测〕那个 cmd 的行为链：

1. 硬编码一个**第三方应用自带**的 python（`…\Tencent\Marvis\…\python311\python.exe`）——
   换台机器就没有（**私人定制**，违反产品化准则）；
2. 起服务：`start.py --no-gui`（**在错的副本里**，数据目录也就是那份副本的）；
3. 然后 `foreach(1..30)` **静默等** `GET /api/status`，最长 **30 秒**；
4. **等到了才**开浏览器：`Start-Process http://127.0.0.1:18920/?boot=1`。

⇒ 两个体验缺口，正好对上老板的三句话：

| 老板要的 | 现在的行为 |
|---|---|
| 先播动画 | 动画（`boot.js`）**要等服务起来、页面能加载后才播**；冷启动这 30 秒**屏幕上什么都没有** |
| 同步加载 | 是串行体感：先静默等，再开页面 |
| 自动进大厅 | 服务起不来 ⇒ **永远不开浏览器**，且**没有任何提示**（最小化窗口一闪，等于没反应） |

〔已实测〕18920 **已经在跑**时双击，这台机器上确实会开浏览器（我复现过：spawn 了 powershell，随后 msedge 起来）。
所以"没反应"发生在**服务没起/起失败**的那条路径上 —— 那条路径**没有任何可见反馈**。

〔实测补充〕开发副本自带 `启动合作社.cmd`（9658 字节）是**带控制台窗口**的老启动器
（读 `deploy/.env` → 选解释器 → 依次起平台/A2A/grpc → 过看门狗 → `cli start --gui` 开 pywebview 窗口 → `pause`）。
它**不是**老板要的形态：有黑框、要敲键、没有过场、也不是浏览器大厅。

## 2. 目标（验收就照这三条 + 一条兜底）

1. **双击立刻有画面**：≤1 秒出现工业 HUD 过场（不是白屏、不是黑框、不是等 30 秒）；
2. **动画与加载并行**：过场里显示**真实阶段**（⑨ 见 §4），不是假装进度；
3. **就绪即进大厅**：健康检查通过后**自动**跳到平台大厅（无需点任何东西）；
4. **失败要说话**：起不来就把「为什么 + 怎么办 + 日志在哪」**显示在同一个页面上**，并给「重试」按钮。
   **绝不出现"双击后什么都没发生"**。

---

## 3. 方案（为什么不是改 cmd）

`cmd` 做不了过场，也做不了"页面轮询自己的状态"——所以引入一个**启动器进程**：

```
双击 .lnk → 启动合作社.cmd（无窗口，秒退）
              └─ 拉起 pythonw tools/launcher.py
                    ├─ ① 立刻在本地起一个**只服务过场页**的临时 HTTP 服务（端口临时选，0 = 让系统给）
                    │     └─ 打开浏览器到 http://127.0.0.1:<临时端口>/  ← 动画从这里播
                    ├─ ② 同时（并行！）在后台拉起平台：<解释器> -m agent_community.platform.server
                    │     （隐藏窗口，stdout/stderr 落 data/logs/launcher_*.log）
                    ├─ ③ 轮询 GET /api/status 判健康（可配置 60s 上限）
                    └─ ④ 过场页每 400ms 拿一次 /state（**同源**，无需 CORS、不需要改平台）
                          · starting（带阶段文字）→ 继续播
                          · ready   → 页面跳 http://127.0.0.1:<平台端口>/   （大厅）
                          · failed  → 页面显示 原因 + 怎么办 + 日志路径 + [重试]
```

要点：

- **临时端口**：不写死任何端口；平台端口仍按现有口径解析（`AC_PORT` > 活着的 PID 记录 > 默认），
  **不新增第二个端口约定**；
- **同源轮询**：过场页与 `/state` 都由启动器自己提供 ⇒ 不用给平台加 CORS，也不动前端契约；
- **过场页复用现有视觉**：只读加载 `agent_community/frontend/boot.css` + `boot_emblem.png` / `boot_gear.png`
  （美术与样式**仍是前端的**，我不复制一份 CSS）；
- **动画播完≠就绪**：过场的最长播放时长固定（约 4.5s，`prefers-reduced-motion` 下直接结束），
  但**跳大厅的条件是健康检查通过**：慢机器上过场停在最后一帧并显示「仍在启动…（已 12 秒）」，不假绿；
- **重复双击**：启动器先探端口，平台已在跑 ⇒ 过场页拿到 `ready` 立刻跳大厅，**不重复拉进程**；
- **不自启**：常驻/开机自启仍归 `tools/autostart.py`（V57 已有），本稿不碰。

## 4. 过场页与 `/state` 契约（启动器内部，唯一）

`GET /state` → 200，JSON：

```jsonc
{
  "phase": "starting",          // starting | ready | failed
  "step": 2,                    // 0..6，见下表
  "text": "正在拉起平台服务…",   // 一句人话（页面直接显示）
  "hint": "",                   // 仅 failed 时有：怎么办
  "log_path": "…\\data\\logs\\launcher_…log",  // 仅 failed 时有
  "elapsed_ms": 3400,
  "platform_url": "http://127.0.0.1:<平台端口>/"   // ready 后给（端口是运行期解析的）
}
```

| step | text（口径） |
|---|---|
| 0 | 读取启动配置 |
| 1 | 选择解释器 |
| 2 | 正在拉起平台服务…（已 N 秒） |
| 3 | 等待端口就绪 |
| 4 | 等待健康检查通过 |
| 5 | 就绪，正在进入大厅 |
| 6 | 失败 |

## 5. 失败分支（每一类都要有具体下一步，不许一句"启动失败"）

| 情况 | 页面说什么 | 怎么办 |
|---|---|---|
| 找不到能跑平台的解释器 | 这台机器上没找到装好依赖的 Python | 装依赖：`python -m pip install -r requirements.txt`，或在 `.env` 里指定解释器路径 |
| 端口被别的进程占着（且不是平台） | 端口 NNN 被别的程序占着 | 关掉那个程序，或设 `AC_PORT` 换个口 |
| 进程起来又退了 | 平台启动后立刻退出（已把最后 20 行日志贴出来） | 按日志里第一条错误改；日志在 `data/logs/launcher_*.log` |
| 60 秒还没健康 | 启动超时（服务可能很慢，也可能卡住） | 看日志；或直接 `python -m agent_community.platform.server` 在控制台跑一次看报错 |
| 浏览器打不开（无默认浏览器） | 已启动成功，但没法自动打开浏览器 | 手动打开 `http://127.0.0.1:<端口>/`（页面上给出可点地址） |

### 6.1 为什么双击入口是 `.vbs` 而不是 `.cmd`

1. `.cmd` 由资源管理器启动**必然闪一下黑框**；`.vbs` 由 `wscript.exe` 跑，**完全没有窗口**；
2. `.cmd` 里找解释器只能靠 `where`/`%~$PATH:P`，而**这台机器 PATH 上的 `python.exe` 是应用商店别名**
   （一跑就退、什么都不干）⇒ 表现就是"双击没反应"。`.vbs` 能用 `Run(...,0,True)` 的**退出码**逐个试，
   试到真的能 `import sys` 的才算数；
3. 两层都**不写死路径**：仓库位置由脚本自身位置算出来，解释器由 `deploy/.env` 或系统提供。

### 6.2 浏览器：**用哪个由配置说，代码不绑定任何一家**

老板 2026-10-21：「**启动后使用火狐浏览器**」。

- 配置：`AC_LAUNCHER_BROWSER=firefox`（写可执行文件名或绝对路径都行；**空 = 系统默认浏览器**）；
- 查找顺序：PATH → 注册表 `App Paths` → 常见安装目录（**按你给的名字找**，代码里不写死某个品牌）；
- 找不到就**回落系统默认**，再不行就弹对话框给出可点的地址 —— 不假装成功；
- 本机落在 `deploy/.env`（部署配置，不进仓库），所以**换台机器/换个人只改这一行**。

### 6.3 启动器不常驻

过场页一跳到大厅，启动器就没人看了 ⇒ **页面 20 秒没有请求就自己退出**（没开成浏览器时放宽到 300 秒，
失败页留 180 秒给人读）。不留后台常驻进程，也不占端口。

## 7. 判据（可执行）

1. `tools/launcher_check.py`（新）——**真跑**：
   - 冷启动：杀掉平台 → 跑启动器 → 断言「过场页 1 秒内可访问」「`/state` 阶段单调前进」「最终 `phase=ready`」→ 断言大厅地址 `GET /api/status` 200；
   - 已在跑：再跑一次启动器 → 断言**没有**第二个平台进程、`phase` 立刻 `ready`；
   - 端口被占：先占一个口再跑 → 断言 `phase=failed` 且 `hint` 非空（**不许只说失败**）；
   - 换端口 / 换数据目录（`AC_PORT` / `AC_DATA_DIR`）→ **不改一行代码**同样走通（产品化判据）；
   - 解释器缺失：用 `AC4_PYTHON` 指向不存在的路径 → 断言 `failed` + 给出安装命令。
2. 桌面侧：`python tools/make_shortcut.py --check` 断言 `.lnk` 指向的路径**真的存在**且在当前仓库内（不许指到别的副本）。
3. 真机：双击一次，秒表记「画面出现 ≤1 秒 / 大厅出现 ≤N 秒」，两次重复双击都不应出现"什么都没发生"。
