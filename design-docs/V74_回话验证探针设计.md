# V74 · 「agent 能否回话」探针（**待拍板，先不动码**）

> 2026-10-21。设计先行；老板拍板前不写实现代码。
> 依据全部来自**真实记录**（`agent_community/data/harnesses.json` 8 条）与已落地的 `V73`。

## 1. 要解决的那一件真事

平台现在能证明的只有**桥配置**这一段。每条记录里平台自己写着（`bridge_template_verified[].evidence.verified_scope`）：

> **仅桥配置**（桥能连平台/领件/回报；且这只桥是**平台在验证间里启动的**）
> ——**harness 侧是否运行该桥、agent 能否回话，本次未验证**

实测 8/8 条都是这个状态。**老板最恨的"看起来成功"就长在这里**：
界面显示"接入成功"，但没有任何一条证据说明"发消息给它，它会回话"。

## 2. 目标（一句话）

让平台能回答：**「给这个 agent 发一条消息，它回了」——有证据吗？证据是什么范围？**
并把答案写进 `V73` 已实现的 `segments.agent_can_reply` 那一段（目前恒为 `unverified`）。

## 3. 三条硬约束（先立规矩，再谈实现）

1. **不烧钱**：默认**关闭**；一次只发 **1 条**探针；有预算闸（沿用 `ai_usage` 的预算熔断），可全局开关。
2. **不假装**：探针必须走**和真实派活同一条投递路径**（同一个桥、同一个队列、同一个回执口），
   不许另开一条"只有探针能用"的捷径——否则测出来的不是产品路径。
3. **不绑定任何 harness 类型**：四种桥型（file_poll / pending_poll / http_api / 人工中转）都要能表达；
   **没有自动回报通道的类型（本机 6/8 是人工中转）不许硬撑成"自动验证"**，见 §5。

## 4. 流程（4 步，每步都留痕）

```
① 选人      指定 harness_id（必须已登记）
② 发探针    平台投递一条带**唯一 nonce** 的消息（nonce 只用于认这次回执，不进业务）
③ 等回执    有回报通道的：等带回 nonce 的回执（超时上限可配，默认 120s）
            没有回报通道的：见 §5（人工确认）
④ 落证据    metadata.reply_probe = {at, nonce, state, source, evidence}
            state ∈ ok / failed / unverified（**失败必须带原因**：超时 / 桥没起 / 回执不含 nonce）
```

- 端点（两个，只读 + 发起）：
  - `POST /api/harness/{id}/probe-reply` —— 发起一次探针（写操作，需本机/授权，遵守现有鉴权）
  - `GET  /api/harness/{id}/probe-reply` —— 查最近一次结果（只读）
- 只读视图：`GET /api/harness/{id}/capability`（`V73` 已实现）里 `segments.agent_can_reply`
  从 `unverified` 变成 `ok` / `failed`，**并带上范围原话**（"本次证明的是：这条桥投递后，agent 回了带回执的消息"）。

## 5. 人工中转型（本机 6/8）怎么算证据

这类没有叫醒命令、也没有自动回执（`wake_wrapper.kind=manual`）：
平台**不假装自动验证**，改走**人工确认**，并把来源写清楚：

```
source = "human_confirm"     # 用户点了「我确认它回了」
evidence = {confirmed_by: <用户>, at: ..., note: <用户填的一句>}
```

- 这样 `agent_can_reply` 可以是 `ok`，但**必须显示 `source=human_confirm`**（界面上与自动回执区分开）；
- 用户没确认时**保持 `unverified`**——不许因为"人没说不行"就当成功。

## 6. 判据（实现后要能一条命令复核）

`python tools/reply_probe_check.py`（新增，真跑）：

1. **有自动回报的桥**（用仓库自带的 file_poll 桩）→ 发起探针 → `state=ok`，且回执里 nonce 对得上；
2. **回执不带 nonce**（桩故意回一条无关消息）→ 必须 `failed`，原因写"回执不含本次 nonce"（不许当成功）；
3. **桥没起** → `failed`，原因写"桥无响应/超时"；
4. **人工中转型** → 只能 `human_confirm` 或 `unverified`；尝试自动验证必须被拒（400 + 说人话）；
5. **默认关闭**时端点返回明确提示（不做任何投递、不发消息）；
6. `capability` 视图：`agent_can_reply` 与 `reply_probe` 一致；没有证据时**仍显示 unverified**。

## 7. 明确不做（防止范围蔓延）

- 不做能力评测/打分（身份定位那条仍是**暂停**）；
- 不做**定期自动探活**（会持续烧钱）；只做"用户点一下，验一次"；
- 不改 `V73` 的三段语义，只是把第二、三段从"永远 unverified"变成"能验、验完如实写"。

## 8. 成本与默认值

| 项 | 默认 | 可配 |
|---|---|---|
| 总开关 | **关** | `AC_REPLY_PROBE_ENABLED=1` |
| 每次条数 | 1 条 | 不做批量 |
| 超时 | 120s | `AC_REPLY_PROBE_TIMEOUT` |
| 预算 | 沿用 AI 预算 | 触顶直接拒绝并说明 |

> 设计意图：**宁可默认关，也不要默认烧钱**；用户想验的时候点一下，验完就有证据落库。
