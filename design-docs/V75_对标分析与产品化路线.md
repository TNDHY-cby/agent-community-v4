## 1. 三条结论（压过细节）

1. **不是一个层级的东西**：对标的 Ekko 是"Agent 宿主/编排的**前端产品层**"，我们是"多 Agent 协作的
   **后端协议与治理层**"。**直接比 star 会得出错误判断**（他们强在安装包/截图/演示/移动端，我们几乎没有）。
2. **我们的真优势在协议与治理**：8 种协议（含 **A2A** —— 对方完全没有）、组长选举、三级讨论、能力匹配派活、
   可验证的判据体系（30+ check 脚本、版本一致性守卫、静默异常治理）。这是外部生态正在对齐的方向。
3. **我们不做的定位**：**不做前端编排工具的替代品**（拼 UI 资源与分发预算，赢不了也没必要）。
   我们的位置是它们缺的 **runtime 层**（`A2A` + `HTTP` 就是接口）。

## 4. 明确不做（防止范围蔓延）

1. **不做替代品**：不追 star、不做通用前端编排工具；只做它们缺的 runtime 层。
2. **不做"看起来很全"的假接入**：四种桥型之外如实说不支持（既有铁律）。
3. **不为单机/单域名写特例**：验收＝换机器 + 换端口 + 换数据目录不改代码（既有铁律）。
4. **不做自动定期探活/评测打分**：烧钱且碰"身份定位"暂停令；只做"用户点一下，验一次"。
