> 2026-10-22。来源：两份外部核对材料（同赛道"可利用之物"清单、与 IBM mcp-context-forge v1.1.0 的对比）。
> 本文只放**已决定的口径 + 可执行清单**，过程材料不进仓库（避免污染建模）。

## 1. 定位声明（对外话术，写进 README）

> **IBM（mcp-context-forge）管"怎么把服务安全地接出去"（南北向网关）；
> 我们管"一群 agent 怎么组织起来干活、怎么算账、谁说了算"（东西向组织运行层）。**

- 两条轴，不是竞品；**不拿对方最强的项去比**（别再说"我们也支持 MCP/A2A"）。
- **鉴权口径**：我们**不补** OAuth/RBAC/SSO 全家桶；**鉴权请前置**（nginx / oauth2-proxy / 反向代理），
  合作社只负责 `policy` + `rule_gate` 这一层治理规则。README 里明写，避免用户误以为我们是网关。

## 2. 三条"不做"（防止把 95k 行撑到 300k 行）

1. **不做网关/代理**（Rust sidecar、南北向流量收敛）——那是对方主场；
2. **不做鉴权全家桶**（JWT/SSO/OAuth/DCR/RBAC/团队/角色/邀请/凭据目录）；
3. **不做可观测全家桶**（OTel/Prometheus/SIEM 导出/metrics rollup）——我们保留 audit / heartbeat / patrol / logs / snapshots 够用。

## 5. 许可合规纪律（新增铁律，写进 AGENTS.md 的"可移植性"旁边）

1. 搬任何第三方代码：**保留原文件头**（版权 + SPDX）→ 在 `THIRD_PARTY_NOTICES.md` 登记 →
   修改过的文件在文件头标注 `Modified by <项目>`；
2. **无许可证的仓库（license=None）一行代码都不许抄**，只允许读思路并自己写；
3. 每次发版前 `python tools/third_party_check.py` 核对：仓库里出现 `SPDX-License-Identifier` 的文件，
   必须在 `THIRD_PARTY_NOTICES.md` 里能对上（判据见 `test_third_party_notices.py`）。
