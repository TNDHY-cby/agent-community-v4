# V83 · 可验证附属记录（签名 / 扫描 / 审计）

> 2026-10-22。灵感来自同赛道"可验证资产三元组"（签名 + 扫描 + Referrer），**代码自己写**。

## 1. 一句话

主记录（harness / 任务）**不动**；往它上面追加**三类可独立拉取**的记录：
`signature`（这条记录被谁在何时签过）、`scan`（扫出了什么）、`audit`（谁做过什么）。

## 2. 三条硬口径（不许含糊）

1. **签名是平台自签，不是 CA**：HMAC-SHA256，密钥来自 `AC_ATTEST_KEY`；
   没有就自动生成并落到 `data/keys/attest.key`（尽量 0600）。接口返回里**必须**带
   `"trust": "platform-self"`，界面/报告不许说成"第三方认证"。
2. **扫描是内置确定性检查**，不装第三方扫描器：卡片一致性（V82）+ 探针新鲜度（V81）+ 桥测试记录。
   每条给 `item / passed / why`。
3. **只追加**：同 `att_id` 不许覆盖（覆盖就等于篡改历史）；要改就新增一条并说明。

## 3. 接口

```
POST /api/attest/{subject_type}/{subject_id}   ← {kind: signature|scan|audit, note?}
GET  /api/attest/{subject_type}/{subject_id}   → 该主体全部记录（时间正序）
GET  /api/attest/{subject_type}/{subject_id}/{att_id}  → 单条
POST /api/attest/verify                        ← 一条记录 → {valid, why}
```

`subject_type` 只允许 `harness` / `task`（其它 400 并列出支持值）。

## 4. 判据

`test_attestations.py`（5 条）：
① 签名记录可验真（`valid=true`）；② 改动一个字节 ⇒ `valid=false`（且说清是签名不匹配）；
③ 扫描报告结构齐（`items[]` 每项有 `item/passed/why`，`trust=platform-self`）；
④ 同 id 追加被拒（只追加）；⑤ 未知 `subject_type`/`kind` ⇒ 400 并给 `supported`。

## 5. 不做

- 不做公钥/证书链（要 PKI 就不是"本地自部署"了）；
- 不搬 agntcy/dir 的 protobuf / OCI Referrer 实现；
- 不做跨注册表同步。
