# V84 · 工作间可被外部发现（virtual server 思想）

> 2026-10-22。灵感：把"一组后端服务打包成虚拟服务器，并可当 A2A agent 暴露"的思路。
> 我们的落点：**工作间**就是天然的一等资源（有成员、有流程、有产物），让它能被外部发现。

## 1. 为什么

现在外部只能通过 `/api/*` 深挖才知道"这台平台在干什么"。要接外部生态，得先让人**看得见**：
一个稳定位置（`/.well-known/`）+ 一份**不泄露隐私**的卡片。

## 2. 口径（先立规矩）

| 规则 | 说明 |
|---|---|
| **默认不可发现** | `Workshop.discoverable = False`；要显式 `POST /api/workshops/{wid}/discoverable {on:true}` 才出现在清单里（对齐"自动兜底默认关"） |
| **只放公开信息** | `workshop_id / name / status / gate 状态 / 成员数 / 当前节点 / 更新时间`；**不放**成员真名、工作目录、token、任务正文 |
| **只读** | `/.well-known/*` 只 GET；已加入外部只读档白名单 |
| **别编** | 没标记的 404；清单里只列 `discoverable=true` 的 |

## 3. 接口

```
GET  /.well-known/workshops.json          → {count, workshops:[卡片摘要]}
GET  /.well-known/workshop/{wid}.json     → 单卡（含 gate 与流程节点状态）
POST /api/workshops/{wid}/discoverable    ← {on: true|false}
```

## 4. 判据 `test_discovery.py`（5 条）

① 默认不出现（清单里没有、单卡 404）；② 打开后出现且字段齐；
③ 卡片**不含**敏感串（成员真名 / 绝对路径 / token 字样）；④ 关闭后立刻消失；
⑤ 未知工作间 404 且说清。

## 5. 不做

- 不做写入型发现（外部不能改我们的工作间）；
- 不做 A2A 卡片自动注册（等 virtual server 契约定了再说）；
- 不暴露 `/api/` 管理面。
