# V85 · 名册生命周期接线（把 V82 的口径用起来）

> 2026-10-22。V82 §4 只定了口径（7 天隐藏 / 90 天清明细 / 48 周期死号），本版**接线**。

## 1. 数据

`<AC_DATA_DIR>/registry_health.json`：
```json
{"示例Harness-A": {"samples": [{"at": "…", "ok": true, "why": ""}],
                  "hidden": false, "hidden_reason": "", "hidden_at": "",
                  "appeals": [{"at": "…", "note": "…"}]}}
```
- 样本上限 **200 条/agent**（超了丢最旧，**不静默**：留 `trimmed` 计数）；
- **只记真实结果**（回话探针 / 桥测试），不编造。

## 2. 规则（沿用 V82，不再发明）

| 判定 | 阈值 | 动作 |
|---|---|---|
| 连续 N 天全部失败 | 7 天 | 进"隐藏候选"（`candidates`） |
| 隐藏 | 人工或维护工具执行 | `hidden=true`，**数据不删** |
| 申诉 | 任意时刻 | `hidden=false` + 记一条 appeals（**可申诉**） |
| 明细清理 | 90 天 | 由 `tools/registry_maintenance.py` 执行，**默认 dry-run** |

## 3. 接口

```
GET  /api/registry/health            → {agents:[{harness_id, samples, days_all_failing, hidden, candidate}], candidates:[...]}
POST /api/harness/{id}/hide          ← {on: true|false, reason}
POST /api/harness/{id}/appeal        ← {note}   （申诉即恢复，并留痕）
```

## 4. 判据 `test_registry_health.py`（6 条）

① 记样本 + 上限截断留痕；② 连续失败天数算得对；③ 满 7 天进候选、6 天不进；
④ 隐藏不删数据（样本仍在）；⑤ 申诉恢复并留痕；⑥ 清理工具按 90 天只删明细（dry-run 不动）。

## 5. 不做

- 不自动隐藏（要人点头或手动跑工具）——"隐藏谁"是有政治含义的动作，不自动；
- 不做 48 周期死号扫描的定时器（等有调度再谈）。
