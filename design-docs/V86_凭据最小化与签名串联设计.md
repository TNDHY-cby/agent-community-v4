## 1. 要解决的两件事（都是真问题，不是漂亮话）

### 1.1 凭据散落

现状：平台的密钥/令牌分散在**至少五处**，没有一处能回答"我现在身上有哪些凭据、在哪、多久没换"：

| 位置 | 例子 | 现状 |
|---|---|---|
| `.env` / `config.local.json` | 各类第三方 key | 只在文档里说要填，**平台不知道有没有填、填的是不是弱值** |
| `<AC_DATA_DIR>/keys/attest.key` | V83 附属记录签名 | 自动生成，权限已收紧，但**没人核对它是否被换过** |
| 中转/外部访问令牌 | `AC_HUB_TOKEN`、外部访问令牌 | 明文在环境里，**用没用过、谁在用，平台不知道** |
| 桥脚本产物 | 生成的 `.ps1` / 配置片段 | 可能带明文 key 落盘，**没有体检** |
| 日志 | 报错正文 | 已做去敏，但**没有统一规则源** |

**要的不是"保管库"**（不搬明文、不引外部依赖、不做 KMS），
而是**一本账**：每条凭据"是什么、在哪、指纹、上次用、要不要换"。

### 1.2 「谁签的」上下游没串起来

V83 已经能签一条记录、能验签；但**卡片和名册上没有指向记录的钩子** ——
界面看到"已扫描/已审计"时，无法当场证明"这条结论来自哪条签名记录"。

## 2. 目标 / 非目标

**目标**
1. 能**列出**平台当前认得的所有凭据：用途、来源位置、**指纹**、创建时间、上次使用时间、是否弱值；
2. 能**体检**散落的明文（`.env` / `config.local.json` / 桥产物 / 日志），只报**位置 + 指纹**，**不回显明文**；
3. 卡片、名册、工作间上挂 **`attest` 钩子**：`{att_id, kind, trust, verified, signed_at}`，
   `verified` 是**当场真验签**的结果（不是存下来的布尔值）；
4. 一条命令改密钥：`tools/rotate_credential.py`（生成新值 → 写回原处 → 旧指纹进"历史"→ 提示重启）。

**非目标（明确不做）**
- ❌ 不做密钥保管库 / KMS / Vault（老板已定：不引外部依赖、不做网关）；
- ❌ 不搬明文位置（搬一半比不搬更糟：会出现"两处都有一份、不知道哪份生效"）；
- ❌ 不做 OAuth/RBAC/SSO（老板 2026-10 已拍：**鉴权请前置**，平台不冒充身份提供方）；
- ❌ 不动前端 `frontend/**`（归 MiMo；本稿只给契约）。

## 3. 设计 A：凭据账本（`platform/credentials.py`）

```
<AC_DATA_DIR>/keys/credentials.json        # 只有指纹与元信息，**没有明文**
{
  "entries": [
    {"id": "cred-0001", "purpose": "attest_key", "source": "data/keys/attest.key",
     "fingerprint": "9f2c1a7b4d80", "algo": "sha256", "created_at": "...",
     "last_used_at": "...", "strength": "ok|weak|unknown", "rotated_from": "…" }
  ]
}
```

- **指纹口径一处真相**：`sha256(明文) → 前 12 位十六进制`；全项目只经 `fingerprint()` 计算；
- `scan()` **只读**已知来源，产出"路径 → 指纹/强度"，**绝不把明文写进返回值或日志**；
- `strength`：长度 < 16 / 等于示例占位值（`sk-your-key` 这类）/ 与用户名相同 ⇒ `weak`；
- 账本**可以被删**：删掉只会丢"上次用/历史"，`scan()` 能重建 —— 不做成必须一致的状态机。

## 4. 设计 B：体检端点（只读，进只读白名单）

```
GET  /api/credentials            → {entries:[…], summary:{total, weak, stale}}
POST /api/credentials/scan       → {found:[{purpose, source, fingerprint, strength, why}], skipped:[…]}
```

- `scan` 是**写请求**（会更新 `last_used_at`/账本）⇒ 必须进前台白名单，且**不许页面加载时自动调**；
- 失败要说话：扫不了的文件（权限/不存在）进 `skipped` 并给原因，**不许静默当"没问题"**；
- **绝不**返回明文；判据里专门用"塞一个哨兵明文，拉响应里不许出现"来验。

## 5. 暂不做：把签名串到卡片/名册（**明确不做，附理由**）

原稿设想过：卡片/名册/工作间带 `attest: {att_id, trust, verified}`，`verified` 每次现验签。

**不做的理由**（老板 2026-10-22 拍板）：可发现默认关、外界没有消费方，
做完只有我们自己看；等真有第三方在读卡片时再谈。**不是遗忘，是明确暂缓。**
（若将来要做，口径仍按原稿：现验签、缺记录时整段缺席、不显示成"已核实"。）

## 5b. 暂不做：自动轮换（**明确不做，附理由**）

用户当前没有"定期换密钥"的需求；真换 key 时**改一处 + 重启**即可。
`tools/rotate_credential.py` 不建（避免多一个会打断正在跑任务的自动化）。


## 6. 判据（全部真请求 / 真文件）

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | 账本里**没有明文** | 塞哨兵 key 到 `.env`，`scan()` 后读 `credentials.json` 字节，不许含哨兵 |
| 2 | 指纹稳定 | 同一明文算两次指纹相同；改一个字节即变 |
| 3 | 弱值识别 | 放 `sk-your-key` ⇒ `strength=weak`，`why` 说清 |
| 4 | 体检不静默 | 指向权限不可读的文件 ⇒ 进 `skipped` 且有原因（不许"0 问题"） |
| 5 | 桥产物里的明文真被找到 | 在 `<AC_DATA_DIR>/bridges/…` 写一份带假 token 的 `.ps1` ⇒ `found` 里有它、带指纹与位置 |
| 6 | 响应体不明文外泄 | `GET /api/credentials` 与 `POST /api/credentials/scan` 的响应体里都不含任何明文 |
| 7 | 变量引用不算明文 | 桥脚本里写 `$env:AC_TOKEN` / `{{AC_TOKEN}}` ⇒ **不许**报成明文（防误报） |
| 8 | 换目录仍能跑 | 换 `AC_DATA_DIR` + 端口，体检照常出结论（不写死路径） |

## 7. 迁移与兼容

- 老数据没有账本 ⇒ 首次 `scan` 自动建，`first_seen` 记真时间，**不假装很久以前就在管**；
- `AC_ATTEST_KEY` 与账本脱钩：账本只记**指纹**，换密钥不改账本结构；
- 删掉账本 ⇒ 只是丢"多久没换/历史"，`scan()` 能重建（不做成必须一致的状态机）。
