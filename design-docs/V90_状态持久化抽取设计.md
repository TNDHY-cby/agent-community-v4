## 1. 为什么不直接 `move_endpoints.py` 那样整块搬函数

`server.py` 有一份**隐藏的陷阱**：`python -m agent_community.platform.server` 时存在
**两份模块对象**（`__main__` 与包模块），模块级全局（`tasks` / `workshops` / `DATA_DIR` …）两边互不可见。

- 若把 `save_state()` 原样搬进新模块、再用 `from . import server` 读全局：
  **运行中的 `__main__` 副本写盘时，会去序列化包模块那份（空的）全局** ⇒ 正好复现"把数据写成 `{}`"的事故。
- ⇒ 正确做法是**反转依赖**：新模块不认识任何全局，只接受"成品"（payload dict + 数据目录）。

## 2. 结构

| 层 | 文件 | 职责 |
|---|---|---|
| 纯函数（可单测） | `platform/state_store.py` | `block_reason()` 判定该不该拒写 / `write_payload()` 原子逐文件写 / `read_json()` 容错读 / `disk_has_data()` |
| 编排（保留在 server） | `platform/server.py::save_state()` | 从**本模块自己的全局**组装 payload → 问 `block_reason()` → 交 `write_payload()` → 成功才置"所有权" |
| 同上 | `platform/server.py::load_state()` | 仍在本文件（它必须往本模块全局里填），只把"读 JSON"委托出去 |
