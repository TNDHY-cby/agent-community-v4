# V94 · 视觉粘贴：点住输入框之后按 Ctrl+V（老板 2026-10-24 定）

> **状态：已实施并真机跑通（2026-10-24 07:3x）** —— 平台自己把 `请回复数字 9` 送进 Trae 并回车，
> Trae 回了 `9`（截图证据在继承书 §11.7）。
> **一句话**：平台要能自己把一句话送进"应用自己画的输入框"（Electron 类，系统层看不见控件）——
> 做法不是去读它的控件，而是**像人一样**：点一下输入框（光标落进去）→ 剪贴板 → 按 `Ctrl+V`。

## 1. 为什么（真机结论，2026-10-24 07:0x）

老板在 Trae（Electron）里亲手输入 `请回复数字 7`，平台按回车 → **消息发出去了、Trae 回了 `7`**。
但把同一句话交给平台"自己送"时：

| 通道 | 结果 | 原因 |
|---|---|---|
| `cdp` | ✗ | 目标没开 `--remote-debugging-port` |
| `native`（WM_PASTE + WM_GETTEXT 读回） | ✗ | Electron **没有原生文本控件** |
| `uia` | ✗ | 找不到可编辑元素 |
| `clipboard` | ⚠ 名义可用 | **只把字放进剪贴板，不粘贴** ⇒ 一个字都没进框 |

⇒ 四通道里唯一还有点希望的 `clipboard` 档**少做了最后一步**；而"最后一步"正好是老板 2026-10-24 的原话：

> 「你用脚本点击输入框，（浮标出现在输入框）后直接用脚本模拟键盘 `Ctrl+V`」

## 2. 方案（最小成本版）

在 `platform/delivery.py` 的 `clipboard` 档里，按这个顺序做，**每一步都可能拒绝往下走**：

```
① 抬到前台（有标题就 focus；没有标题就跳过）
② 点输入框 —— 用**框选区域**（首选）/ 教过的位置 / 视觉估位给出的相对坐标
   点之前自证：落点必须在这个窗口上（WindowFromPoint），否则不点
③ 设剪贴板（这一步原来就有）
④ ★按 Ctrl+V —— **只有②真的点进去了才按**（没点进去就不按，避免粘到别的程序里）
⑤ 可选：按回车 / 点框好的发送按钮（`enter:true` 时）
```

**关键取舍**：④ 的**前提是②成功了**。没有可靠位置就不粘贴——宁可如实说"没送出去"，也不能把内容粘到用户别的窗口里。

## 3. 判据（怎么算成）

| # | 判据 | 怎么判 |
|---|---|---|
| ① | 没位置时**不按** Ctrl+V | `state=queued_for_human`，`paste_ok=false`，原因说清 |
| ② | 点进去了才按 | 真机：焦点在前台的那扇窗上，粘贴后**输入框区域画面变了** |
| ③ | 粘完**不谎报** | 读不回文字 ⇒ `state=sent_unverified`（不写 `delivered_verified`） |
| ④ | 粘贴**前后画面**对比（Electron 唯一可得的信号） | 输入框那一条带的灰度差比 > 阈值 ⇒ "像粘进去了"；没变 ⇒ "没粘进去" |
| ⑤ | 真机端到端 | 平台自己粘 `请回复数字 N` + 回车 ⇒ 目标回话 |

**关于"光标（浮标）出现在输入框"**：像素上没法稳定判"光标出现了"（它会闪）。
所以本设计用两个更硬的替代信号：**点前自证**（落点在目标窗口上）+ **粘贴后画面变化**（框里多了一行字）。
两者都不成立就如实说没成，不假装。

## 4. 边界与风险

- **只对"能看见的窗口"成立**：最小化/被完全遮挡时拒绝（既有规矩）。
- **粘错地方的防线**：点前自证 + 前台自证；任一不成立就不按 Ctrl+V。
- **剪贴板会被覆盖**：这是半自动档的固有代价（既有行为，不新增）。
- **读不回文字**：`state` 最多到 `sent_unverified`；要 `delivered_verified` 得走 CDP 或原生控件。
- **不做的事**：不猜应用专属快捷键、不写死任何应用名/坐标（反私人定制，`PRODUCTIZATION.md`）。

## 5. 通用化（等本次跑通再做）

1. 位置来源统一走"框选 > 教过 > 视觉估位"（已经是这个顺序，不新增第二份）；
2. 粘贴后画面比对做成 `screen_vision` 的一个函数（`changed_band()`），别处也能用；
3. 前端框选 UI（后端 `regions` 端点已通）：用户框一次，之后不再需要视觉估位。

## 6. 实施结果（2026-10-24 07:3x，真机跑通，**含三处当场踩出来的坑**）

**结论**：平台自己完成了 `点输入框 → Ctrl+V → 看图核对 → 回车`，Trae（Electron）回了 `9`。
用到的输入框位置来自**框选区域**（`POST …/regions`，前端 UI 还没接，本场用接口按真实截图画上去的）。

### 6.1 坑一（最严重）：抓图位图按"缩小尺寸"开 ⇒ 估位一直分析的是**窗口左上角**

`grab_gray` 原来把位图开成 `240x150`（降采样后的大小），而 `PrintWindow` 是按窗口真实尺寸（2163x1353）画的
⇒ **只有左上角 240x150 个像素进了位图**，其余被裁掉。于是"视觉估位"分析的从来不是整扇窗，而是左上角一小块；
它给出的 `rel_y` 乘回整窗高度纯属巧合。**修法**：位图按 `cw x ch` 开，再在 Python 里按 `step` 降采样。

### 6.2 坑二：点得很早，粘得很晚 ⇒ 前台早就换人了

投递流程里"点一下输入框"发生在最前面，之后还要走 `native`/`uia` 两档（各一次 PowerShell 注入，好几秒），
等到剪贴板档真按 `Ctrl+V` 时**前台已经不是目标窗口**了 —— 表现就是"点了、也按了，字没进框"。
**修法（`input_sim.ensure_foreground`）**：临粘之前**重新抬前台并自证**（轮询确认 `GetForegroundWindow`），
再**重新点一次**输入框；任一步不成立就**不按** `Ctrl+V`（宁可如实失败，也不粘到别人程序里）。

### 6.3 坑三：画面变化的阈值要用实测值，不能拍脑袋

同一窗口连抓三次（静止）：**0.0000**；空输入框 → 粘一句话：**1.27%**；已有文字 → 再敲 3 个字：**0.68%**。
⇒ 阈值取 **0.3%**（`band_diff`）。另外每个分析格子取 3×3 个采样点求均值（只取一个点会漏掉细笔画）。

| 抓的必须是整扇窗（DPI 那一课） | `tools/vision_capture_check.py` |

### 6.5 仍然不成立的（**别当已经解决**）

- **自动估位（不给框选/不教位置时）仍然不准**：修好整窗抓图后，它在这套深色界面上给出的带在
  `rel_y≈0.43`（消息区），不是输入框（≈0.88）。所以现在能用的是"**框选 > 教过位置 > 视觉估位**"里的前两档。
- **Electron 读不回文字**：`state` 最多到 `sent_unverified`；要 `delivered_verified` 得走 CDP 或原生控件。
