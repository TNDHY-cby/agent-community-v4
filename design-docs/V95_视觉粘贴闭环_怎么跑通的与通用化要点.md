# V95 · 视觉粘贴闭环：**怎么把一个"叫不醒的桌面 agent"叫起来并拿到回话**

> 来源：**实测**（2026-10-24 老板真机跑通：平台把「请回复数字 9/11」送进对方应用并得到回话；
> 前端框选/绑定/试投链路真页面走查通过；后端 `tests/test_input_regions.py` / `test_delivery_state.py` /
> `tools/visual_script_check.py` 全绿）；**范围**：跨平台通用，不针对任何具体应用。
> **本文是"怎么做到的"的**唯一**书面口径**（写给人看，也给下一个会话接手用）。

---

## 0. 先用大白话说一遍（30 秒版）

大部分闭源桌面 agent（聊天式的那些）**不会自己醒来读平台**，你发消息过去它也不知道。
所以平台要像人一样：**找到那扇窗 → 把光标点进输入框 → 把那句话粘进去 → （可选）按回车/点发送 → 看画面有没有变**。
"框选输入框"就是用户告诉平台"输入框在哪一行"的那一下 —— 一次框完存下来，以后都按它去点。

---

## 1. 用户视角的九步（就是界面上能看到的）

| # | 动作 | 用户做啥 | 平台做啥 |
|---|---|---|---|
| 1 | 选员工 | 在下拉里选一个已登记员工 | —— |
| 2 | 找窗口 | 填一个"会出现在目标窗口标题里的字"→ 点「让平台去找」 | `POST /api/docking/locate` 列窗口并打分，回 `hwnd / 标题 / 客户区尺寸 / 是否最小化 / usable` |
| 3 | 选一个候选 | 点一下 | 记住 `hwnd + 标题 + 客户区尺寸` |
| 4 | 框输入框 | 点「截一张图」（或「用剪贴板里的图」「上传图片」）→ 在图上**拖一个框**住能写字的那一行（发送按钮可选） | 只在前端：把框换算成**相对比例**（0~1），基准用**客户区尺寸** |
| 5 | 保存框选 | 点「保存框选」 | `POST …/regions`（存比例+关键词+frame）；**紧接着 `POST …/bind` 把这扇窗绑给这个员工**（否则下一步认不出目标） |
| 6 | 试投 | 点「试投一句「请回复数字 7」」 | `POST …/deliver`：抬到最前 → 点框的上三分之一 → `Ctrl+V` → 截图比对 → （可选）回车或点发送按钮 |
| 7 | 看结果 | 看结果区四句话 | 按 `state` 说：已送达（读回一致）/ 已送出（未核实）/ 已放进剪贴板等你 Ctrl+V / 没有送出去 + 原因 |
| 8 | 存档（可选） | 「保存为该员工的激活方式」 | 写员工档案（可回退） |
| 9 | 平时叫醒 | 「一键脚本激活」或导出的 `.ps1` | 平台按档案里的标题/关键词/框选再走一遍 |

## 2. 三条硬约束（决定了为什么必须这么设计）

1. **平台不许猜目标**。目标只能来自用户给的（窗口标题 / 手动绑定 / 框选时选中的那扇窗）。
   猜不到就**如实拒绝**（"既没有手动绑定目标，也没有会话名"），绝不盲投 —— 盲投会把话打进别人的程序。
2. **Electron 类目标读不回文字**。系统层看不到它的输入框（那是应用自己画的），所以"到底进去没有"只能靠
   **画面变化**：粘贴前后对输入框那一条带取差（`paste_seen` / `paste_ratio`）。读不回就只说"已送出、未核实"。
3. **窗口在前台 ≠ 焦点在输入框**。所以必须先**点一下**；点之前自证落点是不是目标窗口，
   没走到前台/没点进去就 `exit 5`/`not_sent`，**一个键都不按**。

## 3. 契约（前端只用这些，别自己发明）

```
POST /api/docking/locate                {keywords:[…]} → candidates[{hwnd,title,class,pid,score,
                                                          width,height,client_w,client_h,minimized,usable}]
GET  /api/docking/harness/{id}/screenshot?hwnd=…|?title=… → image/png
       响应头 X-Client-Width/Height（**真实客户区**，算比例只能用它） / X-Image-Width/Height（图被缩过）
GET  /api/docking/clipboard-image        → image/png（用户刚截在系统剪贴板里的那张；非 Windows 501）
GET  /api/docking/harness/{id}/regions   → {regions|null, hint}
POST /api/docking/harness/{id}/regions   ← {input:{x,y,w,h}, send:{x,y,w,h}, keywords:[…], frame:{w,h}}
DELETE /api/docking/harness/{id}/regions
POST /api/docking/harness/{id}/bind      ← {hwnd,title} | {ws,idx}      （框选保存后自动调它）
POST /api/docking/harness/{id}/deliver   ← {text, enter?, prefer?, idx?}
       返回 state / paste_ok / paste_seen / paste_ratio / press_ok / press_how / press_note / attempts[]
```

**投递优先级**（后端定的，界面照实显示）：`框选 > 教过的位置 > 视觉估位 > 只放剪贴板`。
**落点**：框的**上三分之一**（不是正中 —— 用户往往把底下那排小按钮一起框进来）。

## 4. 通用化清单（换一台机器必须还成立）

| 变化 | 平台怎么表现 | 要求 |
|---|---|---|
| 换目录 / 换端口 / 换数据目录 | 前端所有请求走相对路径 + `location.origin`；不写死端口 | ✅ 不改一行代码 |
| 换一个**应用**（不同进程/不同界面） | 只认用户给的标题关键字与框选，代码里没有任何应用名 | ✅ |
| 换**窗口标题** | locate 按"包含关键字"匹配，用户可改关键词 | ✅ |
| 换**分辨率 / DPI / 缩放** | 比例是相对客户区算的；截图按真实客户区标尺寸 | ✅（DPI 已修：过去会按 2/3 裁） |
| 换**语言 / 主题** | 视觉估位只做"横向宽带"检测，不认文字；认文字那路要 CDP/UIA，没开就如实说 | ✅/如实说 |
| 窗口**最小化** | `usable=false` + 占位尺寸（如 237×39）**被拒收**；提示先恢复或用自己截的图 | ✅ |
| 窗口**被遮挡** | 抬不到前台 ⇒ 不点、不按（`exit 5` / `not_sent`） | ✅ |
| 目标**没有可点区域**（命令行类） | 不会瞎点：只放剪贴板并说明"半自动" | ✅ |
| 目标**没有窗口**（纯网页） | 走 CDP 那条：找页面 → 指认输入框 → 塞文本（能读回） | ✅ |

- 本文与界面文案里的例子都是虚拟名（"示例应用 / 示例窗口"）；

## 5. 今天踩过并已修的坑（每条都留了判据）

| 现象 | 根因 | 修法 |
|---|---|---|
| 框得再准，试投还是"投递没成功" | 员工**没绑窗口** ⇒ 按员工那条路认不出目标 | 保存框选时**自动 `POST …/bind`**；另加「把这个窗口绑给当前员工」按钮 |
| `/bind` 点了没反应（没有网络请求） | `/bind` **不在写白名单**，`dockPost` 本地就拦了 | 白名单 + 交接预检 + FE-26 三处同步 |
| 存进去的 `frame` 是 237×39，比例全错 | Windows 给最小化窗口的**占位尺寸** | `_boxApplyClient` 统一拒收（minimized 或 <200），说人话 |
| 在图上拖框变成"拖图"，之后点什么都失灵 | `<img>` 默认可拖动 | `draggable=false` + `pointer-events:none` |
| 一拖框整个弹窗被关掉 | 框选块原在窄右栏（`overflow:auto` 裁切），mouseup 落到浮层背景 | 挪成卡片第一行整行（grid 三行 lead/box/left+right） |
| 比例对不上 | 用了 PNG 像素而不是响应头 `X-Client-*` | 只认 `client_w/h`（现在改成 locate 那条的尺寸更稳） |
| "没有检测到输入框" 说了假话 | 拿 `need_human` / `detail` 文字猜 | 只读 `state` 四态 + `text_control.why` 原样显示 |
| 界面话术让人以为"点框中心" | 落点其实已改成框的上三分之一 | 文案改"框到能写字的那一行最稳" |

## 7. 还没做（等老板给具体要求，别自己长）

- 面板没主动指出"哪个员工已经绑好窗口、现在就能用"；
- 多窗口/多会话同名的选择只有一个下拉；
- 框选只支持两个框（输入框 + 发送按钮），没有"整块聊天区"的概念；
- 视觉估位在深色界面上仍会指到消息区（所以框选仍是主路径）。
