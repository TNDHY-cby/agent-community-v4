## 1. 老板原话要点（拍板，不是我的转述加工）

**场景**：没有高级协议适配的 harness（clipboard 档 / http 只落盘档）**不能自己醒来**，
平台只能靠视觉脚本激活：**拉到最前 → 点输入框 → 粘贴固定话术（提醒检查邮箱）→ 发送**。
本流程**只是大厅对接中心里的"注册模板"**，具体工作间里还要配置（工作间版待老板另给）。

**① 选 Harness**：只保留**一个输入框**；窗口名就是软件名，**会话名取消**（对接中心只做模板性质注册）。
用户输入模糊名 → 点确认 → **下滑出探测到的相似窗口真实名**（替代原来的"让平台去找"按钮）；
点选某条 ⇒ 真实名换入输入框 + **同时绑定**，下方小字「当前已绑定：<真实窗口名>」；
点错了就手动清空输入框、重新输入、再点确认，平台重新搜索下滑。

**② 图样与位置**：框选时提示"**不要过分超出目标大小**"；**脚本点击默认点中间**。
要框：会话列表 / 新建会话 / 输入框 / 发送按钮；输入框的**引导词**（老板不确定用途，见 §4）。
按钮：读取剪贴板截图 / 重新读取截图 / 重新框选（全部重来）；测试新建会话 / 测试发送消息（默认文本
「你好（请直接回复你好）」）/ 保存为该 Harness 的脚本激活方式（**测试都通过才保存**）。

**③ 通知规范**（写进模板的固定行为）：
1. 激活话术**文本固定**；
2. **每次只做一次**：点输入框 → 粘贴 → 发送（统一话术），避免输入错误；最后**把平台拉回最前**，恢复合作社展示；
3. 若不需要把对象拉最前，**尽量后台做（但别最小化它）**。

## 6. 追加（2026-10-24 19:xx，老板两条真机反馈）

**老板原话**：「不应该问是哪个员工，而应该问是哪个 **harness**，这也说明之前的注册不是 Harness 通用模板注册，
而是注册了具体员工」＋「**新建会话之后就没办法发送通知了**」。

### 6.1 归属＝harness（后端本来就对，界面要改）

后端存储**一直是以 `harness_id` 为键**：`regions`（`data/input_regions.json`）、`bind`（`data/input_anchors.json`）
都是 `<harness_id> → …`，没有任何"员工/工作间"参与。**大厅对接中心这条模板路不该出现"员工"字样**
（"保存为该员工的激活方式"是**工作间**那条路，属于另一套口径，别混）。
⇒ 界面要改：选择器与按钮文案一律 **harness**；大厅里不要留"员工的激活方式"那类入口。

### 6.2 「新建会话之后发不出通知」——改成**一次跑完**

新增 `POST /api/docking/harness/{id}/visual-run`：

```
body: {text?, enter?:true, new_session?:true, restore_focus?:true, settle_new?:1.2}
→ {ok, steps:[{name,ok,why,pasted,ratio}], state, focus_restored, why, text}
```

固定顺序、一条链跑完：**① 抬前台并自证 → ② 点「新建会话」（等界面切过去）→ ③ 点输入框+粘贴+看画面变没变
→ ④ 发送（有发送按钮就点它，否则回车）→ ⑤ 把平台拉回最前**。
任一步失败就**停在原地**并说清是哪一步（后面不再点 —— 前提已经不成立了）。
拆成两个请求时，中间那段（新建会话已点、界面正切）没人管，正是"新建会话成了、通知发不出去"的来源。

**顺带修的真问题**：平台作为**后台进程**调用 `SetForegroundWindow` 会被 Windows 前台锁直接拒
⇒ 表现是"永远抬不到前台、于是永远不粘"，整条视觉激活在服务里等于不可用。
现改为失败后用 `AttachThreadInput(本线程, 前台线程, True) → BringWindowToTop + SetForegroundWindow → 解绑`
（官方文档承认的路子）。真机复验：一次 `visual-run` 完成 前台 → 粘贴(ratio 1.36%) → 回车 → 还前台，
目标回了 `12`。
## 7. 记一笔：**"锁定并点击已有会话"漏了 —— 归工作间对接中心那版**（老板 2026-10-24 19:xx 原话）

> 老板：「忘记加入已有会话的锁定和点击了，不过这是工作间对接中心的」

**口径**：**大厅模板这版不做**（它只负责"新建会话 + 发通知"的模板注册）；
"锁到某个已有会话、每次都点它"属于**工作间对接中心**，等老板给那版规格再动。

**先把难处写下来，免得那版又走一遍弯路**（读不回文字是 Electron 的硬约束）：

| 要做的事 | 难点 | 现在能给的硬信号 |
|---|---|---|
| 锁定某个**已有会话**（不是新建） | Electron 里**读不到会话行的文字**，没法"按名字找"；只能按**列表里的相对位置**（会话列表框里的第 N 行）或像素特征 | 位置（框内的相对 y）+ 点击后**画面变没变**（`band_diff`） |
| 每次激活先点它确认 | 列表会被新建/排序改变 ⇒ **相对位置会漂** | 点完比画面：变了 ≠ 一定是"切到了那个会话"；得靠"列表外观指纹"（那一行的缩略图/颜色）才行 |
| 想真正"认名字" | 得让目标暴露可读通道（CDP / UIA / 无障碍） | 有 CDP 或 UIA 时可以直接按名字点，**那才是能核实的做法**；没有就只能在界面上如实说"按位置点，可能漂" |

**因此工作间那版到时候要老板定的就一件事**：会话是"按位置锁"（能用、但界面要如实说会漂）
还是"要求目标开调试端口、按名字锁"（能核实、但要多一步）。这条我不替他定。
## 8. ★口径变更（老板 2026-10-24 20:xx）：**不做会话选择/锁定**

> 老板原话：「**不做会话选择了，这是闭关锁国，闭源即资本自私，他们只配同时接入一个会话进行工作**：
> **注册照旧，和现在一样的就行**，到时候开了工作间要拉进来，**脚本桥就不用改了**，
> **要求用户自己把那个会话点开就行**，平台只用把属于它的通知**按照脚本给到**就行」

这条**覆盖 §7**（"锁定已有会话"不再做，不是欠账，是**不做**）。落到代码上：

| 位置 | 口径 |
|---|---|
| 注册（大厅对接中心） | **照旧**：四块框 + 测试 + 保存为激活方式，一个字不改 |
| 运行时 | **不管会话**：用户自己把目标会话点开，平台只做"点输入框 → 粘话术 → 发送" |
| `visual-run` | `new_session` **默认 false**（只往"你现在开着的那个会话"送）；要新建的场合显式传 true |
| 工作间 | 到时候把同一套脚本拉进来用，**脚本桥不改** |
| 界面话术（前端） | 加一句：**"请先把目标会话打开"**；别出现"会话列表/选择会话"这类入口 |

理由（老板给的）：闭源应用本质上一个实例**同时只接一个会话**，做会话选择是"闭关锁国"式设计；
把"切到哪个会话"这个动作交回用户，平台只保证"该到的通知按脚本送到当前会话"。

**判据**：`test_default_is_no_new_session_just_current_one`（默认不点「新建会话」，步骤就是 前台→输入框→粘贴→发送→还前台）。
