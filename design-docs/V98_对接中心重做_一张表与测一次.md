# V98 · 对接中心重做：**一张表 + 每行一个「测一次」**（老板 2026-10-25 拍板方向）

> **状态：方案（等老板点头再让前端动手）**。老板原话：
> 「对接中心是真的乱，没有之前的『注册 harness』一目了然和即刻测试，但是之前的那个少了脚本注册。
> 可是对接中心里面乱七八糟的有一堆空壳应用，根本用不了。」

## 1. 老板要的三件事（翻成设计语言）

| 老板说的 | 要的东西 |
|---|---|
| 「没有之前那个一目了然和即刻测试」 | **一屏一表**：已接入的 agent 一行一个，**每行一个「测一次」当场验** |
| 「之前那个少了脚本注册」 | 注册入口要**两个**：`+ 注册 Harness`（协议）与 `+ 配脚本`（视觉激活） |
| 「一堆空壳应用，根本用不了」 | 表里**只列真注册的**；不可用的必须**写明不可用 + 原因**，**不给点了没反应的按钮** |

## 2. 页面结构（从上到下就三块）

```
┌ ① 我要做的事（两个按钮，永远在这) ────────────────────────────┐
│  [+ 注册 Harness]  协议型：MCP / HTTP / ACP / A2A / 桥 / 人工     │
│  [+ 配一套视觉脚本]  桌面型：截图 → 框选 → 测试 → 保存              │
└──────────────────────────────────────────────────────────┘
┌ ② 已接入的 Agent（一张表，一目了然）──────────────────────────┐
│ 名字           协议    能不能被叫醒   上次测过              操作      │
│ Cherry Studio  mcp     ✅ 能          3 分钟前 ✅ 3 个工具   [测一次][加入工作间][详情] │
│ Trae(开发)     clipboard ⚠ 只能人工   1 小时前 ⚠ 无接口可测  [视觉自检][加成员][详情] │
│ （不可用的行：整行灰 + 一句话原因，按钮置灰，不给假按钮）                        │
└──────────────────────────────────────────────────────────┘
┌ ③ 详情（点某行才出现，抽屉）──────────────────────────────────┐
│ 顶部永远写清「这是谁的」：<名字> · <协议> · <harness_id>            │
│ 里面才是：桥配置 / 激活方式 / 视觉脚本 / 会话与通道                    │
└──────────────────────────────────────────────────────────┘
```

**三条硬规矩**（治"乱"）：
1. **一屏只做一件事**：① 是入口，② 是现状，③ 是细节 —— 别把"脚本激活/架桥/送话/框选"平铺成一堆卡片；
2. **每个动作都带主语**：按钮上必须写着"给**谁**做"（点进去的抽屉标题就是它），不许出现无主的"脚本激活 / 架桥"；
3. **空壳零容忍**：不可用的一律"灰 + 原因 + 不给按钮"；点下去没反应的按钮等于骗人。

## 3. 后端已就绪（这次已实现，前端直接用）

| 端点 | 干什么 |
|---|---|
| `POST /api/docking/harness/{id}/test-now` | **即刻测一次**，按协议自动选测法：<br>`mcp` → 真调 `initialize`+`tools/list`，回工具数与名字；<br>`http`/`http_api` → 真 GET，回状态码；<br>`file_poll`/`pending_poll`/`clipboard` → 如实说"没有可调接口"，指向视觉自检/验证间；<br>其它 → 指向 `/verify`。**结果写进档案 `metadata.last_test`** |
| `GET /api/docking/overview` | 每条 harness 现在带：`last_test`（上次结果）/ `needs_visual_session` / `joinable` / `next_step`（协议型与桌面型分开写） |
| `POST /api/workshop/{ws}/members` | **加成员**：MCP/HTTP 类**不需要新建会话**，直接加进来就能派活（后端已验证可加） |

真机实测：MCP 那条 → `ok=true，3 个工具，201ms`；桌面那条 → `ok=false，如实说"没有可调接口，去视觉自检"`。

## 4. 「空壳应用」怎么清（两类，分别处理）

1. **数据里的假条目**：已清过一批（2026-10-24 删了 4 条测试注册的垃圾 harness）；以后**不带令牌、没有协议、没有绑定**的登记，`overview` 里直接标"空壳（不可用）+ 原因"，界面按第 2 节灰掉；
2. **界面上的假入口**：凡是"点了必须还有前置条件却不告诉你"的按钮，一律改两条路之一 ——
   **要么给前置条件的一句话 + 去哪儿做**，**要么直接置灰并写原因**。

## 5. 前端要做的（照第 2 节重排，别加新功能）

- 删掉现在散落的卡片区（脚本激活 / 架桥 / 送话 / 框选各占一块），收进 ③ 抽屉；
- ② 表每行加 `[测一次]`（调 `test-now`，把返回的 `detail` 直接显示在行内）；
- 行内显示 `last_test`（时间 + ✅/⚠ + 一句话原因）；
- 抽屉标题固定写「<名字> · <协议> · <harness_id>」。

## 6. 不做的事（避免又长出一堆）

- 不做"多选批量测试"（先一行一次，够用再说）；
- 不做"协议参数编辑器全集"（注册时该填什么由平台探测补齐，缺的用 400 说清）；
- 不在大厅里做工作间的配置（大厅只做模板，工作间那边另说）。
