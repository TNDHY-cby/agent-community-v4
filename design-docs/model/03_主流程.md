### 4.1 如何**激活一个 agent 新会话**（操作 + 契约）

> ⚠️ **本节讲"激活"，别与"接入"混**（老板规则 20 的教训）：
> **接入**（本节上方步骤 0 ＋ 下方五步话术）解决"**这个 harness 怎么接到平台、怎么架桥**"；
> **激活**（本节）解决"**接进来之后怎么给它开一个新会话并命名**"（步骤 4/7/8/9）。
> **接入的五步**：注册 → 配叫醒 → 起桥 → 自检 → **持久跑桥**；
> 判据：**前 4 步绿＝配置可行，第 5 步绿＝真的接上了**（少第 5 步，平台派的活只会躺在队列里没人取）〔实测 2026-10-13〕。

**一句话**：平台**调用该 harness 注册时提交的 `new_session` 脚本**（`<python> 脚本 --input payload.json`），
**脚本在 stdout 打印 JSON 自证**；没配脚本就走**人工指引**（不算失败）。

**① 注册时先准备好**（步骤 0，`POST /api/harness/register`）：
```json
{
  "harness_id": "示例Harness-A",          // 必填
  "ai": { "model_name": "示例模型" },      // 必填
  "scripts": {
    "new_session":    { "NEW_SESSION_CMD": "python my_new_session.py",  "foreground": "never" },
    "rename_session": { "RENAME_CMD": "python my_rename.py \"{new_name}\"", "foreground": "never" },
    "deliver":        { "DELIVER_CMD": "python my_deliver.py",          "foreground": "never" }
  }
}
```
`scripts.*` **可选**；`foreground` 决定"能不能自动"（`never/optional/required`）。

**② 三条激活路径**：
| 场景 | 怎么触发 | 条件 |
|---|---|---|
**开工自动** | 在工作间点「开工」`POST …/start`（先跑 4/7/8/9） | **配了 `new_session` 且 `foreground ≠ required`** |
**批量** | `POST …/onboard-members`（body 省 member_ids＝全体） | 同上 |
**单个 / 没自动时** | 成员卡按钮 或 `POST …/member/{mid}/establish-session` | 手动，随时可用 |
**换会话（上下文老化）** | 成员卡「停用通道」→「新建通道」：`channel/retire` → `channel/establish` | 先停后建；序号 +1；自动补做步骤 5 |

**③ 你的脚本要怎么写**（最小契约〔源码 `action_scripts.py:160-201`〕）：
```python
# my_new_session.py  ——  平台这样调用你：
#   python my_new_session.py --input <payload.json>      环境变量 AC_ACTION=new_session
#   payload 例：{"name_hint": "<平台给的名字>"}
import json, sys
payload = json.load(open(sys.argv[sys.argv.index("--input") + 1], encoding="utf-8"))
# …在这里真的去开一个新对话（调你的 harness 的 CLI/API/无头入口）…
print(json.dumps({"action": "new_session",
                  "evidence": {"session": {"id": "<会话id>", "name": payload.get("name_hint", "")}}}))
```
- **判定**：退出码 0 且 stdout 有 JSON ⇒ `ok=True`；给了 `evidence` ⇒ **`verified=True`（才算成功）**；
  没给 `evidence` ⇒ `verified=False` ⇒ 界面显示「**⚠ 待人工/未核实**」（准则⑤）；
- stdout 没有 JSON / 脚本不存在 / 超时 ⇒ `ok=False` + `error`（**如实报，不假成功**）。

**④ 没配脚本时（人工模式）**：平台**不报错**，而是给出 `manual[]` 指引（例："请新建一个对话（随后平台会重命名为：…）"），
并把可复制的投递文本落成 `<隔间>/deliver_text.md` —— **人工做完即等效**，平台只是不把它标成"已自证"。

**⑤ 命名与重命名**（步骤 7/8）：名字由**平台生成**：`<工作间id>-<项目>-<职位>-<成员id>[-序号]`，
写进 `session_aliases[0]`（**身份凭据**，放首位）；重命名靠 `rename_session` 脚本，没配就人工复制粘贴。
