## 5. 数据落点模型

```
<AC_DATA_DIR>/                       # 默认为仓库内 data/；隔离实例必须改（AC_DATA_DIR）
├─ workshops/
│  └─ ws_<短id>/                     # 一个工作间目录
│     ├─ hall.md                     # 大厅内容（任务原文）
│     ├─ AGENTS.md                   # 工作间级指引
│     ├─ <职位>_<成员id>/            # ★隔间（该成员**唯一可写**目录；可被继任者继承＝已实现，V53）
│     │  ├─ input/ output/ temp/     # 〔源码 compartment.py:41 SUBDIRS〕
│     │  ├─ inbox/ replies/          # ★邮箱（平台只往他自己投）〔:47 MAILBOX_SUBDIRS〕
│     │  ├─ scripts/                 # 该成员的动作脚本（new_session/rename_session/deliver.py）
│     │  ├─ bridge.py                # 当前通道的桥（换通道时归档到 channel_<序号>/）
│     │  └─ deliver_text.md          # 未配 deliver 脚本时的人工投递文本
│     └─ library/                    # ★共享资料库（全员可读）
│        ├─ README.md plan.md        # 索引与规矩；分工安排（**平台自动生成，勿手改**）
│        ├─ framework.md + framework.history/   # 项目框架（可编辑；覆盖前自动备份）
│        ├─ model.md + model.history/          # ★项目模型（五块；保存前备份）
│        ├─ integration.md           # 阶段整合清单（平台生成）
│        └─ <agent名>-<职位>/assignment.md      # 每人一个分工文件夹
├─ verify_sandbox/                   # ★低耗验证间（**一次性**，拆了就没了，只留模板）
│  └─ vs_<harness_id>/验证员_v0/      #   验证间自己的隔间（发探针用）；`compartment_removed: true` 后目录已删
└─ （审计 ring 上限 500、`handover_receipts.json` 等）

<仓库内>/agent_community/bridges/        # ★桥的**另一个**落点（不在 AC_DATA_DIR 里）
├─ <harness_id>/bridge.py               # `bridge/generate` 省略 out_dir 时的默认落点；
│                                       #   ⚠️ `out_dir` 必须在这个目录内，否则 400
│                                       #   含**真实 Agent-Token**（扫描器跳过此目录：不随仓库出去）
└─ （.bridge.lock = 单实例锁文件）
```

**谁可写**：成员 → **只写自己隔间**；`library/` 是**共享区（共识产物）**；`plan.md` 平台自动生成勿手改。
**桥有两个合法落点**：① 隔间里的 `bridge.py`（工作间通道用，换通道时归档）；
② `bridges/<harness_id>/`（**接入侧持久跑桥**用，话术第 5 步的默认位置）。**别混**：验证间的桥在 `verify_sandbox/` 下，拆间即删〔源码/实测〕。
