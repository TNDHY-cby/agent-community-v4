## 6. 接口面模型

**实测挂载端点共 369 个**〔口径由 `tests/test_model_docs.py` 钉死：遍历 `app.routes` 并展开 `_IncludedRouter.original_router.routes`，去掉 `HEAD/OPTIONS` 与 FastAPI 自动挂的 4 条文档路由，再按 `(method,path)` 去重〕。按域分组（实测）：

| 域 | 端点数 | 说明 |
|---|---|---|
| `/api/workshop/{ws_id}/…` | **112** | 工作间主域：讨论/成员/会话/通道/资料库/整合/恢复 + **v5 的名单/证据/闸门/派活/目录/产物/验收/归档/结构化消息/控制台上下文** |
| `/api/harness/{harness_id}/…` | **51** | 接入后的 harness 侧操作（含注册/桥/探测/工具面） |
| `/api/docking/…` | 39 | 对接中心（登记/自检/话术/一键配置） |
| `/api/tasks/…` | 15 | 任务与状态机（v4 视图） |
| `/api/workshops/…` | 11 | 工作间集合级操作（搜索/证据/巡逻） |
| `/api/room/…` | 9 | 早期讨论室模型（v4 经典流程遗留，仍在） |
| `/api/monitor/…` `/api/peers/…` `/api/handover/…` | 各 8 | 监控室 / 点对点对端 / 交接 |
| `/api/mind/{agent_key}` | **6** | **v5 心智根**（建/读/追加记忆 + **待审队列：列表 / 读原文 / 记审批 / 落地 apply**） |
| `/api/ailp/types` | 1 | **AILP 2.0 字段表**（唯一真源，前端照它渲染卡片） |
| `/api/lead-roster`、`/api/harness-tooling` | 各 1 | **v5 入口**：组长候选 / harness 工具面与"能不能当组长" |
| `/api/protocols` | 1 | 协议目录（每项带 `layer`+`semantics`+`status`） |
| `/mcp` | 2 | 平台当 **MCP 服务器**（POST 调用；GET 如实 405） |
| 其余（`/api/policy` `/api/plugins` `/api/relay` `/api/peer-tasks` `/api/task` `/api/agents` 等） | 各 1~6 | 策略/插件/中转/对端任务/任务/员工 |

**2026-10-18 新增/确认的关键端点**（都取自 `routers/`，一处真相）：

| 端点 | 作用 | 谁在用 |
|---|---|---|
`GET /api/version` | 版本事实：`current` / `install_dir` / `data_dir` / `update_safety` / `notes`（**不联网猜**） | 一键更新插件、前端 |
`GET /api/version/latest` | **只读**查远端最新版（10s 超时 + 60s 缓存；**失败如实给 `error`，绝不把"查不到"说成"已最新"**） | 前端「检查更新」按钮 |
`POST /api/workshops/{id}/search-request` | 派"信息搜索"任务（V55：平台不搜，搜索由 agent 做） | 工作间 |
`POST /api/workshops/{id}/evidence`、`GET …/evidence` | 信息卡（证据）写入/读取；默认**不回摘录原文**（限量再分发） | 工作间 |
`POST /api/workshops/{id}/patrol`、`POST …/patrol/{id}/result`、`GET …/patrols` | 巡逻员派单/回报/列表（V56：**"它说修好了"不算修好**，必须复验） | 恢复链第 2.5 步 |
`GET /api/harness/register-prompt` | 六种协议各自的**登记话术**（示例 JSON **原样可提交**） | 对接中心「复制话术」
`GET /api/harness/mcp-config` | **把本平台挂成 MCP 服务器**的照抄配置（`http` 给桌面类＝`{"url": "<地址>/mcp"}`、`stdio` 给命令行类；解释器/仓库根/地址都是运行时算出的；令牌不进配置）＋ `format=md` 给人看 | 对接中心「让它挂上平台」（`V104`）
`POST /mcp` | **平台当 MCP 服务端（HTTP）**：`initialize`（回 `Mcp-Session-Id`）/ `tools/list` / `tools/call` / `notifications/*`；工具表与 stdio 版**同一份** | 对方的 agent 自己来调（`V104` §7）
`POST /api/progress` | **它在干活时报一步**（`text` / `task_id?` / `kind=step|note|block|done`）—— 平台只记录它自己报的 | 界面「工作过程」（`V105` §6）
`GET /api/progress` | 看「工作过程」：按时间正序（可按 `harness_id` / `task_id` 筛） | 同左
`GET /api/harness/{id}/progress-guide` | 给它的引导：干活时怎么报进度（含「顺手写进你自己会话」） | 对接中心「复制要求给它」
`GET /api/mcp/calls` | **它到底来没来过**：每次调用的客户端名 / 工具 / 成败 / 时间；**空＝一次都没来过**（别拿"平台调它的插件"当证据） | 界面「它来过的证据」（`V104` §7）
`GET/POST /api/docking/harness/{id}/truth-config` | **真相核对**的配置：登记对方应用自己的库文件（保存前**真打开一次**：文件/表/列不对就 400 并列出实际表列） | 对接中心「真相核对」（`V102`）
`POST /api/docking/harness/{id}/truth-check` | 现在就去库里查一次口令：`code` 0=有 / 1=没有 / 2=核对不了（**2 既不算通过，也不算"库里没有"**） | 对接中心；`test-now` 会自动跑同一份逻辑（`platform/session_truth.py`）
`POST /api/docking/harness/{id}/test-now` | 带 `text` 就真发；回包里 `delivery_mode`（`plugin_db_write`／`tool_call_only`／`platform_mcp_server`）、`delivered_to_agent`、`received`（进了它的库）与 `answered`（**它自己生成**的消息）、`verified`（口令带回）、`truth_verified`、`agent_reply`、`app_alive`；`wait_ms` 控制等多久再读 | 对接中心第 ④ 步（`V102`/`V103`/`V104` §7） |

**按流程归属**：接入类 `harness/register`；激活类 `establish-session`/`deliver-bridge`/`onboard-members`/`channel/*`/`recover*`；
工作类 `ailp`（结构化讨论）/`tasks/{seq}/review`（验收）/`evidence-view`（证据只读）/`dispatch`（派活）/`integrate-report`/`members`/`start`；只读 `members-status`/`offline-report`/`compartments`/`library`/`roster`；v5 自验 `members/{seq}/handshake`（A 档口令）/`bridge-probe`（B 档桥取件）。

> ⚠️ **2026-11-01 修**：本行原来列了 `discuss` 与 `select-members` —— 两者**都已退役**
> （`410 FREECHAT_RETIRED` / `410 AI_SELECT_RETIRED`），现行讨论入口是 `POST …/ailp`，验收是 `POST …/tasks/{seq}/review`。

> ⚠️ **自省注意**：FastAPI `include_router` 的路由在 `_IncludedRouter.original_router.routes` 里，
> 只遍历 `app.routes` 取 `.path` 会**漏掉全部子路由**〔源码/实测〕（写法见 `tests/test_sessions_v15.py::_mounted_paths()`）。

## 6.1 协议分层（**按层说能力，不排名**）

| 层 | 谁在做 | 协议 |
|---|---|---|
| ① 身份与意图 | 平台（名单/成员/组长/方向） | —— |
| ② 任务契约 | 平台自研（回执 + 任务账本 + 证据 L0~L4 + 闸门四要素） | —— |
| ③ 传输与调用 | 适配器（各自独立进程） | **MCP＝工具面** · A2A＝对等任务语义 · ACP＝会话轮次 · HTTP/gRPC＝通道 · 桥＝文件 · WS＝事件流 · pipe＝同机 |
| ④ 触达 | 三档 | 协议唤醒 / 桥标记 / 人工 |

> MCP **只**表达「它调我的工具」，不表达身份、任务归属与验收；SSE 未实现（目录里写明）。
>
> 组织形态（Cell 拓扑）与团队资产、分层治理的**模型骨架**见 V116 **§22~§24** —— 它们都在第①层（身份）与第②层（契约），
> **不需要新协议**（选票/计票/危急度都是平台自己的状态机）。
