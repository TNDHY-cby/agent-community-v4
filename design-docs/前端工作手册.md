## 1. 五个必知事实（不知道这五条，写出来的一定返工）

1. **前端不是独立的**。页面 → `server.py`（FastAPI）→ `platform/`。
   **界面里每一个"当前阶段/能不能按/该显示什么"都必须来自后端**，不许前端自己算——
   前端自己算过的东西，**刷新就打架**（实测：点了"结束讨论"，前端把变量改成 selecting，
   后端仍是 `discussing`，**刷新打回一级讨论**）。

2. **工作间有五步，且"一步一步来"是这个产品的核心**：
   `① 一级讨论（和平台 AI）→ ② 选定员工 → ③ 二级讨论（组长）→ ④ 工作中 → ⑤ 三级讨论`
   **谁负责哪一步**：①②⑤ 平台 AI / 组长介入；③④ 才是"员工干活"。
   ⇒ 界面**不该在第一步就把第四步的按钮摊出来**（原话：「有一些按不了，我不知道怎么按」）。

3. **"一条桥 = 一个具体会话"**（老板 2026-10-11 定）。
   桥是**平台派生**的东西：通用桥模板存在 harness 上（**一个 harness 只允许一条**，裁定 1B），
   在工作间里渲染成**该成员专属的桥产物**（落它自己的隔间）、并绑到它的具体会话。
   ⇒ 界面**不许让用户填路径**（路径由平台派生），也不许自己拼模板名（要显式传）。

4. **失败必须说话**（准则⑤，本项目的硬规矩）。
   反例（都真实发生过）：消息压邮箱没人取但平台一声不吭；选人失败界面把后端的原因吞掉；
   叫醒命令没配但显示"已配置"。⇒ 任何"没做成"都要在**点击处**给出**原因 + 怎么办**。

5. **改前备份、改完真刷新再看**。备份后缀只能用 `*.bak` / `*.bak_<日期>` / `*.old_` / `*.before_*` /
   `temp/*`（发布脚本与开源 `.gitignore` 靠这些后缀排除）；**新备份放 `temp/`，别再堆进 `frontend/`**。
   前端不硬刷新（Ctrl+F5）看到的是旧画面，**别拿旧画面下结论**。

## 2. 判断"这段 UI 该不该显示"的唯一正确来源

**权威接口**（都在真实例实测过）：

| 你要知道什么 | 查哪个 | 权威字段 |
|---|---|---|
当前是第几步、这一步**该按什么** | `GET /api/workshop/{ws}/sidebar` | `stage.id/index/label`、`visible_actions`、`more_actions`、`blocked_reason` |
成员状态 / 孤儿 / 桥 | `GET /api/workshop/{ws}/members-status` | `members[].orphan*`、`channel`、`bridge_ref`、`harness_id` |
消息**送到没有** | `GET /api/workshop/{ws}/delivery-status` | `headline`、`stuck_reason`、`advice` |
**通没通**（四态） | `POST /api/workshop/{ws}/member/{mid}/self-check` | `state=ok/no_reply/not_picked/not_set_up` |
四种桥型「该填什么」 | `GET /api/bridge-catalog`（+ `/{kind}`） | 每型：`谁提供/怎么填/怎么自证/常见坑` |
职业候选 | `GET /api/role-catalog` | `groups`（**别在前端再抄一份**） |
某个 agent 的通用桥模板 | `GET /api/harness/{hid}/bridge-templates` | **至多一条**（裁定 1B） |
叫醒命令配了没 | `GET /api/harness/{hid}/wake` | `configured`、`status_text` |

**判断规则（照做就不会返工）**：
1. **阶段相关内容**：一律以 `sidebar.stage` 为准，**先渲染 `visible_actions`**，
   次要的进「更多」（`<details>` 默认**收起**）。**不要**在前端维护阶段判断表。
2. **"还没走到的阶段"**：**保留、灰显、标明"到这一步自动可用"、并禁用其内部控件**。
   ⚠️ **不要隐藏**（我藏过一次，老板直接问"三级讨论区怎么没了"——藏掉就看不到全貌）。
3. **拿不到数据时**：**降级显示全部入口**（不藏），并明说"阶段接口暂不可用"，不许留白。
4. **孤儿成员（agent 已删）**：**先查注册表**（`/api/harness/list`）确认它还在，
   **再去查它的模板** —— 否则会去打一个必然 404 的接口，
   而**浏览器只要收到失败响应就记控制台红错**（JS 里判 `resp.status===404` **挡不住那条日志**）。

## 6. 两条新增教训（2026-10-11 收尾时补，都有真实事故）

**① 验收脚本编号要先确认，别撞号。**
我把 V41 的桥模板验收写成 `fe25_check.js`，而 **示例Harness-F 的 FE-25（看板汇总）同时用了同一个文件名**
⇒ 提交时**互相覆盖**（实测：他的 `9dbca11` 盖掉了我的脚本；我的 `9a89c96` 实际只落进 `register.html`，
**提交标题却写着"新增 fe25 验收"** —— 连提交信息都失真了）。
⇒ **规矩**：新增 `verify/*_check.js` 前**先看目录里已有哪些编号**，必要时在协作通道确认；
提交后用 `git show --stat` 核对**实际落盘的文件**，别只信提交标题。
（我的那条已改号为 `fe26_check.js`。）

**② 比较"剪贴板/文本相等"前要归一，否则会把正常差异认成"正文丢了"。**
示例Harness-F 排查 FE24 时踩到：Windows 剪贴板把 176 个 `LF` 变成 `CRLF`，
源 5407 字符 vs 剪贴板 5583 字符 ⇒ 看着像"复制内容不一致"，**其实内容没丢**。
⇒ 比较文本前先归一换行（`CRLF→LF`）再逐字符比。
同理两处**度量陷阱**：`<details>` 关闭后 `getClientRects()` **仍可能返回矩形**
（判可见要用 `checkVisibility()`）；`offsetParent` 对折叠内容也不可靠。
**凡是"看起来坏了"的测量结论，先怀疑度量方式，再怀疑产物。**

## 7. V53 隔间继承：成员卡要显示什么（**2026-10-17 新增，前端契约**）

员工换人后，继任者可以**继承前任隔间里的产物**（后端已实现：`platform/inherit.py` ＋
`POST|GET /api/workshop/{ws_id}/member/{member_id}/inherit`）。前端要做的只有两点：

1. **成员卡显示「继承自 X」**：读 `GET /api/workshop/{ws_id}/members-status` 里新增的三个字段
   `inherited_from` / `inherited_at` / `inherit_note`（如「搬 12 项 / 跳过 2 项 / 失败 0 项」）；
   没继承过时 `inherited_from` 为空 ⇒ **不要凭空显示「继承已完成」**。
2. **替换成员时给一个「从谁继承」的选择**（同工作间内的成员）；不选就是**不继承**——
   平台**不会替你猜**（400 会明说）。

⚠️ 三条不许：① **不许自己在界面算「搬没搬」**（判定在后端；`verified` 是逐项核对出来的）；
② **不许**把「跳过项」藏起来（要能展开看到原因：超限/撞名不一致/邮箱不继承）；
③ **不许**覆盖继任者自己改过的文件——后端会拒绝覆盖，界面照实显示「未搬运（内容不同）」。

继承文全文可读：`GET …/inherit` 返回 `legacy_text`（超 32 KiB 会 `legacy_truncated=true`）。

## 8. V54 登记面板：**「把这段话发给你的 AI」是首选**（2026-10-17 拍板，前端契约）

后端已就绪：**`GET /api/harness/register-prompt`**

```
GET /api/harness/register-prompt?wakeup_method=<协议>&harness_id=<可选>&format=text|json
→ {"prompt": "<整段话术>", "wakeup_method": ..., "known_protocol": true|false,
   "platform_url": ..., "supported_protocols": ["http_api","mcp","acp","file_poll","clipboard","http"],
   "note": ...}          # format=json 时另给 minimal_json / steps / bridge_kind / source
```

**面板怎么摆（两栏，同一张卡）**

| 栏 | 内容 |
|---|---|
| **首选**「把这段话发给你的 AI」 | 一个**协议选择器**（六选一 + "我还不确定"）→ `<pre>` 话术（只读、可滚动）+ **复制按钮**（成功要有反馈）+ 一句"它注册完，你回来刷新即可" |
| 次选「或者你自己填」 | 现有的平台探测表单（① 探测并登记 / ② 只存草稿），**保持不动** |

**三条不许**（与预检一致）：
1. **不许前端自己拼话术**——文本必须来自上面那个端点（否则又是两份口径）；
2. **不许把"复制成功"说成"注册成功"**（三态如实：复制 ≠ 注册 ≠ 验证）；
3. 不许在话术/界面里写死端口或本机路径（地址由后端给）。

**选"我还不确定"时**：`known_protocol=false`，话术是"先自测四项 + 六种对照"——**照实显示**，
不要把某一档硬塞给用户（平台不猜）。
