## 三、逐项设计

### 3.1 `identity.py`（P1 身份凭证）

**新增文件**：`agent_community/platform/identity.py`（原样搬运，63 行）

机制：`HMAC-SHA256(config.agent_token_secret, harness_id)` → 64 位 hex；
消息头 `x-agent-token`；token 存 `HarnessInfo.metadata["agent_token"]`，随既有 `harnesses.json` 持久化（**不新增存储文件**）。

**配套改动**：

| 文件 | 改动 |
|---|---|
| `agent_community/config.py` | `DEFAULT_CONFIG` 增加 `agent_token_secret: ""`；首次使用时由 `identity._ensure_secret()` 生成 `secrets.token_hex(32)` 并 `save_config` 持久化 |

**挂接点（V-9 主线精确位置）**：

| 位置 | 改动 |
|---|---|
| `platform/routers/harness.py` `register_harness()`（L173） | 注册成功后：`existing = info.metadata.get("agent_token") or issue_agent_token(info.harness_id)`；写回 `metadata["agent_token"]`；响应体返回该 token。**幂等**：已存在则复用 |
| `platform/routers/harness.py` `harness_message()`（L289） | 准入处校验：目标 harness 已签发 token 时，要求 `x-agent-token` 匹配 → 缺失 401 / 不匹配 403 |
| `platform/routers/harness.py` `harness_task_result()`（L342） | 同上 |

**兼容策略（关键）**：**只对"已签发 token"的 harness 强制校验**。存量未签发 token 的旧 harness 一律放行，
不做强制升级、不做批量补签。→ 老桥零改动继续跑。

**统一校验辅助**：在 `platform/identity.py` 内新增一个 `check_request_token(headers, harness_id) -> tuple[int, str] | None`
（返回 `None` 表示放行，否则返回 `(http_status, error_message)`），三个挂接点共用，避免逻辑三处漂移。

### 3.2 `audit.py` + `GET /api/audit`（P2 审计）

**新增文件**：`agent_community/platform/audit.py`（原样搬运，79 行）
纯内存 ring buffer + 惰性追加写 `data/audit.json`，上限 500 条，任何异常仅打印不阻塞。

**新增文件**：`agent_community/platform/routers/audit.py`
```
GET /api/audit?limit=&event=&actor=   → {"events": [...]}   # 只读，时间倒序
```
`limit` 需夹紧（`1..500`，默认 100），非法值回落默认，**不抛 500**（沿用 4.2.2 的输入健壮性教训）。

**挂接点**：

| 事件 | 位置 |
|---|---|
| `harness.register` | `routers/harness.py` L173 末尾（与 P1 签发同一处） |
| `workshop.create` | `routers/workshops.py` L101 |
| `workshop.review` | `routers/workshops.py` L751 |
| `workshop.complete` | `routers/workshops.py` L784 |

**单例归属**：`audit_log` 定义在 `platform/audit.py` 模块级。
相对导入在 `__main__` 与 `agent_community.platform.server` 两个副本下都解析为同一个绝对模块名
`agent_community.platform.audit`，**不产生 V-9 记录在案的"模块双副本状态分裂"**，无需进 `state.py`。
（若要更保守，可在 `state.py` 加一行 `from .audit import audit_log  # noqa` 再导出，二者等价。）

**必须在 `router` 注册处挂载**：`server.py` 中与其它 router 并列 `app.include_router(audit_router)`。

设计稿原定 `platform/mcp_server.py` / `platform/a2a_server.py`。**实测该位置不可用**：

`agent_community/platform/__init__.py:3` 有 `from .server import app, agents, tasks, discussion_rooms`
—— 任何 `platform.*` 子模块一被导入，就会连带执行整个 `server.py`（FastAPI + uvicorn +
静态前端挂载），且 `server.py` 会向 **stdout 打印启动横幅**。

后果：`python -m agent_community.platform.mcp_server` 的 MCP 协议流第一行是横幅而不是 JSON-RPC，
**MCP 客户端会直接解析失败**；同时 "零第三方依赖" 的宣称也不成立（实际依赖 fastapi/uvicorn）。

**修正**：两个文件迁至 `agent_community/` 顶层包（其 `__init__.py` 是惰性的），
调用方式变为 `python -m agent_community.mcp_server` / `python -m agent_community.a2a_server`。
迁后 stdout 纯净、真正零第三方依赖。**这是对设计意图的实现，不是增删设计。**
