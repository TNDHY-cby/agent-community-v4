## 2. 维护约定（防止模型被历史污染）

1. **只写当前口径**：任何"曾经怎样 / 旧版写的是什么 / 已停更"都不进模型——那是 `CHANGELOG.md` 的活。
   （真需要解释"为什么这么定"，写一句**理由**就够，不要写版本号与旧数字。）
2. **数字必须实测**：分册里的行数/条数/份数，改代码后**同一次**更新，否则守卫会红（见 §3）。
3. **一处真相**：同一个事实只在一处写全，其余分册只放**一句结论 + 链接**。
4. **拆而不散**：新增内容先判断属于哪个分册；跨两册的，写在更"上游"的那册并让另一册链接过来。
5. **改分册要回主索引核对**：主索引 §0 那十条是"给新人的五分钟版"，口径变了要一起改。

## 3. 守卫（模型文档不许漂）

- `agent_community/tests/test_model_docs.py`：
  - 主文件 ≤ **200 行**、每个分册 ≤ **400 行**（超过就该再拆）；
  - 主文件 §1 里列的**每个分册都必须存在**，且每个 `model/*.md` 都被主文件引用（不许有孤儿）；
  - 主文件与分册里**不许出现历史污染标记**（如"旧版"、"已停更"、"原实现"、以及具体旧数字）。
- `agent_community/tests/test_design_index.py`：设计稿索引与文件不许漂移（含 `model/` 分册）。
