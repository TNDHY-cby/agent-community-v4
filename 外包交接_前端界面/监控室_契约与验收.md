## 1. 端点（全部已实现，服务在跑）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/monitor/health` | 能不能用/编码/上限/帧率/AI 状态（**一处真相**，页面据此决定亮不亮） |
| GET | `/api/monitor/agents` | **选择器**：能开哪几个、为什么不能开、现在开没开 |
| POST | `/api/monitor/watched` | **就地开关**：`{harness_id, on:true|false}`（可选 `hwnd`/`title` 手动指定窗口一次） |
| GET | `/api/monitor/watched` | 已开名单（画面墙用） |
| GET | `/api/monitor/{hid}/frame?max_w=320` | 一帧 **PNG**；放大就 `max_w=0` |
| GET | `/api/monitor/sources` | 可抓窗口列表（**只在"手动指定一次"时**用） |
| GET | `/api/monitor/{hid}/stream` | 本版**永远 501**（只做快照墙）——界面别放这个按钮 |
| POST | `/api/monitor/{hid}/observe` | 观察：`{changed, diff_ratio, still_for_seconds, note, ai:{ran,why}}` |

## 2. 页面结构（两栏 + 顶栏）

```
┌ 顶栏：正在看 N 路 / 上限 6        [AI 观察 ○关闭] ┐
├───────────────┬────────────────────────────────┤
│ 候选 agent 列表 │ 画面墙（只放已开的）              │
│ ○ 已架桥的      │ ┌────────┐ ┌────────┐          │
│ ● 正在看        │ │ 320 宽 │ │ 320 宽 │  ← 点击放大 │
│ ✕ 不能开(原因)  │ └────────┘ └────────┘          │
└───────────────┴────────────────────────────────┘
```

- 列表数据 = `/api/monitor/agents`；开关 = `POST /api/monitor/watched`；
- 画面 = `<img src="/api/monitor/{hid}/frame?max_w=320&t=<时间戳>">`，
  **每 `1000/fps` 毫秒换一次 `t`**（别同时开多路高频请求；默认 1 帧/秒）；
- 放大 = 同一个端点 `max_w=0`（原尺寸），弹层显示；
- 顶栏"正在看 N 路" = `watched_on`，上限 = `max_watch`。

## 3. 显示规则（判据）

| 字段 | 怎么显示 |
|---|---|
| `eligible=false` | 置灰 + 显示 `bridge.why` 原话（如"先去把桥测通"）；**仍要列出来** |
| `window.can_capture` | `true` 正常显示；`false` 显示 `window.why`；**`null` = "还没试过"**（灰字，别标红） |
| `monitor.state` | `running` / `stopped`（附 `why`，比如"超过 60 秒没人看，已自动停抓"） |
| `observe.note` | 有值就显示（如"画面已经 12 秒没变化（可能卡住了…）"） |
| `ai.ran=false` | 显示 `ai.why`，**不要**当错误标红（默认关是设计，不是故障） |

## 4. 绝对不要做

1. 不要做"连续视频"按钮或 WebSocket 推流（`/stream` 501）；
2. 不要让用户填窗口句柄/挑进程——认不出来时给"手动指定一次"入口就够了（`/sources`）；
3. 不要把 `can_capture=null` 显示成红/失败；
4. 不要隐藏不可开的 agent（用户需要知道为什么开不了）。

## 5. 验收（自己跑一遍就算过）

1. 打开页面 → 顶栏显示 `正在看 0 路 / 上限 6`；
2. 列表里出现已注册的 agent；不可开的行置灰并显示原因；
3. 点某个已架桥 agent 的开关 → `POST /watched` 200 → 瓦片出现真实画面（PNG）；
4. 点瓦片 → 原尺寸放大（`max_w=0`）；
5. 关掉 → 瓦片消失，顶栏路数减少；
6. 把被监控的窗口**最小化** → 瓦片应显示具体原因（"最小化时系统不渲染内容，抓不到"），
   **不是**一张黑图、也不是空白；
7. `GET /api/monitor/health` 的 `supported=false`（非 Windows）时，整页显示"该功能只在 Windows 上支持"。
