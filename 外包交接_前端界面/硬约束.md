## 1. 职责边界：对接中心 ≠ 说明书

| | 对接中心（你在做的这页） | 流程说明（`hub.html`） |
|---|---|---|
| 干什么 | **当场办事**：登记、探测、脚本激活、建会话、送桥、抢救、通道 | **只讲不做**：讲清流程与边界 |
| 页面正文 | **动词 + 操作面**（按钮/输入/结果） | 说明与图 |

- 对接中心**只做接入与激活**；**讨论与工作一律留工作间** ⇒ 代码里出现 **`/discuss` 即 FAIL**。
- **正文不许出现教程式段落**（"三步骨架""怎么自己验证通了没""自测"这类 ＝ 说明书特征）。
- 对接中心里**最多留一条**「去流程说明 ↗」链接（指向 `hub.html`）；现在页面里的讲解内容要**搬回 `hub.html`**，不是删掉。

## 2. 第一屏＝各种功能模块（老板裁定的）

**第一眼看到的就是"我们能替你做哪些事"** —— 一屏**功能模块**（卡片/瓦片），每块点进去**当场办**。
不是点名册优先、也不是排障台优先。

为了能自动验收，**只需要一个锚点**：每块功能模块上带 `data-dock-service="<id>"`，id 取下面这 8 个（≥6 块）：

```text
register           登记一位新员工      script_activate    脚本激活（本版核心）
archive            员工档案（含详情）   session_bridge     建会话 / 送桥
onboard_recover    批量对接 / 掉线抢救  channel            通道停用 · 新建
bridge_helper      架桥辅助            ask_frontdesk      问前台
```

模块**列得出来、点得下去、办完有结果**；办不成**当场说清为什么、下一步你去哪**。

## 3. 写请求白名单（**页面里非 GET 的请求只能落在这 17 条上**）

```text
POST /api/harness/pre-register
POST /api/harness/probe-register
POST /api/harness/register
POST /api/workshop/*/onboard-members
POST /api/workshop/*/recover-scan
POST /api/workshop/*/member/*/establish-session
POST /api/workshop/*/member/*/deliver-bridge
POST /api/workshop/*/member/*/recover
POST /api/workshop/*/member/*/channel/retire
POST /api/workshop/*/member/*/channel/establish
POST /api/harness/bridge-path
POST /api/harness/bridge-verify
POST /api/harness/auto-connect
POST /api/assistant/chat
POST /api/docking/locate            ← FE-26 新增（只读语义，但走 POST 带 body）
POST /api/docking/try-activate      ← FE-26 新增（试投一次；**只能由界面按钮调**）
POST|GET /api/docking/harness/*     ← FE-26 新增（档案读写；`*` 是 harness_id）
```

- **`GET` 不受本白名单限制**（白名单管的是**非 GET**）。本版另外新增两条**只读 GET**：
  `GET /api/docking/keyword-suggestions?harness_id=…`（候选关键词，**每条带出处**）
  与 `GET /api/docking/harness/{id}/export.ps1`（脚本 `.ps1` 副本下载）。
- **写请求只有一条通道**：一个包装函数（当前实现叫 `dockPost()`，**请保留这个名字**），
  它内部查 `DOCK_WRITE_WHITELIST` 常量（**请保留这个常量名与这 17 条内容**）。
  白名单是"权限面"的判据，绕过它就等于没有闸。

## 4. 三态如实（**不许"看起来成功"**）

| 状态 | 界面必须显示 |
|---|---|
| `verified === true` | 「✓ 已自证 / 完成」**才可以**出现 |
| `verified === false` / `null` / 缺失 | **一律**「⚠ 待人工 / 未核实」 |
| 失败 | **当场说清原因 + 下一步去哪**（后端有中文 `error` 字段，**原样显示**） |

- **任何路径都不许出现"完成"字样**，除非 `verified === true`（反向断言）。
- **失败必须说话**：不许出现"点了没反应"的死状态；空状态要给**动作**（点什么）而不是给解释。

## 5. 两个入口、同一页面（`V34` §1）

- `/docking.html` = **总控**（跨工作间）；`/docking.html?ws=<工作间id>` = **锁死单间**。
- 同一份 HTML／JS 用 `?ws=` 区分（**不是两套界面**）；请保留 `URLSearchParams` + `DOCK_GLOBAL` 这套判断。
- **单间模式不出现工作间选择器**（否则工作间入口能看/动别的间）；**注册是全局能力，只在总控出现**。

## 6. 脚本激活工作台（本版核心，四屏）

照 `FE-26` §3.1 的口径：**① 用户填关键词 → ② 让 agent 去定位 → ③ 落成具体视觉激活脚本**。

| 屏 | 界面要办的事 | 用到的端点 |
|---|---|---|
| 屏 1 填关键词 | 输入框（多个关键词用 `|` 分隔）＋**可点即填的候选**（每条显示出处）；候选**由平台给**，别自己编 | `GET /api/docking/keyword-suggestions` |
| 屏 2 让平台去找 | 按钮「让平台去找」；逐条显示 窗口标题 / 进程 / pid / 能不能注入 / 匹配分；**找不到要说清试了什么 + 给"把关键词放宽"的下一步** | `POST /api/docking/locate` |
| 屏 3 确认 + 试投 | 选中候选 → 按钮「就是这个窗口，试一次」→ **三态如实**回报（送出去≠送到了） | `POST /api/docking/try-activate` |
| 屏 4 成稿保存 | 显示**脚本正文**（可看、可复制、可手改）＋按钮「保存为该员工的激活方式」；保存后能**导出 `.ps1` 副本** | `POST /api/docking/harness/{id}` ＋ `…/export.ps1` |

**边界（`FE-26` §3.3，别越线）**：生成候选/定位/生成正文/解释为什么 —— 平台 Agent 可以自动做；
**试投**与**保存**必须**用户点**（一次一按、可审计）。平台**不会**替你动桌面。

## 7. 员工档案「详情」（老板裁定的四块，可看可改）

每行一个「详情」按钮 ⇒ 同一页抽屉（不跳页），四块：

```text
① 框架性能（harness_type / version / transports / tools[] / ai.capabilities ＋ 平台算出的档位事实：只读）
② 适配模型（ai.* ：model_name / provider / capabilities / max_tokens / can_see / can_code …）
③ 具体桥模板（该 harness 选的桥模板 ＋ bridge_dir ＋ bridge_status）
④ 激活方式（wakeup_method 及其那一支字段 ＋ **视觉激活脚本本体**）
```

改完**必须回显平台重新判定的事实**（换了 `wakeup_method` ⇒ 档位事实跟着变）；
**不许"改了但界面还显示旧的"**。保存走 `POST /api/docking/harness/{id}`（**不重建会话/桥**）。

## 8. 反私人定制（老板原话：「以后再这样搞私人定制我们就死了」）

- **不许写死只有某台机器才有的东西**：端口、`localhost:数字`、绝对路径、真实 harness 名、用户名。
- 示例一律**虚拟名**：`示例Harness-A`、`sk-your-key`、`api.example.com`。
- 地址一律**相对路径**（`/api/...`）；需要完整地址时用 `location.origin`，不要写死主机端口。
- 判据：**换目录 + 换端口 + 换数据目录、不改一行代码能走通**。
